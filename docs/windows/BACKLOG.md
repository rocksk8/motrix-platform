# 各視窗的待辦佇列

> **使用者 2026-09-22 裁示：「你安排，避免讓視窗閒置。」「排程交給你安排，我要結果。」**
>
> 🔑 **那是常設規則，不是一次的安排** ⇒ 所以它需要一個落點，
> 而不是靠 A 每次記得。〈修作法不要修結果〉。
>
> **A 維護這個檔**（B／C／D 讀，不寫）。
> ⚠️ **這個檔不是權威規格** —— 條文在 `STATE.md`，這裡只排順序。

---

## 📐 運作方式

```
1  每個視窗手上永遠是一個「佇列」，不是一件事
2  做完一件 ⇒ 直接往下一件，不要回來問
3  整個佇列做完 ⇒ 回報並向 A 要下一批，⚠️ 不要空著
4  被擋住（等別人交件、等 A 裁示）⇒ 明著講「我在等什麼」，並跳到佇列裡的下一件
   🔑 〈握著鎖的一方沉默成本不在自己身上〉：「進行中」不是合法回報
```

### ⚠️ A 的義務（寫下來，因為它是最容易漏的一側）
```
任何視窗回報「做完了」而 A 沒有立刻補上下一批 ⇒ 那個閒置是 A 造成的
⇒ A 要維持這個檔至少比目前進度多兩件
```
📌 已經發生過一次：**A 叫 C 停手，而 C 待寫的正好是打包守門在等的那四條**
⇒ 損失一次 7 分 11 秒的全量測試。**停手條件與交付條件之間沒有橋。**

### 🔴 一支測試只涵蓋一條編號（2026-09-22 新增，C 提）
今天有 **五次**「寫了但編號對不上」（SO6／WB3／YA3／YB2／BR2），**五次都是同一個動作**：
**把兩條規格折進一支測試**，而守門只看得到其中一條，然後報「另一條沒有人寫」。
⚠️ **守門目前看不出「一支測試涵蓋兩條」** ⇒ **那是這五次的共同成因。**
🔑 而 C 對其中一次的自評值得留著：
> 「我把 **YA1 的位置用在 YA3 的內容上** —— 而我今天早上才叫 A 去查同一類。
> 那不是『忘了』，是**我知道那個陷阱而沒有去對編號** ——
> **記得有陷阱，不等於檢查過自己有沒有踩到。**」
