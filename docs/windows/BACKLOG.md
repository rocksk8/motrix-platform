# 各視窗的待辦佇列

> **使用者 2026-09-22 裁示：「你安排，避免讓視窗閒置。」**
>
> 🔑 **那是常設規則，不是一次的安排** ⇒ 所以它需要一個落點，
> 而不是靠 A 每次記得。〈修作法不要修結果〉。
>
> **A 維護這個檔**（B／C／D 讀，不寫）。
> ⚠️ **這個檔不是權威規格** —— 條文在 `STATE.md`，這裡只排順序。

---

## 📐 運作方式

```
1  每個視窗手上永遠是一個「佇列」，不是一件事
2  做完一件 ⇒ 直接往下一件，不要回來問
3  整個佇列做完 ⇒ 回報並向 A 要下一批，⚠️ 不要空著
4  被擋住（等別人交件、等 A 裁示）⇒ 明著講「我在等什麼」，並跳到佇列裡的下一件
   🔑 〈握著鎖的一方沉默成本不在自己身上〉：「進行中」不是合法回報
```

### ⚠️ A 的義務（寫下來，因為它是最容易漏的一側）
```
任何視窗回報「做完了」而 A 沒有立刻補上下一批 ⇒ 那個閒置是 A 造成的
⇒ A 要維持這個檔至少比目前進度多兩件
```
📌 今天已經發生過一次：**A 叫 C 停手，而 C 待寫的正好是打包守門在等的那四條**
⇒ 損失一次 7 分 11 秒的全量測試。**停手條件與交付條件之間沒有橋。**
