## §1 判準

> ### 一筆資料被放棄了，而**沒有任何地方說它被放棄**。

```
for row in rows:
    try:
        …
    except Exception:
        continue          # <= 這一筆沒了，而迴圈結束時沒有人知道少了幾筆
```

### 🔑 它與「有沒有 `continue`」不是同一個問題

```
✅ 合法：多路徑輪詢（讀不到就試下一個）
✅ 合法：這一筆本來就不該處理（過濾）
🔴 違規：這一筆**應該**被處理，而它被丟掉了，**且沒有計數、沒有 log**
```

### ☠️ 最貴的形狀：**成功的會寫 log，失敗的不會**

`archive.py` 的 `_prune_cloud_backups`：
```
刪掉一個過期備份   => 寫 log
名字不合法而跳過   => **不寫**
=> 那個目錄**永遠不進保留政策**，而 log 上看起來一切正常
```
🔑 〈防護的副作用落在盲側〉的教科書形狀：
**你看得到它做了什麼，看不到它沒做什麼。**

## §6 修法：**迴圈要有一個計數器，結束時報一次**

```python
skipped = 0
for row in rows:
    try:
        …
    except Exception:
        skipped += 1
        continue
if skipped:
    logger.warning("prune_cloud_backups: 跳過 %d 筆（名稱無法解析為日期）", skipped)
```

### 🔴 **不要每一筆各 log 一次**

```
☠️ 一個壞掉的來源會產生幾千行 log ⇒ 真正的訊息被洗掉
📌 〈告警必須有速率上限〉：設計時就要想「失控時怎麼關掉」
```

### ⚠️ 而「報一次」要報**在使用者看得到的地方嗎？**

```
分兩種：
甲 **背景批次**（備份保留、排程）=> log 就夠，**而要有人會去看**
乙 **使用者觸發的查詢**（報表、儀表板）
   => 🔴 回應裡要帶「**這次略過了 N 筆**」
   ☠️ 否則使用者拿到一份**少了幾筆而看起來完整**的報表
   🔑 而報表的用途就是拿去做決定 —— 少的那幾筆不會有人發現
```

⇒ §3 的「報表／儀表板」那 6 處屬**乙**，其餘多屬甲。
📌 而甲乙的分法**要 B 逐處判**，§3 的分組只是起點。

## §7 驗收（`AC1`）

```
① 後端  37 處每一處都有判斷結果；要改的那些有計數器 ＋ 結束時報一次
        乙類（使用者觸發）的回應要帶 skipped
② 前端  乙類的畫面要顯示「本次略過 N 筆」
        ⚠️ 而 N=0 時**不要顯示** —— 常態下多一行雜訊會讓它被忽略
③ 頁面  ⓐ 種一筆壞資料（例如名稱不是日期的備份目錄）-> 跑一次
           => log 裡有「跳過 1 筆」
        ⓑ 乙類：種一筆壞資料 -> 開報表 => 畫面說「略過 1 筆」
        ⓒ 負對照：全部資料正常 -> **不出現任何略過訊息**
           🔑 少了 ⓒ，「永遠印一行跳過 0 筆」也會綠
```
