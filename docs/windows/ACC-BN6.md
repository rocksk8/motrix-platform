📌 而使用者原話點名的是 **4 個概念**：
> 「**報價多少、成本多少、衍生成本、比例最後總利潤多少**」

⇒ **這一格要 A／使用者確認**：獎金單要照抄的是
```

```
⚠️ **在確認之前，不要拿「十二」去驗收** —— 那個數字沒有出處。

```

而退回的理由會是「少了一格」—— 一句**聽起來完全合理**的話。
📌 這就是為什麼驗收表要**自己去數**，不要接收轉述的數字。

```

⑨ round(762,761 × 0.01) = round(7,627.61)             =     7,628  ✅
⑩ 762,761 − 271,320 − 7,628                           =   483,813  ✅
⑪ 483,813 ÷ 2,713,200 × 100 = 17.83…                  =      17.8  ✅

### ☠️ 而我第一次算錯了 —— **這一列留著，因為驗收的人會踩同一顆**

```

   => 十一格裡有 7 格對不起來，我差一點報成缺陷
✅ 實際算法是 `grandTotal` = （items 小計 × (1+稅率)）＋ **人員費用**

## §4 🔴 而這張單上有一個**已經存在的不一致**（不是 B 造成的）

```
第 12 格「與原始報價毛利差異」profitDiff
   完結當下存的值         = **−337,439**
   拿今天的資料重算       = 483,813 − 741,577 = **−257,764**
   差 79,675
```

**原因**：`profitDiff = netProfit − origNetProfit`，而 `origNetProfit` 讀的是
**報價單的 `tot.netProfit`** —— 那張報價單在精算完結**之後**又被編輯過。

☠️ 而畫面上**沒有任何提示**：
```
✅ 承攬商成本改了  => `dispatchStale()` 有黃色警示條（settlement.html:252-262）
🔴 原始報價改了    => **沒有任何警示**
```
🔑 ⇒ **一個已經存在的警示機制，只涵蓋兩個來源裡的一個。**

📌 **對 `BN6` 的意義**：獎金基數讀的是 `settlement.summary.netProfit`（**已存值**，
本例 483,813），**不受這個漂移影響** ⇒ 這一格**不擋 `BN6` 驗收**，
⚠️ 但使用者若把「與原始報價毛利差異」也放進獎金單，**那一格會與精算頁對不起來**。

## §5 拆發那一段：**基數 → 各人 → 餘數**

使用者原話：「**再用這個利潤去拆發比例**」

### 三層，而**每一層都要能單獨核對**

```
第一層 基數      = 真實淨利 = **483,813**（本例）
                   🔑 來源是 `settlement.summary.netProfit` 的**已存值**
                   ⚠️ 不是現場重算 —— 兩者在本例相同，而在漂移的單上會不同
第二層 各人      = 基數 × 各人比例
第三層 餘數      = 基數 × 總比例 − Σ各人
```

### 🔴 餘數那一格**一定要印出來**

☠️ 它最容易被做成「**四捨五入後對不起來而沒有人說**」。

```
驗收句：把畫面上「各人金額」逐筆加起來，
        **必須等於「總發放額 − 餘數」**，一元不差。
⚠️ 而餘數**不可以是負數** —— 負餘數代表發出去的比池子多
⚠️ 餘數也**不可以被平均塞給某個人** ——
   那會讓「各人比例 × 基數」與「他實際拿到的」對不起來，
   🔑 而使用者是拿比例去驗的
```

```
我沒有讀 helpers/bonus.py 的現行實作 —— B 可能正在改它
⇒ 取整方向（無條件捨去／四捨五入）要對照 `SPEC-BN8`，**不是對照程式**

## §6 「可預覽」與「可匯出 PDF」的驗收句

使用者原話：「**可預覽、可匯出pdf**」

```
可預覽
  ⓐ 不離開原視窗（比照報價單與傳票的 modal 預覽）
  ⓑ 預覽內容與匯出的 PDF **是同一份版面**
     ☠️ 兩份版面的失敗模式是「預覽對、印出來不對」，而那要印出來才發現
  ⓒ 未簽核完成時，預覽**看得到**而畫面上要說它還沒完成
     📌 傳票那邊已經這樣做了（`JV11`：預覽隨時可看、匯出才擋）

可匯出 PDF
  ⓓ PDF 上要有**公司抬頭**與**用印欄**（使用者早先裁過）
  ⓔ 用印欄的列數**從簽核設定算**（使用者早先裁過）
  ⓕ 十一格（或 §1 確認後的那一組）在 PDF 上**與畫面逐格相同**
     🔑 ⓕ 要用**這一張真實單**（`MQ-202608-007`）對，不要用測試資料
```
