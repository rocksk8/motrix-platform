## §1 事實（`helpers/startup.py:138`，`main.py:528` **無條件呼叫**）

```python
INSERT INTO users (…) VALUES ('demo', ?, '展示帳號', '**superadmin**', ?, 1, ?, **0**)
_hash_pw("**60575481**")
…
logger.info("已建立展示帳號（demo），密碼 60575481")   # 🔴 **明文密碼進 log**（A 補）
```

```
🔴 role                 = superadmin
🔴 密碼                 = **60575481**，公司統一編號
                          （印在客戶自己匯出的 PDF 頁尾上 —— `reports.py:74`）
🔴 must_change_password = **0**   <= 不強制改密碼
🔴 而它**寫進 `logs/server.log`**（明文）
```

⚙️ 而我查了三件，**三件都空**：
```

③ 授權底座處理了嗎    => **沒有**（`licensing.py` 提到 demo = 0 處）
```

> ### ☠️ **每一個賣出去的安裝都有一個 `demo` superadmin，
> ### 密碼是一個印在他們自己 PDF 上的數字，而沒有辦法關掉。**

## §2 ✅ 資料隔離**是真的** —— 而它**破過兩次**

### ⚙️ 隔離的機制（`routers/auth.py:394` 實讀）

```
username == 'demo' =>
   `reset_demo_db()` ＋ token 帶 `DEMO_TOKEN_PREFIX`
   => middleware 把**每一個後續請求**（含 `_require_user()`／`_audit()`）路由到隔離的 demo DB
docstring 逐字：「**never touches real data**」
```

> ### ⇒ ❌ **不是「客戶資料會外洩」** —— 那個說法不成立。
> ### ✅ 是「**客戶的系統裡有一個他不知道的 superadmin，而它的密碼是一個公開數字**」。
> ### 🔑 **真正的問題不是它能做什麼，是它不該在那裡。**

### 🔴 而「隔離是真的」這句話**要帶註記**（A 交代）—— 而破過的是**兩次**

```
① `f8867ea` fix(DM1)  **本 repo**
   demo 重置時**整張保留 `account_items`** =>
   ☠️ **下一個客戶看得到上一個客戶建的自訂科目**
   commit 訊息逐字：「而它不會報錯——**要到有人在客戶面前打開科目樹才發現**」
② `4130d28` fix「demo 模式背景執行緒隔離漏洞」  ⚠️ **不在本 repo**
```

#### ⚠️ 而 A 給的座標 `4130d28` **在這個 repo 裡指不到**

```
⚙️ `git log -1 4130d28` 在 MOTRIX-ERP => **fatal: unknown revision**
⚙️ 而在 `C:/Users/hichan`（家目錄 repo）=> ✅ 找得到
🔑 成因：MOTRIX-ERP 是 `e6bf102` 那次**拆出來的獨立 repo**，
   而 `4130d28` 是拆分**之前**的 commit
```
> ### 📌 ⇒ **跨 repo 的 commit 座標指不到，而它失敗的樣子是「這個 commit 不存在」** ——
> ### ☠️ 那句話讀起來像「你記錯了」，而實際上它在另一棵樹上。

```
⇒ 引用拆分前的歷史時要**明著寫是哪一個 repo**
🔑 而本規格用 ① 當主要依據 —— 它在本 repo 裡，**任何人都查得到**
```

### ⇒ 那個註記**要怎麼寫**

```
❌ 「隔離從來沒出過問題」        <= 假的
❌ 「隔離不可信」                <= 也不對，機制是對的
✅ 「隔離的**機制**是對的，而它的**邊界**被踩破過兩次 ——
    兩次都不是機制錯，是**有人加了一張表／一條路而沒有想到它**」
```
🔑 ⇒ 那正是為什麼「**它不該在那裡**」比「它做得到什麼」重要：
**一個不存在的帳號，不需要任何隔離。**

## §3 處置：**預設不跑**

### ① 開關，而**預設關**

```
`MOTRIX_DEMO_ACCOUNT=1` 才建立（環境變數；與既有的
 `LICENSE_GATE_ENABLED`／`TENDER_RADAR_ENABLED` 同一個做法）
🔑 判準：**它對客戶零用途** —— 登入後走隔離的 demo DB，看不到他的資料
```

### ② 🔴 密碼**不可以只換成另一個寫死的**

```
☠️ 換成 'demo1234' => 同一個問題，換一個數字
✅ 開關開啟時**產生隨機密碼**並寫進 `_write_initial_credentials()`
   —— 與 `init_default_admin` 同一條路
🔴 而 `logger.info(… 密碼 …)` 那一行**整句拿掉**
   ☠️ 不是「改成隨機密碼所以印出來沒關係」——
      `logs/server.log` 是**永久追加**的，而它沒有輪替（`EM7 §6` 查過它零消費端，
      而「沒有人看」不等於「沒有人拿得到」）
```

### ③ 既有安裝：**停用，不刪列**

```
🔴 開關只管**建立**；既有的由 migration 設 `active=0`
⚠️ 不可以「開關關著就刪掉它」——
   ☠️ 那會在有人正在用展示時把帳號刪掉
⚠️ 而**不要刪列** —— `audit_log` 裡有指向它的歷史
   （demo 登入會寫 `auth.login`，見 `auth.py:420`）
```

### ④ ⚠️ 而 demo DB **檔案本身**怎麼辦

```
`DEMO_DB_PATH` 那個檔在磁碟上，而停用帳號**不會**刪掉它
⇒ 本規格**不動它**（它是空的、隔離的、而且刪它要考慮正在進行的展示）
🔑 而要**寫下來**，否則下一個人會以為停用帳號就清乾淨了
```

## §4 驗收（`AC1`）

```
① 後端  demo 預設不建立；開啟時用隨機密碼；`logger.info(…密碼…)` 那一行拿掉
        既有的由 migration 設 active=0
② 前端  無異動
③ 頁面  ⓐ **全新安裝**（不設環境變數）-> `users` 表裡**沒有 `demo`**
           🔑 ⓐ 是核心
        ⓑ `MOTRIX_DEMO_ACCOUNT=1` -> 重啟 => demo 建立，
           而 `password_hash` **不是** `60575481` 的雜湊
           ☠️ 少了「不是那個雜湊」，「改成另一個寫死的」會綠
        ⓒ 🔴 `logs/server.log` 裡**搜不到 `60575481`**
           ⚠️ 而要**搜整個檔案**不是只看最後幾行 —— 它是永久追加的
        ⓓ 既有安裝（已有 demo）升級 -> `active=0`，**而那一列還在**
           🔑 ⓓ 驗的是「停用不是刪除」
        ⓔ 負對照：升級之後**登入頁與使用者管理頁沒有壞掉**
           （停用一個 superadmin 不可以讓任何頁面 500）
        ⓕ 🔴 開啟開關後 demo **仍然登入得進去且仍然隔離**
           ⚙️ 斷言：登入後 token 帶 `DEMO_TOKEN_PREFIX`，
              且在 demo 裡建一筆資料 -> 用真實帳號登入**看不到它**
           ☠️ 少了 ⓕ，「把 demo 整個拔掉」也會讓 ⓐ~ⓔ 全綠 ——
              而那不是這一件要做的事
```

## §5 守門

```
✅ 釘：`helpers/startup.py` 裡不存在 `60575481`
   （與 `IA1` 的守門同一支，共用母體）
✅ 釘：**提到密碼的 log，密碼的值不可以在字面值裡**
   ⚙️ 母體（`ast` 已數）：`logger.*` 第一個參數是字串常數且提到
      密碼／password／credential／憑證 = **11 處**
   ⚙️ 而其中**真缺陷只有 1 處**：

🔴 startup.py:158   「已建立展示帳號（demo），密碼 **60575481**」  <= 值在字面值裡

✅ 合法 10 處（**印的不是密碼的值**）：
   startup.py:121   「臨時密碼已寫入 **%s**」            <= 印的是**路徑**
   startup.py:191   「使用者 %s 仍使用弱/預設密碼…」      <= 印的是 username
   startup.py:247   「已清除 superadmin %s 的…解鎖密碼」  <= 印的是 username
   startup.py:213 :272  例外訊息（`… failed: %s`）
   auth.py:129      「無法寫入初始憑證檔: %s」            <= 路徑
   email_notify.py:211 :1402  「SMTP credentials not configured」 <= 沒有印任何值
   auth.py:1131 :1210  WebAuthn 診斷（印 credential id／rp_id，**不是密碼**）
```

> ### 🔑 ⇒ 判準寫成**機械可驗**的，而不是「列一份合法清單」：
> ### **提到密碼的字串裡，密碼的位置必須是 `%s`／`%r`，不可以是字面值。**

```
✅ 那條判準**不會過期** —— 合法清單會（多一行合法的 log 就要改清單）
⚙️ 實作：抓那個字串裡「密碼」「password」後面的 token，
   是 `%s`／`%r`／標點／結束 => 合法；是數字或字母字面值 => 紅
☠️ 而它有一個已知的邊界：`f"…密碼 {pw}"`（f-string）——
   ⚙️ 而本 repo 的 logger 呼叫**沒有一處用 f-string**（11 處全是 %-格式）
   🔑 ⇒ 那是**今天的資料的性質**，不是判準的性質 ——
      寫進守門的 docstring，而不要靠人記得
```
