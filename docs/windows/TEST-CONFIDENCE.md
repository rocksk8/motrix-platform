## 三、⚠️ 而 `2,440 過` 說的是什麼，不說什麼


## 七、⚠️ 而「這次多了幾題」不能用 1,440 去減

```
您可能會這樣算：  上次 1,440，這次 2,440  =>  多了 1,000 題
🔴 而那個減法有兩個問題：
   ① 1,440 那一筆**沒有原始紀錄**（見第六節③）
   ② 中間還有一筆 **有紀錄的**：2026-09-22 20:06
```

### ⚙️ 可查證的成長（口徑分開，不要相加）

```
              2026-09-22 20:06      2026-09-23 本次      成長
一般測試            1,831                2,440          +609
畫面測試               53                   73           +20
```
> ### ⚠️ **不可以拿 `1,884` 去減** ——
> ### `1,884` = 一般測試的 **1,831 過 ＋ 53 跳過**（**全部都是一般測試**，那是它的題目總數），
> ### 而 `2,440` **只有「過」的**。拿「含跳過的總數」去比「只算過的」，相減沒有意義。

```
⚠️ 而這兩次紀錄裡有**兩個 53，它們無關**：
   2026-09-22 一般測試的 **53 跳過**
   2026-09-22 畫面測試的 **53 過**
☠️ 而正是這個巧合讓我們第一次算錯 —— 兩種讀法都得到 1,884。
```

> ### ☠️ 而**題數變多不代表品質變好** ——
> ### 🔑 那 609 題證明的是「我們寫了更多題」，不是「系統更可靠了」。
> ### ⇒ 品質那一格的答案在第四節（**20%**），不在這裡。
