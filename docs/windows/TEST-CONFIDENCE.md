## 三、⚠️ 而 `2,440 過` 說的是什麼，不說什麼

```
它說的：  這 2,440 道題，今天在這個版本上會過
它不說的：功能是對的
          —— 題本身可能寫錯，也可能**根本沒有那道題**
```

> ### 🔑 一句話：**綠燈證明「我們寫的題會過」，證明不了「我們該寫的題都寫了」。**

## 四、🔴 而「該寫的都寫了嗎」——這一格我們量得出來，答案是 **20%**

```
我們自己在規格裡標記過的缺口    **190 條**
其中後來真的回頭查掉的            38 條  =  **20%**
剩下沒有回頭查的                 152 條
```

☠️ **而沒有任何東西在看那些缺口** —— 不是測試、不是守門、不是排程。
（掃過整個專案，唯一命中的是一行註解。）

> ### 🔑 ⇒ 所以那 152 條**不會自己變成紅燈**。
> ### ⚠️ 它們的樣子是：**一切都是綠的，而有些事從來沒有被問過。**

```
⇒ 那 152 條裡，「只有您答得出來」的那幾條，
  已經另外整理成 `KNOWN-GAPS.md`（21 條）。
```

## 五、📌 兩個數字要一起讀

```
2,440 過    =>  **深度**：寫出來的那些，今天是好的
20%         =>  **射程**：而我們知道自己漏了什麼、又補了多少
```
> ### ☠️ 只看前者，會得到一個比實際情況樂觀的印象 ——
> ### 🔑 而它**不是錯的**，只是它回答的不是「這套系統可以出貨了嗎」。
