# `SPEC-UP1` · 四個檔名生成點裡有一個短了 8 bit

> 座標：`f4b4307`（工作樹：本檔為新增）
> 作者：視窗 A-2 ／ 2026-09-23

---

## §1 事實

```
backend/helpers/uploads.py:85              uuid.uuid4().hex[:16]   64 bit
backend/helpers/voucher_attachments.py:275 uuid.uuid4().hex[:16]   64 bit
backend/routers/quotations.py:2302         uuid.uuid4().hex[:16]   64 bit
🔴 backend/routers/system.py:584           uuid.uuid4().hex[**:14**] **56 bit**
```

⚙️ 母體：`grep -rn "uuid4()\.hex\["`（排除 `tests/`／`rollback_snapshots/`／`deploy_packages/`）
```
命中 9 處，切開之後：
   **檔名** 生成 = 4 處（上表）
   **id** 生成   = 5 處（`[:8]`）—— `uploads.py:89`／`voucher_attachments.py:278`
                   ／`system.py:588`／`system.py:1720`／（`archive.py:227` 是完整 hex）
⚠️ id 與檔名是**兩種東西**，不要混在一起數 —— `[:8]` 在 id 上不是缺陷
```

## §2 🔴 它違反的是一句**寫死在原始碼裡**的不變量

`backend/routers/vouchers.py:1093-1096` 逐字：

> `voucher_attachments` 的實體檔放在 `/api/uploads/` 底下，那一層的
> 保護完全站在「檔名猜不到」（**`uuid4().hex[:16]`，64 bit**）——**不是
> 站在授權上**：目錄名可猜、任何登入者都進得了。

### ⚙️ 而那句話是**對的** —— 我複驗過整條路

```
GET /api/uploads/{file_path:path}（routers/uploads.py:77）
   有 ?pt=  => HMAC 驗章（1 小時、綁單一路徑）✅ 那是對的設計
   沒有 pt  => `_require_user(authorization)`
              🔴 **只驗「有沒有登入」，不驗「能不能看這個檔」**
=> ⇒ 一個登入中的低權限使用者，**知道路徑就拿得到檔**
```

### ☠️ 而 `system.py:584` 那條路的目錄名**完全可預測**

```
path = f"{url_prefix}/worklog_{wid}/{today}/{fname}"
         └ "projects"   └ **序號**      └ **日期**   └ 唯一的亂數
=> 前三段都猜得到 ⇒ **保護就只有那 56 bit**
```

## §3 🔴 而嚴重度要講準 —— **我不主張 56 bit 可破**

```
56 bit 線上暴力猜 = 每一次猜都要打一次 HTTP
=> 這**不是一個實務上做得到的攻擊**
☠️ 而我若把它寫成「有資安漏洞」，A 會照那個嚴重度排順序 ——
   那會擠掉真的該先做的事
```

> ### ⇒ 這一件的理由**不是**「56 bit 不夠」，而是：

```
① **一致性**：4 個點裡 3 個是 16，1 個是 14
   => 那是**打字**，不是決定（沒有任何註解解釋為什麼這裡要短）
② 🔑 **它讓一句寫死的不變量變成局部為假**
   `vouchers.py` 的 docstring 說「保護站在 uuid4().hex[:16]」
   => 讀到那句話的下一個人**會相信整棵樹都是 64 bit**
   ☠️ 而那句話是這條路上唯一寫下來的保護說明
```

📌 〈散文對工具是隱形的〉的反面：
**這句散文寫得很好、理由完整、位置也對 —— 而沒有任何東西在維護它的真假。**

## §4 處置：**`[:14]` → `[:16]`，零遷移**

```python
# backend/routers/system.py:584
fname = uuid.uuid4().hex[:16] + ext.lower()
```

### ✅ 為什麼不需要遷移既有檔案（實查）

```
讀取  照片記錄裡存的是 `path`（完整相對路徑）=> 讀檔走存下來的字串
刪除  `system.py:623` `fp = os.path.join(base_dir, '..', photo['path'])`
      => **也是走存下來的 path，不重算檔名**
⇒ 舊檔照舊、新檔 16 碼，**兩者並存不會有任何問題**
```

⚙️ 而開發機上**這條路一張照片都沒有**：
```
work_logs 共 2 列，照片總數 = **0**
=> `[:14]` 到今天為止**沒有產生過任何一個檔名**（至少在這台機器上）
🔴 而正式機**未知** —— 我不碰正式機
⚠️ 但由上面那條「不重算」⇒ **正式機有沒有都不影響處置**
```

### ⚠️ 而 `ext.lower()` 那一半**不要順手改**

```
其他三處是 `+ ext`，這一處是 `+ ext.lower()`
=> 那是**另一件事**（副檔名大小寫正規化），而它看起來也像不一致
☠️ 一個「把這行改成跟別人一樣」的修法會把 .lower() 一起拿掉
🔑 本規格只改切片長度，**`.lower()` 保留**
```

## §5 守門

```
✅ 釘：**所有檔名生成點的切片長度 ≥ 16**
   ⚙️ 量法：`ast` 掃 `uuid4().hex[:N]`，取 `ast.Subscript` 的上界常數
      🔴 用 `ast` 不要用 regex —— regex 會撿到註解與 docstring 裡的
         `uuid4().hex[:16]`（`vouchers.py:1094` 那句話裡就有一個）
         📌 而那正是「數程式會做什麼一律用 ast」的一個現成實例
   ⚠️ 只算**指派給檔名變數**的那些，`id` 的 `[:8]` 不在母體內
      => 判準：這個值**有沒有被接上副檔名／寫進 open()**
```

### 🔴 正對照用**合成誘餌**，不可以留著真缺陷當對照（A 的裁示）

```
❌ 錯的做法：把 system.py:584 留成 [:14] 當正對照
   ☠️ 那樣守門在它修好那天就失去正對照，而**沒有人會發現**
✅ 對的做法：測試裡放一段**合成的原始碼字串**餵給掃描函式
   誘餌 A  `fname = uuid.uuid4().hex[:14] + ext`   => **必須亮**
   誘餌 B  `fname = uuid.uuid4().hex[:16] + ext`   => **不可以亮**
   誘餌 C  `"id": uuid.uuid4().hex[:8]`            => **不可以亮**（是 id 不是檔名）
   誘餌 D  註解裡寫 `uuid4().hex[:14]`             => **不可以亮**（ast 看不到註解）
🔑 D 是這把尺唯一會誤報的地方 —— 而它同時證明「我用的是 ast 不是 regex」
```

⚙️ **而誘餌要走受測物那條量測路徑**：
```
誘餌 A~D 要餵給**守門自己呼叫的那支掃描函式**，
不是在測試裡另寫一份判斷邏輯
☠️ 否則量法壞掉時誘餌照樣全綠 => 你會跑去讀別人寫對的碼
```

### ✅ §8⑤ 補查：`[:8]` 是**陣列索引**，不是憑證

```
⚙️ 以 file_id／photo_id 為路徑參數的端點 = **16 支**
   DELETE 15 支 ＋ GET 1 支（`vouchers.py:1081`）
🔑 而**每一支的路徑都先有父資源**：
   /api/quotations/{quote_no}/…/files/{file_id}
   /api/work-logs/{wid}/photos/{photo_id}
   /{voucher_id}/attachments/{file_id}
=> 授權在**父資源**那一層做完，`file_id` 只是在已取出的陣列裡選一項
   （`helpers/uploads.py:103` `next(f for f in existing_files if f["id"]==file_id)`）
```

```
✅ 唯一的 GET（`vouchers.py:1081`）核對得更緊 —— :1120 逐字：
   `WHERE voucher_id = ? AND file_id = ? AND deleted_at = ''`
⇒ **32 bit 在這個位置完全夠** —— 它不承擔任何保護責任
```

📌 ⇒ 這證實了 §1 的切分（**id 與檔名是兩種東西**）
🔑 而它原本是我推的，現在是量的 —— 兩者在文件上長得一樣，所以要標出來。

```
⚠️ 而這條結論的**射程**：它說的是「今天沒有人拿 file_id 當唯一條件」，
   **不是**「`[:8]` 永遠安全」 ——
   ☠️ 哪天有人加一支 `GET /api/files/{file_id}`，32 bit 就變成唯一的保護
   ⇒ 守門要不要釘這一條，是 A 的決定（本規格不釘）
```
