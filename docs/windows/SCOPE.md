# SCOPE — 這一包收哪些編號（只有視窗 A 寫）

> 建立 2026-09-22，因為視窗 C 指出一件結構性的事：
> **「守門是打包的閘門，而它的輸入正在以快過我收斂的速度成長。」**
> ☠️ 那道閘門因此**量不出「還差多少」**：它永遠紅，而紅的原因每次都不同。
>
> 📌 這正是〈迴圈的目標函數〉：**每一輪都成功，而整體愈來愈難完成 —— 問題不在任何一輪裡。**
> ⇒ A 的裁示：**採 C 的第 2 案（閘門與清單再拆）**，不採第 1 案（凍結編號）。
> 🔑 理由：凍結編號是**修結果** —— 下一次發現得快一點，同一件事就再來一次。
> 拆出範圍檔是**修作法**：閘門從此只看範圍內的，而「發現新東西」不再等於「閘門更紅」。

## 🔴 這是權威清單。守門只看這一份。

**規則**：
1. **新編號預設進 `NEXT`**，不進 `THIS`。要進 `THIS` 要 A 明著搬過來。
2. ⚠️ **搬進 `THIS` 的同一個動作要寫理由**，理由只有一種形狀：**使用者的原話**，或**它是 `THIS` 裡某一條的前置**。
3. ⚙️ **反向控制**：`NEXT` 為空時要有人懷疑 —— **不是清完了，是沒有人在往裡面放。**
