## §1 ✅ A 的兩維度讀法**成立**，而實際是**三個維度**

### ⚙️ 實查

```
維度一 簽核  `bonus_awards.status`
             **草稿 ／ 待審核 ／ 簽核中 ／ 已核准**（四個，`bonus.py:812/861` 實寫）
維度二 撥付  `is_paid()`（`helpers/bonus.py:309-321`）—— **推導，不是欄位**
             `voucher_no_payment` 非空（主路：出納開發放傳票回填）
             或 `paid_manually_at` 非空（退路：最高管理者手動標記）
維度三 有效  `voided_at`（已有 `GET /awards?include_voided=`）
```

⚙️ 今天的實際資料（5 張）：
```
status   已核准 × 4 ／ 草稿 × 1
撥付     `voucher_no_payment` 與 `paid_manually_at` **全部是空字串** => 5 張全未撥付
作廢     `voided_at` 全空 => 5 張全有效
```

🔑 而 A 那句「若做成一串互斥標籤，『已審核』與『未撥付』會互相吃掉」——
☠️ 成立，而且**今天就會發生**：切到「已撥付」會是空的，切到「已核准」有四張，
使用者**分不出「沒有已撥付的單」與「篩選壞了」**。

## §2 🔴 A 問的第一格：「送審中」對到兩個狀態 —— **合併，而理由是系統自己的**

### ⚙️ 兩個「要人動手」的地方，都把它們當成**同一個集合**

```python
# bonus.py:843   核准
if status not in ("待審核", "簽核中"):
# bonus.py:903   退回
if status not in ("待審核", "簽核中"):
```

> ### 🔑 **系統在每一個要人動手的地方，都沒有區分它們。**
> ### ⇒ 「還沒簽完的」是一個真實的集合，而它已經被寫成程式碼了。

⚙️ 而兩者的差別只是**進度**：
```
待審核  已送出，**第一關還沒動**
簽核中  至少一關簽過（`nxt = "已核准" if idx >= len(tiers) else "簽核中"`，:861）
=> 兩者**要找的人是同一個**：當前那一關的簽核者
```

### ⚠️ 而合併有一個代價，要處理掉

```
A 的規則：「篩選標籤要與畫面上既有的狀態文字**逐字相同**，不要另外發明一套」
🔴 而「送審中」**不是**四個 status 之一 => 合併等於發明一個新詞
```

> ### ⇒ 解法：**「送審中」是集合的名字，`待審核`／`簽核中` 是成員的名字。**

```
篩選標籤   「送審中」          <= 集合
每一列的狀態欄  `待審核` 或 `簽核中`  <= **逐字不變**
☠️ 畫面上**不可以**出現「這張單的狀態是送審中」——
   那才是發明了一套並行的命名
```
⚙️ 守門釘得到：**`待審核` 與 `簽核中` 這兩個字串仍然出現在列的狀態欄**。

## §4 A 問的第一格（呈現）：**一排頁籤，而且互斥**

### ⇒ 建議

```
全部 ｜ 草稿 ｜ 送審中 ｜ 已核准・未撥付 ｜ 已撥付        ＋ ☐ 顯示已作廢
```

```
草稿            status == '草稿'
送審中          status in ('待審核','簽核中')
已核准・未撥付  status == '已核准' && **!is_paid**
已撥付          **is_paid**
```

### 🔑 為什麼把「已核准」與「未撥付」寫成**一格**

```
使用者列了五個詞，而其中「已審核」與「未撥付」**在結構上是同一批單**
（今天那四張同時滿足兩者）
❌ 做成兩個頁籤 => 同一張單出現在兩個地方，而計數加不起來
❌ 只做「已核准」 => 使用者說的「未撥付」沒有落點
✅ 合成一格且**標籤同時含兩個詞** => 兩個詞都在畫面上，而集合只有一個
```

> ### ✅ 而互斥帶來一個**會自己翻臉**的守門：
> ### **四個頁籤的計數相加，必須等於總筆數。**

```
🔑 其餘每一種檢查都只會說「通過」——
   而加總在分類重疊或漏掉時**會自己算不平**
☠️ 若哪天有人把「已核准」拆成獨立頁籤，這道守門當天就紅
```

⚠️ 而「顯示已作廢」是**獨立的一個核取方塊**，不是第六個頁籤：
```
它是第三個維度（有效／作廢），與狀態正交
✅ 沿用既有的 `GET /awards?include_voided=`，**不要另做一個**（A 已指出）
⚠️ 而勾選之後，作廢單要**併進各狀態頁籤**還是獨立列出 —— 見 §7①
```

## §6 A 問的第二格（空狀態）：🔴 **三種原因裡，有一種說不出來**

```
① 這個狀態現在真的沒有單         => ✅ 說得出
② 有，但被「不顯示作廢」藏起來了  => ✅ 說得出（前端知道自己勾了沒）
③ 有，但**你看不到**（非管理者）  => 🔴 **說不出來**
```

### ☠️ ③ 為什麼說不出來

```
`list_awards` 對非管理者是 `continue` —— **別人的單根本不在回應裡**
=> 前端**不知道**外面還有幾張
```

> ### ⇒ 而「讓後端多回一個『你看不到 N 張』」**不可以做**：
> ### 🔑 那個數字本身就是資訊 —— 他會知道公司這個月發了幾張獎金單。
> ### 📌 而那正是 `BN9` 收緊可見性要擋的東西。

### ⇒ 空狀態的措辭

```
① 「目前沒有草稿狀態的獎金單。」
② 「目前沒有草稿狀態的獎金單。**（已作廢的單未顯示，可勾選上方切換）**」
   🔑 ②只在「有作廢單被藏起來」時才加那一句 —— 而前端算得出來
      ⚠️ 前提是 `include_voided=1` 那一份資料在手上；若不是，
         就**不要顯示那句話**（不要用「可能有」的措辭）
③ 不加任何額外說明 —— **不要暗示「可能有你看不到的」**
   ☠️ 那句話會讓他去問別人，而答案是他本來就不該知道的
```

## §7 🔴 要 A 或使用者裁的兩格

### ① 勾「顯示已作廢」之後，作廢單**併進頁籤還是獨立**

```
甲 併進去（一張已核准後作廢的單，出現在「已核准・未撥付」裡，加個作廢標記）
   ✅ 一個維度一個控制項，最單純
   ⚠️ 而「已撥付然後作廢」會出現在「已撥付」裡 —— 那句話讀起來是矛盾的
乙 作廢單獨立一區（列在最下面）
   ✅ 不會與任何狀態的語意打架
   ⚠️ 而它等於把三維度攤成兩個清單
```
📌 **我傾向甲**，而「已撥付且已作廢」那一格要在列上明著標，不能只靠灰色。

### ② 使用者說的五個詞，我合併成四個頁籤（§4）—— **要不要回報給他**

```
🔑 他列的「已審核」與「未撥付」今天是同一批單，
   而我把它們寫成一格「已核准・未撥付」
⚠️ 若他心裡的「已審核」是指**含已撥付的全部已核准單**，那我做窄了
⇒ 這是一句話就問得清楚的事，**而我不該替他決定**
```

           🔑 ⓓ 是核心 —— 空清單與壞掉的篩選要分得開
        ⓔ **加總自檢**：草稿＋送審中＋已核准・未撥付＋已撥付 == 全部的筆數
