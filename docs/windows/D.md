## §3y · `/api/auth/me` 回不完整的 200 會把權限洗掉

**as-of**：2026-09-22。對象：`deploy_packages/20260922_033314_c4f7c65/frontend`
（＝正式機 08:41 起在跑的那一包）。發現者：D，在建置重現環境時撞到。

### 症狀
畫面變成「**你沒有這個頁面的權限**」，而 `localStorage` 裡的 `role` 與
`modules` 已經被清空。⚠️ **重新載入不會自己好** —— 要等下一次 `/api/auth/me`
回應正確才修回來。使用者看到的是「我的權限被拿掉了」。

### 機制
`frontend/static/sidebar.js:890-907` 取得 `/api/auth/me` 之後，
**無條件**把回應寫回 `localStorage`：

    stored.modules = d.modules
    mods = Array.isArray(d.modules) ? d.modules : []

⇒ 回應是 **HTTP 200 但缺 `modules`／`role`** 時：
1. `d.modules` 是 `undefined` ⇒ 寫進 `localStorage` 把既有值蓋掉
2. `mods` 變 `[]`、`role` 變空 ⇒ `computeFlags()` 的 `has()` 全 false
3. `ni()` 把 `map.html` 收進 `_deniedPages` ⇒ `_showNoPermission()` **替換整個 DOM**
4. 🔴 **那個替換是單向的**：稍後正確的回應修好了 `localStorage`，
   **DOM 不會恢復**，要再載入一次才會。

### 重現步驟
1. 讓 `/api/auth/me` 回 `200` 且 body 不含 `modules`（例：`{"items":[]}`）
2. 開任何一個有模組閘的頁面（`map.html` 最快）
3. 畫面出現「你沒有這個頁面的權限」
4. 檢查 `localStorage.motrix_session`：`modules` 已消失
5. **把 `/api/auth/me` 修回正確，重新載入** ⇒ 第一次載入仍然是拒絕畫面
   （sidebar.js 在 script 解析時就讀了已被污染的 `localStorage`），
   **第二次載入才恢復**

### 判準（這一條的「修好了」長什麼樣）
- 回應缺 `modules` 或 `role` 時 ⇒ **拒絕那一筆，不要覆寫既有值**
- ⚠️ 不可以用真假值判斷：`modules: []` 是合法的（真的沒有模組）而
  `undefined` 是「這次回應沒帶」——**兩件事不同**，要用 `Array.isArray()`／
  `=== undefined` 區分，不要用 `|| []`

### 為什麼它不會被報修
權限被拿掉的使用者會去問管理員，而管理員在後台看到的權限**是正確的**
（資料庫沒被改，只有那台瀏覽器的 `localStorage` 被洗掉）
⇒ 雙方各自看到一致而互相矛盾的事實。
