## §4 🔑 這一件真正要交付的：**一個會過期的判斷，要有重新檢查的觸發點**

### ❌ 不是「把 uploads/ 加上授權」

```
那是一個大改動（16 種子目錄各有各的擁有者規則），
而 `UP1 §3` 已經說明：**檔名猜不到在實務上不是一個做得到的攻擊**
=> 今天沒有已知的外洩事件，也沒有使用者回報
🔑 ⇒ 把它做成緊急修補，是**用一個沒有發生的風險換掉真正該做的事**
```

### ✅ 而要做的是**三件小的**

```
① `vouchers.py:1093` 那句話**加一句射程**
   「⚠️ 這段描述的是**傳票附件**。`uploads/` 底下今天有 16 種子目錄，
     而它們的內容敏感度不同 —— 新增一種時要重新判斷這個代價還接不接受。」
   🔑 ⇒ 讓那句話**說出自己的邊界**，而不是讓下一個人以為它涵蓋全部

② 🔴 **新增子目錄時要有人做一次判斷** —— 守門（§5）
   判準：這個子目錄裝的東西，**被一個不相干的登入者看到會怎樣？**

③ `projects/worklog_*` 那一種**單獨處理**（唯一已知裝位置資料的）
   ⚠️ 而處置要 A 裁：見 §6①
```

> ### 🔑 ⇒ 交付的不是「修好」，是「**下次它變壞時會有人知道**」。

## §5 守門

```
✅ 釘：`uploads/` 的子目錄**清單是封閉的**
   ⚙️ 量法：`ast` 取 `save_document_files()`／`copy_into()` 的第一個位置參數
      ＋ `_photo_root()` 那一條（**它不走那支函式**）
   => 與一份明碼清單比對；多一種 => **紅**
   🔑 紅的訊息要寫：「新增了子目錄 `X`。`uploads/` 底下**沒有授權檢查**，
      任何登入者知道路徑就讀得到。請確認 `X` 的內容可以接受這一點，
      並把它加進 `docs/windows/SPEC-UP3.md §2` 的清單。」

⚠️ 而那三個 `<f-string>` 與兩個 `<變數>` **要明著登記成「動態」**
   ☠️ 否則守門每次都會把它們算成「不在清單裡」=> 永遠紅 =>
      最省力的反應是**把守門拿掉**
   ⇒ 登記形狀：`quotations.py:3189`（動態，前綴 `quotation_`）等

🎣 誘餌（合成）：
   A  多一個 `save_document_files("new_thing", …)`   => **必須亮**
   B  既有 15 種原封不動                             => **不可以亮**
   C  一個走 `_photo_root()` 的新路徑                => **必須亮**
      🔑 C 是關鍵 —— 它是今天唯一被兩份盤點各漏掉一次的形狀
```

📌 ⇒ 這道守門**驗的是「有沒有人做過判斷」**，不是「內容安不安全」。
☠️ 後者寫不出判準，而前者寫得出。
