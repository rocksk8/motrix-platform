## 一、這一包修了什麼（給使用者看的版本）

### 1. 🔴 部署失敗時，畫面不會再騙你

```
以前：勾了「略過自動回滾」而健康檢查失敗 ⇒ 畫面記成「成功」
      —— 而正式機上跑的是一個沒通過健康檢查的版本
現在：那條路會被判定為失敗
```

**同一族還修了四處「安靜失敗」**：

| 原本 | 現在 |
|---|---|
| 製作回滾快照時複製失敗 → **沒有訊息** | 會中止並報錯 |
| 自動回滾時複製失敗 → **不中止，繼續往下** | 會中止並報錯 |
| 手動回滾時複製失敗 → **沒有訊息** | 會中止並報錯 |
| 回滾做到一半失敗 → 畫面說「已還原」 | 說得出「**正在還原、還原到一半**」 |

☠️ **其中「製作快照」那一條最重要**：它做的是**你要回滾時用的那份快照**。
以前失敗不會有任何訊息，**而你要到真的需要回滾那一天才會發現快照是殘缺的**
——那一刻沒有第二次機會。

### 2. 兩道原本可以「安靜關掉」的守門

```
驗包腳本  忘了帶版本參數 ⇒ 以前印個警告就放行，現在直接失敗
migration 兩個視窗同時加同一個版本號 ⇒ 以前要到第一次啟動才爆，現在跑測試就紅
```

### 3. 側欄「財務」

```
✅ 底下從 1 項變成 3 項：營運報表／出納／（之後會再加）
✅ 出納**拆成獨立頁面**（以前是營運報表裡的一個頁籤）
✅ 修掉四處分組權限漏設 —— 只有地圖／庫存／涵蓋度權限的人，
   以前**看不到他被授權的那一項**
✅ 只有出納權限的人，以前會看到一個叫「營運報表」的項目（點進去是別人的頁）
   —— 現在不會了
```

## 二、🔴 這些話**不可以**當成「已驗證」

> 放行清單第 ⑤ 項：交付說明不含超出證據的措辭。以下是逐項的證據天花板。

### (a) 「勾了略過回滾會被記成失敗」——**那一條永遠不會被實測**

```
要實測它，得在正式機上製造一次健康檢查失敗
⇒ **那不是任何視窗該做的動作**
```
⇒ 它的證據是三層：**讀碼 ＋ 靜態值域檢查 ＋ 用合成字串測判定函式**。
**那是它的天花板，不是欠帳。**

### (b) 「財務有下拉選單了」——**只對有出納權限的人成立**

```
有出納權限   財務底下 2 項以上 ⇒ 有下拉面板
只有報表權限 財務底下 1 項     ⇒ 純連結，**沒有下拉**
```
⚠️ **你是超級管理員，所以你一定看得到。而你的員工不一定。**
📌 這不是缺陷，是「只有一項就退化成純連結」那個既有設計的結果。

### (c) 「資金水位沒問題」——**已實看、未逐筆對帳**

你的原話是「比較沒有問題」。自動檢查驗得到「兩頁有沒有讀同一組端點」，
**驗不到算出來的數字對不對**。

### (d) 權限受限的那一側，**沒有人在那個位置上看過**

```
你是 superadmin ⇒ 永遠看到權限最全的那一版
⇒ 只有出納權限的人看到什麼，**你結構上看不到**
```
⇒ 目前只有程式模擬過權限組合（涵蓋不到 CSS 與實際渲染）。
