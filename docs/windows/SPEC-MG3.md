## §1 🔴 因果鏈比「迴圈裡吞例外」更長 —— **它會被 commit，而版號照樣推進**

```python
# db.py:955  _m008_fix_legacy_owner_names(conn)
for r in rows:
    try:
        d = json.loads(r["data_json"] or "{}")
        if d.get("ownerName") in old_names:
            d["ownerName"] = correct
            conn.execute("UPDATE customers SET data_json=? WHERE id=?", …)
    except Exception:
        pass                      # 🔴 ① 吞掉，而**迴圈繼續**
…
conn.commit()                     # 🔴 ② 最後照樣 commit
```
```python
# db.py:854  執行迴圈
for i, fn in enumerate(_MIGRATIONS, start=1):
    if i <= current: continue
    fn(conn)                      # 🔴 ③ **沒有 try、沒有交易包裝**
    _set_version(conn, i)         # 🔴 ④ 而版號照樣 +1
```

### ⇒ 四步合起來

```
① 第 N 筆的 JSON 壞了 => 跳過，而**前面已改、後面繼續改**
② 走到最後 `conn.commit()` => 「**改了一半**」**被寫進磁碟**
③ 沒有例外往上傳 => 沒有任何一層知道出過事
④ `_set_version(conn, 8)` => **下次啟動不會重跑**
```

> ### ☠️ **那一批客戶永遠停在「有些改了、有些沒改」，而重跑救不了它 ——
> ### 因為版號已經推進。**

```
🔑 而它與 `QS1 §2` 的洞 B（比對到 0 筆）**不同**：
   洞 B 是「什麼都沒做」=> 重跑一次就好
   🔴 這一支是「**做了一部分**」=> 重跑也只會從已經改過的狀態再跑一次
⚠️ 而 `_m008` **是冪等的**（改過的 `ownerName` 不在 `old_names` 裡了）
   => 重跑**不會壞**，只是**也不會補**那些壞掉的 JSON
```

## §3 處置：**三件，而第一件與 `MG4` 是同一支 helper**

### ① 迴圈要有計數器，而**失敗要中止**

```python
skipped = []
for r in rows:
    try:
        …
    except Exception:
        skipped.append(r["id"])
        continue
if skipped:
    raise MigrationIncomplete(          # 🔑 **自己的型別**，不是 RuntimeError（見下）
        "m008：%d 筆 customers 的 data_json 無法解析，id=%s。"
        "**這支 migration 未完成，版號不會推進。**" % (len(skipped), skipped))
conn.commit()
```

```
🔑 為什麼是 **raise** 而不是「記一筆 log 繼續」：
   ✅ raise => `_set_version()` 不執行 => **版號停住** => 修好資料後重跑
   ❌ 繼續 => 版號推進 => **那幾筆永遠不會再被處理**
☠️ 而這一格與 `EM7` 的裁定**相反**（那邊是「計數＋結束報一次，不中止」）——
   🔑 差別在**可不可以重來**：
      EM7 的迴圈是**每天跑的排程** => 中止會讓整批停擺，而明天還會再跑一次
      migration **一個版號只跑一次** => 不中止就等於**永久放棄那幾筆**
```

> ### 📌 ⇒ 判準：**「跳過一筆」可不可以接受，取決於「還有沒有下一次」。**

### 🔴🔴 而**光是 raise 不行** —— 查完呼叫端之後處置要改

```
⚙️ `main.py:525  init_db()` 是**模組層級的呼叫**（不在函式裡、**沒有 try**）
=> `_m008` 拋例外 => 模組 import 失敗 => **uvicorn 起不來**
```

> ### ☠️ **一筆壞掉的 `data_json`，會讓客戶的整個系統開不了機。**

```
🔑 而我原本的理由（「一個看得見的失敗比一個看不見的成功好」）**仍然成立** ——
   只是「看得見」不該等於「**完全不能用**」
📌 ⇒ 〈一個限制的代價，要用「他被迫改走哪條路」來算〉——
   而這裡他被迫走的是「打電話說系統壞了」
```

### ⇒ 第三條路：**版號不推進，而系統照常起來**

```python
# db.py:854  執行迴圈
for i, fn in enumerate(_MIGRATIONS, start=1):
    if i <= current: continue
    try:
        fn(conn)
    except MigrationIncomplete as e:      # 🔑 **自己的例外型別**
        logger.error("migration %d (%s) 未完成：%s", i, fn.__name__, e)
        break                              # 🔴 **不 set_version，而且不再往下跑**
    _set_version(conn, i)
```

```
✅ 版號停在 i-1 => **下次啟動會重跑** => 修好資料後自動補上
✅ 系統照常起來 => 客戶能用
✅ 而 `migration_log`（`MG4`）裡查得到「第 8 版沒跑完，是哪幾筆」
```

### 🔴 而 `break` 之後**不可以繼續跑後面的 migration**

```
☠️ 繼續跑的話，系統會在一個「**第 8 版沒做完，而第 9~103 版做了**」的狀態
   => 而版號會說它是 8 => **版號與實際狀態不一致**
🔑 那比「停在第 7 版」危險得多：**版號是所有重跑邏輯的依據**
```

### ⚠️ 而**只有回填型**適用這一條

```
🔴 DDL 型失敗（ALTER／CREATE 失敗）**必須擋住啟動** ——
   schema 不完整而系統起來 => 到處 500，而使用者看到的是隨機的錯誤
✅ 回填型失敗（資料改一半）=> schema 是完整的 => 系統起得來
🔑 ⇒ 判準：**這一支失敗之後，schema 還完整嗎？**
   完整 => 起來（本條）／不完整 => 擋住（維持今天的行為）
⚠️ 而那要靠 **`MigrationIncomplete` 這個型別**來分 ——
   ☠️ 用 `except Exception` 會把 DDL 失敗也放行，而那是更糟的那一邊
   📌 〈用自己的例外型別，讓呼叫端分得出「規則擋下來」與「資料庫壞了」〉
      （`helpers/edit_log.py:46` 的 `MissingOldValue` 同一個做法）
```

### ② 回報走 `MG4` 的 `report_backfill()`

```
⚙️ 而 §1 的 raise 與 MG4 的回報**不衝突**：
   raise 之前先 report_backfill(conn, 8, "_m008", changed=n, skipped=len(skipped), details=…)
   ⚠️ 而那一筆**要在 raise 之前 commit** ——
   ☠️ 否則 raise 之後整個交易回滾，**連「為什麼失敗」都沒留下**
   🔑 那是一個需要**獨立連線**或先 commit 再 raise 的細節，B 要注意
```

### ③ 🔴 中斷**要有一個吵得起來的落點**（A 補的第四件）

> A：「『起不來』是一個很吵的訊號，而『起來了但少做了一半』是安靜的。
> ☠️ **你把它從吵的那一側，推到了安靜的那一側。**」

```
✅ 成立。§3① 的第三條路讓系統照常起來 => 而**沒有人會知道它沒跑完**
☠️ 而今天已經踩到兩次同一件事：
   `EM7`  `logger.warning` 的消費端 = **0**
   `RT1`  `retention` 欄位的讀取端 = **0**（B 今天實查）
```

#### ⇒ 中斷時**多寫一列 `audit_log`**（`_system_audit()`）

```
🔑 為什麼是 audit_log 而不是只有 migration_log：
   `audit_log` **有現成的消費端**（`audit-log.html` 讀的是**表**不是 log 檔）
   而 `migration_log`（`MG4`）的端點與入口**還沒做**
⚠️ 而**只在真的中斷時寫** —— 正常跑完不可以多一列
   📌 與 `EM7 §6` 同一個判準，照抄
```

#### 🔑 而兩個落點**職責不同，不是重複**

```
audit_log      「**第 8 版沒跑完**」        <= 要**被看見**（有頁面）
migration_log  「**是哪幾筆、原值是什麼**」 <= 要**查得到**（明細，量大）
☠️ 把明細也塞進 audit_log => 一次失敗寫幾百列 => 把操作軌跡洗掉
☠️ 只寫 migration_log => 回到「沒有人會去看」
```
