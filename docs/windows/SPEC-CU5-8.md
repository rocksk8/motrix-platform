## CU5 標頭整理＋分頁改名（已落地）
```
第一列   客戶名＋狀態（已成案／待 X／已結案／半解鎖中）· 存檔狀態 ·「更多」·「儲存」
第二列   報價單連結 · 單號 · 專案名
更多     產生專案報告／解鎖／重新上鎖／完結案（完結案仍只給最高管理者）
子分頁   執行管理的「專案資訊」→「成員」
收款     「案件資訊」的收款管理整段（款項明細、請款單、開票申請憑據）搬到「財務」分頁
```
- ⚠️ **財務分頁的可見範圍**：搬家前收款在「案件資訊」，看得到案件的人都看得到（沒有財務檢視權的帳號照 CM13
  遮蔽金額、可登預計收款日／發票／備註；CM14b 出納唯讀模式在這裡登錄收款）。
  ⇒ 為了不讓搬家收掉任何人的權限：**「財務」分頁人人看得到，但只有收款那一段**；應收應付總覽、叫料、精算
  仍只給 `canSeeFinancial()`（與搬家前相同）。
- 健康總覽「前往」：`payment`、`payment_requests`、`invoice_vouchers` ⇒ `fin`（沒有財務檢視權的人照樣去 fin，
  因為那裡有收款）；`settlement` 與額外支出沒有財務檢視權 ⇒ 退回 `biz`。
- 營運報表收款相關清單（未收款、未填日期、收款資料異常）的連結帶 `&tab=fin`，提示文字改「財務 → 款項明細」。
- 出納唯讀的提示在「案件資訊」與「財務」各一份。
- 「完結案」「備注」等用字**沒有改**：屬 CU2（hichan-a3）。

## CU6 標明即時儲存／按儲存（已落地，2026-09-24）
```
即時儲存   人員角色、專案期間、收款管理、叫料清單、設備、執行進度（勾完成／日期／比例／負責人／拜訪）
           ＝改完 1.5 秒自動存（caseRecord）或改了就打 API（階段）
按儲存     承攬商派發、出貨單、完工單（視窗內儲存）、額外支出（逐筆儲存）、叫料（材料訂購）、分配成員
例外       派工／叫料的發票日期、額外支出的發票日期與付款日：在「按儲存」區塊內但改了就自動存（標記的 title 寫明）
```
- 標記：`<span class="save-mode" data-save-mode="auto|manual">`；即時儲存成功 ⇒ 旁邊閃「✓ 已存」1.6 秒。
- ✓ **只掛在伺服器回成功的分支**（`flashSaved()`）：存檔失敗不閃（有題；突變「開始存就閃」⇒ 紅）。

## CU7 表單標籤與必填（已落地，2026-09-24）
- 款項明細每一格、人員角色三格、專案期間兩格：`<label for>` 綁到欄位 id（點標籤 ⇒ 焦點到欄位）。
- 必填 *：已收款期別的「收款日期」「實收金額（含稅）」（後端本來就要求），並設 `aria-required`。
- 勾「已收款」的當下還沒填收款日期 ⇒ 游標帶到日期欄並框紅；**不自動填日期**（收到錢是人的判斷，2026-09-11 既有原則）。
  狀態存在元件（`needReceivedDate[item.id]`），不寫進 item——寫進 item 會跟著存進 data_json。
