# `SPEC-EM13` · 同一句話混用兩套詞彙

> 座標：`08bb8b2`（工作樹：本檔為新增）
> 作者：視窗 A-2 ／ 2026-09-23
> `STATE.md` 原列：「**5 處**」⇒ **複量 6 處**（第 6 個詞是「專案經理」，不是出納／財務）
> ## ⚠️ **相依 `SPEC-EM2`** —— `EM2` 沒落地之前做這一件沒有意義（§2）

---

## §1 判準

> ### 同一句權限訊息裡，一半是**角色**、一半是**模組** ——
> ### 而使用者在畫面上**只找得到其中一半**。

```
「僅管理員、**出納**或**財務**可查閱」
  管理員  => 角色（users.html 的 roleLabels，**客戶可改**）
  出納    => **模組權限**（user_has_module(user, "cashier")）
  財務    => **模組權限**（user_has_module(user, "finance")）
```

☠️ ⇒ `EM2` 把角色名改成動態之後，這幾句會變成
**「一半動態、一半寫死」—— 看起來比現在更一致，其實沒有。**

---

## §2 🔴 相依關係：**`EM2` 先，這一件後**

```
EM2 未落地 => 這 6 句裡的「管理員」還是寫死的
           => 改模組那一半沒有意義（兩半都寫死，至少是一致的）
EM2 落地後 => 角色那一半跟著設定走、模組那一半不動
           => **這時候才會出現不一致**
```
📌 ⇒ 本規格排在 `EM2` 之後。**現在寫是為了讓 `EM2` 落地時不會忘記它。**

---

## §4 🔴🔴 而第 6 處**不只是詞彙混用** —— 它是四個地方三種說法

```python
# routers/material_orders.py:93-95
# 3. 權限檢查：只有 admin+ 或有**報價單編輯**模組的使用者可以修改叫料
if user["role"] not in ("superadmin", "admin") and not user_has_module(user, "project_manage"):
    raise HTTPException(403, "權限不足：只有管理員或**專案經理**可以修改叫料")
```

```
程式檢查   user_has_module(user, "**project_manage**")
畫面標籤   users.html:806   label:'**案件叫料－修改**'
碼內註解   「有**報價單編輯**模組的使用者」
錯誤訊息   「只有管理員或**專案經理**可以修改叫料」
```

> ### ☠️ **四個地方三種說法，而沒有一種是「案件叫料－修改」以外的人找得到的。**

🔑 使用者看到「專案經理」，去「使用者管理 → 權限設定」找「專案經理」——
**找不到**，因為那一格叫「**案件叫料－修改**」。

📌 ⇒ 這一處**同時屬於 `EM10`**（導航指示對不上入口 ／ 指向畫面上不存在的東西）。
⚠️ 而 `EM8` 已裁定併入 `EM10` ⇒ **這一處要在兩邊都登記**，
否則做 `EM13` 的人會只改詞彙、做 `EM10` 的人會以為它不在自己範圍裡。

## §5 🔴 而模組**沒有一份可用的後端標籤表**（實查）

```
backend/trail.py:62  MODULE_LABELS
   ⚠️ 它是 **API 路徑** 對照表（"access-guide" / "approval-queue" / "cashier" …），
      **不是權限模組表**
   ⚙️ 而它**沒有 `finance`**、**沒有「專案經理」**
      （`cashier` 剛好兩邊同名 —— 那是巧合，不是設計）

frontend/pages/users.html:799-811  權限目錄
   ✅ 這是**唯一**一份模組 -> 中文標籤的對照
   {key:'cashier',        label:'出納（標記已匯款/已收款、銀行對帳）'}
   {key:'finance',        label:'應收帳款／銷售訂單'}
   {key:'project_manage', label:'案件叫料－修改'}
   {key:'financial_view', label:'財務金額可視'}
```

### ⚠️ 而 `cashier` 的兩份標籤**不一樣**

```
trail.py:71         "cashier": "**出納**"
users.html:811      label:'**出納（標記已匯款/已收款、銀行對帳）**'
```
🔑 ⇒ 這一件的底層問題與 `EM2` **同構**：**同一個東西有兩份名字，而它們會漂移。**

## §6 處置

### 三條路

```
甲 模組名也動態化
   ⚠️ 需要一份**後端**模組標籤表 —— **現在沒有**（§5）
   => 要把 users.html:799-811 那份搬到後端或做成共用
   ✅ 與 EM2 對稱  ❌ 它把一件小事變成一次資料搬遷

乙 訊息不指名
   「您沒有查閱此頁的權限」
   ✅ 最便宜、詞彙混用直接消失
   ❌ 使用者不知道**要去開哪個權限** —— 而那正是他下一步要做的事

丙 訊息指向**畫面上的那一格**（建議）
   「需要「出納」或「應收帳款／銷售訂單」模組權限
     （使用者管理 → 權限設定）」
   ✅ 照 `EM10` 的兩層判準：目的地是**畫面上找得到的字串**
   ✅ 順便修掉 §4 那一處（「專案經理」-> 「案件叫料－修改」）
```

### ✅ 建議：**丙**，而它需要 §5 那份表**只搬 6 句用得到的鍵**

```
不做全表搬遷 —— 只把這 6 句用到的 4 個鍵寫成一份小常數：
   cashier ／ finance ／ project_manage
   ⚠️ 而**值要與 users.html 逐字相同**
```

**丙這個處置自己的副作用**（分開寫）：
```
⚠️ ① 又多了一份標籤（第三份）—— §5 已經有兩份而且不一樣
      🔑 ⇒ 這一份要配一道守門：**與 users.html 的 label 逐字相同**
      ☠️ 沒有那道守門的話，這一件會製造出它自己在修的那個問題
⚠️ ② 訊息會變長（從 12 字變 30 字左右）
      => 而它出現在 403 的 detail 裡，`EM1` 的「讀者是誰」判準要重看一次
⚠️ ③ `cashier` 的標籤（「出納（標記已匯款/已收款、銀行對帳）」）**很長**
      => 訊息會更長 ⇒ 可能要在 users.html 把 label 拆成「短名 + 說明」
      🔴 **而那會動到權限目錄的資料結構** —— 這一格要 A 裁
```

## §7 驗收（`AC1`）

```
① 後端  6 句都改成丙的形狀；模組標籤來自共用常數不是字面值
② 前端  無異動（除非 §6 ③ 要拆 label）
③ 頁面  ⓐ 用一個沒有 cashier／finance 的帳號開出納頁
           => 訊息裡的「出納」「應收帳款／銷售訂單」**在權限目錄裡找得到**
        ⓑ `material_orders` 那一句不再出現「專案經理」
        ⓒ 照著訊息去「使用者管理 → 權限設定」**真的找得到那一格**
           🔑 ⓒ 是 `EM10` 的驗收方式 —— **照著指示點一次**
```

### 🔴 守門

```
✅ 釘：模組標籤常數的每一個值，與 users.html 的 label **逐字相同**
   ⚙️ 正對照 故意把其中一個改掉 -> 要紅
   ☠️ 沒有這一題，這一件會製造出**第三份會漂移的標籤**
✅ 釘：這 6 句裡不出現「專案經理」「財務」這種**不是任何鍵的名字**
   ⚠️ 判準要釘**已知集合**（模組鍵的合法標籤），不要釘「不可以出現某些詞」
   🔑 〈判準的寬窄都會騙人〉：黑名單擋不到下一個被發明出來的詞
```
