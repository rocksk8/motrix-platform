## 🔴 §2 · 最嚴重：`deploy_dashboard.py` 的防線在一個不一定會執行的分支裡

```python
backend/tools/deploy_dashboard.py
570:  if __name__ == "__main__":
572:      uvicorn.run(app, host="127.0.0.1", port=8765, log_level="warning")
```

**它有 13 支路由、0 個請求層的檢查**（`request.client`／middleware／`Depends`／`_require_*` 全部 0 處）：
```
POST /api/build   /api/deploy   /api/rollback   /api/snapshots   /api/log-tail   /api/check-only
GET  /  /api/dev-status  /api/prod-status  /api/packages  /api/history  /api/jobs/{id}  /api/pre-deploy-check
```

☠️ **`uvicorn deploy_dashboard:app --host 0.0.0.0 --port 8765` 根本不會執行第 572 行。**
🔑 **而這個專案的 ERP 本體就是這樣起的** ——
`autostart.bat:31`／`restart.bat:40`／`start.bat:27` **全部是 `uvicorn main:app --host 0.0.0.0`**。
📌 **同一台機器上的人，用同一個習慣去起 dashboard，防線就沒了** ——
而那時 **`/api/deploy` 與 `/api/rollback` 是無驗證的**。

### ✅ 結構上「掛不上去」這一半是成立的（D 實查）
```
deploy_dashboard.py:67   app = FastAPI(...)   ← 是 app 不是 APIRouter ⇒ include_router 吃不下
main.py 的 include_router × 43               全部是 routers.*
全 repo 引用 deploy_dashboard 的 .py          0 支
```
⇒ **它不會被意外掛到 666 那個對外的 app 上。危險只來自「有人手動這樣起它」。**

### ⇒ 要做的
- **HC1.** 🔴 **防護要放在每個請求都會經過的地方**（檢查 `request.client.host`），
  **不是在啟動分支裡**。📌 那是〈防線要在被保護者身上〉。
- **HC2.** **反向控制**：用 `--host 0.0.0.0` 起它 ⇒ **非本機來源必須被拒**。
  ⚠️ **不可以真的在這台機器上開來測** —— 用 `TestClient` 帶不同的 `client.host`。
