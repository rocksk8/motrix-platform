## §5 🔴 那 40 條 —— **守門看不到它們**

```
46 條導航指示裡，**40 條沒有把目的地寫成可比對的形狀**
而 EM10 原本那 4 條裡就有兩條在這 40 裡面：
   reports.py:874          「請於**系統設定**中配置年度目標後…」
   accounting_export.py:422「（請至**系統設定**填入後再匯入 T100）」
   => 目的地是「系統設定」四個字，**它是一個模糊的指向不是一個名稱**
```

☠️ ⇒ **只做第一層的守門會全綠，而 87% 的導航指示從來沒被看過。**

### 兩層判準

```
① 有引號目的地（「…」／『…』／X → Y）
   => 比對前端可見字串；找不到 = 紅
   涵蓋 6/46

② 沒有引號目的地
   => 守門**要求它加引號**，紅的訊息是
      「這句話有導航語氣而沒有指出一個可比對的目的地」
   🔑 **把「無從比對」變成「還沒寫成可比對的形狀」——那是寫得出判準的。**
```

### ☠️ 而第二層有一個**落在盲側的副作用**

> 守門要求加引號時，**對方最省力的反應是把那句導航整句刪掉。**

```
刪掉之後：守門全綠 ✅
          而使用者**連一個錯的指路牌都沒有了** ⇒ 比原本更糟
```
⇒ **反向控制（必要）**：
```
釘「**含導航語氣的訊息總數不可下降**」（基準 46，寫死在守門裡）
⚠️ 而「基準 46」這個數字會過期 => 每次調整基準要寫理由，
   不可以因為紅了就往下調
```

## §7 驗收（`AC1`）

```
① 後端  5 條訊息的目的地字串 = 畫面上的字串
② 前端  ②那條若走乙案，tender-radar.html 要有固定小標
③ 頁面  **照著每一條指示點一次** —— 這是 EM10 與 EM1 唯一不同的驗收
        ⓐ 從訊息出現的那個畫面出發
        ⓑ 只用訊息裡的字去找
        ⓒ 走得到 = 過
        🔑 ⓑ 是重點：**知道答案的人照著走一定走得到**
           ⇒ 驗收的人不可以是寫這條訊息的人
```
