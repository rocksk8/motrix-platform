## 7. 發現
**S-1（建議）｜差額拆解在「已有單據」時誤導。** `pdf_gen._orig_reserve_note` 與 `reports.py`（`reserve_split`、Excel 欄 24「其中：其他」＝`gp_diff − reserve`）把「報價預留」整額當成差額的一部分。預留沒發生（沒單據）時是對的；但**已有一張等額運費單據**時（我上一份設計文件的範例）：淨利差只有 +50，卻寫「其中報價預留間接成本 5,000」、Excel「其他」＝−4,950。因為實際側已把運費單據算進成本，那 5,000 並非「多賺」。提案：說明改為「報價預留 X；其中已有單據入帳的部分已計入實際成本」，或「其他」欄標明「含已入帳的間接成本單據」；或不顯示「其他」。S。

**S-2（建議）｜舊虧損報價的原始側：頁面與伺服器分配不同，完結後畫面會變。** 報價存的 `charityDonation` 為負（舊公式）時，頁面 `origFloor` 把原始公益金當 0 並讓預留吸收差額（探針：頁面 公益 0／預留 6,950；伺服器 公益 −50／預留 7,000，淨利都是存的 −21,950）。完結時伺服器覆蓋，凍結值＝伺服器的（公益 −50），重新載入後畫面與 PDF 顯示「公益捐款 − −50」。僅虧損且早於本班的報價受影響，金額＝負的 1%。提案：`original_side()` 對 `direct<0` 也把原始公益金取 0（並以 `reserve = totalIndirect − admin − 存的公益金` 保持恆等式，或與頁面同一公式），兩邊同式。S。

**N-1（觀察）**：頁面以 `saved.schemaVersion === 2` 判斷、伺服器 `>= 2`（`settlement.html:1216,1218`）——日後出現 3 會前後不一致；建議頁面也用 `>= 2`。
**N-2（觀察）**：36–38 班已完結的虧損案（存檔公益金為負）在案件頁、營運報表顯示成「− −510」（`case-management.html:2783`、`reports.html:2262` 都寫死「− 」前綴）。只影響顯示；已凍結不改。
**N-3（觀察）**：報價核准理由門檻讀 `tot.netMarginPct`（`quotations.py:114` 清單）。虧損報價新公式的公益金為 0（不再是負），淨利率比舊值低約 0.01×虧損／稅前，可能讓極少數臨界案件多觸發一次「淨利率低於門檻」理由；**未驗證**實際門檻值。
**N-4（觀察）**：見 §2——偽造 v2＋0 與使用者直接填 0 同能力，可接受。
**N-5（觀察）**：作者另有 e2e（`test_e2e_settlement_zero_and_loss_2026_10_05.py`）我沒跑（建包期間）；v2 重存舊草稿、虧損提示文字、報價單虧損提示都只經讀碼確認。
