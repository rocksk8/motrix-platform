| 級 | 項目 | 理由 |
|---|---|---|
| **P0（共同底座，先做）** | 共用元件核心＋H（名稱／小字代碼／標籤／「?」／與預設不同／來源）＋「?」四段說明（由登錄表產生，新增 `SettingDef.when`）＋**草稿＋儲存列＋離開警告＋儲存通知（SPEC §13）**＋**設定中心外框（SPEC §14）**＋設定中心搜欄位 | 所有頁共用；使用者點名的痛 |
| **P1** | #1 信件收件矩陣（76 列）、#2 使用者個人權限（30 鍵×人）、#3 LINE 事件（hichan-6 稿，第一個接入者） | 項目最多、點擊成本最高、最常動（新進／調職） |

## 七、後續票（本次不做，先列出來）

### 7.1 「整包寫入、沒有並行控制」（PM 2026-11-13 提出；h3 盤點發現）
這些儲存路徑是**整份覆寫**，沒有版本或 compare-and-set；兩位管理者同時改不同欄位／不同人，後存的會把先存的蓋掉。批次與「復原這一批」的 CAS（SPEC §5）**目前只涵蓋設定中心與各矩陣頁**，下列不在內：

| 項目 | 問題 |
|---|---|
| `quote-terms-presets`（報價條款預設） | 整包寫入，無並行控制 |
| insurance profile（保險設定） | 整包寫入；兩個管理員改**不同人**仍會互相蓋掉 |
| t100 config | 整包寫入 |
| operating-targets（營運目標） | **只存一年**：設新的一年，舊的那年就消失 |
| bonus rate／split | 分兩次寫入（非原子），中途失敗會留下半套 |

處理方向（後續票）：加 `expected_values` 或更新時間檢查（比照 SPEC §5）；operating-targets 改成逐年保存；bonus 合併成一次寫入。**不在 `feat/settings-matrix-rollout` 範圍。**
