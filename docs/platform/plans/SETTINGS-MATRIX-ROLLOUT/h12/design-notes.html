2. 外框與共同元件（SPEC §14）

  • 頂列：欄位級全域搜尋（點結果跳到該頁並框出該欄）、「待生效 N」、「最近變更」；分段全部｜業務｜財務｜系統｜安全；左側兩層導覽：分類 → 白話群組名（取自 shell_groups.json），旁邊顯示「與預設不同 N」橘點數與 🔴「內含高風險項目」。分類只有這一套，我原本自己的四分類已拿掉。
  • 偏離外框的一處：builder_* 13 個群組合成一頁「自訂功能的開關（13 組）」，因為它們有「總開關＋子開關」的階層，分開 13 頁反而看不出誰沒開；請 PM 認可。「清單與畫面用語」依分類拆成「清單與下載檔名用語」（系統）與「網路規劃、採購、住宿的狀態名稱」（業務）兩頁。
  • 每列：白話名稱＋小字代碼＋標籤（影響大／需外部設定／影響別人／個人／進階；另有「調小＝放寬」「只需等待」）＋來源徽章（預設／公司‧誰‧何時／等待生效／未儲存）；與預設不同的列左邊橘條。
  • 「?」由登錄表產生：這是什麼＝question＋help｜什麼時候要改＝SettingDef.when，逐欄（external_login 14、retention 11、download_name 21 都已逐欄寫在盤點表備註）｜改了會影響什麼＝impact＋riskText｜建議值＝recommended，沒有 recommended 的欄位整段不顯示（external_login 5 欄：三個預設不強制角色、算外網的網址、內網網段）。
  • 重設為預設＝刪除公司設定值（不是寫入預設值）：按鈕有 tooltip，草稿與確認視窗都寫「重設為預設（刪除公司設定）」，儲存後來源徽章回到「預設」。

3. 草稿、儲存與復原（SPEC §13、§5）

步驟樣品怎麼做
點選＝草稿改值、勾格、批次動作都只改畫面；草稿列左黃條＋「未儲存」；頁面頂端固定儲存列「你有 N 項未儲存的修改　[放棄][儲存]」；草稿跨頁保留（外框切換頁面不丟）；有草稿時關閉或重新整理頁面有 beforeunload 警告
儲存 → 確認視窗分區列出：立即生效／要等 N 天才生效（只需等待）／放寬（第二位最高管理者核准＋等 N 天）＋放寬後果／連帶失效／「還不會生效：需先開啟…」／批次略過項目與原因／營運設定「我了解會影響全公司」／通知預覽（最高管理者、受影響角色；高風險另發 LINE；批次合併一則）／變更原因（影響大、安全、等待中的項目必填且 ≥4 字）。天數讀 confirmDays（樣品示意 7，預計生效日現算）
放寬後果文字缺失確認視窗會標紅「登錄表缺少放寬後果文字，不能送出」並鎖住按鈕；樣品建置時另有檢查：任何 loosen 欄位的盤點表文字都必須有「放寬…後果：」句
結果吐司分開寫「已生效 N 項；M 項等待核准／等待生效（預計 ○/○ 生效）；已通知最高管理者」
復原這一批逐欄 compare-and-set：記下這批自己寫入的欄位與值；復原時只有「那些欄位目前值仍等於我套用的值」才回寫（原本沒有公司設定的，回寫＝刪除）；任一欄被別人改過→整批拒絕，顯示「誰、何時、哪一項、值怎麼變」；同群組別的欄位被改不會誤拒。含影響大／安全／等待項目的批次不提供復原（確認視窗先說明）。可用吐司的「（示範）別人剛改了其中一項」模擬

4. 批次規則落地（SPEC §4）

  • 勾選格只給 ① 欄；🔒＝永不批次（滑過看原因）；批次動作只有套用建議值／套用預設組合／重設為預設，沒有「全部開啟」。沒有 recommended 的欄位在套用建議值時略過並寫「這欄沒有建議值」。
  • 批次動作的結果只進草稿，視窗說「已加入草稿 N 項，略過 M 項，還沒有寫入」；要到儲存確認才寫入。
  • 預設組合都是提案：profiles() 目前為 0，所以按鈕與預覽都標「提案」；實作前要先登錄進 registry（list_view 3 組、ui_format 3 組），使用者看過才上線。cases_merge_won_tab 已移出「全部開放」組合（影響所有人看到的案件分頁，單獨設定）。
  • 前置相依補進：list_view 報價單 3 欄 → 報價單管理版面；list_view 案件 3 欄 → 案件管理版面；list_prefs → 改版前先預覽。儲存視窗會列「連帶失效」。
