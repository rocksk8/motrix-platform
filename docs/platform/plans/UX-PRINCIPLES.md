## 1. 六條「看就懂」原則

1. **每一頁回答三個問題**：這是什麼頁？我在這裡能做什麼？下一步是什麼？——標題回答第一題、一句說明回答第二題、唯一的主要按鈕與空狀態回答第三題。
2. **一頁只有一個主要動作**（一顆實心主按鈕）。其他動作降級，而不是並列。
3. **用選的，不要用打的**。凡是系統知道選項的欄位（人、客戶、狀態、日期、月份、單據類型、角色），一律用選單／日期挑選器；不要求使用者記得代碼、格式、逗號分隔、公式、路徑。
4. **用使用者的話**。畫面上不出現資料表欄位名、英文代碼、HTTP 狀態碼、JSON 路徑、內部班次代號；統一用 §6 用語表。
5. **狀態說人話＋下一步**。每個狀態都要讓人知道「現在卡在誰／下一步誰做什麼」；不能只有顏色。
6. **錯誤說原因＋怎麼辦**，永遠保留使用者已填的內容。

> 與既有規格的關係：原則 2、4、5 落實 `UI-HEADER-COLOR-SPEC.md` §2 的「單一 H1＋一句說明＋右側主要動作」與 §3「一種顏色只回答一個問題」。

## 2. 頁面骨架

### 2.1 固定順序（由上到下）

```
麵包屑      一級群組 › 本頁                         （.pg__crumb data-crumb-auto，不手寫一級名稱）
標題        本頁名稱（H1，只有一個）                  （.pg__t）
一句說明    這頁做什麼、什麼時候用（≤ 40 字）          （.pg__s）                 主要動作（唯一實心按鈕）→ 右側（.pg__a）
提示框      只有需要使用者注意時才出現（藍／琥珀）     （.callout / .callout--warn）
篩選列      ≤ 4 個常用篩選＋搜尋；其餘收進「更多篩選」
清單／內容  表格或卡片
分頁或「載入更多」
```

HTML 骨架（沿用現有類別，頁頭規格見 `UI-HEADER-COLOR-SPEC.md` §2）：

```html
<div class="pg">
  <div class="pg__l">
    <nav class="pg__crumb" data-crumb-auto aria-label="目前位置"><span>客戶與業務</span></nav>
    <h1 class="pg__t">客戶管理</h1>
    <p class="pg__s">維護客戶資料與聯絡人；報價單會從這裡帶入客戶。</p>
  </div>
  <div class="pg__a"><button class="btn btn-primary">新增客戶</button></div>
</div>
```

### 2.2 規則

| 項目 | 規則 |
|---|---|
| 標題 | 用「使用者要做的事或看的東西」，不用技術名詞或內部代號。與選單名稱完全相同。 |
| 一句說明 | 寫「做什麼＋什麼時候用」，不寫「本頁提供…功能」。範例：✅「看誰還沒簽、誰簽了。輪到你的單據會排在最上面。」❌「簽核佇列管理頁面」。 |
| 主要動作 | 一頁只有一顆實心 `.btn-primary`，放頁頭右側。清單頁的主要動作通常是「新增○○」；待辦頁沒有新增，主要動作放在每一列。 |
| 篩選 | 常用篩選 ≤ 4 個，預設就是「最常用的情境」（例：預設只看「我的」「進行中」），並顯示目前條件（例：「顯示：我負責的、進行中，共 12 筆」＋「清除條件」）。進階篩選收進「更多篩選」，**不能被收起的是搜尋**。 |
| 清單 | **新人預設欄位 ≤ 7，使用者可自行加欄、並可切「緊湊」密度（沿用使用者偏好，不另建設定）**；第一欄是「單號／名稱」可點進去；狀態用徽章（§5）；金額靠右、日期靠左；每列的操作 ≤ 2 個外露，其餘收進「⋯」。**預設排序要有理由**（待辦＝最急的在前；歷史＝最新在前），並在畫面上寫出來。 |
| 載入中 | 顯示「載入中…」；超過 3 秒要有進度提示；**載入失敗必須顯示原因與「重試」**，不可顯示空白（現有 5 頁會吞錯誤，見 hichan-1 提案 T5）。 |
| 空狀態 | 分三種，各有固定寫法（§2.3）。 |
| 一頁多件事 | 超過一種工作就拆分頁籤（`.tab-bar`／`.tab`），每個頁籤本身遵守本骨架；不要一頁塞多張表。 |
| 頁面寬度 | 內容最大寬沿用 `--v4-max`（1200px）；密集表格可滿版，但表頭要固定。 |

### 2.3 空狀態（`.empty`）三種寫法

| 情況 | 內容 | 範例 |
|---|---|---|
| **還沒有資料**（第一次） | 一句「這裡會放什麼」＋**一個**主要動作 | 「還沒有客戶。客戶是報價單與案件的起點。」［新增客戶］［匯入 Excel］ |
| **篩選後沒有結果** | 說明「目前條件沒有符合的」＋「清除條件」 | 「沒有符合『進行中、王小明』的案件。」［清除條件］ |
| **沒有權限／尚未開通** | 說明「為什麼看不到」＋「找誰」 | 「你的角色看不到成本資料。需要請找最高管理者。」 |

## 3. 按鈕層級

沿用現有類別；**同一層級只留一個寫法**，其餘變體逐步收斂。

| 層級 | 類別 | 外觀 | 什麼時候用 | 位置 |
|---|---|---|---|---|
| **主要** | `.btn .btn-primary` | 實心品牌紅 | 這一頁／這個對話框「最該做的一件事」：新增、儲存、送出 | 頁頭右側；對話框右下 |
| **次要** | `.btn .btn-ghost` | 白底灰框 | 其他一般動作：匯出、篩選、返回、取消 | 主要按鈕左邊 |
| **危險（一般）** | `.btn .btn-danger` | 淺紅底細紅框 | 刪除、停用、移除：可救回或影響範圍小 | 與主要按鈕分開，不並排緊貼 |
| **重大不可逆** | `.btn .btn-reject` | 白底 2px 粗紅框 | 駁回結案、永久刪除：不可逆 | 一律要二次確認（§3.2） |
| **簽核核准** | `.btn .btn-approve` | 實心深綠 | 只用在簽核流程的「核准」 | 簽核區塊 |
| **文字動作** | `.btn-sm`＋連結樣式 | 小字 | 表格列內的次要動作 | 列尾 |

> 顏色規則見 `UI-HEADER-COLOR-SPEC.md` §3：**實心紅＝要我做的事，不是「有問題」**。因此主要動作與危險動作靠**形狀**區分（實心／細框／粗框），不靠色相。

### 3.1 寫法

1. **動詞＋對象**：「新增客戶」「送出簽核」「儲存設定」「匯出 Excel」。不要只寫「確定」「提交」「OK」。
2. 對話框按鈕：**取消（次要）在左、主要在右**；主要按鈕文字要重複動作（「刪除這張報價單」，不是「確定」）。
3. 按鈕**變灰（disabled）必須讓人知道為什麼**：旁邊或提示寫「請先選擇客戶」。現有設定中心「儲存」在原因空白時灰掉且沒說明，屬此類缺陷。
4. 送出中：按鈕顯示「送出中…」並鎖住，避免重複送出。
5. 圖示按鈕必須有文字提示（`title`／`aria-label`）。
6. **收斂**：`.btn-secondary`→`.btn-ghost`、`.btn--ghost`→`.btn-ghost`、`.btn-xs`／`.btn--sm`→`.btn-sm`、`.btn-add`（20 處）視用途改 `.btn-primary` 或 `.btn-ghost`；`.btn-del`→`.btn-danger`。逐頁改，不一次動。

### 3.2 危險動作的確認

| 等級 | 例 | 確認方式 |
|---|---|---|
| 可救回 | 刪除到資源回收筒、停用帳號 | 一句確認：「刪除後可到『資源回收筒』救回」＋［刪除］［取消］ |
| 影響他人 | 改簽核流程、改權限、停用模組 | 先顯示影響範圍（「會影響 8 位使用者、3 張進行中的單據」），再確認 |
| 不可逆 | 駁回結案、永久刪除、清空 | 要求輸入單號或原因，主要按鈕用 `.btn-reject` |

## 4. 表單

### 4.1 結構

| 規則 | 說明 |
|---|---|
| 分組 | 用區塊小標題 `.sec-t` 把欄位分成 3～6 組（例：基本資料／聯絡人／收款）；一組 ≤ 6 欄；最常用的組放最上面，不常用的收進「更多設定」。 |
| 欄位順序 | 依使用者思考順序（誰→什麼→多少→何時），不依資料表欄位順序。 |
| 一欄或兩欄 | 桌機最多兩欄；長文字、地址、備註佔滿一列。手機一律一欄。 |
| 標籤 | 在欄位**上方**，用名詞（「客戶名稱」），不用句子。 |
| 儲存方式 | **每個控制項都明說自己怎麼存；同一區塊內不混用**（細則見 §4.6）。r1 的「全頁統一按儲存」**已撤回**：案件頁的即時儲存是 2026-09-24 使用者表單 CU6 的刻意設計並有專屬 e2e，推翻它會讓每個階段勾選多一次點擊，且把併發編輯的衝突粒度從「一欄」變成「整頁」。 |
| 預設值 | 預填最常用的值，並標明「（預設）」或在說明中寫出；使用者不需要懂就能跳過。 |

### 4.2 必填標示

- 必填欄位標籤後加紅色 `*`，**表單頂端寫一次**「* 為必填」。`*` 要有 `aria-required`／螢幕閱讀器可讀的「必填」。
- 若一張表單大多數欄位都必填，改成標「（選填）」於少數選填欄位。**不要兩種都標。**
- 按下儲存時，**一次列出所有缺的欄位並捲到第一個**，不要一次只報一個。

### 4.3 說明文字放哪裡

| 種類 | 放哪 | 寫法 | 類別 |
|---|---|---|---|
| 整頁／整組說明 | 標題下方一句，或藍色 `.callout` | 這組設定影響什麼 | `.pg__s` / `.callout` |
| 欄位說明 | **欄位正下方**灰字，一句 ≤ 30 字 | 「這欄是什麼＋範例」（例：「報價單上顯示的有效天數，預設 30」） | 統一用 `.form-hint`（取代 `ns-desc`／`hint`／`sc-help`） |
| 範例 | placeholder | **只放範例，不放說明**（欄位一有字就消失，說明會看不到） | placeholder |
| 影響警告 | 欄位下方琥珀 `.callout--warn` | 「改了之後會…」 | `.callout--warn` |

### 4.4 錯誤訊息的寫法

公式：**發生什麼事＋可能原因＋怎麼辦**。位置：**錯在哪個欄位，就貼在那個欄位下方**（紅字 `--danger`，並在頁頂摘要錯誤數）。

| ❌ 不要 | ✅ 這樣寫 |
|---|---|
| 「422 Unprocessable Entity」「[object Object]」 | 「這張單據沒有送出：還缺『客戶名稱』。」 |
| 「申請人尚未歸屬任何部門」 | 「你還沒有所屬部門，所以不能送簽。請找管理者在『組織架構』指定部門後再送出。」＋［前往設定］（有權限者） |
| 「workflow.states[1].approval.tiers[0].when：…」 | 「第 2 個簽核關卡的條件有誤：…」 |
| 「請確認後端伺服器是否在線」 | 顯示伺服器回傳的具體原因；真的連不上才說「目前連不到系統，請稍後再試；問題持續請聯絡管理者」 |
| 「非正式機環境，已擋下寄送（見 _smtp_send_blocked）」 | 「目前這台是測試環境，所以沒有真的寄出。」 |

- 不顯示：HTTP 狀態碼、例外名稱、欄位英文名、檔案路徑、SQL、JSON 路徑。
- **保留使用者已填內容**；失敗後畫面維持原狀態（草稿仍是草稿）。
- 成功也要回饋：「已儲存」（綠，3 秒淡出）；重要動作（送出簽核、核准）要說明**接下來會發生什麼**（「已送給王主任簽核，結果會通知你」）。

### 4.5 用選的，不要用打的（對照表）

| 使用者要填 | ❌ 現況常見 | ✅ 規範 |
|---|---|---|
| 日期 | 手打 `2026/11/13` | 日期挑選器；常用範圍給快捷（今天、本週、本月） |
| 年月 | 手打 `202001` | 年、月兩個下拉 |
| 人（簽核人、負責業務） | 手打帳號 | 可搜尋的人員選單（顯示姓名，不顯示帳號） |
| 客戶、廠商、料號 | 手打名稱 | 搜尋式選單，找不到時給「新增」捷徑 |
| 是／否 | 填 0／1 或打字 | 開關或兩個選項 |
| 類別、狀態、角色 | 手打代碼（`finance`、`purchase_req`） | 下拉，顯示中文名稱；代碼由系統產生並隱藏 |
| 金額 | 手打含逗號 | 數字欄＋自動千分位＋單位（元） |
| 多個選項 | 逗號分隔文字 | 多選核取方塊／標籤輸入 |

## 5. 狀態徽章：配色與意義

**一個狀態只有一種顏色，全站相同。** 顏色之外**一定要有文字**（不靠顏色單獨傳達）。新頁用 `.st-chip`＋`MotrixStatus.chipClass()`；既有 `.badge--*` 保留並隨改版換成對應的 chip。對照表（沿用現有類別，不新增顏色）：

| 意義 | 顏色 | 狀態詞（畫面統一用這些） | 現有類別 |
|---|---|---|---|
| 尚未開始／草稿 | 灰 | 草稿、未開始 | `st-chip--draft`／`badge--draft` |
| **輪到有人處理（等待）** | 琥珀 | 待簽核（值＝待審核）、待處理、即將到期 | `--pending`／`badge--warning` |
| 進行中 | 藍 | 簽核中、進行中、處理中 | `--signing`／`badge--signing` |
| 完成、通過 | 綠 | 已核准、已完成、已收款 | `--approved`／`badge--approved` |
| 已送出、已發出 | 青 | 已送出、已寄出 | `badge--sent` |
| **被擋下／退回** | 紅 | 已駁回、已退回、逾期、失敗 | `--rejected`／`badge--danger` |

規則：
1. 徽章文字 ≤ 6 字；是**狀態不是按鈕**（不可點，要點就另放按鈕）。
2. 狀態旁要能看到「**卡在誰**」：簽核中顯示「簽核中（王主任）」或鼠標提示；逾期顯示「逾期 3 天」。
3. 紅色徽章＝**需要處理的問題**；不拿來標示「一般的結束」。已駁回（紅）與已作廢（灰）要分得出來。

6. 不要新增狀態詞：新增狀態前先查此表；多個流程的相同意義用相同詞。

## 7. 數字、日期、金額

**一律經共用格式器**（`frontend/static/motrix-format.js`）：`MotrixFormat.num／money／date／dt／status`。新程式不得直接呼叫 `toLocaleString(`（現有 95 處陸續改）。格式選項（千分位、小數位、日期樣式）由設定中心「畫面格式」決定，不在頁面寫死。

| 項目 | 規則 |
|---|---|
| **金額** | 千分位；**整數元**（報價單的單價可顯示小數）；幣別放數字前（`NT$ 1,234,000`）或欄位標題寫「（元）」，一頁內只選一種；靠右對齊並用等寬數字（`font-variant-numeric: tabular-nums`，現已有 38 處用）；負數顯示 `-1,200` 並用 `--danger` 色；金額 0 顯示 `0`，**沒有資料顯示 `—`**，不留空白。 |
| **百分比** | 最多 1 位小數（`12.5%`）；毛利等利潤類用既有紅黃綠門檻（設定中心可調）。 |
| **一般數字** | 千分位；數量為整數不顯示小數；單位寫在欄位標題。 |
| **日期** | 預設 `YYYY/MM/DD`（由 `MotrixFormat.date` 決定，可在設定中心改成 `YYYY-MM-DD`）；不使用民國年、不顯示英文月份、不省略年（跨年資料會混淆）。 |
| **時間** | 24 小時制 `HH:mm`；清單預設只顯示日期，點進去才有時分。 |
| **相對時間** | 只在 7 天內使用（「3 天前」「今天」），並在提示顯示完整日期；**到期／逾期用具體天數**：「還有 3 天」「逾期 5 天」，逾期用紅色。 |

| **電話、統編** | 原樣顯示，不加千分位；輸入欄用 `inputmode="tel"`／`numeric`。 |
| **空值** | 一律 `—`；不要顯示 `null`、`undefined`、`NaN`、`0001-01-01`。 |

| **字級** | 內文 ≥ 14px、輔助文字 ≥ 12px（與桌機最小字級一致）；輸入欄 ≥ 16px，避免 iOS 自動放大 |
| **版面** | 一欄；篩選列收成「篩選」按鈕（開底部抽屜），已套用的條件顯示成可移除的標籤 |
| **表格** | 預設欄位在手機上改成**卡片列**（第一行單號＋狀態徽章，第二行客戶與金額，第三行日期與負責人）；細節進詳情頁；不要硬縮小表格 |
| **主要動作** | 手機上主要按鈕固定在畫面底部（sticky），或放在頁頭下方滿版；不藏在「⋯」裡 |
| **對話框** | 全螢幕（或接近全螢幕），按鈕固定底部，取消在左、主要在右 |
| **輸入方式** | 正確的 `type`／`inputmode`（`tel`、`email`、`numeric`）；日期用原生挑選器；人與客戶用搜尋式選單 |
| **不靠 hover** | 任何資訊／動作不能只在滑鼠移上去才出現；提示改成點擊或直接顯示 |
| **導覽** | 必須有漢堡鈕或底部導覽，所有一級選單可達（hichan-4 範圍） |
| **簽核手機化優先** | 「簽核待辦」是最需要手機操作的功能：清單卡片＋單頁核准／退回，不需要橫向捲動就能完成 |

### 9.1 專家效率驗收（r2 新增；對應 hichan-6 問題 4）

每次改版**必須同時驗「新人看得懂」與「老手不變慢」**。定義 5 個高頻任務，**改版前後各量一次「點擊次數／鍵盤可達」，不得增加**：

| # | 高頻任務 | 現況基準（需在改版前實測並寫入 PR） |
|---|---|---|
| E1 | 新增報價單並送簽 | 點擊數、是否可全程鍵盤 |
| E2 | 複製上一張報價單成新單／新版本 | 是否一鍵 |
| E3 | 在清單上標記案件進度（例：標「已成案」） | 現為清單列上的小選單，**一次選取**；不得搬進詳情 |
| E4 | 找到某客戶的所有報價單與案件 | 搜尋→結果點擊數 |
| E5 | 核准一張單（手機與桌機） | 點擊數；手機不需橫向捲動 |

**不得移除的既有捷徑**：清單列上的案件進度小選單；通知與信件的深連結（現有帶 `tab=` 的連結：`case-management.html?q=…&tab=` 的 `dispatch`、`shipping`、`exec`、`fin`，以及 `payment-request.html?tab=mine`、`cashier.html?tab=payreq`，完整清單與 e2e 見 PROPOSAL §3.2）；報價單的「已核准、尚未送客戶」狀態（業務要採取行動，不可被併入「已送出」）；預設篩選須**記住每人上次選擇**，且「清除條件」一鍵（輪流接手的同事、助理、主管看得到全部）。
**要補的面向**：鍵盤操作（Tab 順序、Enter 儲存、Esc 關閉對話框、列表上下鍵）；複製報價單與版本；批次動作（批次核准、批次寄信）；可記住的欄位與排序；資訊密度（緊湊檢視開關）。這些在 r1 完全沒提。

**5 秒測試**：給一位沒看過這頁的同事看 5 秒，問「這頁做什麼？你現在要按哪裡？」答不出來＝不合格。
**新人測試**：用「新進業務第一天」的任務清單（見 `UX-BUSINESS-PAGES-PROPOSAL.md`）實際操作，記錄求助次數。

## 11. 守門做法（r2 新增；對應 hichan-6 §2.1）

通則：**能守門的一律做成「基準數字只許降不許升」（ratchet），不是「一次要求全站為零」**，否則第一天全紅、接著被關掉。P0 階段**只出報告、不擋 CI**（PM 裁示）。

| 原則 | 能否自動檢查 | 守門寫法 |
|---|---|---|
| §1.1 每頁回答三問 | 部分 | 檢查：有頁頭、剛好一個 H1、`.pg__s` 有字且 ≤ 40 字；不檢查品質 |
| §1.2 一頁一個主按鈕 | 可（要定義範圍） | **頁頭 `.pg__a` 內、對話框與樣板之外、可見**的 `.btn-primary` ≤ 1；ratchet |
| §1.3 用選的 | 不能 | 只抽查 `input` 的 `name`／`placeholder` 含 `code`／`path`／逗號等；其餘靠 §9 人工清單 |
| §1.4 用使用者的話 | 可（需白名單） | 禁用詞掃描：**只檢查「顯示名稱表預設值」與「未登錄的硬寫字串」**，客戶改過的不擋；白名單見 §6.5 |
| §1.5 狀態說人話＋下一步 | 不能 | 只檢查「每個狀態徽章有 `title` 或旁註欄」；品質靠人 |
| §1.6 錯誤說原因 | 部分 | 掃 `[object Object]`、HTTP 狀態碼、`undefined`、`NaN` |
| §2.2 預設欄位 | 可 | 數 `<th>`；ratchet；須提供「可加欄」才符合 |
| §4.6 儲存方式標示 | 部分 | 既有 CU6 e2e 當基準；新頁含 `data-save-mode` 以外的自創標記則報告 |
| §5 一狀態一色 | 可 | 對照 `MotrixStatus.MAP`／顯示名稱表預設色調與 CSS |
| §7 數字日期經 `MotrixFormat` | 可（ratchet） | 現有 95 處 `toLocaleString(`：「不得增加」，不是「必須為 0」 |
| §8 手機規則 | 可（e2e） | Playwright 390px：`scrollWidth <= clientWidth`、可點元素 ≥ 44px |
