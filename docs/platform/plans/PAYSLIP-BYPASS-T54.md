# 勞報單簽核卡死的出口（第 54 班；使用者回報）

分支 `wip/t54-05-payslip-bypass`（基準 origin/platform）。程式見 payroll CHANGELOG (next)。

## 成因（讀程式＋測試重現）
- `POST /api/payslips/{no}/approve`：先過 `check_no_tier_self_approval`（Q-S6：送審人 = 操作者且還有別的在職最高管理者 ⇒ 403），再過 `check_approve_permission`（必須是當層排序最前的未簽核人或其代理人）。
- 當層排序最前的未簽核人就是送審人 ⇒ 送審人被 Q-S6 擋；另一位最高管理者不在層內（403「此層需由…簽核」）或同層排在後面（403「請等待…先完成簽核」）⇒ **沒有任何人簽得了**。
- 其他單據（請款單、開票申請、承攬商匯款、派發、額外費用、材料申請、出貨、完工、報價、獎金分潤／更正）只在「沒設簽核層」的後備路徑才套用同一條自核限制，有簽核層時送審人可簽自己那層 ⇒ 沒有同型卡死。

## 今天不改程式的出路
1. 另一位最高管理者開該勞報單 → 『退回』（填原因）→ 由他『送審』→ 原簽核人簽核。
2. 或到 系統設定 → 簽核流程設定（`payslip_approval_flow`／統一流程）把第一層改成不是送審人的最高管理者；或移除簽核層（⇒ 其他最高管理者即可核准）。

## 驗收字句（給步驟檔）
- 勞報單簽核層第一層設為送審人本人時，另一位最高管理者按『簽核（核准）』會被要求輸入原因；輸入原因後勞報單變『已核准』，稽核紀錄出現 `payslip.approve_bypass`（含代核人、被代簽核人、原因），送審人與其他最高管理者收到通知。
- 送審人本人再怎麼按、不論有無原因，都不能核准自己送審的勞報單。
- 簽核人不是送審人時，非當層簽核人仍被擋（不給代核）；整條鏈只有一位簽核人且他仍在職時也不給代核（他自己簽，缺席走轉簽）；該簽核人已停用才可代核。
- 同一個人在同一張勞報單不能簽出兩格：已簽過第一層的最高管理者，不能再用代核簽第二層。
