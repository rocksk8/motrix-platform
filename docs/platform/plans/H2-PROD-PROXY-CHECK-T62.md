# H2 步驟檔補充：正式機檢查『Edge 代理旗標有沒有被遵守』（唯讀）

## 為什麼
H2 的 PDF 渲染硬化用 `--proxy-server=http://127.0.0.1:9`（必定連不上的代理）加 `--proxy-bypass-list=<-loopback>`，讓『直接寫 IP 的網址』（例如 `http://10.0.0.5/`、`http://169.254.169.254/`）也連不出去。受管機器上的群組原則（Edge 的 ProxySettings／ProxyMode／ProxyServer…）可能蓋掉命令列旗標；那樣這一層無效（其他層——CSP、出入口標籤中和、輸出逸出——仍在，風險只是少一層）。這支檢查腳本在正式機實測旗標有沒有生效。

## 腳本
`backend\tools\check_edge_proxy_hardening.py`（只用標準函式庫；不 import 系統任何模組、不讀資料庫、不寫 logs／uploads／資料庫）。
它做的事（全部在本機、不連外網）：①只讀 Edge 代理相關的群組原則登錄值與環境變數並列出；②在 127.0.0.1、127.0.0.2 與本機區網 IP 各開一個臨時監聽埠；③用 Edge headless 各渲染兩份只含 `<meta http-equiv=refresh>` 的 HTML：對照組（不帶代理旗標，應該『有連線』，證明這台機器能偵測）與硬化組（帶代理旗標，應該『0 次連線』）；④印出白話結論與 JSON，結束時把暫存資料夾整個刪掉。耗時約 1～2 分鐘（每個位址 2 次渲染）。

## 怎麼跑（正式機，在 backend 資料夾，用正式機的 Python）
```
cd <安裝目錄>\backend
<正式機的 python.exe> tools\check_edge_proxy_hardening.py
```
不需要停服務、不需要管理員權限；可以在服務執行中跑（它用自己的暫存 profile，不碰服務的 Edge profile）。

## 怎麼看結果（結束碼＋最後一段結論）
| 結束碼 | 意義 | 要做什麼 |
|---|---|---|
| 0 | 代理旗標有效（對照組有連線、硬化組 0 次） | 沒事，H2 這一層在正式機有效 |
| 1 | 旗標被蓋掉（硬化組仍有連線）；輸出的『Edge 代理相關群組原則』欄會列出覆蓋它的原則 | 回報開發；那一層無效，其他層仍在。要不要請 IT 調整該群組原則由使用者決定 |
| 2 | 無法判斷（對照組也沒有連線，常見原因：本機防火牆擋了 loopback 或 Edge 被管制） | 把整份輸出回報給開發 |
請把**整份輸出**（含最後的 JSON）貼回給開發。

## 對系統的影響
無：不改設定、不改檔案（只在 %TEMP% 建立並刪除 `motrix_proxy_check_*` 暫存資料夾）、不連外網、不影響服務。
