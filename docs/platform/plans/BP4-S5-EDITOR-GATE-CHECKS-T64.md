# BP-4 S5：額外通知編輯器——閘門要跑的瀏覽器／e2e 檢查（T64）

> 作者：本分支只做了靜態與單元檢查（node 假 DOM、後端 pytest）。**下面這些必須在真實瀏覽器上由閘門跑過才算完成**；本分支沒有跑。
> 對象：`frontend/static/notify-action-editor.js`、`frontend/pages/approval-settings.html`（掛載點與載入器）、後端 `routers/notify_actions.py`、`helpers/notify_actions.py`。
> 前置：測試機開 `builder_notify.enabled`＋`builder_governance.enabled`；至少兩位最高管理者帳號（A 作者、B 核准人）；一位管理員、一位業務、一位檢視者；開發機信件硬擋維持開啟（不寄真信）。

## 1. 旗標關／權限
1. 兩個旗標都關：開簽核設定頁——**沒有**「額外通知」按鈕；網路面板只多一次旗標讀取（`/api/…/settings` 類），沒有 `notify-action-editor.js`、沒有 `/api/notify-actions/*`。
2. 只開 `builder_notify`、治理關：載入器會載入編輯器，但 `GET /api/notify-actions/status` 回 `enabled:false` ⇒ 畫面仍然什麼都不畫。
3. 兩個都開、管理員（非最高管理者）登入：不載入編輯器程式；直接打 `POST /api/notify-actions/x/preview` 回 403。

## 2. 清單與新增
4. 最高管理者開簽核設定頁 → 「額外通知」按鈕可展開；第一次展開才讀清單（`GET /api/definitions/notify_action`）；空清單顯示「還沒有額外通知」。
5. 「新增通知」→ 選事件（四個白話事件名）→ 按「用建議內容填入」：名稱、對象、標題、內文一次帶入，且**不出現任何代號**（檢查選單選項、標籤、晶片、錯誤訊息；尤其不得出現 `completion_note`、`in_app`、`role:`、`na_…`）。
6. 收件人挑選器：只有「事件裡的人（依事件而異）／角色／群組／指定人員」；指定人員顯示名稱不顯示帳號；選自訂模組事件時沒有「案件負責業務」；最多 8 項，第 9 項被擋並說明。
7. 條件：欄位選單只有該事件的可篩選欄位；最多 3 條；同欄位不能重複。
8. 內容：占位符按鈕插入游標位置；打 `http://…`、`<b>`、`$`、`/`、「已核准」會當場出紅字說明；超過字數上限當場說明。

## 3. 試跑（唯讀）
9. 「試跑看看」：顯示「預計會通知約 N 人」、「過去 30 天平均每天約 X 則」、命中與否（範例資料）、收件人清單（只有類別與人數，**沒有姓名**）、逐角色文字（切換最高管理者／管理員／業務／工程師／檢視者／財務）。
10. 對照資料庫：試跑前後 `notifications`、`ui_definitions` 筆數不變；沒有寄信；只多一筆稽核 `notify_action.previewed`。
11. 第一次發布的新動作：紅框「放寬」＋原因（「新增通知動作…」）＋「需要第二位最高管理者核准」；停用／縮小：綠字「立即生效」。

## 4. 發布與治理（兩位最高管理者）
12. A 按「檢查並發布」：先存草稿 → 後端檢查 → 影響預覽面板；按取消 ⇒ **不發布**、訊息「已取消發布（草稿已存）」。確認 ⇒ 回 `pending`，畫面說「待第二位最高管理者核准；核准前不會生效」，**不說已發布**。
13. 核准前觸發事件（例如把完工單送審）：**沒有**額外通知；B 在治理面板「待核准變更」核准、確認期間過後套用 ⇒ 之後觸發事件才有通知（站內通知內容、連結正確；金額類占位符對沒有財務權限的收件人顯示「（略）」）。
14. 放寬類變更（加收件人、加信件、放寬次數、加占位符、放寬條件）每一種都進待核准；收緊（停用、減收件人、加嚴次數）立即生效。
15. 「停用」按鈕：立即生效，清單狀態變「已停用」；再次觸發事件沒有通知。
16. 「版本與還原」：開治理面板；還原到較寬鬆的舊版 ⇒ 進待核准（不立即生效）；還原後清單狀態更新（`onRestored`）。

## 5. 實際派發（事件發佈行）
17. 完工單：上傳簽回附件／送審／核准／退回／撤銷核准 ⇒ 各發一次事件；案件階段到期掃描 ⇒ 每個階段與負責人當天只發一次。收件人只收到自己讀得到的案件的通知（用沒有該案件權限的帳號當收件人，確認收不到；稽核只記「N 人因無權限未通知」，不記姓名）。
18. 節流：同一件事 N 分鐘內只通知同一人一次；「送審後馬上核准」兩則都收得到（去重鍵含新狀態）；每人每天上限生效。
19. 信件通道（開發機只驗不寄）：開信件通道的動作，觸發後 `user_notice` 類型信件進入寄送路徑（主旨前綴【MOTRIX 系統通知】）；收件人在「通知偏好」關掉「管理者自訂的額外通知」後不再收信，站內通知仍在。
20. 壓力：一個動作選「角色：管理員」且有超過 25 位管理員 ⇒ 只通知前 25 位，稽核有「超過上限」人數；事件發佈後業務請求回應時間沒有明顯增加（派發在 commit 之後，且 ≤ 2 秒預算）。

## 6. 回歸
21. 簽核通知用語編輯器（S-X3）與其他設定頁編輯器照常顯示與運作（兩個編輯器同一頁、同一個旗標）。
22. 內建通知與信件（報價單送審、簽核等）在額外通知啟用前後逐字相同；`/api/definition-kinds` 在旗標關時沒有 `notify_action`。
23. 外觀：深色／淺色主題、窄螢幕（手機寬度）下表單不橫向捲動；鍵盤可操作所有按鈕；以無障礙工具確認晶片的移除按鈕有名稱。

## 已知限制（作者未處理，請閘門判斷是否要擋）
- 條件的「值」是自由文字（以頓號分隔），沒有依事件提供值清單；例如附件種類的值是系統內部代號（簽回附件是 `signed`），白話名稱要等插槽編輯器的標籤可用後才能顯示。
- 清單不顯示「待核准」狀態（只有發布當下的訊息與治理面板的『待核准變更』分頁）。
- 沒有刪除動作（以停用代替；歷史版本保留，符合治理帳本）。
