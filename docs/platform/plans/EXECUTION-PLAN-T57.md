## 4 進度追蹤（事實帳；更新規則在下）

### 4.1 狀態機
`not started` → `designing` → `audited`（設計稽核 PASS）→ `coding` → `gate`（凍結樹跑閘門）→ `shipped`（正式機已套用）。
**『完成』定義**：狀態到 `shipped` **且**『第二窗口』對 git／正式機核對過並簽名（誰、何時、核對什麼）。作者自述不算。

### 4.2 交叉核對規則（誰核對什麼）
| 核對對象 | 核對者（不得是作者） | 核對方法 |
|---|---|---|
| 設計稿 PASS | 0d | 對照 repo 事實逐項 |
| 凍結樹內容（版本、manifest、群組、路由） | 98（步驟檔作者）與 0d 各自獨立 | `git show <凍結SHA>:…` 對步驟檔 |
| 正式機已套用 | 1c＋第二窗口（非 5c） | 讀 `H:\我的雲端硬碟\MOTRIX-交付\正式機回報\<時間>_<SHA>_成功\摘要.md` 與 `status\latest.json` 的 `deployed_commit` |
| 分支存在與 SHA | 任一非作者窗口 | `git rev-parse origin/<分支>` |
| 估計人日 | 完成後由 1c 記實際，納入估計校準 | §4.4 |

## 6 流程改善：降低閘門重切

### 6.1 今天的重切原因（事實，供檢討）
| 班 | 紅燈原因 | 作者預檢本可抓到？ |
|---|---|---|
| M3 int-a→b | 字型縮放的靜態測試（報價單 CSS 高度計算） | 是（跑完整 `tests/platform`） |
| MS1 預跑 | A7 四項（案件摘要用途掃描由 E-a 的 `**kwargs` 包裝觸發；內嵌註解白名單以行號為鍵、新增 import 讓行號位移；單位卡缺 `[契約題]`／`DEFAULTS`；新群組欄位缺 `impact_scope`） | 是（跑 `tests/platform` 與 `prepush_check`） |

→ 多數紅燈在 `tests/platform` 與靜態掃描，**作者只跑自己的測試檔就看不到**。

### 6.2 作者送審前預檢清單（每個作者窗口、每次推送凍結候選前）
1. `python tools/platform/prepush_check.py`（重用 `train_preflight` 的 A1～A8 與 A0 反向：wip 分支不得帶產生檔）。
2. **整個 `backend/tests/platform/` 跑一遍**（不是只跑自己的測試）；加 `MOTRIX_TRAIN=1` 才會驗的『產生檔是否最新』類測試不在作者端跑，但作者**不得**提交產生檔（`UNIT-INDEX`／`dep_graph`／`test_map` 由列車重產）。
3. **只在 not_e2e 階段出現的掃描**：新增路由 ⇒ 路由金標；新增 L1 公開介面 ⇒ 快照；新增設定群組欄位 ⇒ `impact_scope` 與基準檔；新增單位卡 ⇒ `[契約題]`；L0／L1 變動 ⇒ 單位卡規則。
4. **A8**：測試直接呼叫 `get_db()` 必須有 DB 夾具。
5. **模組 CHANGELOG 跟著程式走**：程式變動後必須同時有新的 `(next)` 標題；`version_manifest.json` 每模組只能有一列 `"version":"next"`；核心用 `core_bump.py --pending`。
6. **脊柱宣告**：`features[]`／`blocks[]`／`capabilities[]` 驗證器通過；註冊函式只在 L1。
7. **以行號為鍵的白名單**：不在含白名單的檔案裡新增行（併入既有行），否則行號位移會紅。
8. 步驟檔：發布腳本標準 token 數量檢查（標題列一次、尾標記一次、`<N>` 一次、無殘留 `FILL_`），由作者本機跑一次。
### 6.3 流程調整（建議）
- **審查排隊表**（1c 維護）：每個待審項目、預估稽核時數、優先序；2b／1d 輪流做設計互審以分擔 0d。
- **凍結前『預凍結』**：5c 在機器空檔先對候選樹跑 full-lint（約 10 分），紅就退回作者，不佔 not_e2e／e2e。

- **機器規則**：單一重型執行者；閘門／建包期間全窗靜態；RAM 低於 8～10GB 即停。
