# 設計（僅文件）：報價單 PDF 的條款標題改為預設清單可選（census #5）

> 作者 hichan-1f，2026-10-14。**只寫設計，不含程式。** 疊在 BP-3 的「PDF 頁尾／浮水印預設文字」（`helpers/export_templates.py` decorOnly）上。

## 現況（已讀程式）
- 條款**標題**寫在兩處：`backend/pdf_gen.py:356–363`（報價單 PDF）與 `:2238–2241`（另一支報價單輸出，條款區塊 `term_block('付款條件', …)` 等 4～5 次呼叫）；後端 `modules/case/quote_terms.py` 的 `TERMS_FIELD_DEFS`（付款條件／交貨條件／驗收標準／保固條件／售後服務及備註說明）用在送審原因文字（「報價條件已修改…（付款條件、…）」）。表單 `quotation-form.html` 也有同樣的標題（23 處提到條款字樣，含版面與提示）。
- 條款**本文**的預設與條款組已可由管理者調整（`DEFAULT_TERMS`、設定值 `default_payment_terms`、`quote_terms_presets`），所以真正寫死的是**標題文字**。
- 條款是客戶看得到的文字（報價單 PDF），措辭可能有法律意涵（付款條件、驗收標準、保固條件）。

## 目標與不做的事
- 讓管理者把每個條款的標題換成**預設清單裡的另一個說法**（例：「付款條件」→「付款方式」），PDF、表單、送審原因文字同步。
- **不做**：自由輸入標題、增減條款區塊、改順序、改條款本文（本文已有既有機制）。理由同 BP-3：客戶可見文字不開放自由輸入（浮水印審核的結論：預設白名單）。

## 模型
- 新匯出代號 `case:quotation-clause-titles`（decorOnly 的變體，格式 `pdf`，沒有欄位目錄）。範本內容：
  `{"version":1,"format":"pdf","titles":{"paymentTerms":"付款方式","deliveryTerms":"交貨條件", …}}`（只放要改的鍵；沒放＝用程式預設）。
- **每個條款一組預設標題**（寫死在程式，不由使用者新增）：

| 條款鍵 | 預設（今天） | 其他可選 |
|---|---|---|
| `paymentTerms` | 付款條件 | 付款方式、款項約定 |
| `deliveryTerms` | 交貨條件 | 交付條件、出貨條件 |
| `acceptanceTerms` | 驗收標準 | 驗收條件、驗收方式 |
| `warrantyTerms` | 保固條件 | 保固說明、保固內容 |
| `afterSales` | 售後服務及備註說明 | 售後服務、備註說明 |

  清單內容由使用者／法務確認後定稿（上表是起點）。每個值同樣要過 BP-3 的檢查（隱形字元、官方狀態字樣骨架比對、不以 `= + - @` 開頭、無占位符）；因為是白名單，這些檢查只是縱深防禦。
- 驗證器拒絕：不認得的條款鍵、不在該條款預設清單裡的標題、額外鍵。

## 讀取與套用（單一出口）
- 新函式 `quote_terms.clause_title(key, conn=None)`：旗標（`builder_exports.enabled` ＋治理）關、沒有已發布範本、任何錯誤 ⇒ 回程式預設標題（**輸出逐位元相同**）。
- `pdf_gen.py` 兩處 `term_block('付款條件', …)` 改成 `term_block(clause_title('paymentTerms'), …)`；`TERMS_FIELD_DEFS` 的標題改走同一個函式；表單的標題經 `GET /api/settings/quote-terms-defaults`（既有請求，加一個 `titles` 鍵）取得，不新增請求。
- 單據凍結：已送出（已簽回／已核准）的報價單**列印時用當下的標題**或**凍結送出當時的標題**？建議後者——報價單送出時把 `clauseTitles` 存進 `data_json`（與輸出版型的 `outputTemplate: {scope, version}` 凍結同一個思路），之後改範本不改已送出的單據；未送出的草稿用當下範本。這是設計上最需要使用者裁示的一點（見下）。

## 治理
- 走既有的 `export_template` kind 與管線：**任何標題變更＝放寬（客戶可見文字，需第二位最高管理者核准＋確認期間）**；還原到預設＝中性？（建議也走核准，與 BP-3 一致：任何可見文字的變更都核准）。
- 預覽：樣本頁顯示五個條款區塊的標題，並排「目前」與「草稿」；`previewHash` 照 BP-3 規則；預覽不計匯出。
- 旗標與 BP-3 相同（`builder_exports.enabled`，且須同時開啟 `builder_governance`）；關閉時所有輸出逐位元相同。

## 測試計畫
1. 預設＝今天：`clause_title(k)` 在旗標關／無範本時等於 `TERMS_FIELD_DEFS` 與 `pdf_gen` 原本的字串（兩處 PDF builder 的 HTML 逐位元相同，用現有的凍結對照）。
2. 驗證：清單外標題、隱形字元、官方狀態字樣（例：「已核准條件」）、額外鍵 ⇒ 全拒。
3. 凍結：送出後改範本，已送出單據的 PDF 仍是送出當時的標題（若採凍結）。
4. 送審原因文字與表單標題同步（都用 `clause_title`）。
5. 突變控制：移除 `clause_title` 呼叫（回到寫死字串）時，「改了標題 → PDF 跟著變」的測試必須紅。

## 風險與開放問題
- **法律／商務**：標題換字不改條款本文，但客戶合約引用的條款名稱可能改變；請使用者確認可選清單。
- **凍結 vs 即時**（上述）：建議凍結，需裁示。
- **其他輸出**：`routers/system.py`（5 處）、`expense_forms.py`、`payment-request-form.html`、`cashier` 等也有「付款條件」字樣，但屬**請款／出納／費用單**自己的欄位，不是報價單條款；本設計不動，避免誤改。
- 工量：S～M（約 2 天）：函式＋兩處 PDF＋表單端點一鍵＋預覽樣本頁＋測試。依賴 BP-3 上線。
