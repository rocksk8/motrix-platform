# Q-S6「簽核層只列送審人」情境（第 48 班，hichan-ab）

**實際行為**（測試：`backend/modules/payroll/tests/test_payslip_s6_sole_approver_t48.py`，3 題，已過）
- `setting_to_active_tiers` **不會**剔除送審人；手動挑的簽核人原樣保留（部門／處主管層另標 `selfApproval`）。
- 層裡只有送審人時：送審人被 Q-S6 擋（403「不得自行審核」）；另一位在職最高管理者**不在層內**也不能核准（`check_approve_permission` 只認當層簽核人，403）。核准路徑上沒有人。
- **不是永久卡死**：`check_reject_permission` 放行任一最高管理者退回 → 草稿；由**另一位**最高管理者重新送審（送審人≠簽核人）後原簽核人可正常核准。
- 同一人退回後自己重送，簽核鏈重解析仍只有他 → 再卡一次（測試第 3 題）。

**建議（待 node-d8／使用者裁示，本分支未改行為）**
1. 最小：簽核設定頁／送審時提示「此流程的簽核人只有送審人本人，送審後需他人處理」（送審回應可帶 `soleApproverWarning`）。
2. 若要程式解：送審時偵測「所有層都只有送審人」且另有在職最高管理者 → 改走 `org_chain_notice_usernames` 式知會，並允許**層外**最高管理者代核（需裁示：是否破壞「簽核層外不得核」）。
3. 不建議：放寬 Q-S6 讓送審人自核（違反使用者裁示 A）。
