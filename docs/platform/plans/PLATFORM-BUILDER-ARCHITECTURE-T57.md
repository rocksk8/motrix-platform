# 平台建構器（拼圖模型）架構筆記——全範圍可自訂（僅文件，未跑任何測試）

> 日期：2026-10-13　作者：hichan-98　委託：hichan-1c
> 使用者永久決定（10-13，原文）：「既有的也要能自定義編輯，範圍是全部，規則引擎都開放給使用者，只要花一次時間未來使用者要甚麼都能自己在系統內創建，我們只做最後的BUG排查，包含存檔方式、上傳檔案資料夾、建立新的邏輯，這是拼圖的概念」。
> 範圍＝**所有既有功能**都可由使用者自訂：匯出範本（PDF／Excel）、條件式紅字警示／限制規則、自訂按鈕／選單、每個畫面的資料欄位、存檔位置／上傳資料夾、新邏輯。我們只做最後的 BUG 排查。
> 標記：**UNKNOWN**＝沒有證據；pd 的「估」是我的粗估，不是承諾。本文**不改任何既定的安全底線**。

## 0. 結論（先看）

1. **這個平台已經有一半的地基**：定義文件庫（草稿／版本／差異／還原／驗證器／送審，`core/definitions.py`）、自訂模組引擎（欄位型別目錄、公式、狀態與分層簽核〔層可帶條件公式〕、通知、事件、附件、財務接點，`helpers/custom_modules.py` 約 1590 行及 `custom_*` 一組）、模組可自訂點（列表欄位／表單區塊／按鈕／選單／匯出，`core/customization.py` v1）、單據輸出積木（`helpers/doc_render.py`／`doc_template.py`／`output_templates`）、設定登錄＋變更帳本＋待生效＋雙人核准（`settings_registry`／`config_ledger`）。**新決定＝把「自訂模組」那套做法，套用到所有既有功能**，再補上規則引擎、匯出範本建構器、選單／按鈕建構器、欄位權限、儲存位置白名單。
2. **模型＝七種積木＋一個共同的治理層**：欄位目錄、版面／檢視、規則、匯出範本、選單／按鈕、附件／儲存插槽、流程掛鉤；每種積木都是**資料（宣告式定義）**，走**同一個定義文件庫**（版本、草稿、預覽影響、帳本、還原），由**唯一的解析器／評估器**在執行期讀取。
3. **五條硬護欄（使用者要求，寫死）**：①使用者的邏輯**只能是宣告式**（沒有任何程式碼執行）；②**金額與權限遮蔽永遠優先**（使用者永遠無法讓某角色看到他本來看不到的欄位）；③儲存／上傳位置只能從**管理員核准的白名單**挑（沒有任意路徑輸入）；④規則評估在**沙箱**內、有成本上限；⑤每個定義**有版本、有稽核、可還原**；高影響規則帶紅色橫幅＋影響範圍，放寬走第二位核准。
4. **工量（估）**：引擎與建構器約 **95～160 pd**，既有功能遷移到積木約 **25～45 pd**（含逐項黃金對照），合計 **120～205 pd**；以每日 5 pd（4～5 位作者）約 **24～41 個工作日**，再加閘門與稽核（每班約 70 分鐘機器時間＋稽核）。**可信的完成日期：2026 年 11 月底～12 月中**（引擎＋第一批遷移），其後才進入「只做 BUG 排查」；§7 列分階段與每班使用者看得到的東西。這與先前框架化主體（193.5–240 pd）**有重疊**，不可直接相加（§7.3）。
5. **誠實的風險**：「使用者想要什麼都能自己建」的反面是**效能、安全面、支援成本與升版相容**；最難的一題是**客戶改過的定義 vs. 我們之後出的新版預設值**（三方合併），§8 風險 R1–R9 與 UNKNOWN 明列。

## 2. 積木模型（拼圖）

### 2.1 七種積木

| # | 積木 | 使用者在畫面上做什麼 | 定義存放（`kind`） | 執行期讀取者 |
|---|---|---|---|---|
| 1 | **欄位目錄** | 為某個單據／畫面新增欄位、改標籤、改型別、設預設與驗證、設唯讀／必填／顯示條件 | `field_set`（`custom_fields` 的延伸） | 欄位解析器 |
| 2 | **版面／檢視** | 排順序、分區塊、欄寬列高、列表欄位／排序／篩選預設 | `layout`（v2） | 版面解析器（畫面／PDF／Excel 共用） |
| 3 | **規則** | 「當〔條件〕就〔動作〕」：標紅、顯示警示、擋下、要求簽核、通知、計算欄位 | `rule` | 規則評估器 |
| 4 | **匯出範本** | 拖曳版型：抬頭、表格、欄位、頁尾、簽核欄；PDF 與 Excel；通道（客戶版／內部版） | `output_template`（延伸） | 範本渲染器 |
| 5 | **選單／按鈕** | 新增選單項、群組；新增按鈕並指定它觸發的「動作」（開頁、套用範本匯出、改狀態、通知…） | `menu`、`action` | 選單與動作派發器 |
| 6 | **附件／儲存插槽** | 為某單據宣告可上傳的附件種類、可上傳者、數量大小、存放位置（從白名單挑） | `attachment_slot`、`storage_root`（白名單，管理員核准） | 插槽政策檢查 |
| 7 | **流程掛鉤** | 狀態、轉換、各層簽核（含條件）、進入狀態通知、事件 | `workflow` | 流程引擎（沿用自訂模組的狀態機） |

### 2.2 共同契約（每種積木都必須有）
1. **定義＝資料**：JSON，結構由該 `kind` 的驗證器檢查；不認得的鍵＝問題（不靜默丟棄）。
2. **版本與範圍**：`(kind, key, scope)`；scope＝公司／角色（沿用 FL-3）；發布＝不可變新版本；單據建立或送審那一刻**凍結所用定義版本**（FL-3，已有 `def_version` 做法）。
3. **預覽與影響**：發布前一定要看到「這個變更會影響哪些畫面、角色、單據、金額」——由 `impact_scope`（E-e）宣告＋執行期計算的數量（例：「目前有 37 張草稿會被這條規則擋下」）。
4. **帳本與稽核**：每次發布／還原寫 `config_changes`（誰、何時、原因、前後版本、風險等級、`approvals_required`）與稽核事件；通知其他最高管理者。
5. **還原**：一鍵還原到任一歷史版本（＝再發布）；還原到較寬鬆的版本屬放寬 ⇒ 走核准。
6. **風險分級**：每個積木型別的每個動作都有風險類（`none／ops／money／legal／security`）；`money／legal／security` 與放寬類 ⇒ 紅色橫幅＋影響範圍＋第二位最高管理者核准＋確認期間（沿用設定登錄的規則）。
7. **能力登錄**：誰能建立／發布每一種積木（F3 能力；過渡期＝最高管理者）；**建構器本身的權限**屬安全底線，不可被積木改動。
8. **功能狀態**：每個積木型別在功能狀態頁（E-b）登錄；尚未做好的顯示灰色「規劃中（預計 MSn）」。

### 2.3 解析器與評估器（執行期只有這幾個入口）
- **欄位／版面解析器**（脊柱 B4）：輸入（單據類型、定義版本集合、檢視者、通道）→ 欄位清單與尺寸；**先扣權限再回傳**。
- **規則評估器**：輸入（規則集合、上下文＝單據視圖＋使用者＋時點）→ 動作清單；**純函式、無副作用**；動作的執行（通知、寫稽核）由派發器在評估之外做。
- **範本渲染器**：延伸 `render_document`，輸入（範本、視圖、通道、檢視者）；Excel 為第二個適配器。
- **動作派發器**：按鈕／選單觸發的動作只能從**動作目錄**挑（§3.3），每個動作自帶權限檢查與稽核。
- **插槽政策檢查**：`attachment_slots.check_upload/delete`（見完工單附件設計）。

## 3. 護欄（使用者要求；全部寫死，不可由設定關閉）

### 3.1 宣告式，不執行程式碼
- 條件語言＝**受限的運算式**：欄位引用、字面值、比較（`= ≠ < ≤ > ≥`）、`且 或 非`、`屬於／包含`、日期差、少量算術與彙總（`sum/count/min/max` 只作用在明列的表格欄）；函式來自**固定函式目錄**（沿用 `helpers/formula.py` 的函式集並審視後收斂）。
- **沒有**：迴圈、遞迴、函式定義、任意屬性存取、字串轉程式碼、`eval`、模板語言的任意表達式、外部呼叫（HTTP／檔案／資料庫）。
- 動作＝**動作目錄**中的有限種類（§3.3）；參數經驗證器檢查型別與範圍。
- 測試：**突變測試**——驗證器對任何不在文法內的輸入一律拒絕；靜態守門掃描評估器模組不得 import `eval/exec/compile/importlib/subprocess/os.system`。

### 3.2 金額與權限遮蔽永遠優先
- 所有積木的輸出都在**最後一步**經過遮蔽：欄位解析器先依檢視者的權限（`quote_money_visible`／`money_visible`／欄位權限）扣除欄位，再套版面；規則評估的上下文**只含檢視者本來看得到的欄位**——規則不能讀它看不到的欄位，也就不能透過「標紅／擋下」的結果洩漏它（例：不得用「毛利低於 X 才警示」讓無成本權限者推得毛利）。
- **規則的輸出也分權限**：條件引用了 `internal`／`isMoney` 欄位的規則，其「提示文字」只對有該權限者顯示；對其他人只顯示中性文字或不顯示。
- 匯出範本：`internal` 欄位**不能放進客戶通道**（編輯器不提供、驗證器擋、輸出端再擋——FL §7 沿用）；`isMoney` 標籤不能成為檔名變數（A7 守門沿用）。
- 使用者新增的欄位**預設是 `internal`**（保守）；要設為客戶可見需明確選擇，且屬高影響（紅色橫幅）。
- 測試：**逐角色正反對照**（admin／sales／finance／cashier／engineer／viewer）對每一種積木輸出；以「把金額欄放進客戶通道」「規則引用成本欄」等突變測試證明被擋。

### 3.3 儲存與上傳位置：只從管理員核准的白名單
- 新增定義種類 `storage_root`：管理員（最高管理者）在系統內**登錄**一個根位置（顯示名、實際路徑由安裝時決定的**根清單**中挑選，或在 uploads 底下的子資料夾名稱），經第二位核准後才可被插槽引用。
- 插槽只能選已核准的根；**使用者不能輸入路徑**。伺服器端沿用 `_safe_save_dir`（單段、不含 `/ \ :`、`realpath` 必須在根之下），檔名一律亂數。
- 副檔名與檔頭檢查仍是安全底線（`uploads` 白名單∩插槽 `accept`），**不可由規則或插槽放寬到可執行檔／HTML／腳本**。HEIC 等新類型的放行走安全審查。
- 讀取授權一律走 `uploads.path_access`：**新的根必須帶一個 provider**，沒有 provider＝讀不到（fail closed）。

### 3.4 評估沙箱與成本上限
- 每條規則：節點數上限（例 200）、巢狀深度上限（例 8）、單次評估時間預算（例 20 ms）、單一單據規則數上限（例 50）；清單類（列表標紅）必須**可批次評估**（先編譯成評估計畫，單次掃描列表）且每頁上限。
- 超限＝**降級**（規則失效、記稽核、顯示中性提示），**絕不影響單據的存取或儲存**（規則故障不得阻擋存檔，除非動作是「擋下」且評估成功）。
- 編譯期檢查**循環**（計算欄位互相引用）與**不可決定**（缺欄位）；缺值的語意固定（缺＝不成立，不當 0）。
- 測試：病態規則集（最大深度、最大節點、百萬列模擬）下延遲有上限；時間預算超過時降級行為。

### 3.5 版本、稽核、可還原
- 見 §2.2-4／5；另加：**規則與範本不能就地改**，只能發布新版；單據凍結所用版本；**沒有「直接改資料庫」的後門**（定義文件庫的不可變版本＋觸發器）。
- **試跑（dry-run）**：發布前可對「最近 N 張單據」試跑，列出命中數與樣本（只有有權限的人看得到樣本內容）。

### 3.6 高影響定義
- 判定：風險類 `money／legal／security`、涉及客戶可見輸出、涉及權限、涉及「擋下」動作、**放寬**（移除限制、擴大可見）。
- 一律：紅色橫幅＋影響範圍（單據、角色、金額／個資、可否復原、生效時機）＋帳本＋**放寬需第二位最高管理者核准與確認期間**；收緊即時生效。

## 4. 仍然寫死的（系統運作不變式，附理由）

| 項目 | 理由 |
|---|---|
| 登入／工作階段／伺服器端權限檢查的**核心**（誰是誰、能不能做） | 安全底線；積木只能在權限**之內**再收窄顯示，不能放寬權限 |
| 金額遮蔽的**機制**（`financial_mask`、`isMoney`／`internal` 規則） | 外洩不可靠設定防線 |
| 副檔名白名單與檔頭檢查、路徑安全、亂數檔名 | 檔案系統／協定安全 |
| 資料完整性與交易一致性：migration、鎖、單號原子產生、同交易更新、備份 | 資料不可壞 |
| 稽核紀錄的寫入路徑與不可變觸發器、變更帳本 | 證據鏈 |
| 法定金額進位與稅額算式（`legal_params`、`round_half_up`） | 法遵；規則的「計算」動作只能呼叫這些函式，不能改它們 |
| 簽核鏈引擎（分層、代理、防自核） | 內控；積木只能設定層級與條件，不能繞過防自核 |
| 規則評估器、範本渲染器、解析器**本身**與其上限 | 沙箱邊界 |
| 公司設定閘（第二道）、未核可紅色橫幅（由程式決定、不由版型決定） | 對外文件的最後防線 |

## 5. 既有功能遷移（預設＝今天的行為，不移除）

1. **登記為內建定義**：每個既有功能的現況（欄位、版面、輸出、按鈕、選單、規則性常數如毛利門檻）以**內建版本 v1** 登記進定義文件庫（唯讀基準＋可疊加的公司版本）；沒有公司版本＝今天的行為（沿用「沒有列＝程式預設」的做法）。
2. **黃金對照**：遷移前後對固定樣本逐位元比對（畫面欄位序列、PDF 位元組或正規化後文字、Excel 儲存格、API 回應形狀）；不同＝紅燈。
3. **緊急回退開關**：`MOTRIX_BUILDER_DEFAULTS_ONLY=1`（比照設定登錄的 `MOTRIX_SETTINGS_DEFAULTS_ONLY`）⇒ 所有積木回程式預設。
4. **順序**：先低風險高價值（列表欄位／版面、利潤警示等規則性常數、下載檔名、完工單附件）→ 輸出範本（報價單 PDF 最後，因為 `pdf_gen` 是手寫大檔）→ 欄位權限 → 流程掛鉤。
5. **不移除任何既有端點／鍵**；舊程式讀得到的資料形狀不變。

## 6. 擴充點與契約（讓「只做最後的 BUG 排查」成立的條件）
- **新增一種積木**＝註冊一個 `kind`＋驗證器＋解析器／評估器＋風險分級＋功能狀態；**不必改核心 L0**（`register_kind` 已是這樣）。
- **新增一種動作／函式／欄位型別**＝在**目錄**登記（程式）；這是**仍需開發**的部分（見 §4），但只是增加目錄項，不改引擎。
- **宣告檔格式**（`features[]`）是模組向積木登記自己的唯一方式（E-b 驗證）。
- **相容性**：定義帶 `schema` 版本；看不懂的版本＝不載入、顯示原因（不猜）。
