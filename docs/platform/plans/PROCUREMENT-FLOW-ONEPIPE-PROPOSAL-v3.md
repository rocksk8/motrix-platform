# 第一部分　給老闆看

## 1.1 一頁摘要

使用者說「叫料、紀錄、登載太零散，流程是一條接一條，系統卻拆開」。盤點的結論：**資料真的分成兩條互不相通的線**——案件這條（請購→採購→叫料→確認到貨→材料卡→設備）和倉庫這條（料號→進貨→序號→出貨→設備認領）。一批貨到了，案件按「確認到貨」，倉庫不會有任何東西，要另外重打一次（我們用假資料走過：4 台交換器已到貨，庫存仍是 0）。

我們的做法：在每個案件裡加一個「**物料流程**」畫面（橫向時間軸：叫料→採購→到貨→入庫→領用／出貨→設備登載→保固，顯示每段狀態、**卡在誰手上**、下一步按鈕），再逐步把重複輸入合併掉。**原有頁面全部保留**。不是一次大改：切成小批，每批有自己的開關，關掉＝跟今天完全一樣。

## 1.2 現行規則：哪些改動要第二位最高管理者核准？（先看這個）

下面是**目前系統已經有的規則**（不是新提的）：

| 類型 | 現行規則 |
|---|---|
| 設定中心裡標為「安全／風險」的設定，往放寬方向改 | 等 24 小時＋**第二位最高管理者核准**；往收緊方向改，立即生效 |
| 報價單簽核門檻（毛利、有效天數、折扣）與應收寬限天數 | 放寬須第二位最高管理者核准＋確認期（2026-10-14 裁示，僅限這兩類） |
| 權限矩陣裡的**高風險動作**：看金額、看敏感資料、核准、付款、刪除、管理設定 | 授予須填原因、等確認期；**放寬須第二位最高管理者核准** |
| 調整單據流程（誰簽核、要不要簽核） | 放寬須經最高管理者核准流程與確認期 |
| **只有一位最高管理者的公司** | 沒有第二位可核准，改為「寫明原因＋等待確認期＋警示並通知」（設定中心放寬為 24 小時）；權限矩陣的高風險動作同樣降級為此做法 |

**不在上面的**（今天改了就**立即生效**，沒有第二位核准）：入庫（新增／修改進貨）、建立請購單、新增每日工作事項。這三項目前只是程式裡「限管理員」之類的寫死檢查，改程式發版即生效，系統不會要求任何人核准。

因此本提案裡每個涉及權限的決策項，都會明講它是 **〔現行規則〕**（照現有機制就會被管）還是 **〔新規定〕**（我們建議新增、現在並不存在，你可以不採用）。

## 1.3 不需要任何決策就能先做的批次

這幾批**不動任何權限、不動簽核、不改資料結構**，各有自己的開關（預設關），關掉＝與今天逐位元相同。老闆若只想先拿「不動權限」的部分，這些可以直接開工：

| 批 | 做什麼 | 規模 |
|---|---|---|
| **P0a 入口與連結** | 從案件直接開請購單／採購單（不用重新搜尋案件）；案件頁能直接落在「材料申請」子頁；死連結修好（出貨單通知連到不存在的頁面）；保固頁案號可點 | 小 |
| **P0b 工作日誌補案件欄** | 工程師寫日誌可選案件，日誌出現在該案動態與專案報告；日誌的可見範圍不變 | 小 |
| **P0c 先出貨後登載不再衝突** | 序號出貨後，同一案件再登載設備不再報「序號衝突」（他案已使用仍報衝突） | 小 |
| **P1' 物料流程時間軸** | 新的案件「物料流程」畫面，**只顯示今天算得出來的格子**（叫料、採購、到貨〔逐張單：到了／沒到〕、出貨、設備、保固；入庫格見下）；「下一步」先做成「開對應頁並帶好案號」 | 中 |
| **P0d 保固通知納入已結案案件** | 已結案案件的保固到期也會通知；**開關預設關**；打開後只通知「打開之後才到期」的，打開當下**不會**把歷史舊案一次寄出（會寄信給外部客戶，所以特別安全處理） | 小 |

**入庫格在 P1' 的樣子**（一條規則）：沒有倉儲模組 ⇒ 該格不出現；有倉儲模組但暫時讀不到 ⇒ 顯示「庫存暫時讀不到」（不是隱藏，避免誤以為沒有倉儲）；有倉儲模組、但一站式到貨還沒上線 ⇒ 只顯示**已出貨／已安裝**的台數，其餘標「第 2 階段後提供」；一站式到貨上線後 ⇒ 完整顯示。

## 1.4 需要老闆決定的事（依「決定後解鎖哪一批」分組）

> 每題格式：**問題 → 選項 → 建議 → 各選項的代價（中性陳述）→ 之後能不能改**。「建議」只是我們的傾向，不是預設答案。

> **名詞先說清楚**：系統的帳號類別（角色）只有六種——最高管理者、管理員、業務、工程師、檢視者、財務。**「採購」與「庫存」不是角色，而是「模組權限」**（勾了才看得到那些頁面）。我們走查用的「新進採購」帳號，實際設定是：角色＝檢視者，另外勾了採購、庫存、設備、供應商四個模組。下面提到「採購的人」，指的就是「**擁有採購（或庫存）模組權限的人**」；如果要新增一種「採購」角色，那是更大的變更，需另外決定。

### A．權限類（決定後才能開工的批）

#### D3　擁有採購模組權限的人可以做什麼？　→ 解鎖 **P5a（新進採購的第一道牆）**
> **✅ 使用者裁示（2026-11-13）：選 A**——可建請購單、可看供應商唯讀名單；材料申請（叫料）仍需金額檢視權。
現況：擁有採購模組權限的人看得到「採購管理」，但那頁只能看、不能做事；供應商名單對他是空的；請購單入口因權限要求（要「報價單」權限）而被擋。
- **A**：可建請購單、可看供應商**唯讀**名單；叫料仍需金額檢視權。
- **B**：A 再加「可建叫料」。
- **C**：維持現況（只能看）。
- 代價：A——要放寬請購入口權限，並先確認供應商名單的銀行帳號欄位對採購遮蔽（過去有過銀行資料外露的缺口）；B——叫料單有單價與金額欄，採購沒有金額檢視權時，這兩欄要選一個：**遮蔽**（需要改叫料單表單，中等工作量）或**顯示**（等於給採購「看金額」權限，那是高風險動作）；C——不需任何變更，新進採購第一天仍只能看。
- 規則：請購入口與看供應商名單＝**〔新規定才會被管〕**（今天立即生效）；若方案涉及「看金額／看敏感資料」＝**〔現行規則〕**，須第二位最高管理者核准＋確認期；只有一位最高管理者的公司則降級為「原因＋確認期＋警示」，沒有第二位核准。
- 之後能不能改：收緊隨時、立即生效；再放寬又要走一次核准。

#### D9　誰能入庫？（新進貨、修改進貨）　→ 解鎖 **P2a／P2b（一站式到貨）**
> **✅ 使用者裁示（2026-11-13）：選 A＋採用新規定**——開放給擁有採購或庫存模組權限的人；入庫列入權限矩陣的一個動作，授予要原因與確認期，放寬要第二位最高管理者核准（只有一位最高管理者的公司降級為「原因＋確認期＋警示」）。
現況：入庫（建立／修改進貨批次）限管理員；採購與現場工程師做不了。
- **A**：開放給「擁有採購或庫存模組權限的人」（案件擁有者與現場工程師若沒有這兩個模組權限則不含）。
- **B**：維持僅管理員。一站式到貨對非管理員**只完成案件那一半（確認到貨、材料卡、設備預填）**，畫面明示「入庫需管理員處理」，並由**對帳表**列出「案件已到貨、庫存還沒有」的清單讓管理員補入庫。
- 代價：A——入庫權限擴大，進貨資料（含成本）的修改面變大；B——每批貨都要管理員補一步，對帳表會常有待辦。
- 規則：入庫**不屬於**現行高風險動作清單，所以今天**不需要**第二位核准。**〔新規定〕建議（若選 A）**：把入庫做成權限矩陣裡的一個動作，並比照高風險動作要求原因、確認期、放寬須第二位核准。你可以選擇採用或不採用；不採用則 A 一旦上線立即生效。只有一位最高管理者的公司：採用新規定時降級為「原因＋確認期＋警示」。
- 之後能不能改：收緊隨時；放寬依上面規則。

#### D5　每日工作事項要不要開放現場人員新增？　→ 解鎖 **P4（紀錄整併）**
> **✅ 使用者裁示（2026-11-13）：選 A**——開放現場人員新增與自己相關、掛在案件上的事項；修改與刪除仍限最高管理者。
現況：只有最高管理者能新增，也不接收案件上下文。
- **A**：開放「建立與自己相關、掛在案件上的事項」；修改與刪除仍限最高管理者。
- **B**：維持現況。
- 代價：A——現場人員可自行建立事項（範圍限與自己相關、掛案件）；B——工程師仍要請最高管理者代建。
- 規則：新增每日事項**不屬於**現行高風險動作，今天立即生效；是否比照要第二位核准＝**〔新規定〕**，建議不必（範圍已限縮）。
- 之後能不能改：隨時。

### B．流程與政策類

#### D6　請購→採購→叫料的「兩次核准」要怎麼處理？　→ 政策題（不阻擋任何批次；P2a／P2b 不必等這題的答案）
> **✅ 使用者裁示（2026-11-13）：選 B**——材料申請連到已核准採購單明細就免再簽（以採購單核准為準，保留到貨確認）；屬放寬簽核，須走最高管理者核准流程與確認期；已在簽核中的材料申請不追溯，只有之後新送審的適用。
使用者原話是「叫料、紀錄、登載太零散」。**我們判斷**重複核准與重複輸入是零散感的重要來源（這是我們的推論，不是使用者說的）。現況事實：新叫料**必須**連到已核准的採購單才能送審，所以一筆採購＝採購單簽一次＋叫料再簽一次。
- **A**：維持兩次核准（現況）。
- **B**：**叫料連到「已核准採購單的明細」就不再簽一次**（以採購單核准為準，保留到貨確認）。這是**新設計**（不是改一個開關），工作量約中等；要定義「叫料與採購單內容不一致時怎麼辦」；**已在簽核中的叫料維持原流程、不追溯，只有之後新送審的叫料適用新規則**。
- **C**：**回到只簽叫料、採購單不再是前提**（系統有一個常數可以這樣回退舊流程：叫料不再要求先有已核准採購單）。
- 代價：A——兩次簽核維持，無開發成本；B——要新設計與新測試，且是**放寬簽核**，內容不一致的處理要先定；C——採購單與叫料脫鉤，兩份資料靠人對照。
- 我們的建議：**B**；若老闆不想放寬任何簽核，選 A。C 與「讓採購單到叫料連成一條」的方向相反，我們不建議。
- 規則：**B**——做成單據流程的調整後，屬**放寬簽核＝〔現行規則〕**：須經最高管理者核准流程與確認期。**C**——目前只是程式裡的常數，改程式發版就生效，**現在沒有任何規則會攔它、也不會有人被詢問**；要被規則管，須先把它改成設定中心裡「放寬方向」的設定。只有一位最高管理者的公司：降級為「原因＋確認期＋警示」。
- 之後能不能改：B／C 上線後回到 A＝收緊，立即生效。

#### D7　分批到貨／短交怎麼記？　→ 解鎖 **P2b**（顯示「到貨 4／12」）
> **✅ 使用者裁示（2026-11-13）：選 A**——材料申請新增「已到數量」、可分批累計；「預計到貨日」先不加。
現況：到貨是「每張叫料單一個到貨日」，沒有「到了幾件」；到貨後若要改數量，必須退回草稿重簽，所以分批到貨只能拆單。
- **A**：叫料單新增「已到數量」欄位（可分批累計）。
- **B**：維持拆單重簽（現況）。
- 附帶：要不要新增「預計到貨日」？（現在沒有這個欄位，系統也刻意不追供應商前置時間。）建議先不加。
- 代價：A——新增欄位（到貨欄位本來就不算簽核要重簽的內容，所以不影響簽核），但要定義**累計規則與超收怎麼辦**，資料寫入後欄位就存在；B——分批到貨永遠只能拆單，時間軸只能顯示「這張到了／沒到」。
- 之後能不能改：選 B 之後想改 A 隨時可以（加欄位）；選 A 之後想拿掉，已寫的到貨數量會成為歷史資料，**不好完全回退**。

#### D2＋D8（連動的一組）　領料與耗材怎麼處理？　→ 決定範圍
> **✅ 使用者裁示（2026-11-13）：D2＝A、D8＝A**——先不做領料單；耗材（無序號）以材料申請的數量為準，到貨即視為現場領用、不進庫存。
**這兩題互相連動，請一起回答**：D8 的選項取決於 D2。
現況：系統沒有領料單；庫存全案假設每件有序號；無序號的耗材（線材、接頭）目前**沒有任何地方可以登記**。
- **D2 要不要做領料單（領用、扣庫存、記領用人）？**　A 先不做（出貨與設備登載已覆蓋主要消耗）　／　B 現在就做。
- **D8 無序號耗材怎麼辦？**
  - **A**（搭配 D2-A）：以叫料單的數量為準，**到貨即視為現場領用**，不進庫存；
  - **B**（需要 D2-B）：進庫存但以數量計，要領料才扣。
- 代價：（D2-A＋D8-A）工作量最小，但看不到耗材餘量；（D2-B＋D8-B）要新增「數量型庫存」與一整張領料單，範圍約變成兩倍。D2-B 搭配 D8-A、或 D2-A 搭配 D8-B 不成立。
- 之後能不能改：A 組合之後要加領料單＝另開一批，可以，但屬新增工作。

#### D1　叫來的料都要入庫嗎？　→ 決定範圍（影響入庫格的畫面）
> **✅ 使用者裁示（2026-11-13）：選 A**——到貨時二選一：入庫，或直送客戶現場（直送者仍可登載序號與設備）。
本題只針對**有序號的品項**；無序號耗材（線材、接頭）怎麼辦由下面「D2＋D8」決定，兩題互相影響（D1 選「一律入庫」時，D8 的「到貨即視為領用、不進庫存」就只能用在耗材）。
- **A**：到貨時二選一——**入庫**或**直送客戶現場**；直送者仍可登載序號與設備。
- **B**：一律入庫。
- 代價：A——直送列在時間軸上顯示「略過」，且直送者的序號沒有庫存側紀錄（設備登載照常）；B——每筆到貨都要進倉庫流程，沒有倉庫的現場直送案需要變通。
- 之後能不能改：A→B 容易（直接要求入庫）；B→A 也容易（多開一個選項）。

#### D4　保固起始日預設取哪一天？　→ 解鎖 **P3**
> **✅ 使用者裁示（2026-11-13）：選 A**——預設出貨日，沒有出貨單（直送）時依序退到到貨日、完工日；只預填、存檔前由人確認、不自動寫入；設定可改成以完工日為預設。
- **A**：預設**出貨日**；沒有出貨單（直送）時依序退到到貨日→完工日；**只預填，存檔前由人確認，不自動寫入**；設定可改成以完工日為預設。
- **B**：預設完工／驗收日。
- **C**：維持空白（現況）。
- 代價：保固起算常是合約條款（出貨、驗收？），預設值屬商業判斷；A、B 都靠預填＋人確認避免靜默改保固；C——沒填起始日的設備永遠不會被提醒。
- 之後能不能改：預設值隨時可改，已存的設備列不會被追溯修改。

#### D10　退貨／RMA／換貨要不要納入？　→ 決定範圍
> **✅ 使用者裁示（2026-11-13）：選 B（納入，退換貨這輪一起做；使用者未採用我們的建議 A）**——新增 P7 批次（見 §2.4），並衍生兩個小題，**同日（2026-11-13）使用者亦裁示**：**D12＝C**（換機後新機預設沿用原機保固到期日，存檔前由人確認、可改成重新起算）、**D13＝A**（比照入庫 D9：同一組權限、列權限矩陣動作、必填原因、不另外簽核）。選單見 `ONEPIPE-DECISIONS-MENU.md` 第四組。
現況：序號只有「在庫／已安裝／已出貨／作廢」四種狀態，沒有退貨。
- **A**：本輪不納入，另案評估（換機、退貨仍靠人工與留言）。
- **B**：納入（新增退貨狀態，連動案件與保固）。

- 之後能不能改：A→B＝新增一批，可以。

#### D11　要不要通知「下一個人」？　→ 解鎖 **P6**
> **✅ 使用者裁示（2026-11-13）：選 A**——輪到某人時站內通知他（只通知「輪到你」的人）；LINE 照既有規則預設關、只給指定的人。
現況：成案、採購單核准、到貨確認，都不會通知下一步的人，採購要自己每天開畫面看。

- **B**：不做，靠時間軸的「卡在誰手上」自己看。
- 代價：A——多一批小工；B——採購仍要每天打開畫面。
- 之後能不能改：隨時。

## 1.5 另案提醒（不在本提案）

| 8 | **簽核流程調整**（D6✔B） | 放寬簽核，走核准流程與確認期；不擋其他批，排最後 |

D6 不阻擋任何批次：P2a／P2b 只動庫存端。P1' 只需讀 provider。

**降級情境**（驗收要測）：M03 缺席 ⇒ 入庫格隱藏；M03 在但 provider 出錯 ⇒「庫存暫時讀不到」；D9-B 時呼叫者無入庫權 ⇒ 只做案件那半＋對帳表（不整張失敗）。

## 2.5 驗收

1. 新進採購 5 分鐘內能從「採購管理」進到某案叫料並知道下一步（P0a／P1'）。
2. 從案件開請購單不需重新搜尋案件（P0a）。
3. 先出貨後登載不報衝突；他案已 installed 仍報衝突（P0c）。
4. 一批 N 台到貨，序號貼上一次，庫存、材料卡、設備列都有（P2b；N≥10）；重複序號逐列回報、其餘照寫。
5. 已結案案件保固到期會通知，**且旗標首次打開不寄任何歷史通知**（P0d）。
6. 工程師在日誌選案件後，該日誌出現在案件動態與專案報告；日誌可見範圍沒有變寬（P0b／P4）。
7. 聚合 API：非該案成員 403；無金額檢視權者回應內無金額欄位；無權段落整段不回傳（雙帳號負向測試）。
8. 倉儲模組缺席與出錯兩種降級，畫面各如 2.2；其餘各段照常。
9. 每批旗標關＝與今天逐位元相同（測試比對）。
10. 點擊數前後對照表（引用凍結的基準）：無一項增加。
11. 單案聚合 API p95 在預算內；首頁看板不產生 N 次聚合。
12. 新畫面用語走狀態顯示名稱表與禁用詞單一來源，不自創。

## 2.7 風險與未驗證

- 評審者沒跑測試與畫面；其「已驗」項是對程式的靜態核對（我與 hichan-9 兩次對原始碼，皆屬實）；「推論」項（通知洪水、請購單單價權限）在開工前清單實測後才算定案。
- 資料雙邊寫入（P2）仍是最大技術風險：案件內嵌 JSON 與庫存表同交易、失敗補償、使用者同時編輯；先在測試機以假案件演練（`_onepipe_shots.py` 假資料可重用）。
- 權限治理缺口：入庫、請購、每日事項今天都是寫死檢查；若老闆要它們被「第二位核准」管住，必須先把它們做成權限矩陣動作／設定中心設定（見 D9、D6），否則只靠發版就能放寬。
