# 使用者自訂邏輯威脅模型與安全需求（草案 r1，0d 獨立稽核；僅文件，未跑任何測試）

> 前提（使用者 2026-10-13 永久裁示）：範圍＝所有功能皆可由使用者在系統內定義——規則引擎開放、匯出範本、條件紅字／上限規則、自訂按鈕／選單、各畫面欄位、儲存／上傳資料夾、新邏輯。
> 本文件只回答：**開放之後，哪些東西必須寫死在程式、每個風險的必備控制、以及證明控制有效的測試（含正對照）**。與 98 的架構／路線圖 r12 對齊：以脊柱 `features[]`／欄位目錄（catalog）／settings 引擎／`publish()` 單一寫入口為載體，不另開第二套機制。
> 讀法：每節 ＝ 威脅 → 必備控制 → 證明測試（P＝正對照：故意放進壞輸入，測試必須紅，證明守門真的會擋）→ 必須寫死。

## 0. 總原則（全部威脅共用）

1. **資料不是程式**：使用者定義的一切只能是「受限語言的資料」（JSON 宣告），由程式內**固定的直譯器**解釋；不得 `eval`／`exec`／`compile`／模板引擎的任意表達式／`pickle`／`yaml.load`（非 safe）。直譯器的運算子、函式、欄位來源是**白名單**，白名單本身寫死在程式。
2. **權限在伺服器端、在最後一哩**：欄位可見性、金額遮蔽、案件權限一律在**資料取出層**（`financial_mask`／`QUOTE_MONEY_KEYS` 等）套用，規則／範本／匯出只能拿到「已遮蔽後」的資料。UI 隱藏不算控制。
3. **單一寫入口＋雙人核准＋變更明細**：任何定義的寫入走 `publish()`（`config_changes` ledger、稽核、放寬需第二位超管）。新的定義種類必須宣告 `risk` 與 `impact_scope`；money／legal／security 級預設走放寬流程。不得有繞過 `publish`／`publish_direct` 的路由。
4. **預設拒絕、白名單、失敗關閉**：未知鍵、未知函式、未知欄位、解析失敗 ⇒ 該定義不生效（回預設行為），不是降級成全開。脊柱損壞才維持 open（既有行為），驗證失敗的功能 ⇒ hidden。
5. **成本有上限**：任何使用者定義都有硬上限（深度、節點數、列數、逾時、輸出大小），上限在程式。
6. **可回滾、可稽核、可停用**：每個定義有版本、可還原、可由超管一鍵停用（kill switch，停用後回到內建行為）；每次生效／被擋都留稽核。
7. **每個新「可定義種類」上線的閘門**：威脅表（本文件第 N 節）逐項勾選＋對應測試存在，才能把 `features[].status` 設為 open（`planned` 期間不可寫）。

## 1. 規則引擎／公式／條件（紅字、上限、動作）

**威脅**：(a) 程式碼執行（表達式被當 Python／JS 執行）；(b) 無窮迴圈、指數爆炸、巨大字串；(c) 規則讀取使用者看不到的欄位再把結果「洩」出去（例：紅字／上限提示間接暴露成本）；(d) 規則改寫金額／狀態（提權、繞過簽核）；(e) 規則互相觸發無限遞迴；(f) 規則在「讀」時有副作用。

**必備控制**
- 規則語言＝純函式、無副作用、無迴圈／遞迴語法；只有比較、布林、四則（`Decimal`/`Fraction`，不用 float）、白名單函式（min/max/round/isblank…）。
- 資料來源只有目錄（catalog）列出的欄位；每個欄位在目錄裡有 `visibility`（角色集合），規則**以執行者的角色**求值：看不到的欄位 ⇒ 該規則對此人**不評估、不回任何由它衍生的訊號**（不回「紅」、不回「超限」，也不回「被隱藏」）。
- 規則的**輸出型別固定**：只能是「標記（紅／黃／提示文字模板）」或「阻擋存檔（附固定模板訊息）」；**不能寫入欄位值、不能改狀態、不能呼叫其他 API**。要有動作（通知、狀態轉換）走各自已存在、已有權限檢查的註冊動作（見 §8），不是規則直接做。
- 規則評估預算：節點數 ≤ N、深度 ≤ D、單次評估逾時，超過 ⇒ 該規則視為「未命中」並記稽核；單一畫面規則數上限。
- 提示文字模板只做「欄位值代入」，代入值一律當**純文字**輸出（前端用 `textContent`，後端 PDF／Excel 走 §2、§3 的跳脫）。
- 阻擋型規則只能**更嚴**；要放寬（移除阻擋）屬 money／legal 影響者走放寬流程（沿用 `loosen` 概念）。
- 規則改動時 `live_impact`：顯示會影響多少既有單據（唯讀預覽，不寫入）。

**證明測試**
- 解析器拒絕清單：`__import__`、屬性存取、下標呼叫、lambda、f-string、`{{ }}`、`${ }`、超長輸入、巢狀深度 D+1、未知函式 ⇒ 全部「不生效」。（P：把其中一項加進白名單，測試必須變紅。）
- 角色矩陣：同一規則，engineer／sales／finance／cashier 對含 cost 欄位的規則，**回應位元組中不得出現**由 cost 衍生的任何旗標；與 `QUOTATION_MONEY_COLS` 對照的掃描測試（P：把某成本欄標成 sales 可見，測試必須紅）。
- 預算測試：構造 10⁶ 節點／深度 10³ 規則，評估時間 < 上限且不拋 500（P：移除預算，測試必須逾時而紅）。
- 無寫入測試：評估前後資料庫 `total_changes` 不變（唯讀連線或比對表內容）。

**必須寫死**：語言文法與函式白名單、輸出型別、預算上限的**上界**（管理者可調小、不可調大）、「規則求值身分＝目前使用者」、規則不能寫入。

## 2. 匯出／列印範本（HTML→PDF）

**威脅**：(a) 範本內 HTML／CSS／JS 注入 → 伺服器端 PDF 引擎載入本機檔案或內網 URL（SSRF／LFI，例如 `<img src="file:///…">`、`<link href="http://169.254…">`、`@import`）；(b) 範本引用不可見欄位（成本、毛利、個資）；(c) 範本替換掉「客戶版不得含內部資訊」的守門（客戶版 PDF 不得有成本／毛利／專案毛利）；(d) 超大／超多頁造成 DoS。

**必備控制**
- 範本＝**宣告式版面（區塊＋欄位占位）**，不接受原始 HTML／CSS／JS。需要樣式者只開放固定樣式選項（字級、對齊、欄寬、顏色色盤）。
- 欄位占位只能指向目錄欄位，且**依使用者角色＋「客戶版／內部版」旗標**過濾；客戶版範本的可選欄位集合＝目錄中標 `external_ok` 的子集（成本／毛利／內部備註永遠不在其中，寫死）。
- PDF 引擎設定：停用外部資源載入（無網路、無 `file:` 協定、只允許內嵌的白名單圖片資產）；圖片只可引用資產庫物件 id，不接受 URL。
- 輸出尺寸上限：頁數、列數、圖片位元組；逾時。
- 範本版本＋核准：客戶版範本變更屬 legal／external 影響 ⇒ 走放寬流程（第二位超管）。

**證明測試**
- 範本含 `<script>`、`<img src=file:///…>`、`src=http://…`、CSS `url()`／`@import`、`<iframe>`、`<object>` ⇒ 儲存時被拒，且渲染時即使繞過儲存層也不發出任何外連（用 stub 掛住 URL 載入器，斷言零呼叫）。（P：stub 開放外連，測試必須紅。）
- 客戶版輸出文字抽取：不得包含 cost／毛利／專案毛利／內部備註的任何值與標籤（以含獨特標記值的測試單據；沿用 `test_customer_pdf_html_has_no_project_margin` 的作法）。（P：把欄位標成 external_ok，測試必須紅。）
- 角色矩陣：engineer 套用含金額欄的範本 ⇒ 該欄為空或範本不可選，輸出中無金額。

**必須寫死**：不接受原始 HTML／JS、PDF 引擎的外部載入全關、客戶版欄位白名單的「永不包含」清單（成本／毛利／內部備註／個資）、輸出上限的上界。

## 3. 試算表／CSV 匯出（公式注入）與匯入

**威脅**：儲存格以 `= + - @ \t \r` 開頭 ⇒ Excel／Sheets 當公式執行（資料外洩、DDE、`HYPERLINK`）；使用者定義的欄名／表頭同理；XLSX 內嵌巨集／外部連結；CSV 編碼／換行注入造成欄位位移；匯入檔 zip 炸彈、XXE、超大。

**必備控制**
- **所有**字串儲存格輸出一律中和：開頭為 `= + - @ \t \r`（含全形與前導空白後的）時前置 `'` 或以文字型別寫入；欄名／工作表名同。集中在**一個**輸出函式，所有匯出走它（結構性：禁止各匯出自行 `ws.append`）。
- 工作表名：禁 `/ \ ? * [ ] :`、長度 ≤ 31（既有陷阱：全形斜線）。
- 只產生 `.xlsx`（無巨集）／`.csv`（UTF-8 BOM、RFC4180 引號跳脫）；不產生 `.xlsm`／`.xls`／含外部連結的檔。
- 匯出內容走 §0.2：資料取出層已遮蔽；匯出欄位集合＝目錄中該角色可見的子集；**欄位選擇器在伺服器端與角色交集**，客戶端送來的欄位清單視為不可信。
- 匯入：大小／列數／欄數上限；zip 展開比與總大小限制；XML 解析關閉外部實體；只讀值不讀公式（`data_only`）。

**證明測試**
- 以 `=cmd|' /C calc'!A1`、`@SUM(1)`、`+1`、`-1`、`\t=1`、全形 `＝` 開頭的值與欄名各跑一次所有匯出端點，讀回 XLSX／CSV：每個儲存格皆不被當公式（openpyxl 讀回 `data_type != 'f'`）。（P：暫時繞過集中函式，測試必須紅。）
- 掃描測試：除集中輸出模組外，匯出程式碼不得直接呼叫 `Workbook`／`csv.writer`／`ws.append`（AST 守門；P：加一處違規，測試必須紅）。
- 欄位選擇器：engineer 在請求中塞入 `cost`／`salary` 欄 ⇒ 被忽略或 403，輸出不含。
- 匯入炸彈：10 MB zip 展開 > 1 GB／billion-laughs XML ⇒ 拒絕且記憶體不暴增。

**必須寫死**：公式中和規則、輸出格式白名單（xlsx／csv）、XML 外部實體關閉、大小上界。

## 4. 儲存／上傳資料夾與檔名（路徑穿越、任意寫入）

**威脅**：設定的資料夾可含 `..`、絕對路徑、UNC（`\\host\share`）、磁碟機根、符號連結／junction、保留名（`CON`、`NUL`）、ADS（`file.txt:stream`）、尾端點／空白；檔名／副檔名導致可執行檔落入網站可服務目錄（`.html`、`.svg`、`.aspx`、`.py`）；寫到系統／程式／資料庫／金鑰目錄（`D:\MOTRIX-KEYS`）；磁碟填滿；覆蓋既有檔。

**必備控制**
- 管理者設定的是**「儲存位置代號」**（對應一個**程式內白名單的根目錄清單**，如 `uploads`、`exports`、`attachments`），代號之下只允許**單層、受限字元**的子資料夾名（`^[A-Za-z0-9_\-一-鿿]{1,40}$`）；**不接受任何路徑字串**。新增根目錄只能由部署設定檔（非 UI）宣告。
- 落地路徑＝`realpath(root / 代號 / 子夾 / 系統產生檔名)`，並斷言結果在 `realpath(root)` 之內（含符號連結／junction 解析後再比）；檔名由系統產生（單號＋亂數＋白名單副檔名），使用者原檔名只存資料庫當顯示名，輸出時走 `download_name`（既有）。
- 副檔名／MIME 白名單（依附件欄位 `kind`）；以內容魔術數驗證，不信副檔名與 `Content-Type`；禁止 `.html .htm .svg .js .exe .bat .ps1 .py .php .aspx .dll .lnk …` 與雙副檔名；一律 `Content-Disposition: attachment`＋`X-Content-Type-Options: nosniff`，不從靜態路由直出。
- 大小／數量／總量配額（沿用 `limits_for`）；寫入用 `O_EXCL`／暫存檔再 rename，不覆蓋。
- 資料夾變更＝新檔寫新位置、舊檔不搬不刪（避免搬遷造成遺失／穿越）；變更屬 `risk=security` 走放寬流程。
- 讀取側同樣解析並斷言在根目錄內（資料庫被改的路徑欄位也不得帶出根目錄外的檔）。

**證明測試**
- 設定值 `..\..\x`、`C:\Windows`、`\\evil\s`、`a/../b`、`CON`、`a:ads`、尾端點、超長、Unicode 同形字、含 `\u202e` ⇒ 全部拒絕。（P：把正規式放寬，測試必須紅。）
- 在根目錄內建 junction／symlink 指向根外目錄 ⇒ 上傳被拒（realpath 斷言）；Windows 無權建 symlink 時以 monkeypatch `os.path.realpath` 的正對照取代，並明講此限制。
- 上傳 `x.html`、`x.svg`、`x.exe`、改名成 `.jpg` 的 HTML、雙副檔名、含空位元組檔名 ⇒ 拒絕或以 attachment 強制下載且 nosniff；內容魔術數不符 ⇒ 拒絕。
- 資料庫路徑欄位被改成根外路徑 ⇒ 讀取回 404/403，不回檔。

**必須寫死**：根目錄白名單來源（部署設定，非 UI）、realpath 包含斷言、禁止副檔名清單的「永不放行」子集、系統產生檔名、attachment＋nosniff。

## 5. 欄位目錄／自訂欄位／畫面欄位（提權與金額遮蔽繞過）

**威脅**：使用者把成本／薪資／個資欄位「加進」某畫面、報表、匯出、通知、搜尋、排序、篩選、分組、統計；利用排序／篩選／聚合（總計、平均）做**旁路推論**（對看不到的欄位排序即洩漏大小順序；篩選 `cost > 100` 即二分搜尋出值）；自訂欄位名稱／選項含 HTML（儲存型 XSS）；自訂欄位覆蓋系統欄位（同名遮蔽）；欄位型別改變使既有資料誤判。

**必備控制**
- **欄位目錄是唯一事實來源**（脊柱 `catalog`）：每欄有 `owner`、`type`、`visibility`（角色／權限集合）、`sensitivity`（money／pii／internal／public）、`external_ok`。自訂欄位預設 `sensitivity=internal`、可見性預設＝建立者角色以下最小集；**提高可見性需放寬流程**。
- 所有「讀取衍生」操作（顯示、排序、篩選、搜尋、分組、聚合、匯出、通知內容、稽核回顯）在伺服器端**先與可見欄位集合取交集**；對不可見欄位的排序／篩選／聚合請求 ⇒ 400（不是靜默忽略後仍用該欄排序）。
- money／pii 欄位永遠走既有遮蔽函式（`financial_mask`），自訂邏輯拿不到原值。
- 自訂欄位 `key` 命名空間（`x_` 前綴）與系統欄位分離，禁止同名；標籤／選項文字存純文字，輸出一律跳脫。
- 欄位型別／敏感度**只能往更嚴改**；放寬走放寬流程。刪除欄位＝隱藏（資料保留）。

**證明測試**
- 角色×欄位×操作矩陣（顯示、排序、篩選、搜尋、聚合、匯出、通知）自動產生：不可見欄位在任一操作的回應中**不得出現值、順序、筆數差異**。（P：對 cost 欄暫時開放排序，測試必須紅。）
- 二分探測測試：engineer 以 `filter=cost>X` 掃描 ⇒ 一律 400，回應長度與時間不隨 X 變化（只斷言 400，不做計時）。
- 標籤含 `<img onerror>`／`"><script>` ⇒ 前端渲染為文字（以靜態掃描前端禁用 `innerHTML` 於使用者定義字串；P：加一處 innerHTML，掃描必須紅）。
- 同名欄位建立 ⇒ 拒絕。

**必須寫死**：money／pii 欄位的遮蔽路徑（不可被目錄設定關閉）、自訂欄位命名空間、讀取衍生操作與可見欄位取交集、敏感度只升不降。

## 6. 自訂按鈕／選單／畫面動作

**威脅**：按鈕綁定任意 URL（`javascript:`、外部釣魚、內網）；按鈕觸發動作時以高權限執行（confused deputy）；選單把使用者導向沒有權限的頁面造成假象或洩漏頁面存在；動作被 CSRF／重放。

**必備控制**
- 按鈕只能引用**已註冊動作（action registry）**的代號＋參數，不接受 URL 或腳本；導航目標只能是站內路由表中的頁面代號。
- 動作以**點擊者**的身分與權限執行，並重做該動作原本的權限檢查（按鈕不攜帶權限）；選單／按鈕顯示再依權限過濾（顯示過濾只是體驗，授權在動作端）。
- 動作參數經 schema 驗證（型別、範圍、白名單）；破壞性動作（刪除、核准、匯出全量）需二次確認＋稽核；動作速率限制。
- 任何會寄信、寫檔、改資料的動作屬 §8／§4 的控制範圍，不另開通道。

**證明測試**
- 按鈕定義含 `javascript:`／`data:`／`http://`／未註冊動作 ⇒ 儲存被拒。（P：放行 `javascript:`，測試必須紅。）
- 權限矩陣：engineer 點擊綁定「核准」動作的按鈕 ⇒ 403，且稽核留下被拒紀錄。
- 路由表 golden：新增動作路由必須進 route_table_golden（既有機制）。

**必須寫死**：動作註冊表、動作端授權、禁止 URL／腳本型目標。

## 7. 儲存層的竄改、回滾與稽核缺口

**威脅**：使用者定義可被靜默改動或回滾（隱藏舊版造成稽核斷鏈）；兩人合謀／單一超管自核；回滾到含漏洞的舊定義；刪除暫存區（回收桶）內容還原後繞過鎖定（匯出後凍結）；批次匯入覆蓋定義；時間戳被前端指定。

**必備控制**
- 所有定義寫入走 `publish()`；ledger 僅附加（append-only），不可改／刪；定義版本不可變；回滾＝發佈一個新版本（內容取自舊版）並同樣走驗證與核准，**驗證用現行規則**（舊版含已被新守門禁止的內容 ⇒ 還原被擋）。
- 放寬流程：申請人≠核准人、同人不重複投票、單一超管環境的處置寫入備註（既有）；核准票綁定「申請內容雜湊」，內容變動 ⇒ 票作廢。
- 時間由伺服器產生；定義的生效／到期時間不接受前端時戳。
- 刪除／回收桶：還原走與新建相同的驗證；被匯出／簽核鎖定的單據，還原不得解除鎖定；回收桶內容不可被規則／匯出讀取。
- 稽核內容含「誰、何時、哪個版本、前後差異、IP」；稽核寫入失敗 ⇒ 該寫入失敗（失敗關閉），不是靜默略過。
- 備份／還原後 ledger 序號與雜湊鏈驗證（可選：每筆含前一筆雜湊）。

**證明測試**
- 直接 SQL 更新 ledger 列 ⇒ 完整性檢查（雜湊鏈或僅附加觸發器）偵測到。（P：不改而查，檢查必須綠；改後必須紅。）
- 還原含禁止內容的舊版 ⇒ 被擋。核准後改內容 ⇒ 票作廢。
- 稽核表唯讀模擬（monkeypatch 讓 `audit` 拋例外）⇒ 定義寫入整體回滾。
- 無寫入 API 繞過：AST／路由掃描，除 `settings_registry.publish` 與 `materialize_due` 外，無人呼叫 `publish_direct`（沿用既有守門並延伸到新種類）。

**必須寫死**：ledger 僅附加、單一寫入口、核准規則（申請人≠核准人）、稽核失敗關閉、伺服器時間。

## 8. 通知／郵件／Webhook 動作（SSRF、郵件濫用）

**威脅**：使用者定義收件人（外部地址）→ 資料外洩、垃圾郵件／釣魚中繼；信件主旨／內文模板注入（標頭注入 `\r\nBcc:`）；Webhook／URL 動作 → SSRF（內網、metadata 位址、`file:`）；通知內容含不可見欄位；通知風暴（規則迴圈觸發）；退信／黑名單造成寄信帳號被封。

**必備控制**
- 信件類型走既有 `mail_types.register`（登記者＝擁有模組、收件人類別為角色／關係，如 `superadmins`、案件負責人）；**不接受自由輸入的外部地址**。若必須開放外部收件人，僅限網域白名單（寫死來源＝部署設定）並需放寬核准。
- 主旨／內文模板代入值先剝除 `\r \n`；標頭由程式組裝，使用者只提供內文占位；內文代入走 §0.2 角色遮蔽（以**收件人**的可見欄位集合過濾，不是以觸發者的）。
- **不提供使用者自訂 Webhook／任意 URL 動作**（此版）。若日後開放：僅 `https`、允許清單網域、解析後 IP 不得為私有／回送／連結本機／雲端 metadata（連線時重新解析、禁重新導向或逐跳驗證）、逾時與回應大小上限、無使用者自訂標頭。
- 速率限制與去重（同事件同收件人窗口內只寄一次）、每日上限、規則觸發深度 1（通知動作不得再觸發規則）。

**證明測試**
- 收件人 `evil@x.com`、`a@b.com\r\nBcc:c@d.com`、主旨含換行 ⇒ 儲存被拒或寄出的 MIME 無額外標頭（以假 SMTP 擷取；P：關閉剝除，測試必須紅）。
- 以收件人角色渲染：含 cost 的占位對 engineer 收件人為空。
- 風暴測試：規則 A 觸發通知、通知觸發 A ⇒ 深度限制終止，寄信數 ≤ 上限。
- （若開放 Webhook）URL `http://127.0.0.1`、`http://169.254.169.254`、`http://[::1]`、十進位 IP、DNS 重綁、302 到內網 ⇒ 全部被拒；P：移除 IP 檢查，測試必須紅。

**必須寫死**：收件人只能是登記類別／白名單網域、標頭由程式組裝、無任意 URL 動作（本版）、觸發深度與速率上界。

## 9. 阻斷服務（昂貴規則／匯出／報表）

**威脅**：全表掃描匯出、無上限列數、笛卡兒積的關聯、規則在清單頁對每一列評估（N×規則數）、同時多個匯出、排程風暴；單機部署（Windows 單一行程）下一個重工作拖垮全站。

**必備控制**
- 匯出／報表：列數上限、欄數上限、逾時、單一使用者並行 1 個、全站並行 N 個、佇列化（背景工作，結果過期清除）；查詢只允許目錄宣告的關聯，且關聯深度 ≤ 2。
- 規則評估：清單頁每頁列數上限 × 規則數上限 ≤ 預算；快取編譯結果（規則版本為鍵）；失敗時降級為「不評估」。
- 寫入側：每使用者定義數量上限、定義大小上限（KB）。
- 讀取端點速率限制；排程類規則（定時）最短間隔寫死。

**證明測試**
- 10⁶ 列假資料匯出 ⇒ 被截斷或拒絕（回明確訊息），耗時與記憶體低於上限（以小型替身設定縮小上限驗證邏輯，不在開發機跑大量資料；P：移除上限，測試必須超出）。
- 並行 2 個匯出同一使用者 ⇒ 第二個 429/排隊。
- 定義大小 1 MB ⇒ 413/拒絕。

**必須寫死**：所有上限的**上界**（管理者只能調小）、單一使用者並行數、排程最短間隔。

## 10. 跨角色／跨租戶洩漏（範本與共享定義）

**威脅**：A 角色建立的範本／檢視／規則被 B 角色套用而洩漏 A 可見的欄位；共享檢視讓低權限者看到高權限者的篩選條件（條件本身是敏感資料，如 `cost>…`）；多租戶（日後獨立販售）下定義、資產、檔案跨客戶可見；匯出檔放在共用資料夾被他人下載；下載連結可猜。

**必備控制**
- 定義帶**作者**與**可套用角色集合**；套用時重新以**套用者**的可見欄位集合求值（不是作者的）；範本中含套用者不可見欄位 ⇒ 該欄為空，且不揭露欄位存在與否。
- 篩選／規則條件本身視為資料：僅對可見該條件所有欄位的角色顯示條件內容，其他角色只見名稱。
- 租戶隔離（若啟用）：所有定義／資產／檔案路徑以租戶代號為命名空間，查詢強制帶租戶條件於資料層（不靠呼叫端）；測試以雙租戶夾具驗證。
- 匯出檔與附件下載一律經授權端點（簽核過的短期權杖或每次檢查權限），檔名不可猜（隨機 id），不放在靜態可服務目錄；過期清除。

**證明測試**
- 雙角色夾具：admin 建含 cost 的範本，engineer 套用 ⇒ 輸出無 cost 值、無欄名洩漏。（P：改用作者權限求值，測試必須紅。）
- 篩選條件顯示：engineer 看 admin 的共享檢視 ⇒ 看不到 `cost>100` 條件內容。
- 他人下載連結（換使用者／換租戶）⇒ 403/404，連結猜測（連號）⇒ 404。

**必須寫死**：以套用者身分求值、資料層租戶條件（若啟用租戶）、下載經授權端點。

## 11. 範本資產與供應鏈（字型、圖片、模板包、第三方程式庫）

**威脅**：使用者上傳的圖片／字型含惡意內容（SVG 內嵌腳本、字型解析漏洞、超大解碼炸彈）；匯入「範本包」（zip）夾帶可執行檔／路徑穿越（zip slip）；從網路自動抓取範本／字型；第三方 JS／CSS 以 CDN 載入被替換；相依套件被投毒。

**必備控制**
- 資產只收白名單格式（PNG／JPEG／WebP；字型僅部署時內建，不接受使用者上傳字型）；**不收 SVG**（或經淨化後轉點陣圖）；解碼前檢查尺寸／像素上限，重新編碼後再存（去除 metadata 與內嵌內容）。
- 範本包匯入：zip slip 防護（每個成員 realpath 在目標內、拒絕絕對路徑／`..`／符號連結成員）、成員數／總大小／展開比上限、只認宣告式範本（`.json`），拒絕任何可執行／腳本成員；包附內容雜湊，匯入前顯示差異，走 `publish()` 核准。
- 不從網路自動抓取任何範本／資產（無自動更新範本）；前端第三方程式庫固定版本＋SRI／自託管（沿用既有建包簽章與 `deploy_manifest` 雜湊）。
- 相依：沿用既有「相依由 PM 決定＋範圍宣告＋鎖定」；新增解析器／渲染相依（PDF、XLSX、影像）列入威脅審查。

**證明測試**
- zip slip 包（`../../x`、絕對路徑、symlink 成員）⇒ 匯入被拒，目標外無檔案產生。（P：移除檢查，測試必須紅。）
- 上傳含 `<script>` 的 SVG／偽裝成 PNG 的 SVG ⇒ 拒絕；像素炸彈（極大尺寸小檔）⇒ 拒絕。
- 靜態掃描：前端頁面不得有未 pin 版本的外部腳本（沿用既有建包檢查）。

**必須寫死**：資產格式白名單、不收 SVG／使用者字型、zip 展開防護、不自動抓網路資產。

## 13. 落地方式（與脊柱對齊）

1. 每一類「可定義種類」在 `module.json features[]` 宣告時，必須在 `catalog`／`labels` 之外新增 `threat_review: [節號…]`（或在驗證器登記 `covers`），驗證器以「是否有對應測試檔存在」作為 `open` 的前置條件；未完成 ⇒ 只能是 `planned`（引擎已擋寫入）。
2. 共用測試夾具：`role_matrix`（角色×欄位×操作）、`hostile_strings`（公式、HTML、路徑、標頭注入、同形字語料）、`fake_smtp`、`fake_url_loader`。語料與夾具一份、各種類共用，避免各自寫。
3. 正對照原則：每個守門測試至少有一個「故意壞」的變體證明它會紅（盤點工具需正對照的既有原則）；稽核時以此檢查「守門真的會擋」，而不只是「測試是綠的」。
4. 上線順序建議（風險由低到高）：①欄位目錄＋標籤（§5）②按鈕／選單（§6，僅註冊動作）③條件紅字／上限規則（§1）④匯出（§3）⑤列印範本（§2）⑥儲存／上傳資料夾（§4）⑦通知動作（§8，無 Webhook）⑧範本包匯入／資產上傳（§11）。每一步上線前，該節測試全綠＋0d 非作者稽核。
5. 開放問題（需 98／1c 決定）：①客戶版範本的「永不包含」清單由誰維護（建議寫死於 `helpers`，變更需 PR 與稽核）；②是否要在 M4 之前開放使用者自訂規則動作（建議不：先做標記型輸出）；③租戶隔離是否在第一期啟用（若不啟用，§10 租戶條目維持 `planned`）；④Webhook 本版不開放，確認。

> 本文件為稽核側需求草案；實際控制名稱、檔名與測試路徑待 98 的架構文件定稿後對齊。

## 14. 使用者自訂流程／狀態機（簽核鏈、簽回、退回、重開）

> 範圍補充（1c，10-13）：流程可由使用者定義——誰能轉換、簽核鏈、是否要簽核／簽回、退回草稿是否留紀錄、重開規則。
> 先說現況事實（已讀 `33b84b332`）：①自訂模組引擎的簽核層可帶**條件公式**，條件**明確為 False 就跳過該層，所有層都跳過 ⇒ 直接當作通過**（`custom_modules.py` ~1318–1345）；算不出來或欄位缺值則「照簽」（fail-closed，正確）。②防自核**不是無條件**：`check_no_tier_self_approval` 只在「沒有簽核層設定」的 fallback 套用（申請人是唯一在職最高管理者時放行）；**有簽核層時**，組織流程算出「申請人本人就是該層主管」的自簽層是被允許的（`case_extra_expenses.py` ~1032 註解，2026-09-15 起）。所以路線圖 r12 §4 寫的「簽核鏈引擎（分層、代理、防自核）寫死」**說得比現況強**——現況沒有「金額單據不得自核」的全域不變式。③變更帳本（`config_changes`）、權限變更、部分編寫紀錄表有 BEFORE UPDATE／DELETE 觸發器；我在 `db.py`／`core` 的搜尋裡**沒看到**一般稽核表（`audit_log`）與簽核歷史（`signed_log`、簽核格）的同類觸發器（可能在別處，UNKNOWN，待 98 核對）。

### 14.1 威脅
| # | 威脅 | 例 |
|---|---|---|
| W1 | **繞過簽核**：定義把簽核層條件寫成永遠不成立、金額門檻設成天文數字、把「需簽核」關掉、轉換直接從草稿到已核准 | 金額單據的簽核層條件 `總額 > 1e12` ⇒ 全部層被跳過 ⇒ 自動通過 |
| W2 | **自核／循環簽核**：申請人同時是簽核人；A 簽 B、B 簽 A 互相核；簽核層成員由申請人自己決定（單據欄位當簽核人來源）；代理人機制把核准權轉給申請人 | 條件公式取「申請人」當第一層簽核人 |
| W3 | **進行中單據孤兒／卡死**：定義改版後，舊單據所在狀態、轉換、簽核層不存在或簽核人已停用；改成要求簽回但舊單據已核准；循環狀態使單據永遠回不到終點 | 刪掉「簽核中」狀態；簽核人全部離職 |
| W4 | **稽核抑制**：定義關閉「退回草稿留紀錄」、關閉狀態轉換稽核、關閉通知；轉換動作不寫簽核歷史；以「重開」洗掉簽核紀錄；用事後改狀態覆寫歷史 | 退回草稿不留紀錄 ⇒ 看不出誰退過幾次 |
| W5 | **重開／撤銷濫用**：重開已簽回、已入帳、已匯出的單據；撤銷簽核後改金額再簽（簽核內容與簽核對象脫鉤） | 已付款的請款單被重開改收款帳號 |
| W6 | **提權**：轉換權限由使用者定義，賦予自己或某角色本來沒有的轉換權（例如「出納可核准」）；轉換動作帶副作用（寫入金額、發通知、入帳） | 工程師被賦予「核准」轉換 |
| W7 | **成本與無限迴圈**：自動轉換鏈（狀態 A 進入自動轉 B 再轉 A）；每次轉換觸發通知／事件造成風暴；簽核層數無上限；條件公式過重 | 兩個自動轉換互相觸發 |
| W8 | **跨文件關聯**：流程動作更新另一張單據（例如核准後自動建立付款），以流程繞過該單據自己的簽核 | 完工單核准自動建立已核准的請款 |
| W9 | **簽核與內容脫鉤**：簽核後內容仍可被改（含附件）而不重簽；或簽的是舊版本定義（單據綁 `def_version` 是正確做法，但新舊混用要明確） | 已核准後改金額不退回 |

### 14.2 必備控制
1. **流程定義的驗證器（發布前）**，對每個狀態機做靜態分析，任一項失敗 ⇒ 不能發布：①所有狀態可從初始狀態到達、且至少有一條路到終點（無孤兒、無死胡同）；②自動轉換圖無環（或每條環必含一次需人工的轉換）；③金額／法定單據類型（`risk=money|legal`）的「到達已核准／已付款」路徑上，**至少有一個需要人工簽核的層**，且該層的簽核人集合在發布當下**至少含一位在職、且不等於可能的申請人集合的人**；④簽核層上限（層數、每層人數）；⑤條件公式只能引用可見欄位、函式白名單、預算內。
2. **簽核跳過條件的保護**：允許以條件跳過層（例：小額免簽）是**管理員政策**，但對金額單據：跳過的條件只可引用**金額門檻**（單一數值欄位與常數比較），且門檻有**程式內的上界或需第二位核准的警示**——超過「最近 N 個月該類單據中位數的 K 倍」或超過寫死上界的門檻視為放寬到幾乎全免簽，需紅色橫幅＋第二位最高管理者核准＋確認期間。所有層皆被跳過 ⇒ 仍寫一筆「自動通過（原因：條件）」稽核。
3. **簽核人身分規則（寫死）**：簽核人 ≠ 申請人的檢查在引擎裡，無法由定義關閉；允許自簽的唯一情形是**現況已有的**：①唯一在職最高管理者逃生條款；②組織流程算出申請人本人就是該層主管，但**鏈上仍須至少有一位其他人**（UNKNOWN：這是新規則，需對現有單據類型逐一核對是否有只含自簽層的鏈；若有，列入遷移例外清單並顯示紅色橫幅）。簽核人來源只能是簽核人目錄（角色／部門主管／指名使用者），**不得來自單據欄位**（避免申請人指定自己的簽核人）；代理人不得是申請人。
4. **轉換權限**：每個轉換宣告「誰能做」，其值取自能力目錄（F3），且**不得超過該使用者本來的角色能力**（建構器只能在現有權限內收窄，不能放寬：例如把「核准」轉換給 engineer 角色 ⇒ 驗證器擋）；「核准」「付款」「入帳」「作廢」「重開」類轉換屬 `money|security`，只能指派給已具對應基礎能力的角色。
5. **進行中單據遷移（W3）**：單據綁 `def_version`；新版定義發布時，驗證器要證明「每個舊版的狀態都映射到新版的狀態」（映射表由發布者填，缺漏 ⇒ 不能發布）或舊單據**留在舊版直到終點**（預設）；改動簽核人時，進行中單據的待簽層重新解析，找不到在職簽核人 ⇒ 升級給最高管理者並告警，而不是卡死。提供「卡住單據」診斷頁（唯讀）。
6. **稽核不可抑制**：①每一次狀態轉換（含退回、重開、撤銷、自動通過、被拒的嘗試）一律寫入簽核歷史與稽核（誰、何時、從哪到哪、原因、定義版本、來源 IP）——**「退回草稿是否留紀錄」對金額／法定單據不可關**（對一般單據可作為選項，預設＝留）；②歷史表與稽核表加 BEFORE UPDATE／DELETE 觸發器（資料庫層不可改）；③重開不清除歷史，只附加。
7. **簽核綁內容**：簽核記錄含單據內容雜湊（或版本號）；核准後內容變動（金額、收款帳號、品項、附件清單）⇒ 自動退回待審核（對金額單據寫死；其他單據可選）。
8. **重開／撤銷規則**：已入帳／已付款／已匯出／已簽回的單據，重開需最高管理者＋原因＋第二位核准，且寫「重開」稽核；定義無法關閉此條。
9. **流程動作的副作用只能走動作目錄**，且被觸發的動作**以觸發者身分**並重新檢查目標單據自己的權限與簽核（W8）；跨單據動作不得建立「已核准」狀態的單據。
10. **成本上限**：層數、狀態數、轉換數、自動轉換鏈長（深度 1：自動轉換不可再觸發自動轉換）、每單據每日轉換數、通知速率（同 §8）。

### 14.3 證明測試（每項含正對照）
- 靜態分析題庫：孤兒狀態、死胡同、自動轉換環、金額單據無人工簽核路徑、簽核人集合含已停用／只含申請人、簽核人來自單據欄位、轉換權限超出角色能力 ⇒ 全部「不能發布」。P：把其中一條檢查拿掉，對應測資必須變成可發布而使測試紅。
- 繞過題：簽核層條件 `總額 > 1e12`、`1 = 2`、引用不可見欄位、算不出來 ⇒ 前兩者金額單據被政策擋或需核准，後兩者「照簽」；所有層被跳過 ⇒ 留下「自動通過」稽核。
- 自核題：申請人嘗試核准自己的金額單據（有層／無層／唯一最高管理者三種夾具）⇒ 與規則一致；代理人為申請人 ⇒ 擋。
- 遷移題：在進行中單據存在時發布刪除某狀態的新版 ⇒ 缺映射被擋；有映射 ⇒ 單據落在對應狀態且歷史完整；簽核人全離職 ⇒ 升級而非卡死。
- 稽核題：以 SQL 直接 UPDATE／DELETE 簽核歷史／稽核表 ⇒ 觸發器擋（P：在測試用副本移除觸發器，同一測試必須失敗）；轉換被拒也有稽核。
- 綁內容題：核准後改金額／收款帳號／附件 ⇒ 退回待審核。
- 風暴題：自動轉換鏈、通知迴圈 ⇒ 深度與速率上限終止。
- 提權題：以建構器 API 把「核准」轉換指派給 engineer ⇒ 400。

| # | 不變式（寫死、設定與定義都不能關） | 理由 | 與現況 |
|---|---|---|---|

## 15. 列印範本的文字、浮水印與背景字、預覽

> 補充 §2：範本可含浮水印／背景字／頁首頁尾自由文字；有預覽功能。

### 15.1 威脅
| # | 威脅 |
|---|---|
| P1 | **文字注入 PDF／HTML**：自由文字含 `<script>`、`<img src=…>`、CSS `url()`、`{{ }}` 占位語法、`file:`／內網 URL；字型名稱注入；超長文字、控制字元、RTL 覆寫（U+202E）造成視覺欺騙 |
| P2 | **冒充官方狀態**：浮水印寫「正本」「已核准」「已付款」，或以背景覆蓋/遮蔽程式輸出的「未核可」紅色橫幅、公司身分、稅籍、法定欄位；客戶版加上內部才該有的字樣；以白色字遮蔽內容 |
| P3 | **以浮水印夾帶資料**：占位符帶入金額／成本／個資到客戶版浮水印（每頁重複，難以察覺） |
| P4 | **預覽洩漏**：預覽用範本草稿渲染真實單據，把未發布範本的內容或遮蔽前資料給無權者；預覽結果被當正式文件下載／寄出；預覽 URL 可猜、被快取 |
| P5 | **效能**：浮水印每頁平鋪大量文字、超大圖、多層透明度造成渲染逾時 |
| P6 | **資產**：背景圖／Logo 上傳（見 §11）；以資產名稱做路徑 |

### 15.2 必備控制
1. 浮水印／背景／頁首頁尾文字＝**純文字欄位**，長度上限（例如 40 字、浮水印最多 1 條），字元白名單（可見字元＋常用標點，去除控制字元與雙向覆寫字元），輸出時一律 HTML 跳脫；**不支援占位符**，或僅支援**客戶版白名單占位**（案件名稱、日期、單號；絕不含金額、成本、個資）。
2. 樣式只開放：位置（預設列表）、角度（有限選項）、透明度**上限**（例如最大 20%，使文字永遠不遮蔽內容）、字級範圍；顏色限色盤（淺灰）。z-order 寫死：浮水印在內容下層，**程式輸出的「未核可」橫幅、公司抬頭、稅籍、法定欄位永遠在最上層且不被覆蓋**。
3. **保留字清單（寫死）**：浮水印／背景字不得含「正本」「已核准」「已核可」「已付款」「已簽回」「作廢」等官方狀態詞（含全形／同義簡寫）的精確比對與近似比對；狀態字樣只能由程式依單據真實狀態產生（沿用 `doc_render` 的「未核可橫幅由程式決定」）。
4. 客戶通道：內部標示類浮水印（「內部」「機密—僅供內部」）不得出現在客戶版；客戶版文字走客戶通道白名單。
5. **預覽**：①預覽以**檢視者自己的權限**渲染（先遮蔽再套範本），且**每頁帶寫死的「預覽」斜浮水印**（不可由範本移除或調淡到不可見）、檔名帶 `預覽_`，絕不計入匯出次數、不寫「已匯出」；②預覽 URL 為需登入的即時產生（`Cache-Control: no-store`），不落地於可公開服務目錄；③範本草稿只有作者與有建構器權限者可預覽；④預覽可用「測試資料」而非真實單據的選項，預設測試資料。
6. 渲染預算：浮水印數量、字數、頁數、渲染逾時；逾時 ⇒ 降級為無浮水印並明確標示，**不阻擋**正式文件但不得因此漏掉程式必出的橫幅。
7. 範本發布屬客戶可見輸出 ⇒ 高影響：紅色橫幅＋影響範圍＋放寬／新增客戶通道文字走第二位核准。

### 15.3 證明測試
- 注入題庫（`<script>`、`</div><div>`、`url(http://…)`、`{{7*7}}`、`${…}`、U+202E、控制字元、5 萬字）作浮水印／頁尾文字 ⇒ 儲存被拒或輸出為純文字；渲染時零外連（stub URL loader 計數為 0）。P：關閉跳脫，測試必須紅。
- 保留字題：「正本」「已核准」「ＰＡＩＤ」「已 付 款」等變形 ⇒ 被拒。P：把保留字清單清空，測試必須紅。
- 遮蔽題：未核可單據的輸出文字抽取必含程式橫幅，且在任何浮水印設定下（最大透明度、最大字級、最前置 z-order 試圖）橫幅仍可見（以版面座標／z-index 斷言或 PDF 文字層抽取）。
- 通道題：客戶版含「內部」字樣浮水印 ⇒ 被拒；含金額占位 ⇒ 被拒。
- 預覽題：engineer 預覽含成本欄的範本 ⇒ 無成本；預覽檔含「預覽」浮水印且無法被範本移除；預覽不增加 `export_count`；無登入存取預覽 URL ⇒ 401；`Cache-Control: no-store`。
- 預算題：浮水印 1000 條／極大字級 ⇒ 被拒或逾時降級，橫幅仍在。

### 15.4 寫死
保留字與狀態字樣只由程式產生、程式橫幅與法定欄位的最上層與不可遮蔽、透明度與字級上界、預覽的「預覽」浮水印與不計次、純文字＋跳脫、客戶通道占位白名單、渲染預算上界。
