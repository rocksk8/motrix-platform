# 建構器：把功能加進既有模組（掛載點）— 設計草案（待裁示）

> 2026-10-01 草擬。狀態：**等使用者選方案**。需求：建構器除了建立獨立大模組，也要能把一個功能（如請款單）掛進既有模組（如「我的工作」）。

## 現況（已查證）
- 自訂模組的選單位置＝`def.menu.group`（顯示名稱）；`core/menu.py:merge_custom` 名稱與既有群組相同 ⇒ **併進該群組成為一個選單項目**。所以「出現在『我的工作』選單下」**已可做**，但它仍是獨立模組（自有權限 `custom.<key>`、自有頁 `custom-records.html?key=`）。
- 做不到的：內建頁面**內部**（例：案件管理頁的頁籤、報價單頁的區塊）嵌入自訂模組。內建模組 `module.json` 沒有宣告可嵌入的掛載點（`customization_note`：搬遷時未宣告）。
- 群組選單只列「目前側欄有的群組名稱」（`readMenuGroups` 讀 DOM），內建群組以 key 管理、自訂以名稱比對 ⇒ 改名會脫鉤。

## 三個方案
| 方案 | 做法 | 範圍 | 風險 |
|---|---|---|---|
| A 選單群組（現況＋補強） | 建構器「選單位置」改成列內建群組清單（取自 `/api/platform/menu`，非讀 DOM），顯示群組 key；補說明「這是選單項目，不是頁內頁籤」 | 前端小改 | 低；不動內建模組 |
| B 頁籤掛載 | 內建模組在 `module.json` 宣告 `mount_points: [{key, kind:"tab", page}]`；自訂模組 `def.mount={module, point}`；該頁載入時向 `/api/platform/mounts?point=` 取清單並以 iframe／內嵌元件顯示 | 後端 registry＋API、案件／報價頁各改一處、建構器新欄位 | 中；權限＝掛載點所在模組權限 ∩ 自訂模組權限；停用模組時掛載一併隱藏 |
| C 兩者 | A＋B | 同上 | 同 B |

## 若選 B 的規格要點
1. **宣告**：`module.json` 新增 `mount_points`，由 `core.customization.validate_manifest` 驗證（鍵：`key`、`kind`=`tab`、`page`、`label`、`context`＝傳給嵌入模組的上下文鍵，例：案件編號）。
2. **定義**：`custom_module` body 加 `mount: {module, point}`（可空＝獨立模組）；驗證器檢查 module 已載入、point 存在、同點不得重複 key。
3. **權限**：能看到頁籤＝有掛載點所在模組權限 **且** 有 `custom.<key>`；後端 `merge` 與列表端點雙重過濾（與 `visible_to` 同源，不另寫一份）。
4. **資料**：單據仍存 `custom_records`；掛在案件下的單據以 `context` 欄位（如 `case_no`）關聯，列表自動帶篩選。
5. **停用／刪除**：內建模組停用 ⇒ 掛載點消失、資料保留；刪除自訂模組沿用 2026-10-01 新增的規則（有單據需二次確認）。
6. **測試**：掛載點宣告驗證、權限交集（擋錯人）、停用後 404／不顯示、e2e 驗頁籤出現與終點狀態＋截圖。
7. **工量估計**：B 約 1～2 個工作班（後端 registry／API 0.5、案件頁嵌入 0.5、建構器欄位＋e2e 0.5～1）；首批只開放**案件管理頁**一個掛載點，其餘照樣板擴充。

## 推薦
先做 **A**（半天內可出貨，解掉「在我的工作下找得到」的需求），B 等使用者確認「要不要頁內頁籤」與首批掛載頁。**需使用者裁示：A／B／C；若 B，首批掛哪一頁。**
