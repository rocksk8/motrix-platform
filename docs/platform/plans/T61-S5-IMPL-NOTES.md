# T61 S5 實作筆記：內建畫面的自訂欄位（案件資訊、供應商先導）

> 日期：2026-10-14　作者：hichan-3c　分支：`wip/t61-s5-impl-r1`　設計：`T61-S5-FIELD-CATALOG-DESIGN.md`（在 `wip/t61-s5-design-r1`）
> 旗標：設定中心「自訂欄位（內建畫面）」＝`builder_custom_fields.enabled`，**預設關閉**。

## 1. 寫入路徑與閘門（誰能寫 `customFields`）

值只能經**閘門** `helpers.builtin_fields.gate(record_type, new, old)` 寫入；每條會寫到單據 JSON 的路徑要嘛過閘門，要嘛強制以資料庫現值為準：

| 路徑 | 做法 |
|---|---|
| `PATCH /api/quotations/{no}/case-record`（分段存檔與舊整包格式） | 過閘門（`case_info`）。分段：送了這個分段才處理；舊整包格式沒送這個鍵＝沒有要改，帶回舊值 |
| `PUT /api/quotations/{no}`（報價單表單整份存檔） | **不過閘門，強制換成鎖內讀到的資料庫現值**（偽造值無效；沒送這個鍵不會把已存的值洗掉）。pre-audit（hichan-04）MUST-FIX |
| `POST /api/quotations`（新建，含複製案件） | 一律 pop，不帶自訂欄位（複製案件＝不複製值） |
| 財務角色（非成員）的舊整包存檔 | 在「只准改款項」的預檢之前，把 `customFields` 換成資料庫現值（不寫入，也不因缺鍵被當成改了非款項欄位而 403） |
| `POST/PUT /api/suppliers` | 過閘門（`supplier`）；PUT 沒送這個鍵＝帶回舊值；送 `{}`＝清掉有效欄位的值；錯誤回 400（POST 在 try 之外丟，不被吞成「建立失敗」） |
| 變更申請核准（已結案半解鎖的案件記錄更新） | **重放排隊時的內容，不重新過閘門**。內容在排隊前已經過閘門（過閘門的位置在排隊之前）；已知的陳舊：排隊後、核准前，若旗標被關或欄位定義被改（停用、改選項），核准套用的是排隊當時驗過的值。可接受（值本身仍是當時合法的值，欄位停用只是不再顯示）；不另外補第二道閘門，以免核准時因定義改變而讓已排隊的變更失敗 |

## 2. 與存檔基準（409）的相容

案件記錄是分段存檔，前端比對「送出時的分段 JSON」與「基準」。為避免「存完之後伺服器的樣子與用戶端的基準不同 ⇒ 下一次存檔誤判成別人改過（409）」：
- 閘門**不補預設值、不改寫值**（除了型別正規化：日期＝YYYY-MM-DD、單選必須在選項內）；
- 前端 `cfSet` 清到沒有值就**刪掉 `customFields` 這個鍵**（伺服器同樣「沒有值就不寫鍵」）；
- 停用／不在定義裡的欄位值，伺服器**原樣保留**（用戶端送來的改動忽略；畫面不顯示它們，所以不會有差異）；
- 測試 `test_consecutive_saves_do_not_raise_false_conflicts` 用用戶端自己的基準連存三次，確認沒有 409。

## 3. 第一版刻意不做

數字型別（可能被拿去放金額）、必填、預設值、F2 個資、公式／參照；角色預覽（第一版所有內部角色看到相同的自訂欄位，編輯器明說）；進客戶輸出（PDF／回簽頁／預覽——有「真的建出 HTML 再比對」的測試，含正對照）；欄位對 P9 版面引擎可見（固定在「自訂欄位」區塊）；內部匯出多一欄。

## 4. 旗標關閉＝今天

- 端點 `GET /api/custom-fields/{類型}`：`enabled:false, fields:[]`。
- 頁面：啟動時多一個 GET；之後什麼都不畫、不掛編輯器（node 實跑：旗標關閉／HTTP 錯誤／斷線三種都一樣）。
- 寫入：用戶端送來的 `customFields` 一律不存、舊值原樣保留（案件、供應商）。
- 回應：沒有值就沒有 `customFields` 鍵（回應鍵集基準不變）。

## 5. 風險與後續

- 案件頁是高流量檔：只加了一個閘門區塊、一個分段標籤、一個 `x-if` 區塊與一個部件（`cfGet`／`cfSet`／`cfIsAdmin`）。
- 治理（3e S2）把「新增欄位」判為放寬 ⇒ 治理旗標開啟時每個新欄位都要第二位最高管理者核准（D3 嚴格，使用者已確認不放寬）；編輯器如實顯示待核准。
- 瀏覽器實機未驗證（只有 node 實跑與契約測試）；e2e 待機器空閒。

## 6. 使用者看到什麼、怎麼開（步驟檔用）

**怎麼開（一次性，最高管理者）**：系統 →「設定中心」→「自訂欄位（內建畫面）」→「要開放管理者在案件資訊與供應商畫面加自己的欄位嗎？」選「開放自訂欄位」並儲存（這是低風險設定，立即生效，可隨時關回）。關閉時畫面、資料、報表與今天完全相同。

**開了之後最高管理者看到**：
1. 案件管理 →（選一張案件）→「案件資訊」分頁最下方多出「自訂欄位」區塊；供應商管理 → 編輯供應商，視窗最下方也有。區塊右上有「編輯自訂欄位」按鈕（只有最高管理者看得到）。
2. 按下去，右側出現「自訂欄位」面板：「＋ 新增欄位」→ 填顯示名稱（例：現場工頭）、選型別（文字、日期、單選、勾選）、單選要填選項（一行一個）、可加填寫提示；上下鍵調順序。**畫面上的區塊會即時出現預覽**（標示「預覽（草稿，尚未發布）」），這時還沒有任何人看到。
3. 「存草稿」（有問題會標在該欄下）、「看差異」（和目前發布版比）、「發布」（先在面板內問一次「確定要發布嗎？」）。發布後所有內部人員在對應畫面看得到並可填寫。
4. 已發布的欄位：型別不能改（要改請停用再新增）；不能刪，只能「停用」（停用前會顯示「已有 N 筆單據填了這個欄位」，資料保留、畫面不再顯示，重新啟用就會再出現）。每個單據類型最多 20 個欄位。
5. 版本清單可以「還原」到任一舊版（會先問）。若同時開啟「建構器治理」，新增欄位屬於放寬，發布會變成「已送出，待第二位最高管理者核准」並顯示生效時間，核准前不會生效。

**其他人（業務、工程師…）看到**：開了且已發布欄位後，在案件資訊分頁與供應商編輯視窗多一個「自訂欄位」區塊，可以填寫（和合約資訊、備註一樣，能編輯該單據的人就能填）；沒有編輯器按鈕。

**不會發生的事**：欄位不會出現在報價單、客戶版文件、結案報告或回簽頁；沒有金額型別；舊單據不需要遷移（沒填就沒有這個欄位的值）；關閉旗標不會刪任何已填的值（只是不再顯示、不能再改）。
