# 材料申請：強制對應採購單＋出貨單連動 規格（第 33 班；2e；docs only）

2026-10-02 16:12。承 `MATERIAL-ORDER-LINK-SPEC.md`（S4a–e，第 32 班已實作）。使用者裁示（第 33 班，不併第 32 班；第 32 班照現有出貨）：
- 流程＝**請購單 → 採購單（皆送審）→ 材料申請（從採購單內容帶入）→ 出貨單連動材料申請內容出貨（出貨也送審）**；像「五金另料」這種一個品項由多張採購單組成。
- (1) 材料申請**強制**：沒有已通過的採購單就不能送審（取代先前「不強制＋標註」；舊單不受影響）。(2) 分頁名稱維持「材料申請」。(3) 出貨單連動材料申請納入第 33 班。
本檔只寫規格，不改程式。用字照 `MATERIAL-REQUEST-WORDING.md`。

## 0. 現況（第 32 班實作 @ wip/t32-s4a-2e 與整合樹）

- 材料申請＝`caseRecord.materialOrders[]`（內容）＋ `case_material_approvals`（審核疊加列，31-C）；連結鍵 `quoteItemId／poDocCode／poLine／overPlanReason`（選填）。
- 連結判定唯一函式 `purchase_items.material_link_status`／`_link_check`：有效採購單＝同案件、待審核／簽核中／已核准、列序／品項對得上；連到有效採購單者金額由採購單負責（單一歸屬）。
- 送審檢查 `purchase_items.material_submit_check`（接縫，d7 於送審路徑呼叫）：品項存在、連結有效、`po_line_taken`、超計畫要原因。**不要求有連結**。
- 物流旗標（`caseRecord.materials[].ordered／arrived`，31-C 守門）：對應已核准材料申請＋到貨確認（日期、人）。
- 出貨單 `shipping_notes`（supply／M03）：`items_json` 自由格式（說明、數量、單位、可選 `part_no`＋`serials` 連庫存序號）；`草稿→待審核→簽核中→已核准`（doc type `shipping`）；核准時序號庫存 `in_stock→shipped`，總帳 E10（只回料號／件數，不帶金額）。**與材料申請沒有任何連動。**
- 採購單金額＝成本（E11／報表料件）；入庫（E08）與出庫（E10）只針對庫存序號，兩條成本路徑互不重疊。

## A. 強制規則

### A.1 送審條件（`material_submit_check` 新增 `po_required`）
材料申請送審必須同時滿足：
1. 至少一條有效的採購單連結，且**每一條連到的採購單狀態＝已核准**（使用者說「已通過」；待審核／簽核中的採購單不夠，見 D-3）。
2. 數量檢查改在**採購單行**：材料申請連到某採購單行的數量合計 ≤ 該行數量（扣掉其他「活的」材料申請已占用者；`po_line_taken` 升級為「數量」版 `po_line_exceeded`）。報價計畫量的超出檢查移回採購單端（採購單送審時已有「超計畫要原因」），**材料申請不再有 `overPlanReason`**（新單不顯示該欄；舊資料保留不動）。
3. 品項一致：採購單行有 `itemId` ⇒ 材料申請 `quoteItemId` 必須同一個（沿用）。採購單行沒有 `itemId`（額外採購）⇒ 材料申請沒有 `quoteItemId`（歸「額外材料」，不扣報價品項）。
未滿足 ⇒ 400，訊息用字表：「需先申請請購單，再申請採購單；採購單通過後，才能對應這筆材料申請。」（無連結）；「採購單尚未通過，通過後才能對應這筆材料申請。」；「對應的採購單已退回（或作廢），請重新申請採購單。」。
草稿**可以先存**（沒有連結也行，使用者先填內容）；強制點在**送審**。伺服器端唯一判定（前端只是提示），d7 的送審路徑呼叫同一個函式。

### A.2 匯入路徑改法（`js/case-management-mlink.js`）
- **「從採購單明細帶入」**成為新增的主要路徑：只列已核准採購單的明細行，且該行還有「可申請量」（行數量 − 活的材料申請已占）。帶入＝建立一筆草稿，連結、品名、單位、數量（預設＝可申請量，可往下改）、單價（唯讀，來自採購單）都已填；供應商由採購單廠商對照主檔帶入（對不到才要選）。
- **「從報價單品項帶入」改變用途**：報價單品項若**沒有任何已核准採購單行**，列為「尚未申請採購單」清單，每列一個「去申請請購單／採購單」按鈕（開請款頁並預選該品項，沿用 S1 的品項挑選器）；**不能直接建立材料申請**。已有採購單行的品項：點它＝展開該品項的採購單行讓使用者勾選（等於採購單帶入的品項視圖）。
- **「＋ 新增項目」（手動）移除**（新單）。理由：沒有採購單就送不出去，留著只會製造送不出去的草稿。舊單列照舊可編輯（舊單身分不變）。
- 新增品項不在報價單、直接買的東西：走「請購單→採購單（行不連品項）」，材料申請從該採購單行帶入，歸「額外材料」。

### A.3 「該材料申請未申請採購單」標註的新定位
- 新流程送審的單一定有連結，標註不會再出現在新單。
- 保留給三種資料：(a) 舊單（`approval_status=''`）沒有連結——**不標**（維持第 32 班規則：舊單不標，$0 不標）；(b) 強制規則上線前已核准／審核中、且沒有連結的單（ grandfather ）——標「該材料申請未申請採購單」並提供「補對應採購單」動作（見 A.4）；(c) 連結失效（採購單作廢）——標註＋「（原連結採購單已失效）」，**且該列不得再送審／不得出貨**（見 C）。
- 簽核佇列 `tags[]`、營運報表備註 `noPo` 維持，用於 (b)(c)。

### A.4 舊單、草稿與既有資料遷移
- **不改資料**（沒有資料遷移）。正式機現有材料申請 0 筆（2026-10-02 主持回報），第 33 班上線時無影響面；以下只是為一般性定義：
  - 舊單（`approval_status=''`）：完全不受影響。
  - 上線前已核准／待審核且無連結：保留、照舊計成本，標註＋「補對應採購單」。補對應＝只允許新增連結鍵（`poDocCode／poLine`），**不重新簽核**但寫稽核列（理由必填、記錄操作人）；金額欄位不可動。若補上後採購單的錢與材料申請的錢會重複 ⇒ 依單一歸屬規則該筆金額自動改由採購單負責（報表／總帳／精算守恆，沿用 S4c）。
  - 上線前的**未連結草稿／已退回**：保留可編輯；送審時被 `po_required` 擋下；頁面頂部顯示「N 筆草稿需先對應採購單」並提供「對應採購單」鈕（打開採購單帶入面板、針對該列）。
- 不做背景自動轉換（不猜使用者要連哪一張採購單）。

### A.5 付款路徑（與強制規則連動，需裁示 D-4）
31-C 的「材料申請匯款申請」付的是材料申請金額；強制對應採購單後，該金額已由採購單（請款單 payout）負責，兩邊都付會**重複付款**（S4c 只處理了成本認列，現金口徑對連結列略過材料申請匯款 ⇒ 匯款會從現金報表消失）。建議：**有連結的材料申請不可開匯款申請**（d7 seam 的「匯款互斥」），付款只走採購單；舊單／grandfather 無連結者的匯款照舊。
判定一律用**有效**連結（`_link_check`），不是 `poDocCode` 有沒有填：採購單作廢／退回而連結失效時，金額回到材料申請，匯款出口必須重新開放（第 32 包探針發現：只看鍵存在會讓這筆既不能走採購單請款、又不能匯款；已在 wip/t33-material-link-fix-2e 修正）。強制規則上線後，同理用於「材料申請送審前須有有效已核准採購單」的判定。

## B. 多張採購單組成一個品項（五金另料）

推薦：**混合模型**——一筆材料申請可含多個採購單行（`poLinks: [{poDocCode, poLine, qty}]`，同品項、同單位），同一報價品項的多筆材料申請在畫面**依品項群組**顯示小計。
理由：
1. **簽核不可變**：材料申請核准後內容鎖定（31-C 實質欄位）。五金另料常是「這個月買了一批、下個月又買一批」；若只允許「一筆含全部採購單」就會每次追加都要重新簽核；「一張一筆、依品項群組」每筆各自簽核、各自到貨確認，與現行「一列＝一份審核單＝一次到貨確認」資料模型相容。
2. **仍允許一筆含多行**：同一次到貨的多張小採購單（螺絲、墊片、線扣）合成一筆申請，簽核與到貨只做一次，不必拆成十筆。
3. **資料相容**：加性。保留 `poDocCode／poLine` 為單連結（＝`poLinks[0]` 別名，舊讀取端不變）；`poLinks` 只在多於一行時存在。`_link_check`／`po_line_*` 對每條連結逐條判定；`linked` ＝**所有**連結皆有效。
4. **群組不引入新實體**：群組只是 `quoteItemId` 相同的材料申請在畫面上的摺疊（小計＝Σ 金額／數量），後端沒有「群組單」。
數量語意：一筆申請的 `quantity` 是**品項單位**的數量（例：品項「五金另料」單位「式」，一筆申請 0.4 式）；各 `poLinks[].qty` 是採購單行自己的單位／數量（可混單位，僅供追溯，不參與品項量運算）。品項層可申請量＝報價量 − Σ 活的材料申請 `quantity`。（五金另料以「式」計的百分比語意需使用者確認，見 D-6。）
超出：材料申請對品項沒有計畫量上限檢查（上限在採購單）；只做「Σ 申請 ≤ 品項報價量」的**警示**（不擋，因為採購單已核過超計畫原因）。

## C. 出貨單連動材料申請

### C.1 目標
出貨單的品項能指向材料申請（的可出貨量），做到「申請了多少、到了多少、出了多少」三個數字對得上；出貨本身仍走既有出貨單簽核（doc type `shipping`），不新增簽核類型。

### C.2 資料模型
- **不跨模組讀表**：出貨單屬 supply（M03），材料申請屬 case（M01）。兩邊以 L1 提供者（registry，與 `approval.queue_items` 同機制）互通，彼此不 import：
  - case 提供 `material.shippable(quote_no)` ⇒ `[{materialItemId, docCode, name, unit, quoteItemId, appliedQty, arrivedQty, status}]`（只含已核准＋已到貨確認、未取消）。
  - supply 提供 `shipping.material_shipped(quote_no)` ⇒ `{materialItemId: 已占用出貨量}`（來源＝`items_json` 內連結；計 待審核／簽核中／已核准，不計草稿／已退回；退回核准＝回草稿＝自動釋放）。
- 出貨單明細列加選填 `materialLinks: [{materialItemId, docCode, qty}]`（存在 `items_json` 列內，加性；舊出貨單沒有此鍵＝不連動、行為不變）。一列可連多筆材料申請（五金另料多筆合成一列出貨）。
- 材料申請端不存出貨量（避免雙向寫入）；**已出貨量一律由出貨單提供者推導**。

### C.3 數量對照與規則
三個量（每筆材料申請）：已申請 `appliedQty`（`quantity`）→ 已到料 `arrivedQty` → 已出貨 `shippedQty`（核准的出貨連結合計）；占用中 `reservedQty`（待審核／簽核中）。
- 到貨量：現行到貨確認是整筆確認（日期＋確認人）。本案**預設整筆到貨 ＝ arrivedQty = appliedQty**；部分到貨（確認時填實收數量）列為選項（D-7）。
- 出貨檢查（出貨單**送審**時與**核准**時各檢查一次，後者防競態）：Σ（該材料申請在所有活的出貨單的連結數量，含本單）≤ `arrivedQty`；超出 ⇒ 400（`ship_exceeds_arrived`）。連到未到貨／未核准／已取消／連結失效的材料申請 ⇒ 400。
- 一列不可同時帶庫存序號（`part_no`＋`serials`）與材料申請連結（兩條成本路徑不重疊：庫存走 E08→E10，材料申請走採購單 E11）；違反 ⇒ 400。
- 取消材料申請：已有活的出貨連結（占用或已出貨）時不可取消（訊息指出出貨單號）。
- 出貨單被退回／撤銷核准：占用量自動釋放（推導值）。

### C.4 簽核與通知
沿用出貨單既有簽核流程與通知；簽核人詳情新增「對應材料申請」欄（單號、品名、本單出貨量／累計已出貨／已到料）。不新增簽核層、不新增 doc type。

### C.5 報表／總帳影響
**無新增分錄、無金額變動**：材料申請的錢已在採購單（E11／報表料件，單一歸屬）；出貨連動只加數量追蹤。E10 維持只針對庫存序號。報表加唯讀欄「已出貨數量」（案件材料申請清單）。守恆測試：加上出貨連結前後，報表／總帳／精算的金額逐位相同。

### C.6 與現行出貨單相容
- 沒有 `materialLinks` 的出貨單（含全部歷史單）：行為、驗證、PDF、通知完全不變。
- 出貨單頁新增「從材料申請帶入」（列出該案件已到料且有剩餘可出貨量者，勾選帶入、數量預設剩餘）；既有「從報價單匯入」「手動新增」「序號挑選」保留。
- PDF 出貨單：帶入的列照常輸出品名／數量／單位；連結資訊不印（內部資料）。
- 是否**強制**出貨單必須連結（有對應材料申請的品項）見 D-8；預設建議**軟性**（有可出貨材料申請的品項卻沒連結時，送審前顯示警示，不擋）。

### C.7 案件頁顯示
材料申請頁的每筆申請顯示「已申請／已到料／已出貨（占用中）」三格與出貨單連結清單；品項群組顯示小計。

- e2e（連續流程）：請購→採購（核准）→材料申請從採購單帶入→送審核准→到貨確認→出貨單從材料申請帶入→送審核准→案件頁三格數字與報表／總帳金額；另一題「五金另料」多張採購單＋多筆申請群組；另一題 grandfather 與舊單不受影響（含 `po_required` 只擋新送審）。

## D. 需要使用者裁示的口徑

1. **草稿可否先存（沒有採購單）**：建議可以先存、送審才強制。若要「連草稿都不可存」，新增流程只能從採購單帶入、不會有未連結草稿。
2. **手動新增與報價單直接匯入**：建議手動新增移除（新單）、報價單品項改成「去申請採購單」；是否同意？
3. **「已通過」＝採購單已核准**（待審核／簽核中不算）？建議已核准；若採購單核准很慢，是否允許「簽核中」先對應、核准後才可出貨？
4. **付款路徑**：有連結的材料申請不再開匯款申請，付款只走採購單（建議）；既有 31-C 匯款（舊單）照舊。
5. **材料申請數量／單價**：單價唯讀來自採購單、數量可往下調（≤ 行可申請量）（建議）；或全唯讀等於整行帶入？
6. **五金另料的語意**：以品項單位「式」計時，一筆申請的數量是否允許小數（0.4 式）當成「這批占品項的比例」？或改為只能整數、每筆申請固定算 1 式？
7. **部分到貨**：到貨確認是否要填實收數量（支援分批到貨與分批出貨）？預設整筆到貨。
8. **出貨單是否強制連結**：有已到料材料申請的品項，出貨單送審時沒連結是警示（建議）還是擋下？
9. **庫存序號與材料申請同列**：建議互斥（一列只能是庫存或材料申請）。
10. **既有無連結的已核准／審核中單（grandfather）**：建議保留並標註、允許補對應（不重新簽核、留稽核）；是否需要補對應時重新簽核？
11. **取消／作廢**：材料申請有出貨占用或已出貨時不可取消（建議）；採購單作廢導致連結失效時，已出貨的部分如何處理（建議只標註，不回溯）？
12. **報價計畫量超出的原因欄**：改由採購單負責、材料申請不再填（建議）；是否同意？
