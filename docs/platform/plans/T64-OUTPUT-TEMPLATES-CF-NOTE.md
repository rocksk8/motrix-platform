## 0. 結論
1. 明細（品項）自訂欄位：可做、風險中；先決條件是『品項列的存檔與 409 基準』要先查清楚（?，§A.4）。**放在 T63 匯出欄位落地並驗證之後**，不與匯出同批。
2. 匯出的自訂欄位欄：先做案件批次匯出（內部、非客戶輸出）；需要『動態目錄』，是 BP-3 目前沒有的能力（✔ 目錄在模組載入時登記）。
3. 輸出範本：**內部報表先行**（結案報表、專案執行報告）；客戶版報價單 PDF 最後做，且 v1 只做『區塊標題＋顯示／隱藏非法定區塊』，**不做自由排序**。
4. `voucher_template`：✔ `modules/accounting/voucher_template.py` 有 `render_summary`，但後端沒有任何呼叫端（只有測試、`db.py`、`archive.py`），前端也沒有頁面。接線＝**新功能**，不是既有輸出的框架化，獨立一條線。

## A. 自訂欄位：報價單明細（品項）與匯出欄位

### A.1 現況
- ✔ 表頭自訂欄位已做（q3）：`builtin_fields.RECORD_TYPES["quotation"]`，值放 `data_json.customFields`，create／update 兩條寫入路徑過 `gate()`，旗標 `builder_custom_fields`，不進客戶輸出。
- ✔ `gate()` 規則可沿用：型別限 `text/date/select/checkbox`（無金額型）、最多 20 欄、序列化 ≤ 8 KB、旗標關 ⇒ 回舊值、不在定義內的鍵保留舊值。
- ✔ 匯出欄位目錄是 `register_export(columns=[…])` 在模組載入時登記的靜態清單（`export_templates._EXPORTS`）；`_cmp_export_template` 以 `registered()` 判斷『新增欄位＝放寬、金額欄標明』。
- ✔ 案件批次匯出（T63）的查詢取整份 `data_json` 後在 Python 讀，沒有 `json_extract`，自訂欄位值可在 Python 端取。

### A.2 設計：明細自訂欄位（Q5）
- 新記錄類型 `quotation_item`（加進 `RECORD_TYPES`），值放**每個品項物件的 `cf`**（`items[i].cf = {key: value}`），不另開表、不改 SQL 欄。
- 核心鍵白名單＝品項物件現有鍵（實作時由程式從品項建構器取得，不手寫）；自訂欄位 key 不得同名（與 q3 同規則）。
- 型別沿用四種，**無金額型**。欄位數上限比表頭更小（建議 6）、每品項序列化 ≤ 1 KB，避免數百列品項把 `data_json` 撐大。
- 寫入閘門：`create_quotation`／`update_quotation` 逐品項過 `gate()`（旗標關 ⇒ 每列回舊值）。複製／續版（-Rn）時 `cf` 是否沿用：照表頭已決定的行為（`QUOTE-CASE-LAYOUT-COUPLING-T62.md` §7）。
- 畫面：用 BP-1 版面引擎的『區塊』放在品項表下方（或品項『更多欄位』展開列），**不動 261 KB 表單的品項表格本體**；只在內部成本分機內顯示（與成本欄同權限）。
- 客戶版／預覽／回簽頁／擇一方案客戶視圖一律不輸出（✔ `case.alt_view` 是客戶版輸出資料的單一來源）。
- 使用數統計要掃品項層，需要新寫（?）。

### A.3 設計：匯出自訂欄位欄（動態目錄）
- 登記時多一種欄位來源 `{"source": "custom_field", "record_type": "quotation"}`；目錄在**讀取時**由 `public_fields(record_type)` 展開成 `cf:<key>` 欄位 id。`definition_problems` 與 `_cmp_export_template` 都要認得 `cf:` 前綴（目前只查靜態目錄 ✔）。
- **治理**：新增 `cf:*` 欄＝放寬（第二位最高管理者核准）；移除＝收緊；改標題／順序＝中性。自訂欄位本身新增已是放寬（q3），匯出欄是第二道，兩道各自核准。
- 遮蔽優先：自訂欄位無金額型；但欄位屬性有 `dataClass`（✔ `_FIELD_KEYS`），標為個資／敏感者 v1 一律**不可選為匯出欄**。
- 客戶輸出：內部匯出（案件批次匯出）可選；任何客戶可見輸出不收（見 Q-A）。
- 稽核：`export_logged` 列數照實；稽核 detail 不寫自訂欄位值。
- 順手確認（✔）：T63 的出納工作表型與營運報表的工作表代號沒有重疊（`_cmp_export_template` 以『子集』找目錄，代號不重疊才不會誤判）；之後新增工作表型匯出要維持代號全域不重疊，或讓比較函式改用匯出代號查目錄（建議後者，列入 P2）。

### A.4 風險與未驗證
- ?：`PUT /quotations/{no}` 的 409 基準對品項內新鍵是否把『別人沒改的列』判成衝突。T59/T60 剛修過材料清單 409 回歸，**品項層動工前必須先看那次修正的範圍**。
- ?：擇一方案（`altGroups`）與回簽鎖定（`alt_lock.PROCESS_KEYS`）：`cf` 要不要列入『回簽後不可改』。建議不列（內部欄位），但需確認鎖定是白名單還是黑名單。
- ?：報價單表單單一 Alpine 元件很大，品項區塊改動風險高。

### B.2 分階段
**階段 1：結案報表、專案執行報告（內部）**
- 先把兩個 builder 內的區塊切成**具名函式**（純重構；golden 證明輸出逐位元組相同），再登記為 BP-3 匯出：新增 `sections` 型（目錄＝`[{id,label,required,money}]`；範本選顯示哪些、可改標題，**順序固定**）。與 `sheets` 型同模型——營運報表 PDF 已用註解標記拿掉段落（✔ `_drop_pdf_sections`），**同一手法**；`_cmp_export_template` 的 `sheets` 分支可泛化。
- 金額區塊標 `money`：沒有財務檢視權者，該區塊整段拿掉。結案報表損益數字維持只讀精算快照（✔ `settlement.summary`），不重算。
- 為什麼內部先行：不是客戶可見、不是法定文件。但**結案報表是結案時自動存檔的稽核文件**，範本改動會讓存檔內容改變 ⇒ §B.3 版本紀錄。

**階段 2：報價單 PDF 區塊標題／顯示隱藏（客戶可見，風險高）**
- 只開放**非法定區塊**的標題與顯示。不可隱藏／改名：公司抬頭、客戶資料、品項與金額表、稅別與稅額、有效期限、簽核狀態橫幅、浮水印規則、頁尾法定字。
- 順序 v1 固定；自由排序列為後續（需使用者明確要求）。
- S-Q2 條款標題已有『送審凍結』機制（✔ 已送審的報價單沿用送審當時的標題）；區塊顯示／隱藏用**同一個凍結機制**：送審當下把有效範本快照進 `data_json`，之後不隨設定漂移。

## C. 需要使用者裁示的問題（每題附建議預設）
- **Q-A 自訂欄位（報價單表頭／明細）要不要出現在客戶版 PDF？** 預設：**不要**。v1 一律不進客戶輸出；日後要開再單獨裁示並走放寬核准。
- **Q-B 內部報表讀範本失敗時：退回完整報表，還是只留必要區塊？** 預設：**退回完整報表並寫稽核**（內部文件、不外送；結案自動存檔不能因設定讀失敗而缺資料）。與營運報表（月報會寄信外送，所以『關起來』）方向不同，請確認。
- **Q-C 報價單 PDF 允許隱藏哪些區塊？** 預設：**只有『售後服務及備註』與『附註』類非法定區塊**，其餘固定；順序固定。
- **Q-D 結案報表自動存檔後，改範本要不要重產舊檔？** 預設：**不重產**（舊檔是當時的稽核紀錄，只記 `tplVer`）。
- **Q-E 明細自訂欄位的用途？**（例：設備序號、保固月數、供應來源）預設：先只做**內部查閱＋案件匯出**，不影響任何計算、不進採購／出貨流程。

## D. 本筆記沒有查證的部分
`PUT /quotations` 品項層 409 行為、`alt_lock` 鎖定名單是白名單還是黑名單、`usage_counts` 掃描範圍、SPEC-VOUCHER 內容、專案執行報告實際可切的區塊、前端報價單品項表格結構。這些都是 A2／P1／V1 動工前的第一步。
