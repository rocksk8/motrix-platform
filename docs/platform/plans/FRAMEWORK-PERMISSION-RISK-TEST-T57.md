# 權限模型：風險與測試策略 — T57 r1（自 FRAMEWORK-PERMISSION-MODEL-T57 §9、§10 拆出）

> 作者 hichan-98；章節編號沿用；僅文件。

## 9 風險與對策
| 風險 | 對策 |
|---|---|
| **鎖死**（最高管理者把自己或所有人鎖在外） | superadmin 直通不存格；權限頁、superadmin 指派、最後一位超管保護寫死不可委派；`perm_reset --to-seed`；`perm_matrix_enabled` 緊急旗標；快照＋一鍵還原 |
| **提權**（用低風險格繞到高風險能力） | 高風險動作寫死清單；代理只能轉自己有的能力且不可再轉；`implies` 閉包在顯示時展開（勾 A 若隱含 B，預覽要列出 B）；`mark` 觸發付款者標 `money`；等價金標抓『種子外多出的授權』 |
| **自我提權**（編輯者替自己加權限） | 放寬＝另一位最高管理者核准＋確認期；只有一位最高管理者時依 T54 §10.8 的『有效人數』規則（確認期內不得先縮減再自核）；稽核通知其他最高管理者 |
| **效能**（每請求檢查 350+ 能力） | 每請求只算一次生效集合（記憶體＋矩陣版本號失效）；T54 F0 已有預算與快取；金標含效能斷言；路由閘 O(1) 集合查詢 |
| **讀取範圍外洩** | 逐案守門與能力**同時**通過（能力只放寬動作不放寬範圍）；`block` 在資料來源端扣鍵（不靠前端隱藏）；`case_read_scope.json` 金標不變；新增 `block` 時掃描匯出／PDF／通知信／儀表板等**所有出口**（沿用 `financial_mask` 的 `QUOTATION_MONEY_COLS` 登記表） |
| **欄位閘漏網**（勾選藏在一般存檔裡） | `gate:"field"` 能力必須登記到『存檔漏斗閘』；靜態守門：寫入點（例 `caseRecord.materials`）不經閘即紅（沿用材料認列的靜態守門做法）；金標 F |
| **兩個家漂移**（設定中心與權限頁都能改同一件事） | adoption：被收編的設定中心項唯讀；守門測試：同一鍵只能有一個可編輯來源 |
| **舊模組鍵與新能力不一致** | 模組鍵＝粗粒度別名（預設集合）；顯示時標『由模組勾選展開』；等價金標 |
| **前後端不一致** | 前端 `can()` 只決定畫面；後端唯一權威；前端基線只減不增；e2e 驗按鈕 |
| **操作成本高（350+ 格）** | 『依事找人』問句式首頁、一鍵組合、預設等價 |

## 10 測試策略
1. **等價金標（永不砍）**：A 判斷層、B 授權矩陣（約 831 路由 × 7 帳號 ≈ 5,800 次空內容請求，只記是否被授權閘擋下）、C 選單、D 代理、**E 區塊、F 欄位閘**。遷移前後 diff 必須為空；有意改變在同一提交更新金標並寫原因。
2. **有效權限快照**：6 角色 × 模組勾選形狀（空／單鍵／全部／含惰性財務勾選）× 綁定/扣項形狀，逐能力輸出 `effective_caps` 的 JSON，前後對照。
3. **反向控制**：每種違規都要轉紅（新增路由未登錄能力、能力無端點且非 `reserved`、`role ===` 新增、`module.json` 宣告缺 `legacy`/白話、被收編設定仍可編輯）。
4. **鎖死演練**：自動化腳本把所有格改成最嚴，仍能以 superadmin 進權限頁並還原。
5. **提權測試**：低權限帳號嘗試經代理、`implies`、個人允許取得高風險能力，全部被擋。
6. **效能**：權限檢查 p95 預算（沿用 F0）；5,800 次金標在單程序數分鐘內完成，可進建包。
7. **e2e（Edge）**：『依事找人』四個例句（看報價單／上傳／勾選材料已到料／看成本）各一條完整流程；正對照＋反對照（掃描器需證明抓得到違規）。
8. **隱私**：`block` 關閉時，API 回應、匯出、PDF、通知信、儀表板全部不含該鍵（與 `QUOTATION_MONEY_COLS` 同源）。
