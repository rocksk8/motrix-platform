### 我提醒 W4 的三個「期望值沒錯、但情境可再強」的地方（非缺陷）
1. **勞報單金額低於法定起扣／門檻**：SLIP-1 給付 6,000（扣 600、補充保費 127）、SLIP-2 給付 10,000（扣 1,000、補充保費 211）是**寫死在資料庫的凍結值**（總帳不重算，所以本驗收對「過帳路徑」是對的）；但依 repo 自己的 2026 版法規參數（`legal_params`：居民 9A／9B 起扣 **20,010**、補充保費門檻 **20,000**），6,000／10,000 的真實勞報單應**不扣繳、不計補充保費**。若有人把這個情境當「扣繳率驗證」會被誤導。建議再加一張 ≥ 20,010 的勞報單（例：30,000 ⇒ 扣 3,000、補充保費 633、實付 26,367，走勞報單 API 算出來而不是寫死），把「法規計算→總帳」串起來。
2. **進項稅額是「估算」**：E04 的 1,000／500 來自派工稅率（5%）× 未稅，引擎標 `tax_estimated`；401 進項 1,500 因此是估算值。真實申報要以扣抵聯的實際稅額（補登 `input_tax`）。驗收文件若註明「進項稅額為估算」會更誠實。
3. **手續費 7243 放營業外**：本系統把 7xxx 且名稱非收益者歸 other_expense，所以淨損表上營業利益不含 15。此分類是產品設計（與標準科目 7 類「營業外」一致），只是報表讀者可能預期手續費屬營業費用——屬呈現選擇，非錯誤。
