## 0. 先看這個：使用者 2026-09-27 已經裁過「請款」要怎麼做

`docs/platform/CORE-SPEC.md` 第 256 列（使用者表單，2026-09-27 23:42）：使用者要「在我的工作中建立一個表單，用於申請請款…上傳檔案、填寫案件、日期，最後上傳發票；結合到案件管理的支出中…同步流程到出納跟當月支出項」，
裁示：**「沿用額外支出，補兩個缺口…——不用自訂模組另建一套單據」**。
已經上線的就是它：**我的工作 →「新增請款」（`pages/payment-request.html`）→ 送審 → 核准 → 出納「請款待付款」→ 營運報表＋總帳（E11／E11b）**，底層是 M01「案件額外支出」（`case_extra_expenses`）。

所以這個系統裡有**兩個叫「請款單」的東西**，方向相反：

| | arap「請款單」`payment_requests` | 「新增請款」＝案件額外支出 `case_extra_expenses` |
|---|---|---|
| 方向 | **對客戶要款**（應收）：綁報價單、套用報價剩餘金額、PDF 用我方抬頭＋我方銀行帳號 | **對公司請款**（應付／費用）：員工或廠商花了錢向公司請款 |
| 核准後 | 只是文件：產 PDF、行事曆；**不進收入、不進總帳、不進出納** | 進出納待付款 → 撥款 → 營運報表支出 → 總帳 E11／E11b |
| 使用者現在要的 | ✗（截圖的差旅費用請款單、請購單是對內） | ✓ |

使用者這次說「沿用請款單、同一張依類型分支」，最貼近的是**右邊這個**（已在正式機使用）。
**⇒ 我請使用者先確認：你說的「請款單」是 2026-09-27 那個「新增請款」嗎？（本文預設是。）** 若是，方案 A2 符合你上次的裁示；方案 B／C（建構器另建單據）**與該裁示相反**，要你明說改變心意才做。

## 1. 四個方案

| 方案 | 做法 | 結論 |
|---|---|---|
| **A1** | 擴充 arap `payment_requests` 加 `kind` | **否決（必須不碰）**：方向錯（應收）、`quote_no NOT NULL`、PDF 與「我方銀行資料不全 ⇒ 428」閘門、行事曆事件「客戶：」、待簽佇列對無案件單據會 DENY 全部人（含 admin）；而且動到正式機在用的客戶請款 |
| **A2（建議）** | 擴充「新增請款」＝`case_extra_expenses`：加 `kind`（類型）＋每類型的**超級管理員可編輯定義**（欄位、明細表欄、下拉選項）；`quote_no` 改可空（以 `''` 存，免重建表）；成本中心＝部門／費用歸屬單位 | 沿用既有裁示；**簽核、出納撥款（IP-100）、實付差異審核、修訂（change-request）、營運報表、總帳 E11／E11b 全都已經在跑**；缺的是「明細表列、每類型欄位、PDF、信件、無案件守門、依科目入帳」 |
| **B** | 建構器四份獨立範本（請購／差旅／採購／零用金） | 便宜（約 8～10 人日）、不碰正式機流程；但**與 09-27 裁示相反**，且建構器**沒有出納撥款**、沒有實付差異審核／修訂，這些要另建（S3） |
| **C** | 建構器**一份**「支出申請單」＋必填「類型」＋依類型顯示的區塊 | 符合「本質是同一張」的想法，但同樣與 09-27 裁示相反；另需新增欄位層級的「依欄位值顯示（showWhen）」（見 §6，約 3～4 人日、L1） |

**建議：A2。** 理由：使用者的兩次意思（09-27 裁示＋今天「沿用同一張、依類型分支」）一致指向同一條流程；A2 是唯一能讓「請款→核准→出納撥款→營運報表＋總帳」**直接沿用已驗證的管線**的方案，出納頁、實付差異審核、修訂流程都不必重做。
代價誠實講：**A2 比 B 貴**（約 15～18 人日 vs 8～10），因為「表單引擎」要自己長（額外支出目前一列＝一個品項，沒有明細表、沒有每類型欄位、沒有 PDF／信件），且要動正式機在用的額外支出（約 60 個測試檔碰到它）。
若使用者要最快上線、願意放棄沿用裁示 ⇒ 選 B（或 C）。

## 2. A2 設計

### 2.1 資料（全部 additive，舊資料行為不變）
- `modules/case/migrations/0003_*.py`（已登記在 `modules/case/__init__.py` 的 migrations 清單）加欄位，預設值＝今天的行為：`kind TEXT DEFAULT ''`（空＝舊式額外支出）、`data_json TEXT DEFAULT '{}'`（類型欄位值）、`lines_json TEXT DEFAULT '[]'`（明細表列）、`def_version INT DEFAULT 0`（凍結送審時的定義版本，比照 `custom_records.def_version`）、`department_id`（費用歸屬單位／成本中心）、收款人欄（姓名、銀行、帳號；v1 文字）。
- `quote_no` 維持 `NOT NULL` 但允許 `''`（SQLite 不能 ALTER 拿掉 NOT NULL，`''` 同樣滿足，免重建表）；結案閘門、剩餘金額等以 `quote_no IN (…)` 比對的地方天生不會撈到 `''`。
- `total_cost`＝明細列金額合計；`category`＝類型（或第一列科目）；明細逐列的科目另存於 `lines_json`，營運報表／總帳逐列展開。

### 2.2 每類型定義（超級管理員可編輯、不用改程式）
- 新的 `ui_definitions` 種類 `expense_type`（key＝類型代碼，如 `travel`、`purchase_req`、`petty_cash`、`purchase_order`、`general`）：欄位（文字／數字／日期／下拉／單選／日期區間／公式／ref 部門或使用者）、明細表欄（科目下拉、單價、數量、金額公式、發票號碼…）、下拉選項、必填、預設、`payable`（是否進出納；請購單＝否）、簽核流程代碼、預設會計科目對應。
- **驗證與轉型直接重用建構器那一份**（`helpers/custom_modules` 的欄位／明細表／ref 驗證、`helpers/custom_fields._coerce／clean`），不另寫一套；草稿→送審→核准→還原／差異等定義版本機制已有（`core/definitions.py`）。`KINDS` 是 L0 契約，新增一種要照 PLAYBOOK §C-7。
- 超級管理員編輯畫面：v1＝有驗證與預覽的定義編輯頁（JSON＋欄位表格檢視）；v2＝重用建構器的欄位編輯元件。
- 「申請人是否可編輯」「國內／國外」等都只是欄位設定；現有規則「必填欄位不能限制編輯」需放寬為「必填＋預填＋鎖定」。

### 2.3 流程
- **簽核**：沿用統一簽核流程（流程代碼 `extra_expense`）；每類型可另設流程代碼（選用；設定頁 `approval-settings.html` 加一列／類型）；金額門檻用層級條件。簽核人不看案件也要能簽 ⇒ 守門改成「簽核鏈成員」（A1 的 `is_document_approver` 那一套）；目前 `_guard_case` 只認案件擁有者範圍。
- **出納撥款**：沿用 IP-100（`payables.pending`，`modules/case/payables.py`），不必新增提供者與撥款表；已含實付≠應付的**不同人審核**與手續費（`remit_fee_case`）。`payable=false` 的類型（請購單）不進出納。列表欄位 `quoteNo／customerName` 可空，面板已通用。
- **修訂**：沿用 change-request 流程；⚠ 新欄位必須同步加進 `_proposal_from`、`_apply_change`、`detail_extra_expense`，否則修訂時會被**靜默丟掉**（最大的陷阱）。已撥款禁止修訂（W2 意見 #8）。
- **PDF／信件**：額外支出目前**沒有**單據 PDF、沒有信件（只有站內通知）。重用 `doc_template`（輸出版型，每類型一份，含未核可每頁紅色標示）＋ 補「送審／核准／退回／待撥款／已撥款」信件類型。

### 2.4 無案件（成本中心＝部門）
- 守門：`_guard_case`、核准、退回、附件路徑（`modules/case/attachments.py`、`_READ_RULE`）、詳情（`detail_extra_expense`）、待簽佇列（`linkedQuoteNo` 空時不可 DENY）都要接受「無案件」。
- 報表：`_quote_in_department`（`modules/analytics/api/reports.py` ~3415）對無案件列目前會在部門篩選時被排除 ⇒ 改用單據的 `department_id`；`recognition.extra_entries` 回傳加 `kind`、逐列科目（`details["other"]` 已有 `category`）。
- 結案、結算、案件成本：無案件單據天生不進（`quote_no IN` 比對不到 `''`）；日後加回案件欄位＝併入案件成本（見問題 11，避免與現有額外支出重複）。

### 2.5 總帳（W4）與營運報表
- E11（借 `COST_PROJECT`／貸 `AP`）、E11b（借 `AP`＋手續費／貸 `BANK`）已在跑。要加：
  - 無案件時借方落 `EXP_OTHER`（不是 `COST_PROJECT`）；有部門則帶維度。
  - **依類型／科目入帳**：把 `gl_category_map (source, category, role, account_code, nondeductible)` 接上（表已在 migration，**目前沒有任何程式讀它**），逐明細列借對應科目、貸 `AP` 合計；零用金付款方式＝零用金 ⇒ 貸 `PETTY`（1112）。
  - 稅額：使用者尚未決定（總帳 A6）；決定前維持「金額視為含稅全額列費用」＋ 新來源旗標關閉。
- 營運報表：`expense.entries` 由 `recognition.extra_entries` 供應，已有；加 `kind`（類型）與 `department`。

## 4. 撥款細節（W2 補充，適用 A2／B）
1. A2 直接用現有 IP-100；B／C 才需要新提供者。提供者 `mark_paid(conn,key,paid_date,user,remit=None)` 含 `actualAmount／hasFee／fee`，實付≠應付 ⇒ 待審、**不同人**核可／退回（自審 403），手續費進 `expense.entries`（`remit_fee_case`）、E11b 僅在審核通過才處理 actual／fee／diff。
2. 原子付款：條件式 UPDATE（已核准且無付款日）；B 的撥款表要 `UNIQUE(module_key, record_no, revision)`＋同一交易。
3. 提供者 key 必須 URL 安全且跨模組唯一（B：`<module_key>.<record_no>`）。
4. 單號前綴避免與請款單相撞（見 §3）。
5. 員工報銷無扣繳；對外人士（勞務）走勞報單，不走本流程（否則繞過 W4 E06）。
6. **重複計入風險**（問題 11）：有綁案件的差旅／採購與同一筆額外支出重複 ⇒ v1 預設不帶案件欄位。
7. 撥款表（B）或新欄位（A2）都屬核心／案件模組的 migration，L1 全量班。
8. 已撥款禁止修訂。

### 9.1 要 W1 提供的欄位（`case_extra_expenses` 新欄位／`lines_json` 每列）

|---|---|---|

### 9.2 入帳規則（由事件提供者 `modules/case/gl_events.py`＋總帳解析器實作；舊式額外支出 `kind=''` 行為不變）
1. **借方科目（逐列）**：① 查 `gl_category_map`（`source='extra_expense'`、`category`＝類別代碼）→ `role`／`account_code`／`nondeductible`；② 沒有對應 ⇒ 有案件 `COST_PROJECT`（帶案件維度）、**無案件 `EXP_OTHER`（其他營業費用 6134），絕不用 `COST_PROJECT`**，notice 明說「N 列費用類別未設定科目對應，暫列其他費用／專案成本」；③ 解析出的科目不存在或不可入帳 ⇒ `blocked_no_account`（說明缺哪個類別）。
2. **稅額**：列有 `tax`（或單據有稅額欄位）⇒ 借 成本（含稅額以外＝`amount − tax`）＋借 進項稅額 `INPUT_TAX`（1268，`tax_code=IN-5`）／貸 應付（含稅合計）。**可扣抵條件**（營業稅法第 19 條，逐條文字於實作時查證全國法規資料庫後寫進程式註解與 `docs/platform/TAX401-OFFICIAL-FIELDS.md`）：`doc_type=invoice`（統一發票）且類別 `nondeductible=0`；收據／國外憑證／不得扣抵類別（例：交際應酬、自用乘人小客車相關…）⇒ **稅額併入成本、不產生進項稅額列、不帶稅碼**。沒有稅額欄位 ⇒ 整筆含稅全額入帳，`notice`「稅額處理：含稅全額（表單沒有稅額欄位）」。
3. **401 連結**：進項稅額列帶 `IN-5` 稅碼與發票號碼／發票日期（`doc_no`、來源憑證補登 `invoice_date` 覆寫照舊）⇒ 進入 401 第 107 欄；發票日期決定所屬申報期別。
4. **貸方與付款腿**：
   - 應付科目：`payee_kind=vendor` ⇒ `AP`（2171）；`employee`（差旅報銷）⇒ `OTHER_PAYABLE`（2206，對象＝員工；無扣繳）。
   - 權責認列事件＝E11（核准時，日期＝發票日→核准日→憑證日，現行規則）；**付款腿 E11b 依付款方式**：`transfer` ⇒ 貸 `BANK`（有 `paid_bank_account_code` 就用）；`cash` ⇒ 貸 `CASH`（1111）；`petty_cash` ⇒ 貸 `PETTY`（1112）。手續費／實付≠應付差額規則沿用 W2 已做的（核可後才處理）。
   - **零用金支付單**（核准即支付、沒有出納撥款）：一個事件借 費用／貸 `PETTY`（日期＝支付日期），不經 `AP`；零用金撥補（借 `PETTY`／貸 `BANK`）是另一件事，不在本切片。
   - **採購單**：核准時認列（借 類別科目／貸 `AP`），出納依付款條件撥款時才有付款腿；採購的是**存貨**者（料號在 `parts`）走 E08 進貨，不在這裡（見 §9.5 待確認）。
5. **綁案件不重複**：同一張單據只有**一個** E11 事件（`source_key＝單據 id`），案件欄位只決定借方科目與案件維度；日後加回／改綁案件 ⇒ 事件內容變 ⇒ 引擎 drift＋更正草稿（不會另產一個事件）。營運報表的案件成本與總帳同一判準。
6. **部門維度**：總帳分錄目前只有案件／往來／單據維度，**沒有部門欄位**（加欄位屬 migration＝底層）——v1 把部門寫進摘要與 `doc_no` 旁註，部門維度列為後續批次（見 §9.5）。
