> 2026-10-12／設計者 1d（非作者稽核請 0d）。依據使用者指令：**一切以框架／選單為基礎；使用者自行增刪改內容；只有圖形介面，不顯示任何系統參數（代碼、鍵名、列舉值）**。

## 0. 結論（先看）

1. **不用新建一套系統**：定義文件庫（版本、草稿、還原、角色覆寫）、P9 排版器（拖曳、角色預覽、個人層）、輸出版型引擎（`doc_template` 積木，含欄寬）、模組建構器的表單設計器（拖曳、即時預覽）**都已存在**。缺口集中在四處：①內建單據（報價單、請款單…）**沒有登記可自訂點**（`module.json` 的 `customization` 除 tender_radar 外全空）；②排版操作**沒有寬度、列高、欄位挑選**（只有 reorder／hide／relabel／add_section）；③**同一份報價表欄有三份手寫**（畫面編輯表、列印預覽、PDF），沒有單一來源；④盤點**未見報價單 Excel 匯出**（只有案件批次匯出 `case_batch_export` 與會計報表）。
2. **做法**：把 `customization` 擴成 v2（欄位目錄＋寬高＋輸出通道）；新增一個**唯一的解析器**（單據類型＋版面版本＋檢視者權限＋輸出通道 → 欄位清單與尺寸），畫面、列印、PDF、Excel 都吃它的結果；欄位**怎麼畫**仍由程式內的「儲存格畫法」依欄位決定（管理者不寫程式）。
3. **預設＝現況**：預設版面由現有手寫結構轉錄，推上線**零視覺變化**（黃金比對守門）。
4. **金額遮蔽不受版面影響**：版面只決定「顯示」，遮蔽仍在後端；標成金額類的欄位，沒有權限的角色**不論怎麼排都看不到**；內部成本／毛利欄位**永遠不進客戶版輸出**（硬規則）。
5. **版本**：凍結的是**定義版本**（公司版與提交當下存在的各角色版版本號），由伺服器蓋章，不是某個角色算出的結果（§8）；**免資料庫遷移**（只加 `data_json` 鍵，缺鍵＝內建預設）。
6. 工量：報價單先行 **約 16–20 pd**（§12；0d 稽核後由 13 上修，依據與底層閘門項目見 §12）；其餘單據每種 1～2 pd。**不需要使用者回答的事盡量用設定預設值處理**（§13）。
7. **寬度與高度是『檔位』，不是任意數字（FL-7）**：表單欄位寬＝四分之一／三分之一／二分之一／三分之二／整列；表格欄寬＝窄／中／寬／自動填滿（拖曳時吸附到檔位）；列高＝精簡／標準／寬鬆。這是預設且刻意的限制（確保 A4 與手機不壞、黃金比對可行）。若日後需要任意尺寸，**由管理者在設定中心選『尺寸精細度』（預設＝檔位）**開啟，不改程式；開啟屬放寬類（走原因＋核准＋確認期）。

## 2. 原則（來自使用者指令，皆為硬規則）

1. 框架優先：管理者看到的是「目錄＋版面編輯器」，內容（挑哪些欄位、順序、尺寸、文字）由管理者定；程式不寫死業務內容。
2. **畫面只有圖形與白話**：欄位叫「總成本」不是 `totalCost`；寬度顯示『窄／中／寬／整列』與拖曳手把，**不顯示像素、百分比、欄數代碼**；列高顯示『精簡／標準／寬鬆』。任何鍵名、列舉值、錯誤代碼不上畫面（守門測：沿用 `test_settings_ui_plain_language` 樣式）。
3. 不讓使用者寫程式或公式（既有裁示）；計算欄位不可改算式，只能決定**顯不顯示、放哪**。
4. 先查再造：本文所有新東西都標明接在哪個既有零件上（§3～§6）。

## 3. 欄位目錄（Field Catalog）

**位置（過渡 → 終態）**：終態＝與 F7 共用的單據類型登錄（`register_doctype`，FieldGroup 之下加 `fields`）；F7 落地前以 `module.json` 的 `customization`（schema 1 → **2**）為載體，不新建檔案類型，欄位描述與 FieldGroup 逐欄對應。向後相容：schema 1 照舊可載入。每個單據類型（報價單、請款單、採購單、薪資單…）一份目錄；**目錄由程式登記，管理者只能從中挑**（與 P9「不會出現程式沒提供的選項」同原則）。目錄項的 `group` 屬性＝F7 欄位群組鍵（`items`／`pricing`／`cost`／`terms`／`header`…），可見／可改以 F7 為準。

每個目錄欄位的描述（內部鍵不給使用者看）：

| 屬性 | 說明 | 例（報價單品項表） |
|---|---|---|
| 內部鍵 | 程式識別，永不顯示、永不改名 | `unitPrice` |
| 白話名稱 | 預設標籤，可被管理者改（relabel） | 『售價』 |
| 資料型別 | 文字／數字／金額／日期／百分比／選項／長文字／圖片 | 金額 |
| 來源 | 使用者輸入／系統計算（含算式出處）／連動（客戶資料、案件…） | 使用者輸入 |
| **金額類別** | `public`（客戶可見）／`internal`（成本、毛利、管銷：僅內部）／`none`（非金額） | 單價＝`public`；成本單價、毛利率＝`internal` |
| **可見性判定（FL-8）** | 每個欄位宣告『誰算看得到』的**判定函式**：`quote_money_visible`（報價單金額）／`material_money_visible`（叫料金額）／`money_visible`（案件金額）／無（非金額）。解析器據此剔除**欄位、其標題、以及由它衍生的欄位／合計列**（例：毛利率欄隱藏時，單項毛利欄與毛利合計列一併隱藏） | 成本單價＝`quote_money_visible` |
| 鎖定等級 | **核心**（不可隱藏、不可移出表單，只能移動；`OPS_CORE_FIELD`）／**可顯示**（可隱藏、改名、移動；`OPS_DISPLAY_FIELD`）／**必填連動**（有業務必填規則，隱藏等於讓人填不了 ⇒ 不可隱藏） | 品名＝核心 |
| 可用輸出通道 | 畫面編輯／畫面預覽／客戶版 PDF／內部版 PDF／Excel | 成本單價＝僅 畫面編輯、內部 PDF、Excel(內部) |
| 儲存格畫法 | 程式內登記的畫法 id（輸入框、金額、百分比燈號…）；管理者不選、不見 | — |
| 預設寬／最小寬／可否換行 | 預設值取自現況；最小寬防止版面壞掉 | 品名：寬、可換行 |
| 預設列高類別 | 精簡／標準／寬鬆 | 標準 |

**報價單目錄的來源盤點**（轉錄現況，T0 完成）：頭部欄位（客戶、專案、日期、有效期限、聯絡人、稅別…）、品項表欄（現有 11 欄，含 `internal` 的成本單價、毛利率、單項毛利）、合計列（未稅小計、稅額、含稅合計、折讓、運費、各間接費…）、條款五段（付款、交貨、驗收、保固、售後服務及備註說明）、備註。M3 的擇一欄位（`altGroup` 標記、依方案選擇文字）也以目錄項登記，**不另做表單 UI 掛鉤**。

**一致性守門（解決現況兩份宣告）**：測試斷言「目錄中金額類別為 `internal`／`public` 的欄位對應的資料鍵，必須各自出現在 `financial_mask` 的遮蔽鍵清單裡；遮蔽清單中的每個鍵必須屬於目錄中某個金額類欄位或明列為『非顯示欄位』」——兩份宣告永遠對得起來。

## 4. 版面設定（Layout Config）

沿用定義文件庫的 `layout` kind（key＝`<單據類型>`，scope＝`company`／`role:<角色>`，有版本、可還原）；`body` 由 `{"ops":[…]}` 擴為 **v2**，仍可由既有 `compileOps`／`applyOps` 處理：

- **區塊（Section）**：標題、欄位序、是否收合；新增區塊要能放欄位（補上 `add_section` 缺口：`_check_ops` 認得同批新增的區塊）。
- **表單欄位格**：所屬區塊、順序、**寬度**＝12 欄格線上的份數，介面只給預設檔位（1/4、1/3、1/2、2/3、整列）；可顯示／隱藏；改標籤。
- **表格欄**（品項表）：順序、顯示、**欄寬**（比例檔位：窄／中／寬／自動填滿）、對齊；總寬由解析器正規化，不允許超出頁面（§6）。
- **列高**：精簡／標準／寬鬆，套用到表格列與表單欄；長文字欄可設『顯示行數』檔位。
- **輸出通道覆寫**：同一份目錄欄位，在 客戶版 PDF／內部版 PDF／Excel 可各自挑欄位與順序（預設＝與畫面相同再扣掉不可用通道的欄位）。
- 新操作（擴充 `OP_KEYS`，皆不認識的鍵＝驗證問題）：`resize`（欄位格或表格欄）、`set_row_size`、`set_channel`（通道欄位集合）。其餘沿用。
- 套用順序不變：**個人（僅顯示／排序）> 角色 > 公司 > 程式預設**（個人層沿用清單偏好，不能改寬高）。

## 5. 圖形編輯器

**進入點**：超級管理員在報價單頁按『編輯版面』（P9 同頁編輯模式，既有 `layout-editor.js`）；設計器的『左側目錄欄位卡＋中間畫布＋右側即時預覽』沿用 `module-builder` 三欄樣式與 `form-preview.js`（不重寫）。

- **挑選**：左側「欄位目錄」列出可加入的欄位（白話名稱＋小圖示＋一句說明），已在版面上的灰掉；拖進畫布或按『加入』；畫布上卡片可『隱藏』。核心欄位卡顯示鎖頭，不能隱藏。
- **排序**：拖曳卡片到新位置（既有）。
- **寬度**：卡片右緣拖曳把手，**吸附到檔位**；亦有『窄／中／寬／整列』按鈕（鍵盤可用）。表格表頭同樣可拖欄界線。
- **列高**：工具列『精簡／標準／寬鬆』。
- **區塊**：新增區塊、改標題、把欄位拖進區塊。
- **預覽**：右側『以哪個角色看』下拉（沿用 P9 角色預覽）＋『客戶版／內部版』切換：**預覽走真正的解析器與遮蔽**，所以選到無金額權限的角色時，金額欄真的消失（不是前端假裝）。
- **安全網**：『還原成系統預設』『回到上一版』（定義文件庫既有）；發布前列出差異白話摘要（`describeDiff` 既有）；超出頁寬、核心欄位被藏、客戶版含內部欄等問題在發布前以白話阻擋。
- **手機（FL-5）**：編輯器僅桌機（既有 R7）。**預設版面保持今天的手機呈現，不變**；只有『非預設版面』才套用手機單欄堆疊規則（寬度檔位只影響桌機／列印）。測試：預設版面在手機寬度的 DOM／截圖與改前相同（黃金）。

## 6. 單一渲染（畫面／列印／PDF／Excel）

**現況**：品項表欄在 `quotation-form.html`（編輯表、列印預覽兩處）與 `pdf_gen._build_quote_html` 各手寫一份，寬度與欄位集合分別寫死。

**設計**（不重寫成通用模板引擎，風險太高）：

```
(單據類型, 版面版本, 檢視者, 輸出通道)
        │  後端 layout resolver（唯一）
        ▼
ResolvedLayout = 區塊[ 欄位[{目錄項, 標籤, 寬度檔位→實際比例, 列高} ] ]
        │
 ┌──────┼───────────────┬──────────────┐
 畫面/預覽適配器   PDF 適配器       Excel 適配器
 (取 API 結果,   (pdf_gen 用同一份    (欄位順序、欄寬、
  按欄位畫法畫)    欄位/寬度畫表)     標籤取同一份)
```
- 解析器做：套版面 → 扣掉該通道不可用欄位 → **依檢視者權限剔除金額類欄位** → 正規化寬度（總寬＝100% 版面；檔位轉實際比例，最小寬保護；A4 寬度內不得溢出，溢出時依序縮減『自動填滿』欄、再整體等比縮）。
- 儲存格畫法仍在各適配器內依「欄位 id」查表（`cell renderer registry`）；管理者不接觸。**新增目錄欄位＝程式登記一個欄位＋一種畫法**，不屬於管理者能力。
- 前端用 既有 `GET /api/layout/{模組}`（加參數取得『解析後』結果；不另開新端點，§15）取結果；`$store.layout` 擴為提供 `columns(tableId)`、`width(fieldId)`、`rowSize(...)`（沿用既有 store，不另建）。
- **PDF 適配器的實作路線（FL-6，兩步）**：(a) 先保留 `pdf_gen` 手寫 HTML，只讓欄位／欄寬改由解析器供應，與改前黃金逐位元相同；(b) 之後才遷到 Q34／D-32 已規劃的 `quotation` output_template。步驟(b)的目標形態：解析結果轉成 `quotation` 版型的積木（`items_table` 欄含 `width`、`kv_table`、`totals`…），`pdf_gen._build_quote_html` 退場為『呼叫版型引擎』；轉錄期以黃金比對確認逐位元不變。這樣報價單 PDF 與薪資單、開票申請憑據同一個引擎，不是第二套。
- 薪資單、開票申請憑據已走 `doc_template`，其『版面』＝版型積木，**在本框架下被視為另一種適配器**：欄寬沿用 `items_table` 的 `width` 參數與 `_WIDTH_RE` 驗證，編輯器沿用 `module-builder-output.js`；不強迫合併成同一個引擎。
- Excel：盤點未見報價單 Excel 匯出，作為新增適配器（P5）；沿用 `export_logged` 稽核與 `financial_mask`；空字串規則沿用既有 openpyxl 陷阱處理。

## 7. 權限與金額遮蔽（硬規則）

1. **版面只決定顯示，不決定可見性**：金額類欄位對無 `money_visible`／`quote_money_visible` 者，由**後端解析器**直接剔除（不是 CSS 隱藏）；`mask_*` 對資料本身的遮蔽照舊並存（縱深）。
2. `internal` 欄位（成本、毛利、管銷、方案成本比較）**不得出現在客戶版 PDF／客戶預覽／回簽頁／客戶版 Excel**，不論任何角色或版面；編輯器不提供把它放進客戶版的操作；驗證器遇到即擋（發布不過）；輸出端再擋一次（縱深）。
3. 編輯版面本身的權限：預設僅超級管理員（與既有排版器一致）；『誰可以編輯版面』屬設定中心可選項（§9），放寬須走放寬流程。
4. 無金額權限者的『預覽』看不到金額欄位的存在（含標題），避免從欄位標題洩漏結構（與系統中心 `show_denied` 預設隱藏同精神）。
5. 版面定義本身不含金額資料，但含標籤文字（可能是商業用語）：沿用定義文件庫的稽核／版本，不另開洩漏面。
6. **內部輸出通道的閘門必須重用既有的那一道（FL-8）**：內部版 PDF 與（新增的）內部版 Excel 一律走報價單內部 PDF 現有判斷——`_guard_case(allow_approver=True)` 加『內部旗標規則』（`quotations.py` 約 5420–5450，Q35）；解析器的通道扣除與輸出端各驗一次，不得另寫第二套『誰可看內部版』。目錄的金額類欄位鍵與 `financial_mask` 鍵清單維持**雙向守門**（目錄 internal／public 金額鍵 ⇔ 遮蔽清單）。

## 8. 版本與舊單相容

- **凍結的是『定義版本』，不是某個人算出的結果（FL-3）**：版面定義＝定義文件庫的 `(key, scope, version)`，scope 有 `company` 與 `role:<角色>`。**送出（送審）那一刻**，伺服器把當下**已發布的公司版版本號，以及每個已有發布版的角色層版本號**一併記進該單 `data_json.layoutRef`（形狀示意：公司版 vN；各角色層 版本號集合）。之後任何檢視者開這張單，渲染時以**檢視者自己的角色**解析：凍結的角色層版（若該角色在凍結集合中有版本）＞凍結的公司版＞內建預設。這樣核准人、財務、業務看到的各是自己角色在當時的版面，且不隨之後的改版變動。草稿期不凍結，跟隨最新發布版。
- **只有伺服器能蓋章**：用戶端在 `PUT`／其他寫入送來的 `layoutRef`（或任何舊名 `layoutVer`）一律**忽略並由伺服器放回**（比照 `_restore_stamps` 對 `altPicks`／`tot` 的處理）。
- **重新送審、解鎖修改、退回改號的行為（明定）**：①**每次進入 待審核（含解鎖編輯後重新送審）都重新凍結**——因為內容可能已改，採用當下最新發布版；解鎖編輯進行中維持舊凍結直到重新送審。②**`reject_quotation` 退回（單號升 -Rn、回草稿）時清除 `layoutRef`**（草稿期跟隨最新），下一次送審再凍結；退回前的版面紀錄保留在 `editHistory` 與已存 PDF 版本檔。③**核准人在送審後看到的是剛凍結的版本**（凍結發生在送審那一筆交易內，先於通知簽核人）。④已回簽（M3 `is_signed`）後不再變動（本文不新增任何會改 `layoutRef` 的路徑）。
- 舊單沒有 `layoutRef`（含更早的 `layoutVer` 名稱）＝內建預設版面（＝現況）；**不需資料庫遷移，不需回填**。
- 版本被還原／刪除時：凍結集合中的每一個版本內容必須仍可讀（定義文件庫不物理刪除發布版；T1 確認）；某一版讀不到 ⇒ 該層退回下一層（角色→公司→內建預設）並記一筆警告，不使頁面壞掉。
- PDF／Excel 已輸出的檔案不可變（`record_doc_version` 既有的文件版本紀錄照舊）；重印一律按該單凍結的 `layoutRef`，以**重印者**的角色解析。
- 目錄欄位日後被程式移除／改名：版面中失效的點不套用、列在 `dropped`（P9 既有行為），不悄悄略過。

## 9. 預設＝現況；硬規則 vs 管理者選項

**預設（零視覺變化）**：預設版面由現況手寫結構轉錄；上線前以**黃金比對**守門：①畫面——以固定報價資料渲染的 DOM 欄位序列與寬度；②PDF——`_build_quote_html` 對固定資料的輸出，新舊逐位元組相同（或差異僅限已列明的空白正規化）；③無版面定義時任何輸出與改前相同。轉錄完成前不開放編輯。

**硬規則（不可由設定放寬）**：核心欄位不可隱藏；計算欄位的算式不可改；金額類遮蔽（§7）；`internal` 不進客戶版；伺服器端驗證並以已存版本比對；版面變更寫稽核與變更明細；寬度總和受頁面限制。

**管理者可選（設定中心，群組『版面』；預設值為使用者定案值，放寬走原因＋變更明細＋第二位核准＋確認期間）**：誰可以編輯版面（預設僅超級管理員）；是否允許角色版面覆寫（預設允許）；是否開放個人層調整顯示與排序（預設開，沿用現狀）；凍結時機（草稿跟隨／送出凍結；見 §13 Q1）；客戶版 PDF 是否允許管理者隱藏『單價』只留『金額』等（預設允許，涉及商業習慣）。

## 10. 測試清單（紅 → 綠）

1. 轉錄：預設版面 ＝ 現況（畫面欄位序／寬度、PDF HTML 逐位元組、列印預覽）。
2. 目錄一致性：金額類欄位 ↔ `financial_mask` 鍵清單雙向對得上；新增目錄欄位若忘了金額類別 ⇒ 紅。
3. 解析器：角色／公司／預設套用順序；`dropped`；寬度正規化（總寬不超過頁寬、最小寬保護、極端組合）；通道扣除。
4. 權限：無金額權限角色的解析結果與預覽、PDF、Excel 皆不含金額類欄位（含欄位標題）；有權限者有（正反對照）；`internal` 欄位於客戶版輸出出現 ⇒ 紅（突變測：把某 internal 欄放進客戶通道要被驗證器擋下）。
5. 核心欄位不可隱藏／不可移出（驗證器與編輯器雙層）。
6. 版本（FL-3）：送審時凍結『定義版本集合』`layoutRef`（公司版＋各角色層版本）；檢視者以自己的角色解析；改版面後舊單輸出不變；缺 `layoutRef` ＝ 預設；用戶端送來的 `layoutRef`／`layoutVer` 被忽略並由伺服器放回；重新送審重新凍結、`reject_quotation`（-Rn）清除、核准人看到剛凍結的版本；某版讀不到 ⇒ 下一層＋警告。
    6b. 預設版面在手機寬度與改前相同（FL-5，黃金）；非預設版面才套用單欄堆疊。
    6c. 欄位的可見性判定（FL-8）：隱藏金額欄時，其標題與衍生欄位／合計列一併消失；內部 PDF／內部 Excel 與現有內部閘門 `_guard_case(allow_approver=True)`＋內部旗標規則一致（突變：另寫一套閘門 ⇒ 紅）。
7. 白話守門：編輯器與發布訊息不出現鍵名／代碼／英文列舉值／像素數字（守門樣式同設定中心）。
8. 三個適配器共用同一解析結果的一致性（同一單、同一版面，欄位序列在畫面／PDF／Excel 相同，除通道扣除）。
9. `FORM_VERSION` 升版規則：表單改動時守門通過；PDF 版面不在該守門內，新增 PDF 轉錄黃金檔守門。
10. e2e：編輯器拖曳欄寬／列高→發布→新開一張單與舊單各按其版本渲染；手機單欄；以無金額角色預覽。
11. 稽核：版面發布、還原、角色覆寫寫入變更明細（設定中心 ledger 樣式）。

## 14. 單一框架脊柱（Framework Spine）：欄位目錄＋版面＋政策設定＋標籤＝同一個機制

**目的**：M3 擇一方案、完工單帶入報價項目、下載檔名三份設計，以及本文，都在各自發明『挑欄位／決定顯示／政策設定／用語』。使用者要的是**一個機制**，管理者之後不用請工程師。脊柱的零件全部已存在或已設計，缺的是把它們接成**一次登錄**。

```
單據類型登錄（一個單據類型登一次；終態＝F7 register_doctype 的擴充）
 ├─ 語意狀態碼 states_fn            （F7）
 ├─ 欄位群組 FieldGroup + 欄位目錄  （F7 群組 ＋ 本文欄位：型別、金額類別、鎖定等級、通道、預設寬）
 ├─ 白話名稱與單據類型用語          （label_map／relabel：欄位名、狀態名、文件類型用語）
 ├─ 輸出：PDF 版型 / Excel / 列印    （output_template + 適配器，吃解析結果）
 ├─ 版面點（P9 layout points）       （順序、顯示、寬高、通道）
 └─ 政策設定群組                     （設定中心 setting_group：F7 欄位政策、各功能的 P-選項）
```
共同規則：**金額類別一處宣告**（遮蔽、輸出、檔名、帶入白名單共用）；**白話圖形介面**（無代碼）；**放寬走原因＋變更明細＋第二位核准＋確認期**；**預設＝今天**；**版本與還原**走定義文件庫／設定登錄。

### 脊柱的邊界（誠實版）
- **管理者能做**：挑欄位、排順序、定寬高、改名、換用語、選政策選項、改門檻與文字。
- **仍需程式**：新增一種欄位、新的儲存格畫法、新的計算、新的單據類型的結構、涉及金流的連動（與 FRAMEWORKIZE-PROGRAM §4 同一條界線）。
- **脊柱不做**：自訂公式、自訂程式、第二套權限、第二套版本表。

### 工作順序建議（給 PM／1c 排班，非使用者問題）
1. **單據類型登錄的擴充與目錄轉錄（本文 P0）**宜先於 completion-note 與下載檔名的『白名單／變數』改為從目錄產生；但它們都有常數起點，**不阻擋**其先行上線。M3 同理：T1 需要的『報價本文鍵清單』可在本班**本地依目錄格式產出**，不等本文合併。
2. **M3 不等 F7（FL-1）**：M3 以自己的比對實作 T9（H1／H8＋目錄⊆比對集合守門）；與 F7 的對齊是**事後機械式遷移**，不是前置條件。
3. 下載檔名與完工單的『白名單／變數』在目錄落地後改為從目錄產生；在那之前沿用其文件已寫的常數，不得另建設定機制。

## 15. 與其他設計的互通約定（98 交叉稽核＋0d；內部協調，非使用者問題）

1. **單一 DocType 登錄**：文件類型的鍵與白話名稱只有一份（F7／輸出版型／版面／下載檔名／完工單共用）；下載檔名的『文件類型用語表』是同一份標籤的檢視／編輯，不另存。
2. **設定群組代號**統一 snake_case、每個功能一個：本框架用 `doc_layout`（顯示名『版面』）；其餘建議 `completion_note`、`download_name`、`quote_alt`；欄位鍵用 `<群組>.<鍵>`（例：擇一功能總開關寫成 `quote_alt.alt_enabled`，不用 `quote.alt_enabled`）。
3. **端點**：解析後版面併入既有 `GET /api/layout/{模組}`（以參數取得解析結果），不另開 `/api/layout-resolved/…`（本文 §6 先前的名稱作廢）；各功能的『我能做／看什麼』旗標長期應由 F3／F7 能力通道供應，完工單的 `can-author` 為過渡別名。所有新增路由登錄整合點並重產 route golden。
4. **角色名單歸 F3**：『誰可以編輯版面』雖列為設定選項，其底層仍是 F3 能力（`doc_layout.edit` 之類，由 1d 命名）；設定只提供預設能力集合的切換，不另存角色字串。
5. **底層變更集中一班過閘**：`core/customization.py` v2、`helpers/layout_resolve.py`、`helpers/download_name.py` 等 `core/**`／`helpers/**` 變更盡量同一列車，避免多次全量官方閘門。
6. **熱點檔序**：`quotations.py`、`quotation-form.html`（`FORM_VERSION` 每班一次升版）、`pdf_gen.py` 由 PM 排定單一順序；本框架 P2／P3 與 M3 T6／T8 的先後須事先排定（建議 M3 先、本框架接著遷移 M3 欄位為目錄項，或反之，但不可並行改同一檔）。
7. **F7 群組鍵複核（FL-9）**：目錄項的 `group` 對照 F7 的 FieldGroup 鍵（`header／items／pricing／cost／terms／case.*／settlement／delete`）；待 `wip/t54-05-field-policy-design` 定稿時逐一複核，不一致以 F7 為準並修目錄。
