## 3. 檔案擁有權與衝突規則

- `core/definitions.py`、`routers/definitions.py`：只有治理線改（S1、S2、S7）；其他線只呼叫 API。
- `frontend/static/layout-editor.js`：3c 專屬（S8、S4 的掛載點）；治理線只透過 `MotrixDefGovernance.preview()`／`open()` 與之互動，不直接改。
- `helpers/settings_groups.py`、`settings_deploy_baseline.json`、`docs/platform/modules.json`、`route_inventory.json`、`response_keys_baseline.json`、`l1_interface_snapshot.json`：共用生成物，由列車整合者（46）在合併樹重產；各線只在筆記列出需要的條目，不手改。
- 新旗標一律走設定群組（預設 0、`risk=ops`），凍結基準用文字插入。

## 4. 旗標與回退計畫

每個切片一個旗標，預設關；關＝逐位元不變（有測試證明）；緊急回退＝關旗標（已發布的資料保留，停止套用）。`MOTRIX_BUILDER_DEFAULTS_ONLY`（T57 §5.3）在 S2 之後才有意義，屆時一併落地。旗標在正式機的開啟順序：治理（唯讀）→ 選單／版面（低風險頁）→ 欄位 → 按鈕；S2 上線前不在正式機開任何一個。

## 5. 需要使用者決定的事（每項一行；附建議預設）

- D1 新增按鈕首期允許哪些動作？ 建議預設：只允許「導向既有頁面」與「觸發既有匯出」，不允許任何會寫入資料的動作。
- D2 誰可以使用建構器工具（發布版面、選單、欄位）？ 建議預設：只有最高管理者，不開放委派。
- D3 放寬類變更（把欄位／按鈕變多、還原到較寬鬆版本）要不要走「第二位最高管理者核准＋確認期間」？ 建議預設：要，與設定中心的 `change_control`（預設 7 天）同一套；收緊即時生效。
- D4 啟用 S1 後，發布「一定要先看過同一份草稿的預覽」要不要沒有後門？ 建議預設：沒有繞過；預覽服務壞了就不能發布（寧可擋下）。
- D5 `x_` 自訂欄位首期可否是金額類？ 建議預設：不可（只能文字／數字／日期／下拉等非金額欄位），金額欄位等欄位層級權限（F7）完成。
- D6 客戶頁（`customers.html`）由誰擁有，哪些欄位是核心、不能被隱藏？ 建議預設：核心＝公司名稱、統編、狀態；歸屬沿用現在登記它的單位，擁有者再由主持確認。
- D7 快照的保留政策？ 建議預設：全部保留、顯示總筆數與位元組；任何清理需最高管理者核准並寫帳本，且不得低於法定保存下限。
- D8 S0 ①（選單操作文字對非最高管理者一律遮蔽，旗標關也生效）是行為變更，是否同意？ 建議預設：同意（只少了不該看到的目標 id，畫面不變）。
- D9 新旗標在正式機的開啟時機？ 建議預設：S2 上線之前一律關；之後每次開一個、各自觀察一個週期。
- D10 角色版面與公司版面衝突時（公司層改名被角色層的版面蓋過）怎麼辦？ 建議預設：維持「角色優先」，並在預覽與帳本明確顯示「這些角色看到的不會跟著改」。
- D11 `x_` 欄位的資料存放位置？ 建議預設：沿用各單據既有的 JSON 欄位，不新增資料表；若某單據沒有 JSON 欄位，該頁延後到 S7 一起評估（**UNKNOWN：各頁現況需先盤點**）。
- D12 套用時間是否沿用常設指示（週末／下個工作日）？ 建議預設：沿用 `BUILDER-DECISION-PACK-T57.md` §三 第 3 項的既有指示。

## 6. 風險與 UNKNOWN

1. S2 的比較函式：版面、輸出版型、欄位集各自的「放寬」定義要逐 kind 設計；**無法比較＝視為放寬**，起初可能過度嚴格（產生很多待核准項）。
2. S5 的遮蔽不變式是整個計畫中最容易出事的點（規則／欄位繞過金額遮蔽）；每個切片需要非作者權限審查。
3. 各頁「擁有者」不明確（客戶頁在 L1 路由），可能要先做歸屬整理。
4. 沒有真瀏覽器 e2e 的機器時間：t59 的畫面證據全是 node 假環境測試；T60 開旗標前至少要一輪真瀏覽器驗證（由主持排）。
5. 估工量以 T57 §7.1 為基礎，S5、S6 的區間最寬。

## 7. 附錄：案件列表與供應商頁版面引擎的已知限制（來自 3c，`builder_layout.case_management`，wip/t59-bp1-fields-r1 @ f62b49469）

1. 案件卡片對大多數項目不顯示文字標籤，所以除了「業務」以外，改名（relabel）看不出效果；只有業務前綴會讀標籤。
2. 金額、階段進度、日期共用卡片底部同一列；整列依第一個可見項目擺位，列內順序依版面。
3. 編輯器按鈕只在旗標開啟時插在「多選」切換旁；看板與矩陣檢視不能自訂。
4. 金額遮蔽永遠優先：沒有財務檢視權的角色即使版面顯示金額仍看到「—」；`quoteNo`、`dealTag` 是核心，不能隱藏。
5. 供應商頁（同一分支）：7 個非核心欄位的隱藏／改名／排序可用；名稱與啟用是核心。

→ 影響 S4（更多頁面接版面引擎）：每頁都要先寫清楚「哪些項目是核心、哪些改名無效果」，並列在該頁的登記裡，避免使用者以為改了沒生效。
