# 報價單內部功能／案件決策點／頁面顯示模式 框架化範疇（第 54 班；範疇文件，不含實作）

> 來源：node-d8 轉述使用者新需求（2026-10-10）——(1) 報價單內部功能、(2) 案件管理決策點（流程分支／規則）、(3) 頁面顯示模式（欄位顯示、版面、清單預設），都要做成「使用者／主管在系統內決定」，不寫死。
> 性質：只有盤點與排班建議，**不動 M1 程式**。依據使用者核心規則：框架優先、碰到就框架化、白話零技術介面、每個選項宣告影響、安全項可雙向調整但放寬需雙人核准（待生效期＝`change_control.confirm_period_days`，預設 7 天）。
> 盤點方法：三路唯讀掃描 `wip/t54-n39-settings-s0s2` 的程式碼，**行號為該分支當下的引用**，實作前須重新核對（本文件依「引用分支名＋文件版本」規則，不記 SHA）。工量單位 pd：S≤0.5、M 1–2、L≥3。風險詞彙：none｜ops｜money｜legal｜security。
> 對應框架代號沿用 `FRAMEWORKIZE-PROGRAM-T54.md`：F2＝設定中心、F3＝權限矩陣、F5＝編號／狀態碼／標籤、F7＝文件欄位政策（05 設計中）。

## 0. 先講三個與預期不同的事實（影響排班）

1. **「欄位政策 12 組報價」目前不在程式碼裡**：全倉搜尋 `field_policy`／欄位政策皆無；F7 是 05 的設計稿（計畫書 §2 列為「設計」）。本文件所有「欄位可見」類項目的承載者都寫 **F7（待）**，在 F7 落地前不得自建第二套。
2. **`view_filter` 不是執行期機制**：只是命名／標記慣例（`test_view_filter_marking_2026_09_25.py`、`sidebar.js` 的未存檔警告），不儲存也不還原篩選。`user_list_prefs` 只存排序（`sortMode/sortDir/customOrder`），**欄位、檢視模式、每頁筆數沒有落腳處**；`page_definitions` 也不存在（選單來自各模組 `module.json`）。顯示類項目因此多數需要**新增一個顯示偏好框架**（見 §4）。
3. **案件模組沒有宣告 layout 點**：`layout` 種類（`core/customization.py` 的 move/hide/show/relabel…）只對模組宣告的版面點生效，case 的 `module.json` 無此宣告，`layout-runtime.js` 只在 `tender-radar.html` 載入。報價單／案件頁的「區塊順序、分頁順序」要先做 layout 點接線（L 級）。

## 9. 設計筆記：購料報價「擇一方案」與「售後服務及備註說明」（使用者新需求 2026-10-11，經 node-d8；僅設計，不含程式）

### 9.1 需求（原文要點）
1. 購料報價每個品項可勾「擇一方案」；**可有多組**，每組客戶只選一項。報價單層有勾選「合計依方案選擇」：勾選時 合計(未稅)／合計(含稅) 兩格印文字「依方案選擇」而非數字；備註自動加一行列出擇一項次（例：「項次(3)、(4)為網域名稱擇一方案選擇」）。
2. 內部計算：**客戶未選定前，未選的擇一行不計入合計／毛利／管銷**；回簽後案件管理記錄所選項，金額改以所選為準。

### 9.2 資料模型（加欄不改舊語意）
- 品項新增 `altGroup`（字串，空＝非擇一；同值為同一組）與 `altPick`（bool，僅回簽後/內部試算用）。**不用巢狀結構**，舊單沒有這兩鍵＝全部照舊計入（逐位元不變）。
- 報價單層 `totalsByAlt`（bool，預設 false＝今天行為）；`altPicks`：`{組別: 品項id}`，回簽時由案件管理寫入，存於報價單 data_json 與案件（供查詢），**回簽版本戳記**防被後續編輯悄悄改動。
- 組別限制：同組至少 2 項；標題列（`type=header`）不可擇一；一組內全部同為「單價×數量」品項，組別數不設上限（設定中心可設 `quote.alt_groups_max`，預設 10，impact：影響版面）。
- 後端是唯一計算來源：`profit_guard.server_totals` 與前端 `calcTotals` 同式（現行有黃金向量綁定，`item_amount` 為共用切入點）；新增「計入集合」函式 `counted_items(q)`：非擇一項＋（已選則所選／未選則空），**`server_totals`、`server_profit`（成本、進項稅）、管銷、公益捐款全部只走這個集合**，禁止各處各算。

### 9.3 對金額／利潤／管銷的影響（重點）
| 狀態 | 小計／稅／總計 | 成本與進項稅 | 直接毛利、管銷（直接毛利×25%）、營業利益、公益金 | 毛利燈號（margin-tone） |
|---|---|---|---|---|
| 一般（無擇一） | 不變 | 不變 | 不變 | 不變 |
| 有擇一、**未選定** | 只計非擇一項；`totalsByAlt` 勾選時 PDF 兩格印模板文字 | 只計非擇一項 | 同上，只以計入集合為準 | 以計入集合算；**畫面加一行白話提示「尚有 N 組擇一未選，毛利為不含擇一項的暫估」**，燈號不得因此誤報綠燈（有未選組別時燈號最多顯示「暫估」中性色） |
| 有擇一、**已選定**（回簽後） | 計入所選項（金額＝所選） | 所選項成本 | 以所選重算；管銷／公益金戳記沿用既有「歷史不動」規則（已精算／結案不重算） | 依重算結果 |
- 重算時機：回簽寫入所選那一刻，在**同一交易**內重算 `tot` 與利潤欄位並寫稽核（誰選、選哪項、金額前後）；與 `overhead25`（`overheadPct` 戳記、`formulaVer`）互動：只改基數（直接毛利），不改比率與公式版本。

### 9.11 補充（使用者直接指示 2026-10-11）：內部成本面板並列顯示「所有方案」

**原則**：主合計仍排除未選擇一項（9.3 不變）；但**內部成本／利潤面板**要把每個方案各自完整的成本、利潤、毛利並排列出，不是只顯示一個。

**A. 單項方案表（每組一張，逐選項）**
- 對每個擇一組 G、組內每個選項 o：以「基準集合（所有非擇一項）＋ o（該組其他組此時取各自的基準選擇，見 C）」重算，列出：報價金額（未稅）、含稅總計、直接成本、進項稅、直接毛利、直接毛利率、管銷（直接毛利×管銷比率）、公益金、營業利益、營業利益率、毛利燈號。
- 欄位＝方案 A、B、C…並排（手機寬度改為上下堆疊卡片）；表頭標示組別名稱（`altGroup`）與品項項次。
- 一律由後端同一個函式 `plan_view(q, selection)` 計算（與 `server_totals`／`server_profit` 共用 `counted_items`），前端只顯示，不自算（避免與 calcTotals 分叉）。

**B. 每個方案的燈號與管銷（overhead25）**
- 燈號：每個方案各自以自己的毛利率套用現行燈號門檻（Q1–Q8 設定）；「暫估」中性色只用在**主合計**列（因未選），方案欄本身是確定數字，照門檻上色。
- 管銷：每個方案各自＝該方案直接毛利 × 該單戳記的 `overheadPct`（`formulaVer` 沿用），不改比率、不新增公式；公益金基數同單一戳記。已精算／結案的單，方案表僅唯讀顯示且不重算戳記。
- 方案欄為**假設計算**，不寫入 `tot`、不產生稽核（只有回簽選定才寫入）。

**C. 多組合的組合檢視（乘積爆炸的處理）**
- 組合數＝各組選項數相乘（3 組×各 3 項＝27）。設計：**預設顯示「單項方案表」（A）＋「組合檢視」（折疊，預設收起）**。
- 組合檢視：列出全部組合的 總計／直接毛利率／營業利益率／燈號（一組合一列，可排序：毛利率高→低）；超過上限時只列前 N 個（依毛利率排序）並寫「共 M 種組合，僅顯示前 N 種；請收斂擇一組數或調高上限」。
- 設定（群組 `quote_alt`）新增：`combo_view_max`（預設 24，範圍 1–200，impact：影響畫面長度與計算時間；超大值會讓開啟報價單變慢）、`combo_view_default_open`（預設否）。後端計算上限硬頂（200，程式內護欄，不可由設定超過），避免乘積爆炸拖垮；超過硬頂時只回組數，不展開。
- 單項方案表中「其他組」的取值：預設取各組**第一個選項**作為參考基準，並在表頭白話註明「其他組以〔某選項〕計」；使用者可在面板切換基準（僅畫面，不存檔）。

**D. 僅限內部（機密）**
- 成本面板屬成本／毛利資料，沿用既有「被遮罩使用者看不到成本」規則：後端 `plan_view` 端點與回傳欄位依 `cost` 能力過濾，無權限者回應**不含**任何成本、毛利、燈號欄位（不是前端隱藏）。
- **客戶列印／PDF／Excel／回簽頁一律不含此面板**：`pdf_gen` 輸出路徑不引用 `plan_view`；加守門測試——對含擇一的報價單，PDF 文字/HTML 中不得出現成本、毛利、管銷字樣及方案表標題（正反對照：內部畫面有、PDF 無）。
