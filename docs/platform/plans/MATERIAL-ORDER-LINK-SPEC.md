## 2. 從報價單匯入、扣除已匯入量（與 `purchase-items` 同一口徑）

### 2.1 現況【已讀】
- 匯入入口 `openImportModal('materials')`→`doImport()`→`addMaterialFromQuote`（`js/case-management-exec.js:828-865`）：每勾一個報價品項就 push 一筆 `materials[]`（`{id: 時間戳, name, model, qty, unit, ordered:false, arrived:false, …}`）；重複匯入同一品項會**再 push 一筆**（沒有去重）。
- `quoteItemsForImport()`（`:834`）列出所有非 header、有說明的品項，**不看已匯入多少**。

### 2.2 提案
- **材料申請列新增選填鍵 `quoteItemId`**（報價品項 `id`）：由「從報價單匯入」寫入；`materials[]`（物流）項目同樣帶 `quoteItemId`（沿用 31-C 的 `orderItemId` 連到材料申請）。手動新增的列沒有。
- **匯入清單顯示每個品項的**：報價量、**已匯入量**、**剩餘可匯入量**；剩餘 0 的預設隱藏（可展開「已匯完」）；勾選後帶入數量＝剩餘量（可改）。
- **已匯入量的唯一口徑**（與 S1 `purchase_items.usage()` 同一函式擴充，兩個畫面同一份數字）：對一個報價品項，已訂量 ＝
  ① 該案件請購／採購單中的**採購單**明細列（`itemId`＝該品項）數量，狀態計 `COUNTED_EXTRA_STATUSES`（待審核／簽核中／已核准）＋
  ② 該案件**材料申請列**（`quoteItemId`＝該品項）數量，**但排除已連到採購單的材料申請列**（`poDocCode` 有效者——它與那張採購單是同一筆採購，只算一次）。
  材料申請列計入的狀態：已核准、待審核、簽核中、舊單；**草稿與已退回不佔量**（與採購單一致）。請購單**只提示、不扣**（Q3，已裁示）。
- 剩餘 ＝ 計畫量 − 已訂量（下限 0）；`GET …/purchase-items` 的 `remainingQty` 改用擴充後的 `usage()`（對外欄位不變，只是已訂量多算了未連採購單的材料申請）。
- 超出：材料申請列連報價品項且累計超出計畫量 ⇒ 與採購單相同（Q2）：**必須填 `overPlanReason`**，送審時伺服器檢查（`material_guard` 的送審檢查，§4）。

### 2.3 需要 d7 確認的資料點
- `materialOrders[]` 新鍵 `quoteItemId`／`poDocCode`／`poLine` 要進 31-C 的 `material_guard._valid_order`（合法性）與 `content_hash`（實質欄位）；`quoteItemId` 在材料申請核准後不可改（改＝回草稿重審）。

## 3. 材料申請與請購／採購單的連結

### 3.1 資料模型（不新增表）
`materialOrders[]` 新增選填鍵（存在 `data_json`，31-C 的守門統一驗證）：
| 鍵 | 意義 | 驗證 |
|---|---|---|
| `quoteItemId` | 來源報價品項 | 必須在該案件報價內（匯入時帶；手動新增沒有） |
| `poDocCode` | 連到的採購單單號（`PO-YYYYMMDD-NNNN`） | 同案件、類型為採購單、狀態屬待審核／簽核中／已核准；材料申請**送審**時再驗一次 |
| `poLine` | 採購單明細列序（從 1 起） | 該列存在；若採購單列有 `itemId`，必須與 `quoteItemId` 相同 |
| `prDocCode`（資訊） | 連到的請購單 | 同案件、已核准；**只做追溯，不算「已連採購單」**（問題 4） |
- 金額：**有效 `poDocCode` 的材料申請，金額由採購單負責**（營運報表／總帳 E12/E12b 略過該材料申請金額；材料申請頁顯示採購單金額唯讀）；沒有連結者金額照 31-C 規則。
- 與 31-C 的**互斥**（d7 條件）：有 `poDocCode` 的材料申請不可開材料申請匯款申請；已有有效材料申請匯款申請者不可加 `poDocCode`。`poDocCode` 屬實質欄位（進 `content_hash`）。

### 3.2 建立方式（三個入口，連結在建立時就帶好）
1. **從報價單品項**（§2）：帶 `quoteItemId`；使用者可在同一個畫面順手選「連到採購單」。
2. **從採購單明細建立材料申請追蹤**：材料申請頁「從採購單帶入」列出該案件已核准（或審核中）、尚未被材料申請連結的採購單明細列 ⇒ 帶入品名、數量、單位、供應商（採購單 `vendor`）、`quoteItemId`（若有）、`poDocCode`／`poLine`；金額唯讀（來自採購單）。**這是建議的主要路徑**（一筆採購：先採購單、再材料申請追蹤已叫／已到）。
3. **手動新增**（保留彈性）：自由輸入；沒有連結 ⇒ 依 §3.4 標註。

### 3.3 以「走流程簽核過的」為主
- 連結只接受**核准中或已核准的採購單**；採購單被駁回／作廢 ⇒ 材料申請的連結視為**失效**（畫面標「採購單已失效」，並退回 §3.4 的「未申請採購單」判定；金額改回依材料申請自己）。
- 材料申請列表預設只顯示**已核准＋舊單**（含連結狀態徽章）；待審核／簽核中／草稿／已退回在各自分頁（§5.3）。

### 3.4 「該材料申請未申請採購單」的判定規則（單一函式 `material_link_status(order, case_po_rows)`；所有畫面共用）
輸出三態：`linked`（已連採購單）／`none`（未申請採購單）／`exempt`（不適用）。
1. **`exempt`**：金額為 0 的材料申請（31-C Q4：客供料／庫存領用）——**待使用者裁示（問題 1）**，建議不標。
2. **`linked`**：`poDocCode` 存在、同案件、類型採購單、狀態屬待審核／簽核中／已核准，且 `poLine` 對得上。
3. **`none`**（含：沒有 `poDocCode`；連到的採購單不存在／草稿／已駁回／已作廢／別案件）。顯示文字固定：**「該材料申請未申請採購單」**；若原本有連結但失效，補註「（原連結採購單已失效）」。
4. **舊單**（沒有疊加審核列）：**是否標註待裁示（問題 2）**；建議只顯示既有「舊單」灰徽章，不再疊「未申請採購單」（否則歷史資料整片標註＝雜訊）。
5. 與報價單的關係不影響判定：**報價單內品項若未連採購單 ⇒ 標註；報價單外品項（無 `quoteItemId`）未連 ⇒ 標註**，可另帶副註「報價單外品項」（兩者同一個徽章文字，副註只在清單與審核頁顯示）。

### 3.5 標註出現位置（皆讀同一個 `material_link_status`，不各自判斷）
| 位置 | 內容 |
|---|---|
| 材料申請列表（案件頁「財務」材料申請區與「執行進度」材料申請管控） | 列旁橘色徽章「該材料申請未申請採購單」；`linked` 顯示綠色小徽章「採購單 PO-…」（可點開該單） |
| 材料申請審核頁／簽核佇列詳情（31-C 的 `approval.detail` 提供者） | 欄位「採購單連結」＝已連（單號）／**未申請採購單**；超出報價計畫量時另列「超出 N（原因）」 |
| 簽核佇列清單卡片 | 卡片 tag：「未申請採購單」（`approval-queue.html` 目前沒有 tag 欄位 ⇒ **需 L1 小改：項目新增選填 `tags[]` 並顯示**；列為依賴，問題 8） |
| 營運報表（材料申請逐筆明細） | `recognition.material_entries` 的列加 `noPo: true`，報表備註加「｜未申請採購單」；**金額計算與桶不變** |
| 案件頁「待補登」旗標 | 選用：新增旗標 `material_no_po`（只對已核准、金額>0 的材料申請；問題 7）；預設不開 |
| 儀表板／採購頁材料申請進度 | 不變（物流旗標的呈現由 31-C 管） |

## 4. 審核流程如何疊在 31-C（不新增簽核類型、不新增層級）
- **沿用 31-C 的材料申請審核**（`MO-` 單號、同一條簽核鏈、`material_order` 佇列類型）。本規格只在 31-C 的**送審檢查**與**審核畫面**加東西：
  1. 送審時（`material_guard` 的送審路徑）：驗 `quoteItemId` 存在、**累計量上限**（共用 `purchase_items` 的 `overplan`；超出必須有原因，Q2）；驗 `poDocCode`／`poLine` 有效（§3.1）；計算並**把 `material_link_status` 與超出量寫進 `approval_json` 快照**，讓簽核人看到的是送審當下的狀態。
  2. 核准後 `poDocCode` 失效（採購單被駁回／作廢）⇒ 不自動撤銷材料申請核准，只讓判定變 `none`（畫面與報表標註）；是否要把材料申請退回待重審＝問題 5。
- 「到貨確認」「材料申請匯款申請」「物流旗標閘」完全由 31-C 負責，不動。

## 6.0 原題與建議
1. **金額 0 的材料申請（客供／庫存領用）要不要標「未申請採購單」？** 建議：**不標**（本來就不採購）。
2. **舊單（上線前建立、沒有審核列）要不要標？** 建議：**不標**，只顯示「舊單」徽章，避免歷史資料整片標註。
3. **是否強制連請購／採購單？** 選項：(a) 完全不強制，只標註（使用者原話「保留彈性」）；(b) 報價單內品項強制連採購單、報價單外不強制；(c) 金額超過 N 元強制連。建議：**(a)**；日後要收緊再升 (b)/(c)（資料模型已支援）。
4. **只連請購單（`prDocCode`）、沒有採購單，算「已申請採購單」嗎？** 建議：**不算**（請購是意向）；顯示「已請購，未採購」副註。
5. **連結的採購單事後被駁回／作廢，材料申請要自動退回重審，還是只標註失效？** 建議：**只標註**（不動已核准的材料申請），由審核人或申請人處理。

7. **「未申請採購單」要不要進案件頁「待補登」旗標與統計？** 建議：**先不要**（只標註在列表／審核／報表），觀察一個月再決定。
8. **簽核佇列卡片要不要顯示這個標註？** 這需要 L1 小改（佇列項目新增選填 `tags[]`）。建議：**要**（簽核人最需要在清單就看到）。

## 補充（c7 預審後，2026-10-02）：已有付款紀錄的材料申請不視為連結
- 判定：`_link_check` 對「已付金額 > 0 或已付狀態不是 pending」的材料申請回 `(False, "has_payment")`（單一判定函式，報表／總帳／精算／標註同源）。理由：它付出去的錢已記在材料申請上；若事後再連到採購單就會被「連到採購單＝金額由採購單負責」略過，現金口徑的已付金額憑空消失；若兩邊都算則同一筆錢付一次卻記兩次。
- 寫入：`PATCH …/material-orders` 對已有付款紀錄的列**新增**（或更換）採購單連結 ⇒ 400「已有付款紀錄，不可再對應採購單」；既有連結（先連、後付款）原樣存回不受影響。
- 端點改名：連結判定唯讀端點為 `GET /api/quotations/{案件}/material-link-status`（避開「開案件不打 /material-orders」契約測試的子字串）。
