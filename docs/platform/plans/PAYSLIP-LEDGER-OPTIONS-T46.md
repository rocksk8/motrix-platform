# 勞報單新流程對總帳（E06／E06b）的影響與選項（第 46 班；**待使用者／會計裁示，程式未改**）

> 作者 hichan-eb，2026-10-07；來源：t46 複核 M1（hichan-79）。釘住現況的測試：`modules/accounting/tests/test_ledger_payslip_approval_pin_t46.py`。

## 現況（沒有改任何總帳程式）
`modules/payroll/gl_events.py`：E06（借 勞務費用／貸 代扣所得稅、代扣二代健保、其他應付）只在勞報單狀態 ∈ {已簽回, 已付款} 時產生；E06b（付款）只在已付款且非匯款單付款時產生。

第 46 班之後勞報單可由「已核准」直接付款（Q4：簽回檔選填），並且付款填錯退回（unpay）會回到「付款前最近的狀態」。兩者碰到 E06：

1. **沒簽回就付款的勞報單**：E06 在**付款當下才出現**（認列日仍取勞報日期）。
2. **unpay 退回到 已核准／已匯出**（沒有簽回檔）：勞報單離開 {已簽回, 已付款} ⇒ **E06 與 E06b 一併消失**，引擎下次執行對已入帳的部分產生反向草稿（可能落在已結帳期間）。有簽回檔者退回已簽回，E06 保留（與改版前相同）。
3. 待審核／已核准／已匯出 的勞報單不入帳（已匯出本來就不入帳）。

## 選項
| | A：應付在**核准**時認列 | B：維持**簽回／付款**時認列（現況）＋保護 unpay |
|---|---|---|
| E06 條件 | 狀態 ∈ {已核准, 已匯出, 已簽回, 已付款}（作廢、草稿、待審核不入帳） | 不變：{已簽回, 已付款} |
| 認列時點 | 核准日起即有應付（負債成立於核准，與簽回無關） | 簽回後；沒簽回者在付款時 |
| unpay | 不影響 E06（仍在集合內）；只有 E06b 消失 | 退到 已核准／已匯出 時 E06 消失 ⇒ 反向草稿；要另外規則：已入帳（有 E06 傳票且期間已結）時 unpay 一律拒絕或不退出集合 |
| 作廢 | 核准後作廢 ⇒ E06 消失 ⇒ 反向（本來就該反向） | 已匯出作廢不入帳，無影響 |
| 改動範圍 | `gl_events` 一處條件＋ledger 測試改期；**認列時點提前**（過去一律簽回後）要會計同意 | 不改認列；要改 `unpay`（有已入帳 E06 時拒絕）或改 gl 集合 |
| 風險 | 已核准但最終沒付款的單也入帳（需作廢才會沖）；與「簽回是對方確認收款」的內控意義脫鉤 | 沒簽回就付款的單，應付與付款同時出現（E06 認列日仍是勞報日期，可能落在已結期間） |

## 建議
**A（核准時認列）**：負債的成立在核准（公司已確認要付），與簽回無關；也讓 unpay、重新匯出、補簽回都不再影響 E06，反向草稿只剩作廢。代價是認列時點相對舊流程提前，需會計同意並在上線說明。
**本班預設＝現況（B 的「不改」版）**，已用測試釘住；使用者或會計裁示 A 之前不改程式。若選 A，改 `gl_events` 條件並把釘住測試改成 A 的預期；若選 B，另做 unpay 保護。
