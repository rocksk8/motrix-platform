### 1.4 問題分類（證據）
- **T1 分類邏輯**：頁名「通知設定」實為「寄信帳號設定」。LINE、月報收件人、寄送失敗清單同頁。MS 才是「誰收什麼」，月報收件人卻在 NS，MS 還要靠註記導回：「每月營運報表的收件人在「通知設定 → 每月營運報表收件人」維護」（backend/helpers/mail_types.py:34）。證據：NS:176-178、NS:419。
- **T2 用語**：「Gmail SMTP」「SMTP 主機」「連接埠」「App Password」「token」「Callback URL」。證據 NS:239,278,282,271,360,369。
- **T3 填寫方式**：SMTP 主機／埠為自由輸入，應為「信箱服務」下拉（Gmail／Outlook／其他）自動帶；系統網址手填，應取目前網址；LINE 三組金鑰＋網址純手貼。證據 NS:279,283,294,361-376。
- **T4 缺預設值**：預設值是開發方的（`https://172.16.10.177:666` NS:294,574／SYS:2550；顯示名稱「MOTRIX ERP」與後端「MOTRIX專案管理系統」不一致 NS:573 vs SYS:2549）；寄件顯示名稱應預設公司名稱（公司資料已有）。
- **T5 驗證／錯誤訊息**：`PUT /api/settings/email-notify` 完全沒有驗證（SYS:2574-2586；port 非數字、Email 格式、base_url 格式都照存），錯誤要等「寄測試信」才出現。實際字串：「Email 通知功能未啟用」「非正式機環境，已擋下寄送（見 _smtp_send_blocked 說明）」「收件人清單為空」「SMTP 帳號或應用程式密碼未設定」（backend/helpers/email_notify.py:543,546,548,555）、「找不到可發送對象：請確認「信件與通知收件設定」的測試信收件人，並為其帳號填寫 Email」（SYS:2881）、「SMTP 連線失敗（代碼 …）」（SYS:2889）、前端預設「寄送失敗，請確認 SMTP 設定」（NS:735）。其中「非正式機環境…見 _smtp_send_blocked 說明」直接洩漏內部函式名；成功訊息「測試信已寄出，請至管理員信箱確認」（NS:733）沒說寄給誰（後端有 sent_to 但前端不顯示）。LINE：「channel access token 格式不正確：只能是英數與 + / = . _ -，長度 20～512，請從 LINE Developers 重新複製」（SYS:2756）、「對外網址只能是 https://網域（可含埠號 1～65535），不可含路徑、查詢或帳號」（line_notify.py:126）、「訊息要帶連結，必須先設定對外網址（public_base_url）」（SYS:2766）、「啟用 LINE 通知前請先填寫 channel access token」（SYS:2764）【hichan-6 範圍】。「include_links 必須是 true／false」類字串（SYS:2724）屬不該到使用者眼前的 API 錯誤。
- **T6 危險設定沒分層**：「開發機測試模式」與「啟用 Email 通知」同一排（NS:245-258）；SMTP 主機／埠與日常開關同層；「LINE 訊息帶連結」（對外曝露面）與「啟用」同層；改寄件帳號＝全公司通知換寄件人（system_hub_l1.json:145 impact）卻無二次確認。

### 1.5 一般人不該碰（建議歸進階／最高管理者專用）
SMTP 主機、SMTP 連接埠、開發機測試模式、系統網址（應自動、僅異常時改）、LINE 對外網址、LINE Login channel ID／secret、LINE 訊息帶連結。「寄不出去的單據」是狀態檢視，應移到儀表板／提醒中心而非設定頁。

### 1.6 精靈機會
**(A) 設定寄信帳號（現況）**：① 先去 Google 帳戶開兩步驟驗證 ② 到「應用程式密碼」產生 16 碼 ③ 回系統貼「寄件人 Email」「應用程式密碼」 ④ 確認 SMTP 主機／埠（預設 Gmail 可略） ⑤ 填系統網址（預設是別人的 IP，必須改） ⑥ 勾「啟用 Email 通知」 ⑦ 按「儲存設定」 ⑧ 按「寄送測試信」 ⑨ 去「使用者管理」替 admin／superadmin 填 Email，否則測試信「找不到可發送對象」（SYS:2881）；checklist 只提示不引導。
精靈後：①選信箱服務（Gmail／Outlook／其他）②貼「寄信信箱＋通行碼」（附直達連結＋圖解）③系統自動偵測網址、顯示「信件連結會指向 …，正確嗎？」④自動寄測試信給「目前登入者」並顯示「已寄到 xxx@，請確認收到」，成功即自動啟用。

**(B) 串 LINE（hichan-6 範圍）現況**：① 去 LINE Developers 後台建 Provider ② 建 Messaging API channel，發「長效 Channel access token」③ 回系統貼 token、勾啟用、按「儲存 LINE 設定」「驗證 token」④ 若要讓同仁自己綁定：另建 LINE Login channel（需與上面同 Provider、狀態 Published）⑤ 記下 Channel ID 與 secret 貼回系統 ⑥ 設定「對外網址」（需有對外 https 網域／Tunnel，這是 IT 事項）⑦ 把系統顯示的 Callback URL 複製回 LINE Login channel 設定 ⑧ 勾要同步發 LINE 的通知 ⑨ 通知每位同仁到「帳號安全」頁綁定。
精靈後：①「開始串接 LINE」→ 顯示圖解，只要「貼金鑰」一步（token 自動驗證並顯示官方帳號名稱）②（需要同仁綁定時）自動檢查「對外網址是否可用」，不可用就停在「請 IT 協助」並產生一份給 IT 的說明；可用則顯示一鍵複製的回調網址 ③勾選要發 LINE 的通知。

## 2. 信件與通知收件設定 mail-settings.html

### 2.1 基本
- 選單名稱「信件與通知收件設定」（menu_l1.json:185）；系統中心 desc「逐類型設定誰收信、誰收站內通知」（system_hub_l1.json:155）——**實際只管信件＋行事曆，沒有「站內通知」欄位**（描述與頁面不符）。perm=superadmin。
- 一句話：對 42 種（backend/helpers/mail_types.py 的 register 呼叫 42 筆）系統信件逐一決定寄不寄、寄給誰、是否同步到公司 Google 行事曆。

### 2.2 區塊與欄位
- 頁首說明（MS:49，單段 ~330 字）：「每一種系統寄出的信件都在這裡指定收件人。「照預設」依信件類型的預設收件人寄送；「僅超級管理員」只寄給超級管理員；「指定帳號／角色」除了事件相關人員之外，另寄給指定的帳號與角色。系統技術類預設只寄超級管理員。個人仍可在使用者管理中退訂自己收得到的類型。每一列另有兩個互相獨立的公司層勾選：「信件」取消勾選＝這種信不寄給任何人（原本的收件人設定保留，重新勾選即恢復）；「行事曆」勾選＝同步到公司 Google 行事曆。只進行事曆、不寄信也可以；沒有日期或沒有信件範本的格子停用。」
- 橫幅（MS:53-56）：「Google 行事曆目前尚未連線／總開關未啟用：行事曆格仍可先勾選，連線並啟用後才會實際推送。」＋連結「前往 Google 行事曆連線設定」。
- 固定說明（MS:57）：「主旨格式固定為「【MOTRIX 系統通知】分類－事由」，內文依「事由、影響、建議處理、發送時間與來源」呈現；下表的「影響」「建議處理」即為各類信件內文的預設說明。」

### 2.4 問題分類
- **T1**：一頁 42 列 × 8 欄的矩陣，依「信件種類（技術清單）」排，而不是依任務（「誰要收到報價單簽核通知？」）。分類「業務／簽核／系統技術」中，「系統技術」含「備份已停止運作／磁碟空間不足／HTTPS 憑證即將到期／地圖定位額度達警戒線／本公司資料設定狀態告警／測試信」（mail_types.py:205-219）——這其實是**備份與心跳等警報的收件人唯一入口**（見 §5）。證據 MS:69、mail_types.py:24。
- **T2**：「HTTPS 憑證即將到期」「地圖定位額度達警戒線」等信件名；「信件類型」本身。證據 mail_types.py:205,214。

- **T4**：預設收件人由每類 register 決定，OK；但頁面無「全部恢復為標準設定」按鈕。
- **T5**：實際字串：「信件類型不存在：%s」「…，不在本頁設定。」「不認得的角色：%s」「找不到帳號：%s」「指定收件人時，至少要選一個帳號或角色。」「「%s」的信件不能關閉：%s」「關閉「%s」（%s類）的信件後…確認請帶 confirm=true 再送一次」（mail_settings.py:87-124）；其中 409 訊息「請帶 confirm=true 再送一次」是給程式的。畫面讀取失敗顯示「讀取失敗：」＋HTTP 碼（MS:175）。
- **T6**：「信件」勾選即時生效，可一鍵關閉「備份已停止運作」這種告警（雖有 confirm 與 `mailOffLockReason`，鎖定規則見 notify_matrix）；與「收件人設定」需另按儲存的行為不一致，容易以為已存。系統技術類與業務類同表同層。

### 2.5 不該碰／建議分層
「系統技術」分類全部（憑證、備份、磁碟、定位額度、公司資料告警、測試信）→ 進階／最高管理者專用，或預設不顯示。行事曆欄與信件欄應分兩個頁籤（信件 vs 行事曆）。每列的 key 與「影響／建議處理」預設文字不需列出。

### 2.6 精靈機會
任務導向精靈「我想讓誰收到○○」：① 選情境（報價單送審／工作逾期／保固到期／系統故障…）② 選對象（原本的人／某職務／某幾位）③ 顯示「預覽：這封信會寄給 …（N 人）」。現況需要：切分類頁籤→在 42 列中找該列→改下拉→（custom 時）選角色／帳號→按該列「儲存」；且必須先去 NS 設好寄信帳號，系統不會在這頁提醒「寄信尚未啟用」（只有行事曆有橫幅 MS:53，寄信未啟用無橫幅）。

### 3.4 問題分類
- **T1**：事件設定在最上、連線設定在最下，順序與工作流程顛倒（要先連線才有事件意義）。同樣的事件勾選另見 MS「行事曆」欄（兩處維護同一份 `google_calendar.events`，MS:214 註解自承「與 Google 行事曆設定頁同一份」）。證據 GC:173 vs GC:246、MS:85-97。
- **T2**：OAuth／Client ID／Calendar ID／Cloud Console。證據 GC:248,272,283,261。
- **T3**：Client ID/Secret/Calendar ID 全手貼；授權用 CLI 腳本。證據 GC:262-264。
- **T4**：Calendar ID 有預設 primary；事件有預設開關（且會顯示「預設開／預設關」，OK）；Client ID／Secret 無法預設——正因如此該改為共用應用或精靈。
- **T5**：實際字串：「Google 行事曆尚未完成授權（缺少 client_id/client_secret/refresh_token）」「Google 行事曆整合未啟用」（google_calendar.py:86,107）、「建立測試事件失敗（代碼 …）」（SYS:2674）、「events 必須是 {事件代碼: true/false}」「未知的事件種類：…」「事件開關的值必須是 true 或 false」（SYS:2623-2630）、前端預設「建立失敗，請確認設定與授權狀態」（GC:449）。**缺少 client_id/client_secret/refresh_token 三個英文欄位名外露**。`PUT /api/settings/google-calendar` 對 client_id／calendar_id 無格式驗證（SYS:2637-2660）。
- **T6**：「Client Secret」「啟用」與事件勾選同頁同層；啟用後每次核准都會寫公司行事曆（可能含客戶／案件名稱到外部服務），無任何「資料會送到 Google」的提示。

### 3.5 一般人不該碰
Client ID／Client Secret／Calendar ID／OAuth 連線整卡、授權腳本。行事曆事件勾選可留給行政，但應改為「簡單 3～5 個情境」。

### 3.6 精靈機會
現況外部動作：① 開 Google Cloud Console，建專案 ② 啟用 Calendar API ③ 建 OAuth 用戶端 ID（類型選 Desktop app，設同意畫面）④ 複製 Client ID／Secret 貼回系統 ⑤（可選）在 Google 行事曆建次要行事曆並找出 Calendar ID 貼回 ⑥ 勾「啟用」並儲存 ⑦ **到伺服器本機開命令列，在專案目錄執行 `python scripts/setup_google_calendar_oauth.py`**，瀏覽器登入同意（用與寄信相同帳號）⑧ 回網頁確認「● 已連接」⑨ 按「建立測試事件」⑩ 往上捲勾選事件並按「儲存事件設定」。
精靈後：①按「連接 Google 行事曆」→ 網頁跳 Google 登入同意（不需 Cloud Console、不需命令列）②選擇既有行事曆或「新建專用行事曆」③勾選情境（預設推薦組合）④自動建立測試事件並顯示「已在 ○○ 行事曆建立」。

### 4.4 問題分類
- **T1**：與 CP 頁的「PDF 存檔根目錄」「雲端備份目標」（CP:~870-1000）、設定中心 retention 群組三處分別管理「檔案放哪、備份留多久、備份去哪」；使用者要完成「備份設好」得跑 3 頁。證據 system_hub_l1.json:31-52（兩張卡指向不同頁）、CP:948-1000。
- **T2**：「根目錄」「個資」「鏡像」「整庫備份」。證據 ST:88-89。
- **T3**：三個路徑全手打。證據 ST:62-63。無資料夾瀏覽。
- **T4**：預設「自動判斷」很好（留空），但頁面不顯示「自動找到什麼」就要人決定要不要填（有「目前：」文字行 ST:102，OK）。
- **T5**：錯誤逐欄顯示，是四頁中最友善的（storage_locations.py:181-210）；扣分處：「⇔」「互相包含」。
- **T6**：三個路徑權重相同；個資與更新交付會影響資安（個資要放權限更窄處）、更新機制，應放進階。換路徑後舊檔不搬移（system_hub_l1.json:35 impact）頁內沒有提示。

### 4.5 一般人不該碰
更新交付資料夾（整個）、個資資料夾路徑（應由 IT／最高管理者安裝時一次設好）、「建立這個資料夾」。對一般客戶，這頁應該只顯示「備份存放位置：目前＝○○（正常／異常）」。

### 4.6 精靈機會
現況：① 自己確認電腦已安裝並登入 Google 雲端硬碟桌面版 ② 到檔案總管找出同步資料夾路徑並手打（G:\…）③ 若不存在按「建立」（只建最後一層，上一層不存在會報錯）④ 去雲端硬碟網頁確認共用權限 ⑤ 另設個資資料夾，要確認不得在存檔資料夾內 ⑥ 儲存。
精靈後：①系統自動偵測雲端硬碟，顯示「找到：G:\我的雲端硬碟，要把備份放這裡嗎？」②一鍵建立「系統存檔」與「系統存檔_個資」（自動避免互相包含）③顯示「請到雲端硬碟將『個資』資料夾只分享給 ○○」的固定提示 ④跑一次寫入測試，顯示「備份位置正常」。

## 6. 跨頁總評（供精靈與選單重整參考）
1. **一個任務跨多頁**：「讓通知信寄得出去」需依序走 NS（寄信帳號）→ 使用者管理（填 Email）→ MS（收件人）→ NS 寄測試信；系統沒有「完成度總覽」，各頁 checklist 互相不知道對方（NS checklist 4 項、GC checklist 3 項各自獨立）。
2. **相同資料兩處維護**：行事曆事件開關在 GC 與 MS（同一份設定，MS:214）；月報收件人在 NS，信件預設收件人在 MS（mail_types.py:34 以 MANAGED_ELSEWHERE 補丁解決）；備份天數在 CP＋設定中心 retention 群組（舊 key `backup_retention`，settings_groups.py:75）。
3. **「超級管理員」vs「最高管理者」vs「superadmin」並存**（MS:150；NS:426/316；NS:345「只有最高管理者」）。
4. **內部代號外露**：`t.key`（MS:73）、「行事曆代碼」（MS:73）、路徑 `backend/db_backups/`（mail_types.py:213）、`scripts/setup_google_calendar_oauth.py`（GC:263,354）、`_smtp_send_blocked`（email_notify.py:546）、`public_base_url`（SYS:2766 的錯誤訊息）、`include_links`（SYS:2724）。
5. **「開發機／正式機」概念洩漏給客戶**：NS:256、GC:262/292、ST:90、email_notify.py:546「非正式機環境，已擋下寄送」。
6. **預設值是開發方環境**：`https://172.16.10.177:666`（NS:294/574、SYS:2550）。
7. **儲存行為不一致**：MS「信件」「行事曆」勾選即時存、「收件人設定」需每列按「儲存」；NS LINE「同時發 LINE 的通知」勾了立即存（NS:393、SYS:2705）、LINE 其他欄位需按「儲存 LINE 設定」；GC 事件需按「儲存事件設定」、OAuth 卡另需按「儲存設定」（兩顆儲存鈕各存各的，GC:418 註解）。使用者無法預期哪些要按儲存。
8. **錯誤訊息直接顯示後端 detail**（NS:718,735；GC:432,449；MS:208）：多數 400 為給程式的字串（含 enum、欄位名）。
9. **危險分層**：目前四頁皆 superadmin 專用（單層），沒有「日常設定／進階」兩層；建議把 SMTP 主機埠、開發機測試模式、LINE 對外網址／Login channel／帶連結、OAuth 連線、更新交付／個資資料夾、S3 設定、系統技術類信件全部移入「進階（工程師／導入顧問用）」。
10. **hichan-6 範圍提醒**：§1.2/1.3/1.4/1.6(B) 標示【hichan-6 範圍】的 LINE 項目，其中「channel／token／callback／Provider／Published」用語、三段手貼欄位與 verify 訊息，建議合併進 §1.6(B) 的精靈方案由 hichan-6 單一落地，避免與非 LINE 區塊互相衝突；LINE 卡片是獨立 Alpine 元件 `lineNotifyCard()`（NS:514），資料來源 `/api/settings/line-notify`，與 NS 其他卡片無共用狀態，拆分成本低。
