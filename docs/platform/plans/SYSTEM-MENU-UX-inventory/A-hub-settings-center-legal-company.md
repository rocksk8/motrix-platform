## 2. 設定中心 settings-center.html
---------------------------------------------------------------------
### 2.1 基本
- 選單名稱「設定中心」；檔名 settings-center.html；perm=superadmin（menu_l1、卡片、`/api/settings-center/*` 皆 `require_superadmin`，BE/routers/settings_center.py:72,96,116）。
- 一句話：以「群組→欄位」方式調整全系統 165 項數字／開關／用語；每次改都要填原因、有影響預覽、有版本可還原、重要變更需等候＋第二位最高管理者核准。
- H1「設定中心」，眉標「系統設定」，副標（:76）：「系統內可調整的數字與選項集中在這裡。每一項都有預設值、可設定範圍與影響說明；比較重要的變更會先經過確認期間，必要時還需要另一位最高管理者核准，並留下變更紀錄。」

### 2.2 頁面如何組織／搜尋群組
- 左欄為**單層平鋪清單**（`<nav class="sc-side">`，:84-100），順序＝註冊順序（`/api/settings-center/groups` 迭代 `sr.groups()`，settings_center.py:75），**沒有分類／分頁／摺疊**；47 個群組一次排開，工程用的 builder_* 群組穿插在報價、財務之間（例：第 14 builder_status_display 在 ui_format 之前，第 17-25 連續 9 個 builder_*）。
- 搜尋：`<input type="search" placeholder="搜尋設定群組">`（:85），前端只比對「群組名稱＋群組說明」子字串（:365-368 `g.label.includes(q) || (g.help||'').includes(q)`），**不搜欄位名稱**。例：搜「保固」找不到（保固在群組「到期預警」的欄位裡，群組名與說明不含「保固」）；搜「備份」只命中「保存期限」。
- 群組按鈕尾巴徽章：「已調整過」（有過變更）、「開發中」。
- 左欄下方「即將推出」：列出 10 項尚未有群組的規劃功能，文字「開發中，預計 MS2 版提供」（:97、BE/core/features_l1.json:4-13，MS2~MS5 為內部班次代號）。
- 右側：群組標題＋群組 help；頁籤「目前設定｜待生效｜版本與變更紀錄｜預設組」（:112-115）。窄螢幕（<900px）左欄改橫向捲動，搜尋框被隱藏（:60 `.sc-side input{display:none}`）。
- 切換群組有未存修改時被擋：「這個群組有尚未儲存的修改，請先儲存，或按「放棄修改」。」（:370）

### 2.3 欄位呈現（所有欄位共用的元件）
資料全由後端 `field_views` 提供；每個欄位固定顯示：
1. 白話問句 `question`（粗體）＋「建議：X」徽章（:122）
2. `help` 說明
3. 控制項（依 type）：有 choices → 單選鈕（每項附「建議」標與一行影響 `c.impact`）；int/float → number 輸入＋單位＋範圍提示「可設定 a～b 單位」「至少 a（無上限）」「至多 b」（:396-402）；bool → 單一勾選「開啟」（:144）；str → 單行文字框（:148）
4. 紅字驗證訊息（預覽端點回傳）
5. 「目前：X」＋「目前不是系統預設（預設：Y）」＋按鈕「還原預設」
6. `impact` 一句影響說明；若有即時影響則多一句動態影響
7. 分類標籤：立即生效／等確認期間後生效／需另一位最高管理者核准（:462）＋橫幅（紅／黃）
- 進階欄位預設隱藏，連結「顯示進階項目（N 項）」（:175），共 29 個欄位標 advanced（retention 5、download_name 16、quote_alt 3、material_recognition 2、completion_note 2、uploads 1…）。
- 底部固定儲存列（有修改才出現，:289-310）：「已修改 N 項，尚未儲存」、「放棄修改」、逐項「• 效果句」、「⚠ 警告」、textarea 佔位「為什麼要改？（必填，會記在變更紀錄裡）」（必填）、紅色風險時須勾「我已了解上述影響」、按鈕「確認儲存」。**任何一項修改（即使只是把「報價單」檔名用語改成「報價」）都強制填原因。**
- 其他頁籤：
  - 待生效：說明「放寬類或重要的變更不會馬上生效：要等「變更確認期間」，需要時還要另一位最高管理者核准。期間內任何最高管理者都可以撤銷。」＋備註框「核准／撤銷的備註（選填）」＋表格（設定／改成／申請人／原因／生效時間／核准 n／m／核准／撤銷）。
  - 版本與變更紀錄：表格「第 N 版」＋「還原到這一版」＋比較兩版（下拉：系統預設／第 N 版／目前）；還原須填「還原原因（必填）」。
  - 預設組：說明「預設組是一組事先配好的建議值（例如「嚴格」）…」。**實際沒有任何欄位定義 presets**（grep `presets=` 只有文件字串；`sr.profiles()`＝{}），頁籤永遠顯示「目前沒有可用的預設組。」，說明中的「嚴格」例子不存在。
  - 最近的變更（:178-187）：時間／誰改的／改了什麼／原因；空時「這個群組還沒有被調整過，全部使用系統預設。」

### 2.7 錯誤／驗證訊息（實際字串）
- 儲存列預覽錯誤（紅字，`p.message`）：`"%s：%s" % (label, msg)`，msg 取自 SettingDef.check：「不可小於 %s」「不可大於 %s」「必須是整數」「必須是數字」「不是可選的選項」「必須是文字」「這個版本不可小於／大於 %s」（settings_registry.py:~156-176、validate_values）。頁面 `_msg()`（settings-center.html:344-352）：`d.message + '：' + problems.join('；')`，例「設定未儲存（2 個問題）：保存…：不可小於 365」；其餘退回「操作失敗（403）」等含狀態碼字串（:351）。
- 非字串例外洩漏：跨欄位檢查失敗時「跨欄位檢查失敗：%s」把 Python 例外文字直接串出（settings_registry.py:372-373）；「values 必須是物件」「未知的設定欄位」「缺少欄位」（:351,358,372）為 API 層文字，正常 UI 不會觸發但失敗時可見。
- 變更原因空白：「請填寫變更原因」（settings_center.py:122）；儲存鈕在原因空時已 disabled，所以使用者看不到此字串，只看到按鈕變灰（`canConfirm()`，:458-460），**沒有提示為何灰**。
- 只有一位最高管理者時的警告：「目前只有一位最高管理者，沒有第二人可以核准：這項放寬會改為「填寫原因、等 7 天確認期間後生效」，儲存後會留下紀錄。」（settings_registry.py:742，動態天數）。

### 2.8 問題分類
- T1 分類邏輯：**勾（最嚴重）**。47 群組平鋪、依技術元件／註冊順序而非使用者任務；builder_* 12~14 組穿插；備份保留（retention）與「公司資料設定」重疊。證據：settings_center.py:75（無分類欄位）、settings-center.html:84-100（單層清單）、搜尋只比 label/help :365-368。
- T2 用語：勾。「確認期間」「放寬」「建構器治理」「版本帳本」「影子」「MS2 版」「最高管理者」。證據：settings-center.html:97、settings_groups.py:675/445。
- T3 填寫方式：勾。YYYYMM 手打（quote_backfill）、逗號清單（bank_alias_*）、含 `{items}` `{group}` 的範本字串（quote_alt.note_template）、用 0 表示永久（retention）。證據：settings_groups.py:1069/479/187/56。
- T4 缺預設值：基本沒問題（SettingDef 強制有 default＋recommended；"預設組"空是另一個缺口）。證據：settings_registry.py:SettingDef 初始化檢查 default。
- T5 驗證／錯誤訊息：勾（見 2.7）。證據：settings-center.html:351「操作失敗（」+status+「）」；settings_registry.py:372「跨欄位檢查失敗：%s」。
- T6 危險設定未分層：部分做得好（有 risk／loosen／banner／確認期間），但同一清單內「改檔名用語」與「縮短稽核紀錄保存年限」「放寬誰可認列採購單」視覺地位相同，只靠欄位內橫幅；且 retention 的 5 個高影響欄位被標為「進階」收起、不顯眼。證據：settings_groups.py:63-67（audit_log_keep_days risk=legal）與 :55（週備份 advanced）。另：對一般小公司，「每個設定都要寫原因」＋「放寬要第二位管理者」在只有一位管理者時退化為等 7 天，使用者不理解為何儲存後沒生效（storage 訊息 settings-center.html:472）。

## 5. LINE／備份／心跳／授權：設定落點與使用者需填的東西

### 5.1 LINE（落在「通知設定」頁 notification-settings.html:337-414，非設定中心）
- 位置：系統 > 通知設定 > 卡片「LINE 通知」（id=line-panel）；API `/api/settings/line-notify`（BE/routers/system.py:2681 起，僅最高管理者；非超管看到「LINE 通知設定只有最高管理者可以查看與修改。」）。
- 要填：
  1. 「啟用 LINE 通知」勾選（預設關）
  2. 「Channel access token（Messaging API，長效）」password，placeholder「貼上 LINE Developers → Messaging API → Channel access token」；已存值顯示圓點、不動即保留
  3. 「對外網址（LINE 綁定回調用；沒有就留空）」text，placeholder「https://網域（不含路徑）」；頁面再顯示要貼進 LINE 的「Callback URL」`<code>`
  4. 「LINE Login channel（讓同仁自己綁定 LINE 用）」：Channel ID（純數字）、Channel secret（32 位英數字）；說明「必須與上面的 Messaging API channel 在同一個 Provider，且狀態是 Published」
  5. 「LINE 訊息帶連結」勾選（預設關；警告「開啟會讓外部網路連到系統頁面，需先與網路管理確認」）
  6. 「同時發 LINE 的通知」逐事件勾選（即時生效）
  7. 按鈕「儲存 LINE 設定」「驗證 token」
- 工程用語：token、channel、Messaging API、LINE Developers、Provider、Published、Callback URL、public_base_url（label 已改白話「對外網址」）、secret。
- 錯誤字串（system.py:~2725-2760）：「channel access token 格式不正確：只能是英數與 + / = . _ -，長度 20～512，請從 LINE Developers 重新複製」「LINE Login 的 Channel ID 格式不正確（應為純數字，請從 LINE Developers 的 Basic settings 複製）」「LINE Login 的 Channel secret 格式不正確（應為 32 位英數字，請從 LINE Developers 重新複製）」「include_links 必須是 true／false」（鍵名外露）；驗證成功「token 有效：{name}；本月已用 N / 上限」、失敗「驗證失敗（請先儲存 token）」。
- 另外每位同仁要到「帳號安全」頁自行綁定（notification-settings.html:379）。
- 評價：需要申請 LINE 官方帳號＋兩個 channel＋Cloudflare Tunnel（`/api/line/callback` 為唯一對外路徑，system.py:2787 註解）——完全是 IT 作業，應走「安裝人員代設」或精靈。

### 5.2 備份
- 保留天數：兩處可改——設定中心「保存期限」（8 欄）與公司資料設定「備份保留天數」卡（6 欄）；經同一註冊表（system.py:2332）。總覽卡「備份與保留」連結壞（錨點 #backup 不存在）。
- 備份目標（本機／S3）、PDF 根目錄：公司資料設定卡 9、11；上傳檔／報價單 PDF／備份存放位置與容量：「儲存位置」storage-settings.html（卡「儲存位置」desc：上傳檔、報價單 PDF 與備份存放的位置與容量；欄位由他人盤點）。
- 排程（每日備份幾點跑）：無 UI，由 Windows 工作排程器（deploy_dashboard.html 步驟「停用三個排程工作（自動啟動、每日備份、心跳）」，BE/tools/deploy_dashboard.html:342）。備份失敗告警：BE/helpers/system_checks.py、backup_alerts 目錄（沒有設定頁）。
- 一般人缺的：「最近一次備份何時成功」「如何還原」——總覽卡描述有承諾（system_hub_l1.json:43）但頁面無；DR-SOP.md 為文件。

### 5.3 心跳（heartbeat）
- 無任何畫面。設定檔 `backend/heartbeat_config.json` 的 `ping_url`（core/paths.py:99；heartbeat_job.py:71-76），由 Windows 排程每 5 分鐘執行 `heartbeat_job.py`，向外部 dead-man's-switch（如 healthchecks.io）打卡；`ping_url` 為空時只檢查本機（heartbeat_job.py:118 日誌「heartbeat_config.json ping_url 尚未設定，僅檢查本機服務，不對外打卡」）。
- 使用者要做：手動編輯 JSON 檔填網址（工程作業）。設定中心沒有此群組。與「在線時數」「編輯在線（edit-presence heartbeat，routers/system.py:3333，不同功能同名）」易混。
- 建議：總覽新增「系統健康／離線告警」白話卡：填通知 Email 或 LINE，後台代設 ping_url；平常只顯示「最後正常回報時間」。

### 5.4 授權（license）
- 無輸入畫面。授權金鑰是檔案 `backend/license.key`（core/paths.py:100；helpers/licensing.py:61），內容為 base64(JSON＋Ed25519 簽章)，含 customer／tax_id／machine／modules／issued／expires；完全離線驗證。
- 唯一可見處：「模組管理」module-settings.html（狀態「未授權」黃標 `.ms-state--unlicensed`、備註「…（開發模式）：所有模組一律可載入，沒有檢查授權金鑰。」:62-65）；`GET /api/license/status`（routers/licensing.py:19）任何登入者可讀（回 valid／reason／days_left…）。
- 到期提醒在設定中心「到期預警」：欄位「確認檔到期提醒天數」，題目「開發者簽章確認檔到期前幾天，要開始在系統中心提醒？」（settings_groups.py:922 起）——「開發者簽章確認檔」是另一種檔，與 license.key 名稱不同，使用者難以分辨「授權」「確認檔」「開發者確認檔」。
- 使用者要做：把廠商給的 license.key 放到伺服器指定資料夾（無「匯入授權」上傳鈕，也無「授權到期日」總覽）。建議新增「授權」頁：顯示客戶、到期日、模組，並提供「匯入授權檔」。
