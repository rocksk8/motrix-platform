## 0. 導覽與分類的現況（影響這 7 頁的共通事實）

- 頂部導覽的「系統」群組實際只顯示一個連結：sidebar.js:755-760 `_collapseHub`，群組有 hub 項時「導覽列只留這一個連結」，點進 `system-hub.html`。系統中心用 B/core/system_hub.py:29-36 的 8 個分區：帳號與權限／簽核與流程／通知與信件／資料與備份／稽核與紀錄／公司與參數設定／模組與擴充／系統狀態與版本。
- 但 menu_l1.json 的 system 群組（+模組 module.json）實際仍有 24 項，依「order」數字排，沒有分區：模組建構器(5)、支出申請類型(6)、匯款款別設定(7，來自 subcontract/module.json:62)、使用者管理(10)、職責角色(11)、組織架構設定(20)、簽核設定(30)…（menu_l1.json:134-215）。所有本批 7 頁 perm 都是 `"superadmin"`。
- 本批 7 頁在系統中心的分區（system_hub_l1.json）：
  - 帳號與權限：使用者管理、職責角色、權限設定(permission-matrix)、組織架構設定、簽核代理人
  - 簽核與流程：簽核設定、支出申請類型、匯款款別設定（subcontract/module.json system_cards）
  - 模組與擴充：模組管理、模組建構器
  → 組織架構(簽核人來源)與簽核設定被拆在兩個分區；「權限」同時散在使用者管理／職責角色／權限設定三頁。
- 頁頭統一眉標寫「系統設定」（各頁 `pg__eyebrow`），沒有「第一次設定」「建議順序」的導引。grep 只找到 company-setup-required.html（公司資料）有類似引導，沒有針對人員／權限／簽核的精靈。

### 權限在使用者眼前的表達方式（彙整）
同一件事「某人能做什麼」現在有 **6 個互相疊加的概念**，分散 4 頁：
1. 基礎類別／角色層級：6 個固定代碼 superadmin/admin/sales/engineer/finance/viewer（B/helpers/auth.py:160 `VALID_ROLES`）。users.html:562-570 下拉；duty-roles.html:119、124 直接把 `u.role` 原碼印出來。
2. 角色名稱設定：可改 6 個代碼的顯示名（users.html:252-299），但每格標籤印的是英文代碼 `superadmin / admin / sales / engineer / finance / viewer`（users.html:268、272、276、280、284、288）。
3. 自訂角色（users.html:207-249、761-832）：只是「快速套用」按鈕，套用時把模組勾選複製到個人勾選（users.html:1078-1086 `applyPreset`/`applyCustomRole`），之後與範本脫鉤。
4. 存取模組勾選（個人原始勾選，users.html:572-606）：30 個權限鍵，標籤如「出納（標記已匯款/已收款、銀行對帳）」「費用單據（不掛案件的請款／請購／採購／差旅／零用金；新增與編輯）」（B/helpers/module_registry.py:49-80），分 10 大項手風琴（基本/業務/財務/採購/設備/網路架構規劃書/專案/工作/勞務/系統）。
5. 職責角色（duty-roles.html；B/core/migrations.py:420-429 種子 8 個）＋個人扣項。生效權限公式寫在 duty-roles.html:49：「生效權限＝（個人勾選 ∪ 角色權限）− 個人扣項」。
6. 權限設定（permission-matrix.html，L2 模組 permmatrix）：角色×功能×動作矩陣，頁面標「角色與功能／個人／待生效／調整紀錄」四頁籤（permission-matrix.html:198）。

另外「模組」一詞有兩個意思：users.html 的「存取模組」＝權限鍵（如「儀表板」「報價單／簽核佇列」）；「模組管理」＝安裝包裡的軟體套件（會計、案件、外包工班…15 個，module.json）。兩者名稱相同、內容不同。

角色名稱是否以英文代碼顯示：
- 使用者清單、下拉：用中文標籤（可改名）— 良好。
- 職責角色「角色」表：`（r.key + ・系統預設）` 如「（finance・系統預設）」（duty-roles.html:75）→ 英文代碼；「使用者綁定」表「基礎類別」欄印 `u.role`（:124）→ 英文代碼；頂部說明印高敏感權限鍵原碼（:54）。
- 簽核設定頁的簽核人 `roleLabel()` 只對照 4 種角色，engineer、finance 會直接顯示英文代碼（approval-settings.html:1103-1105；角色徽章 CSS 也只有 4 色 :112-115）。

- 儲存按鈕分散：簽核設定每卡一顆＋套用範圍一顆；expense-types 草稿＋發布；users 一次存檔觸發多個 API（users-duty.js 註解：「沒有跨 API 交易：任何一步失敗就停下，並明講「已完成／未完成」」）。

### 8.3 「第一次買系統的老闆：公司有哪些人、各自能看什麼、誰簽核誰」現況流程

現況（需走的頁面與順序，依各頁相依性推出）：
1. 公司資料設定（company-profile-settings，非本批）— 否則有些功能被擋（company-setup-required.html）。
2. 組織架構設定（org-structure）：先建「處」→再建「部門」（部門必須選所屬處，org-structure.html:407-413）。卡點：小公司沒有「處」概念；主管欄標示「先預留」，使用者不知道必須設。
3. 使用者管理 → 新增使用者：填帳號／顯示名稱／密碼；選處／部門；選「角色快速套用」＋「角色層級」＋勾 30 個存取模組。卡點：
   a. 此時還沒有職責角色可選（新增視窗不顯示，users.html:608）。
   b. 不知道哪個範本適合；「sales」是預設。
   c. 帳號 英數字（無驗證）、對方首次登入被迫改密碼但未告知。
4. 回到使用者管理 →「編輯」同一個人 → 才看得到「職責角色與個人扣項」，勾選、可能需填變更原因（高敏感）。若要確認「為什麼這人能做 X」，要跳到「權限設定」(permission-matrix)。
5. 回到組織架構設定：指定處／部門主管（下拉只列已存在的使用者，所以必須在步驟 3 之後）。卡點：與步驟 2 順序顛倒；且標示「未來使用」。
6. 簽核設定：保留預設「申請人組織主管自動簽核」即可；若需特殊流程要懂「統一／獨立」；挑簽核人（人員下拉）。卡點：若未完成 2、5，任一單據送審會被擋（「申請人尚未歸屬任何部門，請聯絡管理員設定部門後才能送審」tiered_approval.py:224；「…尚未指定主管…請聯絡管理員先設定部門主管」）。
7. 若有費用單據：支出申請類型（發布）、匯款款別設定（發布）、簽核設定中對應單據。
8. 模組管理：確認買的功能是否已啟用（重啟後生效，本頁不能重啟）。

順序卡點總結：組織→人→主管→簽核有 4 個迴圈（組織需要人、人需要組織、簽核需要主管）；權限要在 3 個頁面（使用者／職責角色／權限設定）拼湊；沒有「設定完成度」檢視，直到第一張單據送審失敗才知道缺主管。

### 8.4 建議：以任務重新串起來

「公司設定精靈」（首次進入系統中心自動出現，之後可重跑）：
1. 公司有哪些部門？（預設一層「全公司」；可加部門；不要求「處」）
2. 加入員工（姓名、登入帳號、Email；一次可貼多筆）→ 每人選「職務」（職務範本＝現有職責角色 + 自訂角色合併，如「老闆／業務／工程／財務／採購／行政」，中文名稱，不見英文代碼）→ 自動帶出「可使用功能」預覽（中文清單，高風險項目用紅色標「可看金額」「可付款」）。
3. 誰是主管？（每個部門選一位，預設老闆）→ 自動作為簽核第一關。
4. 誰簽核什麼？（以「報價單／請款／出貨／匯款…」為列，下拉選「部門主管／老闆／指定人員／某職務」，預設「部門主管 → 老闆」）。進階：每種單據是否獨立。
5. 完成檢查：列出「沒有部門的人」「沒有主管的部門」「沒有人持有財務職務」等缺口，並一鍵修復。

各頁調整對應：
- 使用者管理：新增視窗內直接含「職務」與「部門」；把「角色層級／存取模組／個人扣項／職責角色」收進「進階權限」；刪除角色名稱設定、解鎖密碼、案件角色未對應等區塊到各自頁面。
- 職責角色＋自訂角色＋權限設定：合併為「職務與權限」一頁；內建範本中文化（例如把「管理員（過渡）」「系統管理…不含任何金額鍵」改為業務說明）。
- 組織架構：可只有一層；主管欄說明「這位會成為預設簽核人」。
- 簽核設定：以單據為列、以「誰簽」為欄；統一／獨立降為進階；簽核人可選職務；頁頂顯示組織缺口警示。
- 模組管理：改名「已購買功能」，只顯示名稱＋狀態＋一句話；啟停按鈕附影響說明；重啟需求由系統自行處理或明講聯絡人。
- 支出申請類型／匯款款別：改名「申請單設定」「付款款別」；代碼隱藏；欄位用中文；以「儲存」取代「草稿／發布」雙段（保留版本在進階）；「出貨範本」改「系統內建範本」。
