# 可見範圍收緊（第 49 班；使用者經 node-d8 於 2026-10-09 表單裁示）

分支 `wip/t49-b5-visibility`（基底 origin/platform 9dcb24ce7）。兩項**收緊**（有人原本看得到、之後看不到），上線備註與驗收項如下。

## 1. 網路架構規劃書：加逐案權限
- 範圍：`GET /api/network-plans`（清單）、`GET /api/network-plans/{id}`；盤點時發現同一份資料還有 Excel／PDF 匯出、拓樸預覽、個資告知查詢，其中匯出與預覽原本**只驗登入**（任何登入者可匯出任一份）——一併收緊（套同一道規則＋要規劃書讀取模組）。
- 規則（與既有 `GET /api/quotations/{案件}/network-plan` 相同）：綁定案件的規劃書，只有該案業務／協作者、admin 以上、持 `case_manage` 者看得到；其他人清單不列、單筆／匯出 404（看不到＝不存在）。沒綁案件的獨立規劃書不受影響。案件模組不在 ⇒ 綁案件的規劃書只給 admin 以上。
- 誰會變：只有 `netplan`／`netplan_edit` 模組、但不是該案業務且沒有 `case_manage` 的人（例：別位業務、工程師）——原本看得到全公司規劃書，之後只看得到自己案件的與獨立的。
- 上線備註：使用者若問「我的規劃書不見了」⇒ 確認他是否為該案業務／協作者，或請管理員把他加入案件協作者／給 `case_manage`。

## 2. 外包名冊下拉：限權
- `GET /api/contractors/selectable`（id／姓名／電話）原本所有登入者可讀；現在限最高管理者、財務角色，或持 procurement／case_manage／contractor_list／payslip 任一模組者；其他 403。
- 前端盤點：唯一呼叫者是 `frontend/js/case-management-dispatch.js::loadVendors`（案件管理頁載入時呼叫）。案件管理頁本來就要求 `case_manage`（沒有則顯示「沒有這個頁面的權限」），所以**沒有任何角色的頁面因此壞掉**（勞報單表單用的是 `/api/contractors`，不受影響；報價單、每日工作等頁沒有呼叫）。前端另加防線：session 沒有上述模組就不送請求。
- 上線備註：若有外部腳本用一般帳號讀這支，會收到 403。

## 驗收項（使用者）
1. 一位只有 `netplan` 模組、不是某案業務的人：規劃書清單看不到綁在那案的規劃書，直接開網址或匯出 Excel／PDF 都顯示找不到；該案業務本人、admin、最高管理者、`case_manage` 人員都看得到。
2. 獨立（沒綁案件）的規劃書，所有有規劃書權限的人照舊看得到。
3. 只有 quotation 權限的人沒有任何頁面出現紅字／空白（案件管理頁本來就開不了）；`case_manage` 人員在案件頁派發表單的「外包名單人員」下拉仍可選人；財務角色與最高管理者同。
4. 沒有任何規劃書模組的帳號打匯出網址 ⇒ 403。
