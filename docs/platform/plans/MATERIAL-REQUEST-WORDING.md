# 「材料申請」用字表（使用者 2026-10-02 裁示，第 32 班改字）

使用者裁示：
1. 「叫料」一律改稱 **「材料申請」**（不再有「叫料單」這個詞）。
2. 原提示「需先連結一張已核准的叫料單」改成「需先申請請購單，再申請採購單，採購單通過後可對應此單」這類字樣；詳細用字由主持先提供（本檔）。

## 提示語（原「需先連結一張已核准的叫料單」）
- 勾「已叫料／已到料」旗標被擋時（`case-management-exec.js` 的 `_moFlagBlockReason` 類函式）：
  - 尚無請購單／採購單連結：**「需先申請請購單，再申請採購單；採購單通過後，才能對應這筆材料申請。」**
  - 已連結採購單但還沒通過：**「採購單尚未通過，通過後才能對應這筆材料申請。」**
  - 連結的採購單被退回／作廢：**「對應的採購單已退回（或作廢），請重新申請採購單。」**
  - 材料申請本身還沒核准：**「這筆材料申請還沒核准。」**
- 彈性路徑（報價單沒有的品項、或未走請購／採購者）的標註：**「該材料申請未申請採購單」**（取代規格中的「該叫料未申請採購單」）。
- 取消：**「取消已核准的材料申請需要填原因（會留稽核紀錄）：」**；成功訊息 **「材料申請已取消」**。
- 隱私告知勾選：**「已告知收款人」**（不變）。

## 邏輯待確認（不在本班改，先記）
提示語暗示「材料申請的物流旗標要對應已通過的採購單」。目前（第 31 包）旗標的閘是「對應一張已核准的材料申請」（31-C 審核疊加表），而不是採購單。第 32 班 S4 的規格仍是「不強制連請購／採購、未連者標註」。若使用者要把旗標閘改成「必須對應已通過的採購單」，是行為變更，需要使用者另行裁示；**本班只改字，不改閘的邏輯**。
