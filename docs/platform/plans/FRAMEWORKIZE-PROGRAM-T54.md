## 1. 完成的定義（DONE）

全部成立才算「跑完」：
1. **沒有寫死的業務值／規則／名單／角色字串**，除了使用者逐項確認的「鎖定清單」（暫列項目見設計稿附錄 B；未確認者仍視為待解鎖，不算完成）。
2. **每個可改的東西在系統內都有頁面**（「系統」樞紐可達），改動必填原因、寫稽核、留版本可還原、可看差異；高風險項再加 24 小時待生效＋通知。
3. **預設＝今天的行為**，每個框架化項目有等值閘門（凍結基準＋等值測試）；部署不寫資料列。
4. **棘輪債務歸零**：`FRAMEWORKIZE-DEBT-T54.md` 所有列為 `done` 或 `locked`（使用者確認）；守門禁止新增。
5. **管理者操作手冊**（每個框架一份）：能改什麼、在哪改、風險與後果、如何還原；由登錄自動產生欄位說明，再補白話文。
6. **白話圖形介面**（使用者 2026-10-10 UX 核心規則）：所有編輯／設定頁只給選項（勾選、開關、下拉、單選），每項有繁中標籤、一行說明，高風險加白話風險提示；**畫面不出現代碼、內部鍵、id、列舉字（如 allow／forbid／in_bin、能力鍵、單據代碼當標籤）**。登錄結構強制要有中文標籤／說明／選項標籤／風險文字，缺就驗證失敗；守門測試掃描產生的頁面字串（正反對照）。
6b. **零技術門檻**（使用者 2026-10-10 強化）：每個設定畫面都當使用者完全不懂技術來設計——①用白話中文**問問題**、選項很少（「財務可以送出勞報單嗎？　可以／不可以」），不放鍵值表；②標出**建議**選項；③常見情境給一鍵**預設組**（如「小型公司」「嚴格管控」），套用前先顯示會造成的效果；④進階選項收在「進階」；⑤複雜設定做成一步一步的精靈；⑥儲存前用一句話摘要（「你即將讓財務可以送出勞報單，24 小時後生效」）並預覽受影響的人；⑦一鍵復原。
6c. **每個選項旁邊都說明「會影響什麼」**（使用者 2026-10-10）：每個欄位與每個選項宣告白話**影響說明**（`impact`）——影響哪些頁面、單據、人；只影響之後的單據還是連既有的也改；能否復原；何時生效；風險提示。可再宣告**即時影響函式**（唯讀查庫回數字，例「會影響 12 張未精算報價單、5 位使用者」；有快取與時限，失敗只顯示靜態說明）。畫面在選項旁放影響面板（切換選項即更新，前後對照），並重複在儲存前的一句話摘要。登錄項目缺影響說明 ⇒ 驗證失敗。
7. 驗收演練：以一份「只改設定、不改程式」的變更清單（調門檻、加類別、改簽核人、改編號前綴、改保存年限）在測試庫完整走一遍並全綠。

## 4. 仍然需要改程式的事（誠實版）

「以後都在系統內改」成立的範圍是**值、規則、名單、對象、版式與選項**。下列仍需要程式變更，並非框架化失敗：
1. **新的能力種類**：例如新的權限能力類型、新的通知管道、新的設定欄位型別（日期區間、金額分段表等）——框架提供「新增一個欄位」的低成本路徑（一個 `SettingDef`），但那一行仍是程式。
2. **新單據類型的結構**（欄位、計算式、與帳務的連動）：自訂模組（定義庫）能涵蓋文件式單據，涉及金流的新計算仍要程式。
3. **計算公式本身**（利潤、稅額、扣繳、進位）：參數可改、公式不可（公式變更是法規或會計決策，需測試與遷移）。
4. **安全修補與依賴更新**、效能與資料庫結構（schema）變更、遷移。
5. **新的外部整合**（新的銀行、電子發票平台、API）。
6. **鎖定清單**中使用者決定不解鎖的項目（密碼雜湊強度下限、稽核不可竄改、簽章與路徑檢查等）。
7. **框架本身的演進**（例：待生效改為雙人核准、設定的環境差異化）。

對使用者的說法：**日常營運與組織變化不再需要改程式；新能力與法規「公式」變化仍需要開發，但多數法規「數字」變化不用。**

**合併的條件與風險控制**
1. **每個框架各自獨立的功能旗標＋「全部回到程式預設」的逃生口**（`MOTRIX_SETTINGS_DEFAULTS_ONLY=1` 已有）；合併班變大不等於一次全開。
2. **部署零行為變更的凍結基準**每個框架一份（Train A 的 `settings_deploy_baseline.json` 是樣板）；基準測試不通過不得入班。
3. **各框架的作者自己的分支，整合者只做合併**（沿用既有列車規矩）；遷移、manifest、CHANGELOG 用「(next) 佔位＋列車取號」，避免合併衝突。
4. **測試時間**：合併班測試量加大 ⇒ 沿用測試影響分析與預跑（PLAYBOOK §G）；同一台機器上同時只有一個官方閘門在跑，作者的全跑等閘門結束再跑（安靜規則）。
5. **風險最高的兩個框架（F3 權限矩陣、F5 狀態碼）不放同一班**，M1 放 F3、M2 放 F5。M1 同時有 F3 與 S1 編輯 UI，**隔離方式**：F3 與 F2 各有獨立旗標；`MOTRIX_SETTINGS_DEFAULTS_ONLY=1` 讓設定全回程式預設；F3 預設樣板＝今天的角色權限（等值證明）且可一鍵關閉回舊判斷；S1 編輯 UI 只讀寫設定中心自己的群組，不依賴 F3 的新能力檢查（superadmin 閘）。F3 延誤時整個 F3 順延到 M2，其餘照出，**不互相卡班**。
6. 若 M1 因 F3 延誤：F1／F2／F4／F11 可先出（獨立於 F3），F3 順延到 M2——**框架之間靠介面解耦，不互相卡班**。
