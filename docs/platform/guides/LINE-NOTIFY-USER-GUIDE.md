## 0. 先搞懂三件事（30 秒版）

1. **LINE 是獨立通道，不依附 Email**（2026-11-12 起）：系統依每種通知的「收件人設定」決定這件事該通知哪些人，**Email 與 LINE 各自發送、各自失敗、互不影響**。沒有 Email、退訂了 Email、或該種信件被整個關掉的人，只要綁定了 LINE 一樣收得到；反過來，Email 照寄給有 Email 的人，不論他有沒有綁 LINE。同一個人兩邊都有，就兩邊都收。
2. 寄信的通知（簽核、指派、業務開發更新、案件、系統告警…，見第 3 節）都**可以**發 LINE，但預設**全部不發**，要最高管理者自己逐項勾；**每一種通知誰要收，也由最高管理者決定**（預設照原本的收件人，也能另外指定角色或個人，見 2.3）。獎金、薪資、勞報單類不提供 LINE。
3. 每個人要自己**綁定**一次 LINE（電腦按按鈕、手機掃 QR），沒綁就收不到。

## 1. 一般使用者：把自己的帳號綁定 LINE

### 1.1 前提（管理者先確認）

「LINE 通知」卡片只有在管理者已經填好 **LINE Login 的 Channel ID／Channel secret** 和 **對外網址** 之後才會出現在使用者畫面。使用者說「找不到綁定按鈕」，先查這個（第 5 節）。

### 1.2 步驟（使用者在**電腦**上操作，再用**手機**掃）

1. 在電腦登入系統。
2. 按畫面右上角頂欄的 **「修改密碼」** 按鈕，進入頁面（頁面標題也是「修改密碼」）。
   - 注意：管理者設定頁的說明文字把這一頁叫做「帳號安全」頁，但畫面上**實際看到的名稱是「修改密碼」**。兩者是同一頁。**待確認**：是否要把畫面用語統一。
3. 往下找到名為 **「LINE 通知」** 的卡片（右上角有標籤，沒綁的時候顯示 **「未綁定」**，綁了顯示 **「已綁定」**）。
4. 按 **「綁定 LINE」** 按鈕（按下去會短暫顯示「產生中…」）。
5. 卡片上會出現一個 **QR code**，下方提示：「請用手機的相機或 LINE 掃描上方 QR，在手機上按『同意』。10 分鐘內有效；完成後這裡會自動更新。」
6. 用**手機**的相機或 LINE 掃描該 QR → 跳到 LINE 的授權畫面 → 按「同意」。
7. 同意之後，LINE 會接著問**要不要加入官方帳號為好友**（系統在授權網址上帶了「同意後詢問加好友」的參數）。請**加入好友**——沒加好友就收不到通知。LINE 上這個詢問畫面的實際按鈕文字：**待確認**（LINE 端畫面，程式碼裡沒有）。

### 1.3 綁定成功會看到什麼（共三處確認）

| 地方 | 看到的內容 |
|---|---|
| **手機瀏覽器**（LINE 導回的頁面） | 標題「**綁定完成**」，內文「已完成綁定，可以關閉這個頁面。之後您勾選的通知會送到這個 LINE。」 |
| **電腦的「LINE 通知」卡片**（約 3 秒輪詢一次，自動更新） | 綠色提示「**綁定完成**」；右上標籤變成「**已綁定**」；下方出現「綁定時間：…」 |
| **手機 LINE 聊天室**（官方帳號傳來一則） | 「MOTRIX 通知已綁定完成，之後會在這裡收到您勾選的通知。」 |

**如果電腦卡片出現紅字**：「已綁定，但測試訊息沒有送達。常見原因：LINE Login 與 Messaging API 不在同一個 Provider。請通知管理員檢查。」
→ 代表綁定資料存進去了，但系統推不出訊息給這個 LINE 帳號。多半是兩個 LINE channel 不在同一個 Provider（建好之後不能搬，只能刪掉重建），要管理者處理。

### 1.4 綁定的規則（使用者常問的）

- QR **10 分鐘內有效、只能用一次**（逾時電腦會顯示「綁定已逾時，請重新操作」）。
- 綁定的是「**按下按鈕那台電腦上登入的帳號**」，掃 QR 的手機不需要登入系統。所以 **QR 等於你的綁定權限，不要截圖、不要傳給別人**。如果發現不是你本人的手機完成了綁定，馬上按「解除綁定」。
- 掃碼之前電腦如果**登出了**，綁定會失敗，重按一次即可。
- 按太快會顯示「請稍候幾秒再按一次」（同一個人兩次發起至少隔 3 秒）。
- 一個 LINE 帳號只能綁在一個系統帳號上；已綁在別的帳號會顯示「綁定失敗」。
- 已綁定時，按鈕文字變成 **「重新綁定」**（換手機、換 LINE 帳號時用）。
- 系統只取得 LINE 帳號的識別碼，**不取暱稱、頭像**。
- 電腦上按「取消」可放棄這次 QR。

### 1.5 手機端可能看到的錯誤頁（逐字）

| 頁面標題 | 內文 | 怎麼辦 |
|---|---|---|
| 已取消 | 您已取消綁定。需要時請回到電腦重新操作。 | 在 LINE 按了取消；重按「綁定 LINE」 |
| 已逾時 | 綁定要求已逾時，請回到電腦重新按「綁定 LINE」。 | 超過 10 分鐘 |
| 連結無效 | 這個綁定連結無效或已使用過，請回到電腦重新按「綁定 LINE」。 | QR 掃第二次、或伺服器重啟過（綁定中的 QR 存在記憶體，重啟即失效） |
| 無法綁定 | 電腦端已登出或帳號狀態已改變，請重新登入後再綁定。 | 重新登入再綁 |
| 綁定失敗 | 綁定沒有成功，請回到電腦重新操作；若持續失敗請通知管理員。 | LINE 端驗證失敗、連不到 LINE、或這個 LINE 已綁別人 |
| 請稍後再試 | 目前要求太多，請稍後再試。 | 系統對外查詢保護，稍等再試 |

另外，如果掃 QR 後**停在 LINE 自己的錯誤頁**（不是上面這些頁）→ 多半是 LINE Developers 的 Callback URL 與系統設定不一致，或 LINE Login channel 還是「Developing」狀態（只有 channel 管理者與測試者能登入），屬管理者設定問題（見第 5 節）。

## 2. 管理員：設定「哪些人收哪些通知」、靜音

> **誰能用**：「通知設定」頁的 LINE 設定**只有最高管理者**能看與改。其他角色進去會看到「LINE 通知設定只有最高管理者可以查看與修改。」

### 2.1 頁面位置

左側選單 **「系統」** 群組 → **「通知設定」**（也可從系統設定總覽的「通知設定」進入）→ 頁面中的 **「LINE 通知」** 卡片。

### 2.2 卡片由上到下的欄位（逐字）

| 欄位／按鈕 | 作用 |
|---|---|
| **本月 LINE 訊息用量**（用量條＋「重新整理」鈕） | 見第 4 節 |
| **用量告警門檻（%，逗號分隔，最多 5 個）** | 見第 4 節 |
| **啟用 LINE 通知**（勾選；旁邊顯示「(目前關閉)」或「(已啟用)」） | **總開關**。取消勾選＝整個公司停發 LINE（Email 不受影響） |
| **Channel access token（Messaging API，長效）** | 已存的 token 顯示成圓點，不改請保持不動 |
| **對外網址（LINE 綁定回調用；沒有就留空）** | 只填網域，不含路徑；下方會顯示要貼到 LINE Login 的 Callback URL |
| **LINE Login channel（讓同仁自己綁定 LINE 用）** | Channel ID＋Channel secret |
| **LINE 訊息帶連結**（勾選） | 預設關閉；開了會讓外部網路連到系統頁面，要先與網路管理確認 |
| **LINE 綁定狀況** | 在職同仁誰已綁定、誰還沒；可一鍵提醒未綁定的人（見 2.5） |
| **要發 LINE 的通知（依模組分組）**（事件清單） | 每個模組一個可收合的區塊，標題顯示「已開 N／共 M」；預設只展開「報價單與簽核」。每項有核取方塊、標籤（「僅 LINE」「LINE 細項」「重要」）、收件摘要與「設定誰要發」，見 2.3 |
| **儲存 LINE 設定**、**驗證 token** 按鈕 | 儲存後按「驗證 token」，成功會顯示官方帳號名稱與本月用量 |

### 2.3 「角色＋個人勾選」怎麼用

規則是**由大到小逐層只縮不擴**，最後實際收到 LINE 的人 ＝

> 該通知的業務收件人（事件相關人員＋「信件與通知收件設定」的收件人設定；**不看 Email、不看 Email 退訂**）∩ 該通知類型勾選的「可收的角色」 ∩ 本人沒有退訂 LINE ∩ 已綁定 LINE ∩ 帳號啟用中

**第一層：公司開關（最高管理者）**
在「同時發 LINE 的通知」清單，每種通知有一個核取方塊，**勾選＝這種通知同時發 LINE，立即生效**（畫面會顯示「已開啟：…／已關閉：…」）。預設全部不勾。

**第二層：可收的角色（最高管理者）**
每種通知下方有一行 **「原本的收件人中，可收的角色：」**，列出六個角色核取方塊：**最高管理者、管理員、業務、工程師、檢視者、財務**。
- 預設六個全勾（＝所有角色，沿用現況）。
- 取消某個角色＝該角色的人**不會收到這種通知的 LINE**（Email 不受影響）；點完立即生效，顯示「已更新『…』可收的角色」。
- 全部取消＝這種通知沒有任何角色收 LINE。
- 這一層設定壞掉時，系統為了不誤推別人，會當成「沒有任何角色允許」。

**指定誰要發（最高管理者；2026-11-13 新增）**
每種通知下方還有一行摘要（例如「收件人：照原本的設定」）與 **「設定誰要發」** 按鈕，按下去可以選：

| 選項 | 意思 |
|---|---|
| **照原本的收件人（預設）** | 就是第 3.2 節講的業務收件人（事件相關人員＋群組），再套上面的「可收的角色」 |
| **原本的收件人，再加上指定的角色／人員** | 在原本收件人之外，另外加上你勾選的角色（該角色所有在職同仁）與你加入的個人（下拉選單選人；清單會註明「尚未綁定」） |
| **只發給指定的角色／人員** | 原本的收件人不收，只有你指定的人收 |

- **你指定的人，不受上面「可收的角色」限制**（那一列只用來縮小「原本的收件人」）。
- 本人在自己頁面關閉的通知，**即使被你指定也不會收到**（chip 上會標「已自行關閉」）；離職或還沒綁定 LINE 的人收不到（標「已離職」「尚未綁定」）。
- 被你指定的人會在自己「修改密碼」頁的「我要收的 LINE 通知」看到這一項（可以自己關掉）。
- 這個設定只管 LINE，**不影響 Email**。「僅 LINE」事件與「LINE 細項」事件沒有自己的 Email，它們的「原本收件人」沿用相近的 Email 通知的收件設定。
- 想讓管理員也收到「業務開發案件更新」之類預設只給案件相關人的通知，就選「再加上指定」並勾「管理員」或加入個人。

**第三層：個人勾選（每位同仁自己）**
同仁綁定 LINE 後，在「修改密碼」頁的「LINE 通知」卡片會多一區 **「我要收的 LINE 通知」**（依模組分組），每種通知一個核取方塊（預設全勾＝收）。
- **取消勾選＝不再把這類通知推到自己的 LINE**，旁邊提示「取消勾選後，這類通知不再推播到您的 LINE（Email 不受影響）。」操作後頁面顯示「已取消：…」或「已恢復：…」。
- 這一區**只列「公司已勾選、且我的角色被允許」的類型**；沒列出來＝公司沒開或角色不被允許，不是壞掉。
- 沒綁定時只顯示「綁定 LINE 後，可以在這裡選擇要收哪些通知。」

### 2.4 「靜音」的幾種層級（整理）

| 想達成 | 怎麼做 | 影響範圍 |
|---|---|---|
| 全公司暫停 LINE | 「通知設定」→「LINE 通知」取消勾選「**啟用 LINE 通知**」→「儲存 LINE 設定」 | 所有 LINE；Email 照寄 |
| 某一種通知不發 LINE | 取消該通知的核取方塊（立即生效） | 該類型的 LINE |
| 某個角色不收某種 LINE | 取消該通知下「可收的角色」中的該角色 | 該角色、該類型的 LINE |
| 某個人**要**收某種 LINE（本來不是他的） | 該通知「設定誰要發」→ 選「再加上指定」→ 下拉選單加入這個人 | 只影響 LINE |
| 某個人不收某種 LINE（自己） | 本人在「修改密碼」頁「我要收的 LINE 通知」取消勾選 | 只影響 LINE，Email 不變 |
| 某個人不收該類 Email | 「使用者管理」→ 編輯該使用者 →「Email 通知偏好」取消勾選該類型 | **只影響 Email，LINE 照發**（兩邊各管各的；要連 LINE 也不收，請本人在「我要收的 LINE 通知」取消，或取消該角色的「可收的角色」） |
| 某種信件整個關掉 | 「信件與通知收件設定」頁（最高管理者）：找到該信件類型那一列，取消「**信件**」欄的核取方塊 | **只影響 Email，LINE 照發**——關信件**不會**停 LINE（LINE 有自己的公司開關：要停請到「通知設定」→「LINE 通知」取消該通知的核取方塊）。登入失敗告警的信件關閉被鎖住，不能關 |
| 要改「誰該被通知」（例如只給最高管理者、或另外指定帳號／角色） | 「信件與通知收件設定」頁（最高管理者）的收件模式 | **Email 與 LINE 共用同一份收件人設定**（收件人只有一個來源）；各自再往下過濾（Email 看有沒有 Email 與退訂，LINE 看角色、個人勾選與是否綁定） |
| 停用帳號 | 「使用者管理」停用該使用者 | 兩個通道都不發 |

> 管理員不能代替同仁勾選「我要收的 LINE 通知」（只有本人能改自己的）。

### 2.5 LINE 綁定狀況與「提醒未綁定的人」（2026-11-13 新增；只有最高管理者）

「LINE 通知」卡片裡的 **「LINE 綁定狀況」**：
- 顯示「已綁定 N／在職 M 人（還沒綁定 K 人）」；按 **「看名單」** 展開：每位在職同仁的姓名、角色、LINE 狀態（已綁定〔日期〕／尚未綁定）、上次提醒時間。名單**不顯示 LINE 識別碼與 Email**。
- 按 **「提醒未綁定的人（K 人）」**：系統對每一位未綁定的在職同仁發**系統內通知**，有 Email 的另外寄一封 **Email**，內容是綁定步驟並附連結（連到「我的帳號」的「通知」分頁，`my-account.html?tab=notify`；該頁上線前，這個連結靠「我的帳號」分支的轉址落到原本的「修改密碼」頁）。完成後顯示「已提醒 X 人（系統內通知）；Email Y 人；沒有寄 Email：Z 人；24 小時內已提醒過、略過 W 人」。
  - 同一個人 **24 小時內只提醒一次**，連按不會洗版；已綁定的人不會被提醒。
  - Email 用的是「使用者額外通知」這種信件：公司在「信件與通知收件設定」關閉了它，或同仁自己退訂了，就只發系統內通知（畫面會註明）。
  - 還沒設好「LINE Login channel」與對外網址時按鈕是灰的（同仁目前沒辦法綁），畫面會說明。
- 名單中已綁定的同仁有 **「解除綁定」**（要再按一次「確定」才會執行；換手機、離職時用；操作會寫稽核紀錄）。

## 3. 目前有哪些事件會發 LINE，以及 LINE 獨立通道的規則

### 3.1 哪些通知可以發 LINE

**原則：寄信有的，LINE 都能發**（約 110 種，**預設全關**）；清單依模組分組、簽核優先：

| 分組（設定頁的區塊） | 有哪些 |
|---|---|
| 報價單與簽核 | 待審核、輪到下一層、審核完成、退回、逾期提醒、審核中被編輯、修改版重新送審 |
| 出貨單、請款與開票、承攬商、費用與完工、材料申請、會計、自訂模組 | 各自的「待審核／下一層／完成／退回」 |
| 業務開發 | 案件指派、取消指派、回覆期限調整、停滯與逾期提醒、記錄批示與回覆、刪除／連結異動申請，以及「業務開發更新」細項（新增案件、狀態變更、進度回報、拜訪記錄、記錄審核通過、轉建報價單） |
| 工作事項 | 指派、完成、逾期、區間到期、被編輯 |
| 案件管理、財務提醒、標案雷達 | 階段到期、專案超期、保固到期、結案相關、發票／應付到期、新標案與標案異常 |
| 系統告警 | 備份、心跳、磁碟、憑證、公司資料、登入失敗鎖定、地圖額度 |
| 通知與報表 | 每月營運報表（只通知，不傳附件）、模組新增與異動、額外通知 |

- **不提供 LINE**：獎金、薪資、勞報單類（含日後新增的薪資類通知）；另有兩個技術性例外：「信件設定測試信」（LINE 有自己的「驗證 token」）、「LINE 額度告警」（用 LINE 發會耗額度，維持 Email）。
- **標籤**：「**僅 LINE**」＝這件事原本只有系統內通知、沒有 Email（取消指派、期限調整、批示被回覆、承攬商附件刪除申請），勾選後才會推 LINE，**不會新增 Email**；「**LINE 細項**」＝信件端是同一種「模組新增與異動」，LINE 端拆成可分開勾的項目；「**重要**」＝系統告警，額度保留時照發。
- **優先級**：每一種通知都有優先級。**簽核與指定人員類是一般等級**；系統告警是重要等級（備份、心跳、磁碟、憑證、公司資料、登入失敗鎖定）。
- **預設收件人**：照該通知原本的業務收件人；「審核完成」預設只給申請人；「業務開發更新」細項預設只給**案件相關人**（業務＋企劃＋被指派人＋建立者，操作者本人除外），拜訪與進度回報等預設都是關的。要改請用 2.3 的「設定誰要發」。
- **內容**：只放單號、名稱、日期這類識別資訊，**不含金額、也不含自由文字**（退回說明、報告內文、備註、批示內容都不傳）；預設**不帶連結**。細節請登入系統看。
- 舊版的「3 個事件」（報價單審核中被編輯、設備保固即將到期、登入失敗鎖定告警）仍在，屬於上表的分組，規則不變：

| 勾選清單上的名稱 | 內部代號 | 什麼時候發 | 業務收件人（Email 與 LINE 共用；各自再過濾） |
|---|---|---|---|
| **報價單審核中被簽核人編輯** | `approval_review_edit` | 報價單在審核中被簽核人改了內容、存檔成功後 | 送審人 ＋ 全部最高管理者 |
| **設備保固即將到期** | `warranty_expiry` | 每日檢查發現設備保固將到期 | 事件收件人＝該案業務負責人；群組＝管理員（群組實際包含哪些角色以「信件與通知收件設定」頁為準，**待確認**）。每個提醒階段（緊急／提早）、每台設備**各推一次**（設備以序號／MAC／名稱識別，與「已通知」記號同一個值；同一張單的兩台同名設備算兩台，各推各的），不會因為信件重試而天天重推 |
| **登入失敗鎖定告警** | `auth_lockout` | 某個來源連續登入失敗 5 次、被鎖定 15 分鐘的那一刻（同一個來源在鎖定期間只通知一次；全系統每小時最多 10 則、**每天最多 20 則**，超過的合併成一則摘要，等視窗有空位才送；兩個上限都能調，見 3.3） | 預設＝最高管理者（可在「信件與通知收件設定」改成只給最高管理者／指定帳號與角色）；**只有收件人才會在「我要收的 LINE 通知」看到這一項**。內容：來源 IP、嘗試的帳號（存在的帳號顯示原名；不存在的只留前 2 個字與字數，像密碼的整個遮掉）、失敗次數、鎖定到幾點，**不含密碼**。屬於「重要」等級，額度保留時照發；但**每月累計不超過月額度的 25%**，超過後只寄 Email（見 3.3） |

### 3.2 誰會收到 LINE（不再依附 Email）

只有同時符合下面全部條件的帳號才會收到：

1. 帳號**啟用中**（停用的人兩個通道都不發）；
2. 是該通知的**業務收件人**（或被最高管理者「設定誰要發」指定；指定的人跳過第 3 條）：事件相關人員（例如送審人、案件業務負責人）加上登記的群組，並套用「信件與通知收件設定」頁的收件模式（預設／只給最高管理者／自訂帳號與角色）；
3. 角色在該通知「可收的角色」內；
4. 本人沒在「我要收的 LINE 通知」取消勾選；
5. **已綁定 LINE**，且有加官方帳號為好友；
6. 公司已勾選該種通知、LINE 已啟用、機器允許對外發送，且**沒有被額度保留暫停**（見 3.3）。

**不需要**：帳號有填 E-mail、沒有退訂 Email、該種信件沒被關閉——這三件只影響 Email，**不影響 LINE**。所以「某人沒 Email 也想收 LINE」只要請他綁定 LINE 即可，不必補 Email。

### 3.3 額度保留與「已推播」記號

- **額度保留**：本月用量達 **90%** 後，「一般」等級的通知（簽核、指派、業務開發更新、報表…）**自動暫停**（系統 log 會記一行），**「重要」等級（系統告警：備份、心跳、磁碟、憑證、公司資料、登入失敗鎖定）照發**；用量回到 90% 以下或下個月 1 日重置後恢復。暫停期間被略過的**每日檢查型**通知（保固到期）會進**補發佇列**，之後由每日檢查重送（見下方「補發佇列」）；即時型通知（簽核、指派等）過了就不補。用量以系統最近一次讀到的 LINE 用量為準（推播後、開設定頁、每日 08:00 會更新），不會為了這個判斷額外呼叫 LINE。
- **已推播記號**：每日檢查型通知（保固到期）Email 暫時失敗時隔天會重試；LINE 不跟著重推——同一台設備、同一個提醒階段只推一次，記號保留 14 天。
- **補發佇列**：每日檢查型通知若 LINE 因**額度保留、暫時失敗、token 失效**沒送出，系統記下這一則，**每天的系統檢查會重送**；成功（或確定永遠送不出去、已被關閉）就移出佇列，**超過 3 天仍沒送出就放棄**（log 會記）。補發時才重新決定收件人（期間新增的管理者或新綁定的人會收到）。**補發的內容是第一次失敗當下的內容**（例如「剩 5 天」可能在 2 天後才送到，最久延後 3 天）。要點：**Email 寄成功不代表 LINE 完成**——兩個通道的送達分開記錄，LINE 沒送出不會被 Email 的成功蓋掉。
- **登入失敗告警的上限**：每小時 10 則、每天 20 則（超過合併成一則摘要）；LINE 另有「每月累計不超過月額度的 25%」（月額度以 LINE 回報的為準；免費方案每月 200 則，即約 50 則；**LINE 回報無上限的付費方案沒有每月上限**，只剩每小時與每日上限；本月用量暫時讀不到時保守用 200；每位收件人算一則）。三個數字都能調，但**設定頁沒有欄位**，要請維運改系統設定：`auth_alert_limits`（`hourly_cap`／`daily_cap`）、`line_notify.month_cap_percent`（`{"auth_lockout": 整數}`，0＝完全不發 LINE）。超過每月上限後 Email 照寄。
- 額度告警本身（`line_quota_warning`）維持**只寄 Email**，不走 LINE。

## 4. 額度告警

### 4.1 是什麼

LINE 官方帳號的免費方案**每月有訊息則數上限**，推播給 N 個人算 N 則。額度用完後 LINE 會拒絕發送，**勾了「同時發 LINE」的通知就不會送到手機**（Email 照常寄）。額度每月 1 日重置。系統只告警，**不會**自動停止推播。

### 4.2 在哪裡看

「系統」→「通知設定」→「LINE 通知」卡片最上方的 **「本月 LINE 訊息用量」**：
- 用量條與文字「本月已用 X / Y 則（Z%）」；顏色分綠（正常）、橘（達警示門檻）、紅（達告警）。
- 「更新於 …」是最後讀取時間；按 **「重新整理」** 立刻重讀。
- 無上限的方案顯示「本月已用 N 則（此方案沒有上限，不會告警）」。
- 讀不到時顯示「目前讀不到用量：…原因」（例如沒貼 token、連不到 LINE）。
- 用量以 LINE 回報的數字為準，不是系統自己數的（在 LINE 後台手動發送也會算進去）。

### 4.3 告警怎麼觸發

- **門檻**：欄位「用量告警門檻（%，逗號分隔，最多 5 個）」，預設 **80,100**，只能填整數百分比；改完要按「儲存 LINE 設定」。
- 用量跨過任一門檻，系統**寄一封 Email 給全部最高管理者**，主旨類似「LINE 本月額度已達 80%（xxx / yyy）」，信件類型名稱為「LINE 本月訊息額度告警」。
- **同一門檻同一個月只寄一次**；一次跨過多個門檻只寄一封。換月重新計算。
- 檢查時機：打開「通知設定」頁時、LINE 推播成功後（隔幾分鐘內合併）、每天 08:00 的備援檢查。沒有常駐輪詢。
- LINE 停用、或開發機標記（擋對外發送）時不會告警。
- 收到告警可以：看用量條、取消不必要的通知類型或縮小「可收的角色」、評估升級 LINE 官方帳號方案。

## 5. 解除綁定與常見問題

### 5.1 怎麼解除綁定

**自己解除**：登入 →「修改密碼」頁 →「LINE 通知」卡片 → 按紅框的 **「解除綁定」** → 顯示「已解除綁定」，標籤變回「未綁定」。（失敗會顯示「解除失敗」。）
解除後系統不再推播到這個 LINE；官方帳號的好友關係還在，要的話使用者自己在 LINE 內封鎖或刪除（LINE App 內操作，**待確認**實際選單）。

**管理員替別人解除**（換手機、換號碼、離職）：
- 「通知設定」→「LINE 通知」→「LINE 綁定狀況」→「看名單」→ 該同仁那一列的 **「解除綁定」**，再按一次 **「確定」**（2026-11-13 新增；操作紀錄會寫「最高管理員解除 LINE 綁定」）。
- **刪除使用者帳號時，會一併解除該帳號的 LINE 綁定。**
- 停用帳號：不會進入收件人名單（見 3.2），但綁定紀錄是否保留：**待確認**。

### 5.2 「收不到 LINE」檢查清單（由上往下查）

**A. 公司層（管理者）**
1. 「通知設定」→「LINE 通知」：**「啟用 LINE 通知」有勾、顯示「(已啟用)」**？
2. Channel access token 已貼、按「**驗證 token**」成功（顯示官方帳號名稱）？
3. 「要發 LINE 的通知」中，**該事件有勾**？（預設全不勾；該模組的區塊要展開才看得到）
4. 該事件下「可收的角色」有勾到這個人的角色？他是不是被「設定誰要發」改成「只發給指定」而不在名單內？
5. 本月用量是否已滿（用量條紅色／「目前讀不到用量」）？額度用完 LINE 會拒收（但 Email 照寄）。
6. 是否為**開發機／測試機**？開發機標記（環境變數 `MOTRIX_EMAIL_SEND=off` 或 `.no_email_send` 檔案）會同時擋信件與 LINE 推播。（「驗證 token」與用量查詢是唯讀，刻意不受此影響，所以驗證成功不代表這台機器會推播。）

**B. 該帳號（是否在該通知的業務收件人名單裡）**
7. 帳號是**啟用**的？（LINE **不需要** E-mail；沒有 Email、退訂 Email、信件類型被關掉都**不影響** LINE，見 3.2。）
8. 「信件與通知收件設定」頁該類型的收件人有沒有被覆寫成別人（只給最高管理者／自訂帳號與角色）？LINE 與 Email 共用這份設定。
9. 這件事**本來**會不會通知他？（例如保固到期只通知該案業務負責人與管理員群組；報價單被編輯只通知送審人與最高管理者；登入失敗鎖定告警預設只通知最高管理者。）
10. 本月 LINE 用量是否已達 90%？達到後「一般」等級的通知會暫停（登入失敗鎖定告警不受影響，但每月累計超過月額度 25% 後也只剩 Email；見 3.3）。

**C. 本人 LINE**
11. 「修改密碼」頁的「LINE 通知」卡片是否顯示 **「已綁定」**？有沒有出現紅字「已綁定，但測試訊息沒有送達…」（→ 兩個 channel 不同 Provider）？
12. 「我要收的 LINE 通知」裡該項是否被取消勾選？（沒列出來＝公司沒開或角色不被允許。）
13. 有沒有**加官方帳號為好友**、有沒有把官方帳號**封鎖／關閉通知**？沒加好友或封鎖，推播會失敗。
14. 綁定當下手機有沒有收到「MOTRIX 通知已綁定完成…」那則？沒收到先懷疑 11、13。

**D. 找不到「LINE 通知」卡片／綁定失敗**
15. 卡片沒出現：管理者尚未填好 LINE Login 的 **Channel ID／Channel secret** 或 **對外網址**。
16. 手機掃 QR 後停在 LINE 的錯誤頁：LINE Developers 的 **Callback URL** 必須與系統顯示的完全相同（依設定指南，正式機為 `https://line.miactw.com/api/line/callback`，含 https、不多斜線；以通知設定頁顯示的為準）。
17. 一般同仁被擋、只有管理者能登入：LINE Login channel 的狀態還是 **Developing**，要改成 **Published**（最常漏）。
18. 兩個 channel（Messaging API 與 LINE Login）不在**同一個 Provider**：綁定看似成功但推不出去；channel 建好後不能搬 Provider，只能重建。

### 5.3 管理員如何查「有沒有真的送出」

LINE 是背景推播，失敗只寫系統 log、不會跳畫面；也不影響信件。log 會記「LINE 推播結果：…」或「沒有可推播的收件人（收件 N 人；角色／個人勾選後 N 人；已綁定 0 人）」，可據此判斷是卡在哪一層。**待確認**：正式機 log 的存放位置與查看方式（本文未查）。
