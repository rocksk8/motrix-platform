## 2. 已結案稽核的重點與學到的事

### 部署儀表板（C 稽核）
- **逾時上限不能比被保護的動作短**：回滾的上限原本比 convert 短。修正後，會改到正式機而且不是原子的動作，逾時不自動中止，改由人看過 log 後解除並寫原因。
- **磁碟檢查只看 C:**：改成只看安裝碟；拿不到碟代號就不放行。
- **輸出編碼取決於呼叫端的主控台**：cp932 環境會亂碼；改由腳本自己固定 UTF-8，測試刻意用 cp932 跑。
- **修正文件本身寫錯了兩處**（B-2a 判讀規則、B-2b 指令少參數）：由稽核者複核抓到，更正時保留錯的原句。

## 3. 跨稽核的系統性問題（初步，隨稽核更新）

- **測試自己擺放受測資料的位置**（D-1 的 lock 位置、9b 演練夾具用空庫而且轉換後不寫資料）：測試驗到的是自己擺的位置，不是實際出貨的位置。對策：夾具一律由產品端的函式產生。
- **守門綁在特定模組上**（9c A-2）：拿掉那個模組就轉紅，而 core-only 正是要販售的形態。對策：守門用合成模組，並加 core-only 反向控制。
- **讀不到被當成「沒有」或「沒事」**：9c A-1 讀不到停用清單時當成沒有停用；D-6 讀不到時沒有任何警示；U10 讀不到 Python 版本時不寫檔也不提示。對策：比照〈唯讀動作：拒絕 vs 略過〉，缺口一律輸出出來。
- **子字串或文字比對的守門是假綠燈**（batch1 A-2、IP-6 欄位對調照綠）：對策是守門改驗行為，不驗文字，並用突變證明。
- **守門隨模組在不在而改變結果**（M12、M04 搬遷時共抓到 5 道）：守門是在「所有模組都在」的狀態下寫的，拿掉任一模組就會誤報，或讓 L1 契約跟著改變。對策：每一班列車都跑 core-only 反向控制，這類問題一次抓出來，不必每搬一個模組才碰到一題；規則是 L1 的契約與守門不可以依賴任何一個 L2 在不在。
- **版號撞號是流程問題，不是個人疏失**：一晚之內 CORE_VERSION 撞號 6 次以上（A2 先後寫過 1.3～1.7，每次都被別人先用掉；C、A、B、O-9 輪流搶 1.8、1.9）。PLAYBOOK §C-7 已改成「合回時才定號」，但每一條線仍然要手動重產 G1 快照與 CHANGELOG，每搶輸一次就重做一次。建議：改成合回工具（modtest --rebase-check 或合回腳本）依 origin 自動取號並重產快照，人只寫 CHANGELOG 的內容。
- **規格寫了守門，但守門不存在**（IP 稽核 X-2：CORE-SPEC §5 說「登記表有守門比對程式碼」）：規格散文對工具是隱形的。對策：規格裡每一句「有守門」都要附上守門的測試檔名。
- **只修一半的防護**（時鐘跳動的處理是「保留 7 份其餘照刪」，多日後全部清光）：對策是加多日或連續模擬題。

- **觀測點綁在名字上，而程式用的是綁名的副本**（M08 M-1、B 的 O8）：守門包 `db.get_db` 記連線，但 helpers 是 `from db import get_db`，拿到的是原函式 ⇒ 經 helpers 開的連線全部看不到，守門永遠判 0。對策：觀測點放在所有路徑都會經過的最底層（sqlite3.connect），並用「經過 helper 開連線」的突變證明看得到。
- **守門的掃描範圍寫死舊目錄，搬遷後對象被搬走**（M08 M-2：憑證守門只掃 `routers/*.py`，搬進模組的 19 支 GET 不在範圍內）：〈守門守的對象被搬走〉的具體形態。對策：範圍一律由 `core.source_tree` 列舉（含模組），並配「合成模組放一個違規」的反向控制。
- **修並發只驗了一個方向，每一輪修正都帶出新的降級**（主持的部署歷史寫入，D 連續三輪抓到）：第一版只鎖寫入端 ⇒ 讀取端讓 os.replace 失敗、掉筆比修正前更多（H-M1）；第二版把「讀不到」當空清單覆寫 ⇒ 200 筆剩 1（H-S1）；第三版另存 pending 卻沒有落點 ⇒ 警告永遠在、蓋掉真正的失敗警告（H-S2）。每一版都通過了作者自己的題，因為題只測作者想到的那條路。學到：修並發時列出所有讀寫者（含儀表板本身的輪詢）逐對測；「另存／暫存」一定要問落點在哪裡、誰會收回。
- **反向控制需要「拿掉模組」，而刪資料夾會被權限擋下**（稽核 ⑰、C 的還原）：稽核員照規則沒有繞過，結果那一段沒有獨立核對。對策：用 `git worktree add --no-checkout`＋`git sparse-checkout` 從一開始就不取出該模組，不刪任何東西，也沒有 `__pycache__` 殘留（主持 G-M1、C 已採用）。建議把它做成 core_only_rc／§B-11 的標準做法。
- **流程規則被主持自己違反**：這幾輪推文件時，主持把 rebase 與 push 寫在同一個指令（PLAYBOOK 與〈rebase 之後先重跑再推〉都禁止），D 也自報一次；帶進來的都只有文件，沒有造成影響，已更正。規則寫在文件裡不會自己生效，最常違反它的是寫規則的人。
