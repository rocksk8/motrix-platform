## 2. 已結案稽核的重點與學到的事

### 部署儀表板（C 稽核）
- **逾時上限不能比被保護的動作短**：回滾的上限原本比 convert 短。修正後，會改到正式機而且不是原子的動作，逾時不自動中止，改由人看過 log 後解除並寫原因。
- **磁碟檢查只看 C:**：改成只看安裝碟；拿不到碟代號就不放行。
- **輸出編碼取決於呼叫端的主控台**：cp932 環境會亂碼；改由腳本自己固定 UTF-8，測試刻意用 cp932 跑。
- **修正文件本身寫錯了兩處**（B-2a 判讀規則、B-2b 指令少參數）：由稽核者複核抓到，更正時保留錯的原句。

## 3. 跨稽核的系統性問題（初步，隨稽核更新）

- **測試自己擺放受測資料的位置**（D-1 的 lock 位置、9b 演練夾具用空庫而且轉換後不寫資料）：測試驗到的是自己擺的位置，不是實際出貨的位置。對策：夾具一律由產品端的函式產生。
- **守門綁在特定模組上**（9c A-2）：拿掉那個模組就轉紅，而 core-only 正是要販售的形態。對策：守門用合成模組，並加 core-only 反向控制。
- **讀不到被當成「沒有」或「沒事」**：9c A-1 讀不到停用清單時當成沒有停用；D-6 讀不到時沒有任何警示；U10 讀不到 Python 版本時不寫檔也不提示。對策：比照〈唯讀動作：拒絕 vs 略過〉，缺口一律輸出出來。
- **子字串或文字比對的守門是假綠燈**（batch1 A-2、IP-6 欄位對調照綠）：對策是守門改驗行為，不驗文字，並用突變證明。
- **版號撞號是流程問題，不是個人疏失**：一晚之內 CORE_VERSION 撞號 6 次以上（A2 先後寫過 1.3～1.7，每次都被別人先用掉；C、A、B、O-9 輪流搶 1.8、1.9）。PLAYBOOK §C-7 已改成「合回時才定號」，但每一條線仍然要手動重產 G1 快照與 CHANGELOG，每搶輸一次就重做一次。建議：改成合回工具（modtest --rebase-check 或合回腳本）依 origin 自動取號並重產快照，人只寫 CHANGELOG 的內容。
- **規格寫了守門，但守門不存在**（IP 稽核 X-2：CORE-SPEC §5 說「登記表有守門比對程式碼」）：規格散文對工具是隱形的。對策：規格裡每一句「有守門」都要附上守門的測試檔名。
- **只修一半的防護**（時鐘跳動的處理是「保留 7 份其餘照刪」，多日後全部清光）：對策是加多日或連續模擬題。
