## 這份驗收和單元／e2e 測試差在哪

| | 單元／e2e（已有） | 本驗收 |
|---|---|---|
| 驗什麼 | 單一事件的分錄形狀、按鈕終點狀態、守門 | **多來源資料走完整條路後，每個報表的每個數字** |

| 判定 | 遇到第一個不符就停 | 每個斷言印「期望／實際」，**全部跑完才判定**；不符＝缺陷清單，不可改期望值遷就 |

## 行為驗證（同一個題的後半）

1. 引擎：15 張草稿（E01、E03、E04×2、E05×2、E06×2、E06b、E08、E09、E10、E11、E12、E12b）＋2 個 native；沒有被擋的。
2. 一鍵確認到過帳（最高管理者；含最終關卡）：15 張全過帳；草稿期間試算表不含它們。
3. **冪等**：再跑引擎新增草稿 0、傳票總數與試算表不變。
4. **已過帳後來源被改**（派工 A 20,000→22,000）：舊傳票不動；舊事件標 drift、新版本草稿、1 張反向草稿（`kind=reversal`、指向原傳票）；已過帳的帳不變、含草稿的試算表仍平衡。
5. **結帳後過帳**：第 3 期結帳後，過帳該期傳票被擋（400），訊息說明期間已結帳，傳票維持已核准。

## 沒有涵蓋的（誠實列出）

- **固定資產（C6）**：分支 `wip/w4-gl-c6` 尚未合入主線，不在本情境。
- **自訂模組入帳（C7）**：`wip/w4-28` 才有，旗標 `custom_records` 仍關、稅額處理待使用者確認。
- **「與總帳差異」對照頁（W2 recon）**：不在主線；本驗收改用「與來源端獨立對照」（上節最後一項）代替，並非營運報表逐月逐類別的對照。
- 獎金金額本身（native 只登記傳票，金額由獎金模組開的傳票決定；本題用兩張手開的獎金傳票代表）。
- 發票折讓／作廢、補登多年、存貨退回入庫（各有單元測試）。
