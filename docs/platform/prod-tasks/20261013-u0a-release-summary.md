## 結論

**U0a 是『預留多據點／多法人』資料結構的底層班：資料庫只做加法，對你看得見的畫面、資料、編號、匯出與權限完全不變。這是你 10-13 答覆『是，盡快』的項目。可上線（待真實演練、凍結樹閘門與最終稽核）。**
- 更新方式：正式機 Claude 自動套用；套用前自動備份並**試還原**；服務會重啟一次、使用者被登出一次。
- 資料庫：**只做加法**——新增 5 張表；38 張既有表加 43 個預設為 1 的欄位（36 張『所屬單位』、2 張『單位』、5 張『所屬法人』快照）；2 張權限表加可為空的範圍欄位。**不改主鍵、不重建表、不建索引**。核心 `schema_version` 維持 118。

## 你會看到的變動

1. **幾乎沒有**：所有畫面、清單、金額、匯出、列印、編號與昨天完全相同；HTTP 回應與 Excel／CSV 匯出**不含任何新欄位**（洩漏防線同班出）。**例外（刻意保留）**：每日自動產生的 JSON 備份檔會保留新欄位（供還原用）；資料庫健檢摘要預設忽略它們。
2. 設定中心與系統中樞**沒有任何新增項目**（單位功能於 `core/features_l1.json` 宣告為隱藏：不顯示、不可用，也沒有『即將推出』預告卡）。

## 本班沒有的東西（請勿期待）

- 沒有單位選單、沒有分公司、沒有隔離、沒有過濾；那是之後的班次（U1 起）。
- 編號、法定連號、稅務抬頭完全不變。
- 已決定不加的測試：demo 模式下『新欄位剝除』專用中介層測試（demo 與正式用同一個應用程式與最外層中介層，已由順序測試與演練 P8 涵蓋）。

## 需要你做的（驗收；全是只看，不寫資料、不改設定）

**A** 日常畫面不變、**B** 匯出表頭不含新欄位、**C** 設定中心與側欄『即將推出』與昨天相同（沒有新增項目）、**D** 取號不變（測試單做完刪除）、**E** 權限不變。細節見步驟檔「需要使用者自己做的」。

## 任何一項不如預期即阻擋

畫面出現單位／所屬法人欄位；匯出表頭或回應出現新欄位；日常資料與昨天不同；編號格式或接續號改變；權限與昨天不同。
