### 這次收緊了什麼（白話）
- 「營運報表」共 11 支報表資料端點（財務報表含 Excel／PDF、應收帳齡、資金水位、稅務匯出、客戶歷史、月趨勢、收款異常、月支出、應收月報；帳差比對走同一道閘）回的都是**全公司金額**。以前只要帳號被勾了「營運報表」模組就能看；現在規則是：
  - **仍可看（不變）**：財務角色、最高管理者。
  - **依旗標與有效權限另行判斷**：財務角色與最高管理者永遠可看（上一條）。旗標 `finance_via_effective` 不是 `off` 時，職責角色授予「財務」能力的帳號本身就可看；只被授予「出納」或「財務檢視」有效權限的帳號，仍須同時有「營運報表」模組才可看。這類帳號一律列『待確認』由使用者決定（步驟 0-A）。**單純勾選「出納」模組不算**：出納／財務這幾個能力由『角色』決定，不看帳號上的勾選，所以「出納＋營運報表」的非財務帳號**一樣被擋**。

import json
import sqlite3
import sys


def jl(raw, default):
    try:
        v = json.loads(raw) if isinstance(raw, str) else raw
        return v if isinstance(v, type(default)) else default
    except Exception:
        return default


def main(path):
    sys.stdout.reconfigure(encoding="utf-8")
    c = sqlite3.connect("file:%s?mode=ro" % path, uri=True)
    c.row_factory = sqlite3.Row
    row = c.execute("SELECT value_json FROM system_settings WHERE key='finance_via_effective'").fetchone()
    flag = jl(row[0], "") if row else "off"
    flag = flag if flag in ("shadow", "on") else "off"
    duty_ok = True
    try:
        bound = {r[0] for r in c.execute("SELECT DISTINCT user_id FROM user_duty_roles")}
        subs = {}
        for r in c.execute("SELECT user_id, perm_key FROM user_perm_subtracts"):
            subs.setdefault(r[0], set()).add(r[1])
        roles = {}
        for r in c.execute("SELECT b.user_id, r.permissions FROM user_duty_roles b JOIN duty_roles r ON r.id=b.role_id WHERE r.active=1 ORDER BY r.id"):
            roles.setdefault(r[0], []).append(jl(r[1], []))
    except sqlite3.OperationalError as e:
        duty_ok = False
        bound, subs, roles = set(), {}, {}
        print("⚠ 讀不到職責角色資料表（%s）：有效模組可能不準；有營運報表的非財務帳號一律列『待確認』。" % e)
    blocked, pending, allowed, others = [], [], [], 0
    for u in c.execute("SELECT id, username, role, modules FROM users WHERE active=1 ORDER BY id"):
        raw = [m for m in jl(u["modules"], []) if isinstance(m, str)]
        eff = list(raw)
        for perms in roles.get(u["id"], []):
            eff += [k for k in perms if isinstance(k, str) and k not in eff]
        eff = [k for k in eff if k not in subs.get(u["id"], set())]
        item = (u["username"], u["role"], raw, eff)
        if u["role"] in ("superadmin", "finance"):
            allowed.append(item)
        elif "reports" in eff or "reports" in raw:
            has_duty = u["id"] in bound or u["id"] in subs
            if not duty_ok:
                pending.append(item + ("讀不到職責角色資料表，無法算有效模組",))
            elif flag != "off":
                pending.append(item + ("財務旗標 finance_via_effective=%s（不是 off），能否看報表要依有效權限判斷" % flag,))
            elif has_duty:
                pending.append(item + ("有職責角色綁定或個人扣項；有效模組%s營運報表" % ("含" if "reports" in eff else "不含"),))
            else:
                blocked.append(item)
        else:
            others += 1
    print("finance_via_effective = %s" % flag)
    print("\n== 1. 套用後會被擋住（啟用中、有營運報表模組、不是財務角色／最高管理者、旗標 off、沒有職責角色綁定）：%d 人 ==" % len(blocked))
    for n, r, raw, eff in blocked:

    print("\n== 待確認：%d 人 ==" % len(pending))
    for n, r, raw, eff, why in pending:
        print("  %s | 角色=%s | 勾選模組=%s | 有效模組=%s | 原因：%s" % (n, r, ",".join(raw), ",".join(eff), why))
    print("\n== 2. 仍可看（財務角色／最高管理者）：%d 人 ==" % len(allowed))
    for n, r, raw, eff in allowed:
        print("  %s | 角色=%s" % (n, r))
    print("\n== 3. 沒有營運報表模組（本來就看不到，只給人數）：%d 人 ==" % others)

2. **勞報單「選派發」改成可搜尋的下拉清單**：預設只列「這張勞報單的受領人在名單內」的派發，可勾「顯示全部」；清單不顯示金額；案件名稱只給看得到該案件的人。另外，勞報單的國籍、所得類別、付款方式、執行業務細項四組下拉選項已進選項清單：**預設與今天的畫面完全相同**；管理者要在設定中心調整，須先開兩個旗標 `builder_option_lists.enabled` 與 `builder_governance.enabled`（預設都是關的，本班不要求開）。國籍與所得類別是固定清單，只能改顯示名稱、不能新增或停用，不影響扣繳判斷；付款方式與執行業務細項是開放清單，可以新增或停用選項。**行為變嚴**：連結勞報單與派發時，受領人必須在該派發的人員名單內，名單外的會被擋下並說明原因。
3. **利潤口徑：公益捐款比率可設定**（設定中心「利潤口徑」，預設 1％，範圍 0～10％）：報價單、精算、獎金明細的「公益捐款」字樣與金額跟著比率走；**每張單據自己記住當時的比率**，完結後改比率不會讓舊單據的字樣或金額改變；管銷比率後備值改取既有的預設管銷比率（預設 25，等於今天）。調低比率視為放寬，要等確認期間並由另一位最高管理者核准；調高立即生效。
4. **法規參數跨年提醒的起算日改為設定**（設定中心「法規參數跨年提醒」）：**預設由 12 月 1 日提前到 10 月 1 日**（使用者裁示）。設定完全沒動，提醒也會從每年 10/1 起出現，所以 10、11 月看到「下一年度的法規參數還沒設定」是預期中的新行為。只影響提示，不改任何稅額、扣繳或勞報單內容。把起算日往後延視為放寬（要確認期間＋另一位最高管理者核准）；往前提立即生效。
5. **首頁待審核與待追蹤報價的金額遮蔽**：沒有報價金額可視權限、又不是送審人或該單簽核鏈上的人，首頁「待審核」清單的報價總額不顯示（顯示「—」），帶金額的審核原因換成「（涉及金額，無財務檢視權限）」；「待追蹤報價」同理。簽核人、送審人、業務、管理員照舊；哪些列會出現不變。
6. **小模組顯示名稱可調整**：網路規劃的狀態、採購建議的狀態、住宿紀錄的計價單位與詢價管道，可在設定中心改顯示名稱。預設與今天逐字相同；只換畫面上的字，狀態值、順序、權限不變。

新增路由：`GET /api/payslip-dispatch-options`（勞報單選派發清單；需登入，未登入 401；走「查看勞報單」權限）。其餘為既有路由的行為變更。新增前端檔：`static/dispatch-picker.js`、`static/display-labels.js`。

- **選單入口不隱藏**：被擋的帳號仍看得到「營運報表」入口，點進去是說明面板；選單權限只能表達「或」，所以金額是否可見一律以後端 403 為準。若使用者希望隱藏入口，是後續產品決定。

- 派發頁的「派發↔勞報單關聯」三支端點（`/api/contractor-dispatches/{id}/payslip-links`）仍是最高管理者判斷，不在權限設定頁（另案）；勞報單「付款方式」是開放清單，伺服器不驗證是否在清單內（既有行為）。
- 派發清單在派發量到數千筆以上時建議改在 SQL 分頁（效能殘留，審查註記）。
- 首頁待審核／待追蹤的金額遮蔽只改回應內容，回應欄位名稱與哪些列會出現不變。
- 已知偶發（不阻擋）：同 T67 步驟檔所列。
