## 這一班有什麼（依主題；使用者看得懂的版本）

**A. 權限與角色**
- **職責角色化 R1**（新頁「職責角色」，只有超級管理員）：把一組權限定義成角色、使用者可綁多個角色、可對個人扣除某項權限；涉及財務金額、出納、系統設定、歷史紀錄、版本紀錄、勞報單的變更必須填原因，每次變更寫入不可修改的紀錄。**上線當天不改變任何人現有權限，也不自動綁定任何人**（零綁定、零扣項；上線前後有逐人等值關卡，見步驟 0 #6、步驟 3 #14）。財務／出納仍只由「財務」角色與超級管理員決定；超級管理員不受影響。個人扣項只影響以模組權限判斷的功能（管理員的一般管理功能仍依角色直通，畫面有警語）。
- **財務角色對他人叫料唯讀**（權限變更）：「財務」角色對**不是自己負責**（非業務、非協作者）的案件，只能查看一般叫料（材料申請）清單、不能編輯；自己負責的案件、最高管理者、管理員不受影響；匯款、發票日等付款相關功能不變。**只因案件角色或階段負責人而成為成員的財務，仍視為非負責人（不能改別人的叫料）**——使用者已裁示不更動。

**B. 信件與行事曆**
- **信件×行事曆矩陣**（「信件與通知收件設定」頁）：每列兩個獨立公司層勾選「信件」「行事曆」。信件取消勾選＝公司不寄這種信（收件人設定保留、重新勾選即恢復）；簽核類／系統類關閉前有確認警告；**資安／營運攸關的信件鎖定不可關**：備份失敗、備份停擺、磁碟空間不足、憑證到期、本公司資料告警、測試信。
- **「關閉」的語意**：寄信端沒有收件人（含部門主管、月報收件人、財務受眾各條路徑，均已逐一擋）。⚠️ **標案雷達 `tender_found` 關閉時，當日彙總不寄，但這批標案仍被標成「已通知」並推進 7 天純記錄期——重新打開後不會補寄關閉期間的標案**。
- **三種新日期型行事曆事件（預設全關）**：設備保固到期日、區間工作事項結束日、案件專案預計完成日；打開後每天對帳一次（改日期、結案、完成、刪除自動同步；已過期日期不新增）。事件只含案號、客戶、設備或專案名稱、區間事項標題與日期，**不含金額、不含負責人姓名**。**保固事件第一次打開時，已成案案件的未過期保固會分散在數天內建完**（每次每日檢查最多 100 個項目，約 200 次 Google 請求；失敗不記為已同步、下次重試，連續失敗 3 次本次收手）。
- 預定付款日提醒信：寄送成功才記「已寄」（SMTP 暫時失敗當天補寄、只在寄信日當天重試；結果不確定或永久失敗時保留記號不重寄並記 ERROR）；一次掃描最多等 120 秒；提醒日遇**國定假日**也順延到前一個工作日（用官方辦公日曆表，2026～2027）；出納退回匯款差額後，行事曆「付款待辦」自動重建。
