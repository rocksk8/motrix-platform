# MS1d 認列被拒立即可見班更新摘要（給使用者；草稿）

> 基準：凍結樹 `train/ms1d-int-a`（待填 SHA），在 MS1c 上線版之上；包名與雜湊在發布時產生，見步驟檔。**版本號、筆數等數值已對候選分支核對，凍結後以凍結樹實際值為準。**

## 結論

**MS1d 是一個小的畫面修正班：材料卡片按『帶入並連結』被拒時，畫面立刻用白話說明並還原，不再先顯示成功、也不再需要重新整理。不是安全修補（伺服器端的拒絕、稽核與寄信在 MS1c 就已生效）。可上線（待凍結樹閘門與最終稽核）。**
- 更新方式：正式機 Claude 自動套用，套用前自動備份並驗證；服務會重啟一次、使用者被登出一次。
- 資料庫：**沒有任何變動**（沒有新表、新欄位、新設定、新路由）。
- 只有 `case` 模組升一版（1.0.182 → 1.0.183）。

## 你會看到的變動

1. **被拒時立刻說明**：沒有認列權限的帳號按『帶入並連結』，數秒內畫面顯示『這個帳號沒有認列採購單的權限，這次認列已取消，並已通知管理員。』（不再有『材料申請審核規則：』的誤導前綴；是否寫『已通知管理員』依設定）。
2. **只還原被拒的那張卡片**：該卡片即時回到伺服器現值（未連結、已申購取消）；其他卡片與你存檔途中新打的修改不受影響。若被拒的是『刪除已認列的卡片』，卡片會依伺服器順序放回原位。
3. **按下去就存檔**：顯示『認列中…』，只有真的存成功才顯示『已認列…』；送審排隊時顯示『認列已送出，待最高管理員審核後才會生效』；存檔失敗時顯示『認列尚未儲存…』並自動重試。
4. 最高管理者的認列行為完全不變。

## 本班沒有的東西（請勿期待）

- 沒有權限變更、沒有新設定／端點／信件類型、沒有新的稽核事件。

## 需要你做的（驗收）

只用**專用測試案件**（含一張已核准採購單、至少兩張材料卡片）：**A** 最高管理者認列照舊、**B** 管理員按『帶入並連結』數秒內看到白話拒絕、卡片維持未連結、其他卡片修改保留、**C** 最高管理者仍可認列、**D** 管理員刪除已認列卡片被拒（卡片留在原位、稽核恰一筆 `recognize_denied`）、**E** 存檔失敗時顯示『尚未儲存』而不是『已認列』、**F** 舊行為不受影響。細節見步驟檔「需要使用者自己做的」。

## 任何一項不如預期即阻擋

非最高管理者認列成功；被拒時先顯示已認列；被拒時其他卡片的修改遺失；刪除被拒的卡片從畫面消失；存檔失敗卻顯示已認列；被拒信件含金額、廠商或明細。（含 `poLink` 的報價單張數大於 0 是正常現象。）

## 閘門結果

由整合者於發布時補入（full-lint、not_e2e、e2e、建包、驗證、演練與非作者稽核）。

## 回滾

沒有資料庫變動，程式可單獨回退到 MS1c，功能與稽核不變，只是畫面訊息回到舊行為；是否回滾由您決定，正式機 Claude 不自行回滾。
