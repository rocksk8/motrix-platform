## 這一班有什麼
- **請款單 A2（全量班）**：「新增請款」加類型支線——請購 PR／採購 PO／差旅 TE／零用金 PC（單號 `XX-YYYYMMDD-NNNN`，可不掛案件）；簽核 → 出納付款（採購單要匯款日＋付款條件、零用金要付款方式）→ 總帳分錄 → 營運報表（依費用類別逐列、部門維度）。可作廢（**僅 superadmin**、僅已核准未付款）；清除／更改已登錄付款日**僅 superadmin**。金額遮蔽（只有申請人／簽核人／出納／財務／管理員看得到）。單據可預覽／匯出 PDF；六種通知信（信內不放金額）。
- **員工收款帳號**（`payroll`）：員工自助維護銀行資料；出納付款時只看遮罩、要看完整帳號走專用端點並留稽核。帳號與戶名列入個資備份（只進個資資料夾）；案件額外支出的收款人帳號同樣。
- **總帳**：費用類別→科目對應（報表設定頁新頁籤）、引擎逐類別借方、零用金貸 PETTY；營運報表「部門」跟業務負責人。
- 其他：精算頁在有金額被遮蔽的費用單據時擋「儲存草稿／完結精算」；簽核佇列卡片顯示單據類型；登入後的簽核彈窗修正（`fix/login-approval-popup@2fcb4fa0`：通知橫幅改以 `/api/approval-queue/count` 計數；核可／退回會把對應通知列標為已讀；只影響報價單流程）。
- 併入本班（主持確認後保留）：**簽核類型編輯器**（a3，etype-editor）<TBD>；**地圖縮放**（`wip/w3-map-zoom-2e@f29993cb`：只改 `pages/map.html`）；**外包人員／協力廠商銀行資料遮罩**（c7）<TBD>；時鐘守門／預檢工具（d7 評估中）<TBD:是否併入>。
- 起草時 int1 版本（建包後以 `module_states.json` 為準 <TBD>）：`accounting` 1.1.46、`analytics` 1.0.21、`arap` 1.0.32、`case` 1.0.56、`payroll` 1.1.16；其餘模組版本不變；`core` CORE_VERSION <TBD>（起草時 1.92＋(next)）。

## 第一次登入後會看到什麼（重要：費用類別預設是**空的**）
- **費用類別清單空 ＝ 尚未設定（設計如此）**：此時四種單據照樣可送審，**不驗證類別**；總帳把費用列到預設科目並標註「類別未對應」。**一旦新增第一個啟用類別，送審立刻改為嚴格驗證**（明細類別必須在清單內）。
- 要啟用類別 → **superadmin 登入 → 選單「財務會計」→「報表設定」→ 頁籤「費用類別科目對應」→ 按「新增費用類別」**，填代碼（發布後不可改）＋名稱，再為每個類別選會計科目（可勾「不得扣抵進項稅額」）。只有最高管理者可改。
- **新權限 `expense_forms`（費用單據）預設不給任何人**：admin／superadmin 本來就能新增無案件單據；其他人要在「使用者管理」勾選才看得到。有案件的請款（舊流程）不受影響。
- 開關：本班沒有新增預設開啟的總帳功能；`gl_settings` 的 `feature.%`（engine_drafts／withholding／source_annotations／tax401）維持套用前狀態。

## 需要使用者自己做的（先看，不要為了測試改正式資料）
1. **設定費用類別**（見上「第一次登入」）：不設也能用（不驗證、總帳走預設科目）；要嚴格驗證與逐類別入帳才需設。
2. 「使用者管理」：決定誰要 `expense_forms` 權限。
3. 登入後開「新增請款」：類型下拉有 請購單／採購單／差旅費用請款單／零用金支付單，選一種會依定義渲染表單（只看，不要送出）。
4. 簽核佇列：卡片顯示單據類型（舊的額外支出仍顯示「案件額外支出」）。
5. **作廢僅 superadmin**：以 admin 登入，已核准未付款的費用單據不應出現「作廢」鈕（以 superadmin 才有）。
6. **部門對帳**：營運報表選一個部門，與「全部部門」的各部門加總（含「未分類」）核對，總額應相等；部門＝案件業務負責人所屬部門。
7. **登入彈窗**：以有待簽核單據的帳號登入，通知橫幅的待簽核數字與「簽核佇列」頁一致；在佇列核可一張後，對應的通知列變已讀（只看，不要為了測試核可正式單據——用已經要簽的單據）。
8. **（併入項目驗收，主持確認後保留）**：簽核類型編輯器 <TBD:驗收方式>；地圖頁縮放（開地圖頁，縮放控制與圖例可用、無 console 錯誤）；外包人員／協力廠商銀行資料在清單遮罩 <TBD:驗收方式>。
