## 規格條件

### 來源：STATE.md〈獎金分潤 BN 系列〉（2026-09-26 M07 搬遷自 docs/windows/STATE.md 移入，原文照搬）

| 編號 | 條件 |
|---|---|
| **BN1** | 獎金頁「產生獎金單」介面（選已結案已精算案件→帶入基數→設分潤→送出）；`POST /api/bonus/awards` 已存在，**本項是接線＋UI** |
| **BN6** | 獎金分潤單**明細表＋預覽**（報價／成本／衍生／比例／淨利 → 拆發）：🔴 **每個數字都讀 `settlement.summary` 已存值，一個都不要算**；⚠️ `dispatchTotal` 只有 6/12 筆有 ⇒ **缺欄位標「無」不是 0**；擴充既有的 `awards/plan/{quote_no}` 不要開新端點 |
| **BN7** | 獎金分潤單**匯出 PDF**：沿用 `JV5` 的 Edge headless（無附件合併 ⇒ 不需 `pypdf`）；⚠️ 驗收要 NFKC（`§214` 康熙部首） |
| **BN8** | 🔴 **獎金分潤單成為第九個 doc type**（使用者裁「現在就開簽核流程」）：實查它**建立之後永遠是「草稿」**（沒有 `submit`／`approve`／`reject`，`UPDATE bonus_awards` 全 repo 只有一處且只寫 `voided_*`）；⚠️ **擋住 `BN7`**（用印欄要讀簽核鏈），`BN6` 可平行；📌 趁 `AS2` 剛做完第八個，同一套機制 |
| **BN9** | 獎金可見性收成**只有最高管理者**：✅ 「與自己無關的單完全不出現」**已實作**（`bonus.py:307-310`）；🔴 差的是 `_is_manager` 現在**包含 `admin`**（docstring 自標「未經使用者確認」）⇒ 使用者已確認**只有 superadmin**；⚠️ `admin` 變成**一般使用者**不是看不到頁面；⚠️ 不要弄壞 `bonus.html:146` 那條「入口看 `can_edit` 不看 `isManager`」 |
| **BN2** | 獎金項目**只有最高管理者可見**：`GET /api/bonus/items` 現在只要求登入；⚠️ 前端要**明著說的拒絕**不是空表（空表＝「沒有資料」，那是另一句話而且是假的） |
| **BN3** | 人員來源新增 **`manual`（手動指定）**：項目直接掛人員清單；🔑 讀法「新增一種來源類型」**技術前提不存在**（系統不知道去哪撈人）；📌 同時解掉 `owner`／`engineer` 兩個欄位不存在的落差；⚠️ 綁帳號不存自由文字 |
| **BN4** | **「產生獎金單」→「產生獎金分潤單」**：逐處查（端點說明／標題／按鈕／稽核／信件） |
| **BN5** | 案件編號改**下拉式選單**：⚠️ **列什麼是全部內容**，不是換一個控制項；列已結案＋已精算、已產過單的**標出來不要藏**；🔑 要有**說得出原因的空狀態** |
| **BN10** | 🔴 **點開一張獎金分潤單要有完整詳細頁**（精算明細＋拆發明細＋簽核狀態，使用者裁）；⚠️ 與 `BN6` **不同**：`BN6` 長在「產生獎金單」段，**要先打案件編號按查詢才出現** |
| **BN11** | 🔴 **獎金單 PDF 要含案件精算明細表**（使用者：彙整成一張表、可參考精算表單介面）；⚙️ **算只有一份**（`settlement.html::calcSummary`），會漂移的是**列的順序與標籤文字**；⇒ 做 `SETTLEMENT_ROWS`（鍵＋標籤＋格式）給 PDF 與 `bonus.html` 共用；⚠️ `settlement.html` 是寫死的表格，重寫它**不在範圍** ⇒ **明著接受一份重複＋守門擋漂移**（斷言 11 個標籤在 `settlement.html` 逐字找得到）；🔴 那道守門誤報時**要改題不要改文案**（`§311`） |
| **BN12** | 🔴 **申請與匯出兩階段都要有詳細預覽**（使用者：比照報價單方式）；⇒ `BN6`／`BN10`／`BN12` **不是三個東西**＝**一個版面 × 兩種資料來源**（plan 沒有 award_id ／ award 有）；✅ 裁定：**recall 要做** ／ **reject 不升版**（使用者裁）／ **解鎖編輯強制重簽不做 —— 前提不存在**（沒有端點可以改比例，前提出現時回來收斂）；✅ **不引進新終態**（「已發放」是 `is_paid()` 推導的，不是 status 值） |
| **BN13** | 🔴 **已作廢的獎金分潤單匯出的 PDF 沒有作廢標記**（`JV23` 的同族，D 盤出）：`bonus_pdf.py` **整支沒有 watermark 機制**，唯一指示是 **9.3pt 小字「狀態　{status}」**；✅ 裁**整套搬 watermark 過去**（放大字體是權宜，浮水印的目的是「不可能沒看到」）；⚠️ **只蓋「已作廢」**（未簽核完成 `can_export()` 已擋住，印它是防一個不存在的狀態）；⚠️ 獎金單**沒有已過帳終態** ⇒ 不要寫那一題；🔴 與 `JV23` 的題要**互相指名是同一類**；⚙️ 會動到 `BN11` 同一支檔 |
| **BN14** | 🔴 **獎金人員來源要有群組區分**（使用者：後勤單位，複數人員**自動計算比例**）；✅ 使用者追裁「**只在這邊獨立設定，不需要共用**」⇒ **不接 `departments`／`divisions`**（那套是「預留給未來簽核路由」，可能全是 NULL）；🔑 **取代 `BN3`** —— `BN3` 被讀成「一次性名單」的前提（「系統不知道去哪撈人」）**被群組消除了**，而使用者說的是「人員**來源**」不是「人員」；✅ 保留 `BN3` 的「**綁帳號不存自由文字**」那條界線；🔴 **成員名單要在產生獎金單那一刻凍結**（同 `QL25`）；🔴 均分的**尾差沿用 `BN6` 的「歸公司留存」**，單位是**基點**；⚠️ 走 `people_for_item()` 唯一接縫（0 人 ⇒ 拒絕該項目，不靜默算 0）；⚠️ C 的 9 題**整批重寫**（表不同） |
| **BN15** | ✅ **獎金單清單與明細補上案件名稱**（使用者驗 `BN10` 回報「只有編號」）：`bonus_awards` **只有 `quote_no`**，而**產生那一側**（`bonus.py:394`）早就查得到 `customer_name`／`project_name` ⇒ ☠️ **同一頁上兩邊不一致**；✅ 已做（`00d6b22`）：`_case_names_for()` **即時查不存快照**；⚠️ 題的 ③ 專防「存成快照」（改 `quotations` 客戶名，獎金單要跟著變）；⚠️ ④ SQL NULL **不可印成字面 `"None"`**（該欄沒有 `NOT NULL DEFAULT ''`） |
| **BN16** | 🔴 **獎金單依狀態切換顯示**（使用者）—— 而那**不是一串狀態，是三個維度**：簽核（草稿／**送審中**＝待審核＋簽核中）／撥付（未撥付／已撥付）／有效性（作廢）；✅ 「送審中」合併的依據是**系統自己的**（核准與退回兩處都寫 `not in ("待審核","簽核中")`）—— **送審中是集合的名字，成員名不變**；✅ 使用者裁「**已審核＝已核准且未撥付**」（他的待辦清單）＋「**作廢預設不顯示**」；✅ **計數不可以有自己的資料來源**（同一個 `awards` 陣列）；🔴 前置：今天五張有四張簽核鏈是空的 ⇒ **造不出「簽核中」** ⇒ 那個頁籤會是「沒資料」而不是「對的」 |
| **BN17** | 🔴 **獎金單退回要有記錄**（使用者：「也要退回的按鈕**並且記錄**」）；✅ 按鈕**早就有**（`bonus.html:544-561` 含原因輸入與空原因擋鈕）——使用者看不到是因為**彈窗是 `BN10` 這一輪才做出來的**；🔴 真缺口與 `JV22` **完全同形**：`reject_award()` **後端沒驗 reason 非空**（前端擋 UI，**直接打 API 繞得過去**）／**沒寫進 `bonus_award_edit_log`**（表 v98 就建了而 `bonus.py` 零筆 `append_edit_log`）／沒有 GET 端點／沒有防刪 TRIGGER；⚠️ **退回→再送審→再退回，第一次的理由不可以消失** |
| **BN18** | 🔴 **產生獎金單時能手動指定人**（使用者裁；舊案件執行人 100% 是空的）；🔑 **推翻了「`BN14` 取代 `BN3`」** —— 當初判準是「一次性名單沒有用例」，**而現在有了**；🔴 **項目層不是單層**（`bonus_award_lines` 鍵含 `bonus_item_id`）⚠️ 今天每張單只有一個項目 ⇒ 兩種做法**結果相同、測試全綠** ⇒ 驗收要造兩個項目的單；✅ 丙：**明著宣告 `person_source_override`** ＋ `person_source_snapshot` 存 `"manual"`；⚠️ `"manual"` **不可加進 `PERSON_SOURCES`**；🔴 **`BN14` 要在它之前或同一輪**（否則同一欄同時有帳號與中文名）；✅ 草稿可改＋留記錄；✅ 提示「要不要順便補執行人」**但不可阻擋** |
