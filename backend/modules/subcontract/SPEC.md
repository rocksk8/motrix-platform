### 來源：31-B 匯款款別（2026-10-02，S0）

| 編號 | 條件 |
|---|---|
| **RK1** | 匯款款別放在定義文件庫（`remit_kinds`／`default`）；沒有發布版＝出貨預設四種（訂金款、進度款、完工款、驗收款）與使用者確認的派發狀態對應；公司發布後以發布版為準 |
| **RK2** | 款別設定的驗證：代碼格式與不重複、名稱必填、`active` 布林、`stages` 必須是派發狀態、啟用中的款別至少一個可開立狀態、至少一個啟用中的款別 |
| **RK3** | 已發布過或已被匯款申請使用的款別代碼不可移除，只能停用（`active＝false`）；改名可以 |
| **RK4** | `GET /api/remit-kinds` 只給管理員以上、只回啟用中的款別（依排序）；完整定義（含停用）與設定的寫入只有最高管理者 |
| **RK5** | 開款別的規則：款別存在且啟用、派發目前狀態在該款別的 `stages` 內，否則回帶原因的說明；公司改規則只影響之後新開的申請 |
| **RK6** | 匯款申請表重建（遷移 0005）：拿掉 `dispatch_id` 單欄 UNIQUE、加款別／分期／作廢欄位；舊列逐欄不變、`kind=''` 且未作廢的同派發仍最多一張、`kind<>''` 同派發同款別同期不重複；冪等；失敗整支撤回、舊表不動 |
| **RK7** | 分期金額規則（`remit_split.plan`）：比例或固定金額；最後一期取剩餘額（補尾差）；稅額逐期算、最後一期補到與整筆一致，各期稅額合計恆等於整筆稅額；超出剩餘額度、累計比例超過 100%、非整數元一律拒絕 |
| **RK8** | 分期匯款申請的建立與試算（`POST /api/contractor-vouchers` 帶 `kind`＋`ratio_percent` 或 `amount`；`POST /api/contractor-vouchers/preview`）：款別存在且啟用、派發狀態在該款別可開立狀態內；金額走 `remit_split.plan`；分期與舊式整筆在同一派發互斥；前期只看未作廢的、序號不回頭重用；個人點工只掛最後一期；試算不寫入且與建立算出同一組數字；不帶 `kind` 的舊式申請行為與回傳形狀不變 |
| **RK9** | 分期匯款申請作廢（`POST /api/contractor-vouchers/{no}/void`，管理員以上、必填原因）：只能作廢該派發最新一張未作廢的分期申請（後進先出）、已付款須先撤銷付款、舊式整筆不能作廢；作廢後狀態＝已作廢、不佔額度（最後一期可重開）、序號不回頭重用、不進待付款與簽核佇列；分期草稿刪除同樣守後進先出；只剩作廢申請的派發不再擋派發編輯／取消／刪除 |
| **RK10** | 案件頁分期匯款申請畫面：款別下拉只列啟用且可在目前派發狀態開立者；試算一律打後端 preview（畫面不自己算金額）；後端拒絕時原文顯示且確認鈕停用；一張派發多張申請依建立順序顯示、已作廢灰字；只有最新一張已送審未付款的分期申請有「作廢」鈕；已申請稅前合計與剩餘額度顯示在卡片上 |
| **RK11** | 分期申請的發票與總帳 E04 逐張（D11 發票可事後補）：`PATCH /api/contractor-vouchers/{no}/invoice` 只給分期申請、作廢的不能登、不影響金額；有未作廢分期申請的派發，總帳 E04 改由各期申請逐張認列（`source_type=contractor_voucher_invoice`、`doc_no`＝該期發票號、事件日＝該期發票日），派發層 E04 不再出現（同一派發只有一種層級）；沒有發票日的期別與非已核准的期別不認列；各期稅前／稅額合計＝派發稅前／整筆稅額；派發層已登錄發票日 ⇒ 不能改開分期、已改分期 ⇒ 派發層不再收發票日；舊式整筆的 E04／E05 形狀不變；E05 `meta.dispatch_invoiced` 分期看該期自己的發票日 |
| **RK12** | 分期匯款申請的 PDF 帶「款別／期別（本期稅前）」並以該期發票號碼取代派發的發票號碼；舊式整筆申請的 PDF 版面不變；作廢的申請不提供 PDF（409）；分期 E04（`contractor_voucher_invoice`）可在總帳「來源憑證補登」補登進項稅額與發票日 |
