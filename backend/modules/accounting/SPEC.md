| **JV6** | 從既有單據帶入分錄（發票／承攬商支出／購料發票） |
| **JV7** | 傳票摘要來源分頁選單（案件／已上傳檔案）→ 帶入摘要 → **可手動填寫或修改**；⚠️ 改過的摘要不可被重新整理蓋回去 |
| **JV9** | 🔴 **「尚未設定公司抬頭」是一行雙重解析**：`_get_setting()` 已 `json.loads` 過，`voucher_pdf.py:82` 又 loads 一次 ⇒ `TypeError` ⇒ **被自己的 `except` 吞掉** ⇒ 印「尚未設定」而設定裡有值；⚙️ 同族掃 366 檔＝**孤例 1 處**；修法是**分開接**不是拿掉 `except` |
| **JV10** | 傳票**原視窗預覽**（沿用報價單的 `previewMode` modal）＋ **匯出 PDF** ／ **匯出 PDF（含附件）** 兩顆按鈕（後端 `?with_attachments=1` 已有）；⚠️ 沒有附件時那顆要停用並說得出話 |
| **JV11** | **未簽核完成不可匯出**（🔴 **閘門在後端**，前端藏按鈕不算）＋ 預覽時**紅字浮水印**「傳票尚未簽核完成」（沿用報價單 3×4 平鋪、rgba(185,28,28,.09)）；🔑 **預覽隨時可看，匯出要簽核通過**；⚠️ 擋下來要說得出**還差誰簽** |
| **JV16** | 🔴 **傳票附件看不到**：上傳／列出／刪除／併進 PDF 都有，**沒有任何端點可以取出單一附件檔案**，而附件列是 `<span>` 不是連結；⇒ ①新增取檔端點（權限同 `GET /{id}`、走 `abs_path()` 防路徑穿越）②預覽 modal 內、**iframe 外側**列出並可點開、標出哪些會併進 PDF；⚠️ **不要改 `preview_html()`**（不帶 `file:///` 圖片的理由仍成立）；☠️ **token 不可進 query string**（uvicorn access log 記整串網址） |
| **JV17** | 🔴 **匯出鈕只留在預覽視窗內**（使用者：避免人員不確認就直接按匯出）；拿掉 `voucher.html` 頁面上那兩顆，保留 modal 內那兩顆，只留「預覽」在頁面上；⚠️ **拿掉的是入口不是檢查** —— 既有「匯出被擋下來」的題要改打 modal 內那顆，**不可以順手刪掉**；⚠️ 要查清單頁有沒有第二個匯出入口 |
| **JV18** | 🔴 **憑證被別張傳票帶入過要標紅字「已計算」**（使用者 2026-09-23）：`case_attachments()` 只檢查檔案在不在，**完全沒查它被用過** ⇒ 同一張發票可被兩張傳票各記一次；⇒ 只在**帶入憑證選單**標＋排到最後＋按 `uploaded_at` 新到舊（使用者裁）；✅ **不必加欄位**（`source_file_id` ＋ `uploaded_at` 已存在）；🔴 **只標記不擋住**——作廢重開會複製附件，擋住會把合法路徑擋死；⚠️ 用過 >1 次要**每一張都列**；⚠️ `source_file_id` 空值要排除否則全部亮紅字 |
| **JV19** | 🔴 **從預覽視窗按匯出，訊息出現在視窗背後**（使用者回報）：`JV17` 把匯出鈕全搬進 modal ⇒ **每一個閘門訊息都會掉進這個洞**；⚠️ `attErr` **同時裝成功提示與錯誤**，兩個渲染點（`:396`／`:540`）⇒ **不可只斷言節點存在**，要釘「使用者看得到」；🔴 三種可能成因（沒渲染／在捲動區外／版本較舊）**修法不同，先重現** |
| **JV20** | 🔴 **傳票不需要「類別」選項**（使用者）；⚠️ **拿掉的是畫面上的選項，不是那個欄位** —— `category` 會被寫進 **T100 匯出檔**（`accounting_export.py:441`）；⇒ 新建與**作廢重開**兩條路都仍寫入預設 `轉`；🔴 題要釘「**T100 那一欄不可以變空**」，觀測點打在**匯出結果**不是 INSERT 參數；⚠️ 送舊 payload（含 category）不可以炸（瀏覽器可能快取舊 js）；⏳ 待使用者確認：全部固定成「轉」而 T100 分現收／現付／轉帳 |
| **JV21** | 🔴 **傳票摘要要能帶入案件底下的支出子項目**（使用者：承攬商有發票有支出、叫料有發票有支出、點選案件內的案件可以帶入子項目）；⚙️ 現況 `summary-sources` 只有**案件本身**與**憑證檔案**，**沒有支出項目**；🔴 要先查：「有發票」是**欄位**還是**有沒有附件**（判定不同）／**有沒有子案件這種結構**（查不出來要問使用者，不可以猜）；⚠️ 不可違反 `JV7`「**帶入是起點不是終點**」（存來源 id 重組 ⇒ 下次打開才變回來）；⚠️ 多列金額後閘門顧慮變大（**從記帳畫面繞過去看客戶清單**）；⚠️ 新增靜態 GET 要宣告在動態路由**之前**（否則 422 不是 404） |
| **JV23** | 🔴🔴 **已作廢的傳票匯出的 PDF 沒有作廢浮水印**（使用者稱重大缺失）：`watermark_html()` **只接在 `preview_html()`**，匯出路徑用簽章預設值 `watermark=""`；🔑 根因＝`JV11` 的前提「未簽核根本匯不出來」被 `JV15`（已作廢一律放行）推翻，**而結論沒跟著翻**；⇒ 修法 `watermark_html(v) if v.get("voided_at") else ""`（**只讓已作廢那半穿透**）；⚠️ 負對照：**已核准／已過帳匯出不可有浮水印**；⚠️ 含附件那條路是另一次 `build_html()`；🔴 改碼時**連那段過期的 docstring 一起改**並寫依據 |
| **JV24** | 🔴 **作廢重開後，新單的憑證來源指向舊傳票而不是原始憑證**：`_copy_attachments_to()` 填的是 `source_doc_no=舊傳票 id`／`source_file_id=舊附件 id`；☠️ ⇒ `JV18` 的「已計算」去查原始憑證**找不到新單** ⇒ 顯示成「未計算」**而它正被使用中** ⇒ **一個假的「未計算」，讓人照著標記去重複入帳**（正是 `JV18` 要防的）；⚠️ `vouchers_all.supersedes_no` **存在而寫入點 0** ⇒ 目前 A→B 的唯一連結就是 `source_*`，**不能只把它改回原始值**（會刪掉那條連結）；⇒ 處置＝沿用原始 `source_*` **＋同時補寫 `supersedes_no`**；📌 不擋 `JV18`（作廢那張不算已使用、重開那張算，兩邊一致） |
| **JV25** | 🔴 **傳票預覽的顯示高度過小**（使用者）—— **`JV19` 的副作用**：固定 72vh 改成 flex 之後附件清單＋訊息優先拿高度 ⇒ iframe 被壓縮（實測 ratio 0 附件 0.649／1 附件 0.670／**10 附件 0.357**）；⇒ 讓三者不競爭同一份高度：訊息固定在 `modal-foot`／附件清單**可捲且有上限**／iframe 拿回大部分且**高度穩定不隨狀態變**；🔴 **`JV19` 三題不可退回**（對照組）；✅ 斷言釘「比例不可隨附件數從 1 到 10 惡化超過 15 個百分點」**比死釘絕對值耐用** |
| **JV26** | 🔴 **`voucher_lines` 有 7 欄已規劃、未接線**（零寫入端、零消費端、全庫非預設值 0）：`dept_code`／`summary_template_id`／`summary_template_version`／`source_type`／`source_id`／`source_amount_snapshot`／`counterparty`；⚠️ `account_name_snapshot` **不屬於這一族**（已接線，由 `post_voucher()` 寫）—— 列上去只為讓 15＝6＋1(id)＋8 的加總對得起來，**而它是特例**；🔴 **接線那天三個寫入點要一起改**（只改一支 ⇒ 建立的沒值、重開的有值 ⇒ 更難查）；⚙️ 守門釘「**三支 INSERT 的欄位清單相同**」，**不要**釘「欄數＝表欄數−N」（後者過期是紅燈，而最省力的反應是把 N 加一）；✅ 裁**現在就加守門** |
| **JV22** | 🔴 **傳票退回要留長期記憶**（使用者：顯示上次退回與這次編修的內容，**不能刪除**）；⚙️ 現況兩半：**退回原因已進 `audit_log`**（一段組好的字串）而傳票頁沒讀它；**「編修了什麼」完全沒有記錄**；🔑 先例＝報價單 `data_json.editHistory` ＋ `_summarize_quote_changes()`，**先問能不能沿用**不要先設計；🔴 「不能刪除」要分三層（不提供入口／端點拒絕／**作廢後仍保留**）；⚠️ 退回會**原地換單號**（`next_revision_no`）⇒ 記錄掛在哪個識別上要先查；☠️ **不可以做成可編輯的備註欄** —— 下一個人會很自然地加上編輯功能 |
